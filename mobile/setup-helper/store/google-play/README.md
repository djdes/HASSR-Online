# «Сетап помощник» в Google Play — что готово и как загрузить

Всё для публикации лежит в этой папке:

| Файл | Что внутри |
|---|---|
| `listing-ru.md` | название, краткое и полное описание, категория, контакты, «Что нового» |
| `data-safety.md` | ответы для анкеты «Безопасность данных» |
| `app-content.md` | остальные пункты раздела «Контент приложения»: доступ для проверки, реклама, рейтинг, аудитория, разрешения |
| `graphics/` | значок 512×512, баннер 1024×500, скриншоты 1080×1920 |

Ссылки для анкет:
- политика конфиденциальности — https://wesetup.ru/setup-helper/privacy;
- удаление аккаунта — https://wesetup.ru/delete-account.

## Сборка для Play

Приложение собирается в двух вариантах, подробно — в `../../README.md`, раздел «Сборка»:
- **`play`** идёт в Google Play: формат AAB, самообновления нет. Play запрещает
  приложению ставить обновления в обход магазина.
- **`site`** раздаётся на wesetup.ru и обновляется само.

Готовый AAB собирает GitHub:
1. Откройте Actions → «Сетап помощник — проверка».
2. Скачайте артефакт `setup-helper-play-aab-N` — это файл `app-play-release.aab`.

AAB подписан нашим ключом выпуска (`../../README.md`, раздел «Подпись»). В Play этот ключ будет ключом загрузки.

## Порядок загрузки

### 1. Аккаунт разработчика — делает владелец
- https://play.google.com/console, взнос 25 $. Российские карты Google не принимает.
- Аккаунт **организации** требует номер D-U-N-S (бесплатно, 1–4 недели) и даёт публиковать сразу.
- **Личный** аккаунт требует сначала закрытое тестирование: не меньше 12 тестировщиков, 14 дней подряд (шаг 7).

### 2. Создать приложение
«Все приложения» → «Создать приложение»:
- название — «Сетап помощник: этикетки»;
- язык по умолчанию — русский;
- тип — «Приложение», «Бесплатное»;
- подтвердить декларации.

### 3. Подпись приложения (Play App Signing) — важно

Выберите «Использовать существующий ключ подписи» → «Экспортировать ключ из хранилища Java». Тогда версия из Play и версия с сайта подписаны **одним ключом**. Телефоны с версией с сайта смогут обновиться из Play без переустановки.

1. Скачайте из консоли `pepk.jar` и `encryption_public_key.pem`. Положите их рядом с ключом:
   - на рабочем компьютере — `C:\Users\Oleg\.wesetup-keys\`;
   - или на сервере — `/var/www/wesetupru/data/secrets/setup-helper/`.
2. Выполните команду. Пароль спросит; он лежит в `setup-helper-release.env`:
   ```
   java -jar pepk.jar --keystore=setup-helper-release.jks --alias=setup-helper --output=setup-helper-signing-key.zip --include-cert --rsa-aes-encryption --encryption-key-path=encryption_public_key.pem
   ```
3. Загрузите `setup-helper-signing-key.zip` в консоль.
4. Удалите zip и `pepk.jar`.

Если выбрать ключ, который создаст Google, публикация тоже пройдёт. Но тогда версии с сайта и из Play будут несовместимы: при переходе приложение придётся переставлять.

### 4. Демо-аккаунт для проверки Google
Проверяющим нужен рабочий вход. Нужна отдельная организация «Google Play — проверка» и в ней руководитель:
- вход по почте и паролю, **без кода из Telegram**;
- реальных данных клиентов в ней нет.

Принтер проверяющим не нужен. Кнопка «Посмотреть шаблоны этикеток» на главном экране открывает все шаблоны и предпросмотр без принтера. Почту и пароль впишите в «Доступ к приложению» (`app-content.md`).

### 5. «Контент приложения»
Заполните по `app-content.md` и `data-safety.md`:
- политика конфиденциальности;
- доступ к приложению;
- реклама — нет;
- возрастной рейтинг — 3+;
- целевая аудитория — 18+;
- безопасность данных;
- новостное, государственное, финансовое, медицинское приложение — нет.

### 6. Карточка магазина
«Развитие» → «Представление в магазине». Тексты — из `listing-ru.md`, картинки — из `graphics/`.

### 7. Тестирование
1. «Внутреннее тестирование» → «Создать выпуск»:
   - загрузите `app-play-release.aab`;
   - заметки о выпуске — из `listing-ru.md`;
   - добавьте свои почты как тестировщиков и установите по ссылке.
2. Только для личного аккаунта: «Закрытое тестирование». Нужно 12 и больше тестировщиков на 14 дней, затем подать заявку на доступ к рабочей версии.

### 8. Рабочая версия
«Рабочая версия» → «Страны»:
- Россия;
- при желании Узбекистан, Казахстан и другие — в приложении русский интерфейс.

Создайте выпуск с тем же AAB и отправьте на проверку. Проверка занимает от нескольких часов до недели.

## Следующие версии

1. Поднимите `appVersionName` и `appVersionCode` в `app/build.gradle`. Номер общий для сайта и Play и только растёт.
2. Заполните `app/release-notes.txt`.
3. Push в master: GitHub соберёт APK для сайта и AAB для Play.
4. **Сайт:** запустите `gh workflow run setup-helper-check.yml -f publish=true` и закоммитьте файлы в `resources/setup-helper/` (`../../README.md`).
5. **Play:** загрузите новый AAB в консоли, в нужный трек.

## Что приложение отправляет на сервер — сверять при изменениях

Почта при входе, модель телефона, версия, id установки, Bluetooth-имя и адрес принтера, отметки о печати (шаблон, копии, время).

Тексты этикеток и история печати остаются на телефоне.

Если это изменится, обновите:
- `data-safety.md`;
- `src/app/setup-helper/privacy/page.tsx`;
- анкету в консоли.
