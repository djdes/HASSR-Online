## Что делаем

Всё, что раньше предлагалось ставить на сервер (GlitchTip, смоук с сервера после выката), переносим в облако:
облачные сессии Claude, GitHub Actions и бесплатный Sentry. На прод-сервер ничего не ставим.

## Критерии приёмки

- **AC1 — смоук одной командой в облачной сессии.** `npm run smoke:local` (`scripts/smoke/run-local.sh`) сам
  поднимает локальный Postgres, создаёт роль и базу (если их нет), применяет схему и сиды, запускает `next dev`
  на свободном порту, гоняет сценарии на базе (`scripts/e2e/run-all.sh`) и смоук в браузере
  (`new-features.smoke.cjs`), гасит сервер и возвращает ненулевой код при любом сбое. Работает только с
  локальной базой. Проверка: полный прогон здесь проходит, лог в `raw/`.
- **AC2 — Playwright MCP в облачных сессиях.** Плагины из `.claude/settings.json` облачная сессия не ставит, а
  `.mcp.json` репозитория подхватывает без вопросов (документация cloud-environments). Добавить `.mcp.json` с
  сервером `playwright` через обёртку `scripts/dev/playwright-mcp.mjs`: закреплённая версия `@playwright/mcp`,
  браузер облака (`CHROME_PATH` / `/opt/pw-browsers/chromium`), `--no-sandbox` только под root, headless в
  контейнере; на компьютере владельца — обычный Chrome. Проверка: рукопожатие MCP, список инструментов и
  открытие страницы через `browser_navigate` здесь.
- **AC3 — проверка прода из облака по расписанию.** `.github/workflows/prod-monitor.yml`: каждые 15 минут
  (и вручную) `scripts/monitor/prod-check.mjs` без зависимостей проверяет `/api/health` (ok, база, версия),
  `/`, `/login`, `/robots.txt`, `/sitemap.xml` по содержимому и что прод не отстаёт от master больше часа.
  Из зарубежных дата-центров TLS к серверу рвётся примерно через раз — повторы на каждую проверку; сетевые
  сбои при живых остальных проверках не считаются падением; тревога в Telegram (тот же бот и чат, что у
  выката) только со второго подряд упавшего запуска, и одно сообщение о восстановлении. Состояние между
  запусками — в кэше Actions, запуск не краснеет (без писем GitHub о каждом сбое). Логика решений покрыта
  unit-тестами (`src/lib/prod-monitor.test.ts`).
- **AC4 — облачное окружение Claude для репозитория.** Скрипт подготовки (зависимости, `prisma generate`,
  роль/база/схема/сиды Postgres, прогрев `@playwright/mcp`) прогнан здесь из родительской папки; предложено
  личное окружение «HASSR-Online» с этим скриптом через `create_environment` (решение — за владельцем в окне
  подтверждения).
- **AC5 — бесплатный Sentry.** Аккаунт на почту владельца (регион EU) зарегистрирован; после ссылки из письма —
  проект Next.js и DSN; подключение `@sentry/nextjs` отдельным PR: без персональных данных, запись сессии
  только при ошибке и со скрытым текстом, отправка через свой домен. Если ссылка не пришла — AC5 остаётся
  открытым и это сказано владельцу (не заявлять готовность).
- **AC6 — проверки.** `npm run typecheck` — 0 ошибок, `npm run test:changed` — зелёный, CI на PR зелёный.

## Вне объёма

- Авторизованные проверки прода (нужен отдельный аккаунт на проде и секрет в GitHub).
- Argos/Percy (вход через GitHub владельца и установка GitHub App — может сделать только владелец).
- Настоящие iPhone (BrowserStack/Kobiton платные).
