# Группа D: серверные писатели `JournalDocument.config` не затирают чужие данные

Дата: 2026-11-26. Статус: **заморожено** (критерии ниже не меняются по ходу работы).

## Контекст

Класс ошибки (PR #357): один путь записи заменяет целую JSON-запись и стирает
поля / строки, которые записал другой участник. Группа D — серверные писатели
конфига документа: адаптеры TasksFlow, внешний API, каскады. Веб-PATCH
(`src/app/api/journal-documents/[id]/route.ts`), `src/lib/brakerage-row-merge.ts`
и маршруты записей — группа C, здесь не трогаются.

## Критерии приёмки

- **AC1 (D1, новая строка на каждую отправку).** Отправка формы задачи TasksFlow
  (`POST /api/task-fill/[taskId]` и `POST /api/integrations/tasksflow/complete`)
  в строчный журнал, где каждая запись — новая строка (`journalFillHints(code).append`:
  бракераж готовой продукции, скоропорт, интенсивное охлаждение, входной контроль,
  списание), передаёт адаптеру уникальный ключ строки (как QR: `<rowKey>#…-<время>`).
  Сценарий: повар отправил блюдо A, комиссия подписала строку A, повар отправил
  блюдо B той же задачей → в журнале две строки, строка A с прежними значениями и
  подписями, строка B без подписей. Для остальных журналов ключ не меняется.
  Сотрудник из нового ключа извлекается как раньше (`extractEmployeeId`).
- **AC2 (D1, выполнение без значений).** Выполнение задачи на стороне TasksFlow без
  значений формы (pull-синхронизация `pullCompletionsForOrganization`, вебхук
  `task-complete`) не стирает и не перезаписывает существующую строку журналов
  бракеража готовой продукции, скоропорта, интенсивного охлаждения, а также строк
  плана аудита, протокола аудита и плана обучения (их запись без значений сбрасывала
  поля в пустые): адаптер возвращает `false`, конфиг не меняется.
- **AC3 (D2, блокировка документа в адаптерах).** Все адаптеры TasksFlow, которые
  читают и переписывают `JournalDocument.config` (приёмка/входной контроль, аварии,
  план/протокол/отчёт аудита, поломки, уборка (матрица пар), жалобы, дезсредства,
  калибровка, ТО оборудования, стеклянные предметы, интенсивное охлаждение, металл,
  СИЗ, списание, обучение, прослеживаемость, план обучения), делают
  «прочитал → поменял → записал» под `withDocumentConfigLock` (SELECT … FOR UPDATE),
  читая конфиг внутри блокировки. Две одновременные отправки в один документ
  сохраняют обе записи. Прямых `db.journalDocument.update({ data: { config } })` в
  этих адаптерах не остаётся.
- **AC4 (D3, внешний API).** `dispatchExternalEntries` читает документ под
  блокировкой строки (`FOR UPDATE` в той же транзакции, что и запись) и считает
  новый конфиг от прочитанного под блокировкой. Для журналов-«конфиг-писателей»
  списки записей (`rows`, а также `receipts`/`consumptions` дезсредств и
  `findings` отчёта аудита) из `data` сливаются по `id`: строка с известным `id`
  обновляется (поля, которых нет в запросе, остаются, напр. подписи), новые
  дописываются, отсутствующие в запросе — остаются. Остальные ключи и `appendX` —
  как раньше. Публичная документация (`/developers`, `/settings/api`, OpenAPI)
  семантику замены строк не обещает.
- **AC5 (D4, каскады).** `applyResponsiblesToDocuments`
  (`journal-responsibles-cascade.ts`) и `syncPointDocumentRows`
  (`point-document-rows-sync.ts`) пересчитывают и пишут конфиг документа от
  прочитанного под `withDocumentConfigLock`; правка строк, сделанная между
  чтением списка документов и записью, не теряется.
- **AC6 (без регрессий).** Обычные потоки не меняются: персональные журналы
  (гигиена и т. п.) получают прежний `rowKey`; повторная отправка одной и той же
  строки QR/TasksFlow-пакета (`appendFinishedProductRows` c одинаковым ключом) всё
  ещё обновляет свою строку; существующие тесты затронутых модулей проходят;
  временный tsc по изменённым файлам — 0 ошибок; ESLint по изменённым файлам —
  0 ошибок.

## Вне объёма

- Веб-PATCH документа, `brakerage-row-merge.ts`, маршруты записей (группа C).
- Писатели `JournalDocumentEntry` (upsert ячеек) — отдельный класс.
- Пустая строка, которую дописывают «чистые» append-адаптеры (аварии, СИЗ и т. п.)
  при выполнении без значений: данных не теряет, упомянуть в PR.
