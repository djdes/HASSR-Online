# QR: сотрудники только своей точки + УФ-лампа без температуры

Дата: 2026-10-27. Ветка: `fix/qr-point-uv` (от `origin/master` 54ff67f5).

## Задача (от владельца)

1. Сотрудник сканирует QR холодильного оборудования — в «Кто вы?» все
   сотрудники всех точек организации. Должны быть только сотрудники той
   точки, где этот объект / журнал.
2. Журнал УФ-лампы: исправить ввод температуры — температур там нет.

## Решения

- Точка оборудования — точка его цеха: `Equipment.area.buildingId`
  (модель «точка → помещение → оборудование» с 2026-10-18, коммит 0e0bdfc7).
  Новое поле не нужно; владелец выбрал «точку у оборудования» — она уже есть
  в окне оборудования («Точка» → «Помещение»).
- Точка склада — `Room.buildingId`, журнального QR — `JournalDocument.buildingId`.
- «Работает на точке» — те же правила, что `workBuildingsForUser`: пустой
  `buildingIds` — везде; в списке только удалённые точки — везде; сотрудник
  офиса работает в офисе, не на торговой точке. Руководство не исключение.
- Фильтр действует, только когда точки включены (`buildingTargets` ≠ `[null]`).
- Список на экране и проверка при сохранении — одно правило.

## Acceptance criteria

- **AC1.** Чистая функция `worksAtBuilding` в `src/lib/building-scope.ts`
  с тестами: пустые точки, только удалённые точки, своя точка, чужая точка,
  сотрудник офиса на торговой точке, объект без точки.
- **AC2.** Наклейка оборудования (`/equipment-fill/<id>`: холодильник,
  УФ-лампа, фритюрница) при включённых точках показывает только сотрудников
  точки цеха; цех без точки или точки выключены — список как раньше.
- **AC3.** Наклейка склада (`/room-fill/<id>`) — только сотрудники точки
  помещения (при включённых точках).
- **AC4.** QR журнала (`/journal-fill/...`) — список «Кто заполняет» по
  точке выбранного документа; документ без точки — как раньше.
- **AC5.** Сохранение проверяет то же правило: POST холодильника, фритюрницы,
  УФ-лампы, склада и отправка формы журнального QR отвечают 403 с понятным
  текстом (`equipmentFill.errors.otherPoint` у объектов).
- **AC6.** Режим «только через вход»: вошедший сотрудник другой точки видит
  на наклейке оборудования и склада понятный экран «другая точка», а не
  пустой список; на журнальном QR — сообщение.
- **AC7.** Окно оборудования с типом «УФ-лампа»: нет полей «Мин./Макс.
  температура» и «Tuya Device ID» (датчик температуры); температура не
  проверяется; сохранение лампы стирает старые нормы температуры.
- **AC8.** Одно правило «это УФ-лампа» `isUvLampEquipment({ type, name })`:
  лампа старого типа «Другое» с названием «УФ-лампа» открывает на наклейке
  «Я включил / Я выключил», а не форму температуры; «Холодильник Уфа» и
  холодильник/морозильник лампой не считаются. Применяется: страница
  наклейки, API УФ, запрос PIN, область журнала по QR, страница точки,
  начальный тип в окне оборудования.
- **AC9.** Лампы не попадают в конфиг журнала холодильников
  (`buildColdEquipmentConfigFromEquipment`), правка лампы не переносит нормы
  в документы холодильников.
- **AC10.** Печатная наклейка УФ-лампы: надзаголовок «УФ-лампа» вместо
  «Температура», шаги «Я включил / Я выключил», без строки «норма …°C».
  Наклейка фритюрницы — надзаголовок «Фритюрница» и шаги про жарку.
- **AC11.** Таблица `/settings/equipment`: у лампы в колонке диапазона —
  остаток ресурса, не «—»/температура.
- **AC12.** `whats-new-notes.ts` обновлён; каталоги ru/en/uz полные
  (`npm run i18n:check`), резервная копия `equipment-fill-ru.generated.ts`
  перегенерирована.
- **AC13.** `npm run typecheck`, `npm run test:gate`, eslint изменённых
  файлов — зелёные.

## Не входит

- Состав документа холодильников точки (сейчас всё оборудование
  организации) — отдельная задача.
- Поля УФ в форме Mini App `/mini/claim`.
