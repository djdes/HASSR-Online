# Прогрев после деплоя упирается в лимит переходов (429)

## Проблема
Деплой #2036 (5c07e19): почти все адреса `scripts/prewarm-routes.sh` получили
429. Запросы curl к `127.0.0.1:3002` идут без `X-Real-IP` → общий бюджет
`ip:unknown`, curl считается автоматикой (6 страниц за 10 с, 30 в минуту,
пауза 30 с). Ответ 429 отдаёт proxy до страницы, поэтому прогрев её не
загружает: первые посетители после рестарта попадают на холодные страницы.
Тот же бюджет потом съедает проверку после рестарта (6 попыток по 429).

## Решение
Одноразовый ключ прогрева на каждый деплой. Шаг 3 деплоя генерирует
случайный `DEPLOY_WARM_TOKEN` (32 байта) до `pm2 start`; процесс сайта
получает его в окружении. Прогрев шлёт его в заголовке `x-deploy-warm`
(из файла, не в аргументах curl). Ограничитель пропускает запрос только при
точном совпадении (сравнение постоянного времени) с ключом из окружения
процесса длиной не меньше 32 символов. Без ключа в окружении (dev, тесты,
старый процесс) исключений нет. Пороги, ключи бюджета и поведение для всех
остальных запросов не меняются.

## Критерии приёмки
- AC1. Запрос страницы с верным `x-deploy-warm` при заданном
  `DEPLOY_WARM_TOKEN` (≥ 32 символа) не ограничивается и не тратит бюджет
  адреса; прочие проверки proxy (404 для `/root`, редиректы прав) остаются.
- AC2. Неверный, пустой, другой длины ключ, ключ при пустом или коротком
  `DEPLOY_WARM_TOKEN` — обычное ограничение (429 после 6 запросов curl).
- AC3. `scripts/prewarm-routes.sh` при заданном `DEPLOY_WARM_TOKEN` шлёт
  заголовок на каждый адрес, ключа нет в командной строке curl; в конце
  пишет число адресов, ответивших 429. Без ключа работает как раньше.
- AC4. `deploy.yml` шаг 3 создаёт ключ до `pm2 start` сайта, в лог его не
  пишет; actionlint и `bash -n` чисты.
- AC5. Живая проверка на dev-сервере: curl без ключа получает 429 после 6
  запросов, с ключом — нет; `npm run typecheck`, `npm run test:gate` зелёные.
- AC6. `docs/page-navigation-guard.md` описывает исключение для прогрева.
