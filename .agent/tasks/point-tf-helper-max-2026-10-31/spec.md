# TasksFlow «Отправить всем», «Сетап помощник» и бот Max — только своя точка

Дата: 2026-10-31. Ветка `fix/point-tf-helper-max` от `origin/master` 39d9d990.

Источник — аудит «похожих проблем» после жалобы партнёра «чтобы ТТ не своё
просто не видела» (журналы точек, PR #65–#67). Нашлось три места на стороне
сотрудника, где точка получает чужое:

1. TasksFlow «Отправить всем» (`bulk-assign-today`, автозапуск после
   саморегистрации — тот же маршрут): документ каждой точки рассылается
   кандидатам со всей организации, строки адаптеров
   (`listDocumentsForOrg`) — по всем сотрудникам организации. Сотрудник
   получает «Гигиена · Точка 2», «Холодильники · Точка 2» и т.д.
2. «Сетап помощник» (`/api/setup-helper/catalog`): телефон сотрудника точки
   получает сотрудников и блюда (документы бракеража) всех точек.
3. Бот Max: предлагает документы всех точек, а запись из мессенджера не
   проверяет точку (`journal-fill-submit`, ветка `messenger`); сводка и
   напоминание руководителя точки — по всей организации.

## Правило точки (как у QR и журналов точек)

- Точки включены: `perLocationJournals` и ≥ 2 точек (`buildingTargets`).
- Документ точки — `buildingId` из точек организации; документ без точки —
  общий, без фильтра.
- Сотрудник работает на точке — `worksAtBuilding` (building-scope): пустой
  `buildingIds` — везде; в списке только удалённые точки — везде; сотрудник
  офиса — в офисе.
- Точки человека — `userBuildingTargets` (пустой `buildingIds` — все точки,
  то есть без ограничения).
- Точки выключены — всё как раньше.

## Критерии приёмки

- AC1. Строки адаптеров TasksFlow у документа точки — без строк сотрудников
  других точек (строки без исполнителя остаются). Действует для всех
  потребителей реестра (`listAdapters` / `getAdapter`): «Отправить всем»,
  каталог журналов TF, привязка строки, строки QR/Max. Общий документ и
  выключенные точки — без изменений.
- AC2. «Отправить всем» для документа точки: кандидаты fan-out, режимы
  «по зонам» (только цеха точки и общие), «по сменам», «по очереди»,
  «каждому из ответственных» — только сотрудники точки документа.
- AC3. «Сетап помощник»: телефон сотрудника, закреплённого за точками, —
  сотрудники только его точек (и без точек), блюда — только из документов
  его точек и общих. Сотрудник без точек, руководство на всю компанию,
  точки выключены — как раньше. Продукты общие для организации (у `Product`
  нет точки) — без изменений.
- AC4. Бот Max: список документов журнала — только документы точек
  сотрудника и общие; запись из Max проверяет точку документа тем же
  правилом, что QR (403 «Этот сотрудник работает на другой точке…»).
- AC5. Бот Max, руководитель, закреплённый за точками: сводка «кто не
  заполнил» и напоминание — только обязательства его точек (и общие).
- AC6. Unit-тесты на чистые правила (строки адаптеров по точке, кандидаты
  точки, область точек сотрудника, документы и люди области);
  `npx tsc --noEmit --skipLibCheck`, eslint изменённых файлов, затронутые
  тесты зелёные. Реальный API TasksFlow не вызывается.

## Принципы TasksFlow (П-1…П-19)

Меняется только выбор, КОМУ из сотрудников Wesetup назначать задачи
документа точки. Создание задач, outbox, Idempotency-Key, sync, статусы —
без изменений; в БД TF не ходим (П-12).

## Не входит

- Ответственные журналов (`/settings/journal-responsibles`) — одни на
  организацию; per-point — решение владельца.
- Создание задач в `bulk-assign-today` напрямую через клиент TF, а не через
  outbox (как было до правки) — отдельная задача по П-15.
- Продукты/номенклатура без точки.
