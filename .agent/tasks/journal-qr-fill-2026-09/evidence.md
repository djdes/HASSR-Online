## Круг 5 (2026-09-20): QR-форма переписана на серверный HTML

Причина: на iPhone владельца страница открывалась ~10 с. По логу nginx все файлы React-версии приходили за секунду, но клиентские скрипты (≈300 КБ gz: Next runtime + React + общие чанки) оживляли страницу через 12–19 с; при эмуляции slow-4G — 10 с. Решение: `/journal-fill/[orgId]/[code]/route.ts` отдаёт готовый HTML (~13 КБ, инлайн-стили, без шрифтов и общих чанков), все шаги — ссылки и `<form method="post">`, инлайн-скрипт необязателен. Общее ядро записи `lib/journal-fill-submit.ts` используется и JSON-API.

## Круг 11 (2026-09-20): пустое поле — понятная ошибка, «Выключено / Нет показания» вместо выдуманного нуля

Запрос владельца по скриншоту: при пустых полях сырая ошибка «Invalid input: expected number, received undefined», хотя подсказка говорит «оставьте пустым и сообщите начальнику»; придумать элегантнее (не 0), и так по всем журналам ввода.

Решение: пустое обязательное поле — не ноль и не прочерк молча, а явная пометка. В карточке холодильника чекбокс-чип «Выключено» (у складов — «Нет показания»): поле гаснет и перестаёт быть обязательным, в журнал идёт прочерк с пометкой в `corrections`, руководитель получает уведомление в Telegram (`notifyOrganization`, тип temperature) и в колокольчик (`notifyManagement`, kind `qr-fill-off`). Если ничего не отмечено и поле пусто — понятная ошибка «Не заполнено: «…», «…»» с подсветкой карточек и подсказкой про пометку; во всех журналах QR-формы пустые обязательные поля теперь перечисляются по названиям (обработка `ZodError` в `submitJournalFill`, `badKeys` → подсветка). Комментарий «что сделали» при отклонении теперь сохраняется и в холодильниках/климате (`corrections` по ключу оборудования / `climateCorrectionKey`), раньше для них он терялся.
