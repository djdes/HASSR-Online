# QR-ввод во все журналы без входа + бракераж: температура по памяти, миграция номенклатуры, «Изменить» из выделения, симметричная печать

## Context

Владелец (2026-09-19): 1) «Т°C внутри продукта» подставлять по прошлому вводу для этого блюда (если колонка включена); 2) ранее введённая номенклатура должна быть в подсказках у каждой организации — миграция с бэкапом; 3) «Изменить» при выделении строки во всех журналах со строками, при нескольких — окна по очереди; 4) на печати ширина шапки = ширине таблицы; 5) QR на ввод данных во **все** журналы без входа: «отсканировал → сайт спросил сотрудника → его температуру → готово», максимально просто; если документов несколько — выбор после сканирования.

Ключевой факт из исследования: у каждого журнала уже есть адаптер (`src/lib/tasksflow-adapters/*`, реестр `index.ts:63-96`, generic-fallback для остальных) с `getTaskForm({documentId,rowKey})` → схема формы и `applyRemoteCompletion({documentId,rowKey,completed,todayKey,values})` → запись в журнал. Обе функции локальные, TasksFlow не трогают (П-12 соблюдён). Рендерер полей `src/components/task-fill/task-fill-field.tsx` чистый и переиспользуемый; валидатор `buildCompletionValidator` в `task-form.ts`. Значит универсальный QR = «сотрудник + строка → форма адаптера → applyRemoteCompletion», без дублирования логики журналов.

## Самокритика первой версии плана (что исправлено)

- QR только для бракеража и отдельная ручная форма — дублировала бы логику; заменено адаптерной формой для всех журналов.
- Автотемпература без флага «подставлено автоматически» затирала бы ручной ввод при смене блюда — добавлен флаг.
- Очередь правок по id ломается, если сохранение пересортировывает строки (приёмка, прослеживаемость) или строка удалена — очередь хранит id и заново ищет строку, пропуская исчезнувшие; отмена явно отличается от сохранения.
- 17 журналов с самодельной полосой выделения сейчас **изменены другим агентом и не закоммичены** (`git status`): правки в этих файлах утащат чужую работу в мой коммит. Правило: перед правкой каждого файла проверять `git diff --quiet -- <file>`; файлы с чужим diff отложить и перечислить в отчёте.
- Повторное сканирование в тот же день: журналы-«записи» (гигиена, здоровье, generic) делают upsert по (документ, сотрудник, дата) — перезапись, а не дубль; журналы-строки (бракераж, приёмка…) — append. Экран результата должен это отражать («Отметка обновлена» / «Строка добавлена · Добавить ещё»).
- Организации с `requireAdminForJournalEdit`: повторная отметка по QR линейным сотрудником должна блокироваться так же, как в `/api/task-fill` (403 → экран «Уже отмечено, изменить может руководитель»).
- Безопасность: QR даёт запись от имени любого сотрудника без входа — та же модель, что у существующих QR холодильника/помещения; ограничители 30/мин на IP+документ, аудит `journal.qr_fill`, `robots: noindex`. Явно проговорить владельцу в отчёте.
- Печать: одной правкой CSS не обойтись — у бракеража ширины `<col>` в `calc(…px)` попадают под правило `col[style*="px"]` (`app-theme.css:1115`); решение — проценты в colgroup + один столбец ширины как в холодильном журнале.

## 1. Универсальный QR-ввод

### Токены и адреса
- `qr-fill-token.ts`: вид `"journal"`, subject `journal:<orgId>:<code>` (`code` = шаблон или `all` для хаба). Бессрочный. `qrFillUrl` → `/journal-fill/<orgId>/<code>?token=`. Расширить `QrFillKind` в `qr-fill-types.ts`, регэксп сканера Mini App `src/app/mini/_components/qr-scanner.tsx:30` (+тест), `robots.ts`, `cookie-consent.tsx`.

### Публичная страница `src/app/journal-fill/[orgId]/[code]/page.tsx` (по образцу `equipment-fill`)
Шаги, каждый на одном экране, крупные кнопки, без лишних полей:
1. **Хаб** (`code=all`): список включённых журналов организации, у которых есть активный документ на сегодня (иконка + название); запомненный последний журнал — сверху.
2. **Документ**: активные документы шаблона без фильтра по точке; один → пропуск; несколько → карточки «название · точка» (`JournalDocument.building`), последний выбор запоминается в `localStorage` по коду.
3. **Сотрудник**: общий ключ `wesetup.qr-fill.employeeId` (существующие страницы холодильника/помещения тоже начинают читать его с fallback на свои ключи) → «Вы: Иванова А. · Сменить». Список — `ORG_ROSTER_WHERE`.
4. **Строка** — только для адаптеров с сущностными строками (уборка: помещения сотрудника, поверка/обслуживание оборудования, аудит-план/протокол, план обучения, список стекла, санитарный день, климат по времени контроля): кнопки из `adapter.listDocumentsForOrg` (rows документа, отфильтрованные по `responsibleUserId` = сотрудник, иначе все). Для per-employee адаптеров пропускается (`rowKey = employee-<id>`).
5. **Форма**: `GET /api/journal-fill/<orgId>/<code>/form?token&documentId&rowKey` → `getTaskForm`; рендер полями `TaskFillField`, дефолты как в `task-fill-client.tsx:93-145` (время = сейчас, ФИО = сотрудник, «Всё в норме»); pipeline-шаги — как чек-лист. Кнопка «Сохранить».
6. **Результат**: «Записано в <журнал> за сегодня» + для append-журналов «Добавить ещё» (сохранённые время/люди остаются), иначе «Готово». Ошибка сети — понятная, повтор.

**Улучшения ввода поверх адаптерной формы** (карта подсказок Wesetup, DSL адаптеров не трогаем — TF-клиент её тоже читает): `src/lib/journal-fill-hints.ts` по коду журнала: какие текстовые поля — наименование (scope `dish`/`product` → `SuggestInput` + чипы недавних через публичный `GET …/suggestions?token`), какие — время (чипы «−15/−30/−45/−1 ч/Сейчас», дефолт для бракеража −30), дефолты (`organoleptic: "Отлично"`), автоподстановка `productTemp` из памяти (п. 2).

### API `src/app/api/journal-fill/[orgId]/[code]/route.ts`
`POST { token, documentId, rowKey, employeeId, values }`: лимитер `qrFillRateLimiter` по `ip:journal:documentId`; `verifyQrFillTokenFor(token,"journal", `${orgId}:${code}`)`; документ активен и принадлежит org; сотрудник по `ORG_ROSTER_WHERE`; rowKey допустим (per-employee → `employee-<employeeId>`, иначе из `listDocumentsForOrg`); `buildCompletionValidator(getTaskForm(...)).parse(values)`; гейт `requireAdminForJournalEdit` как в `api/task-fill/[taskId]/route.ts:123-148`; `applyRemoteCompletion(...)`; `remember` наименований в `NameSuggestion` (по карте подсказок); `recordQrFillAudit` (расширить `kind` на `"journal"`, entity `JournalDocument`); `formFillTiming` с `source: "qr-journal"`. Ответ `{ mode: "appended"|"updated", documentTitle }`.

### Режим QR — настройка организации (решение владельца)
- `Organization.qrFillMode: "public" | "auth"` (`@default("public")`, аддитивно). Переключатель в «Настройки → Соответствие» (`compliance-client.tsx`, PATCH `/api/settings/compliance`) с пояснением: **Публичная форма** — любой, кто отсканировал плакат, выбирает имя из списка; быстро, но при проверке данные можно оспорить. **Через вход** — после сканирования сотрудник входит под своим логином/паролем (или через Telegram), имя не выбирается, запись подписана его аккаунтом; для проверяющих это достоверная подпись.
- Режим действует на **все** QR-формы: `/journal-fill/*`, а также существующие `/equipment-fill/*` и `/room-fill/*` (их страницы и API читают тот же флаг).
- **В режиме `auth`**: публичная страница вместо выбора сотрудника требует сессию — если её нет, `redirect("/login?next=<текущий путь>")` (страница входа уже понимает `next`, `login-client.tsx:19-22`; `requireAuth` сегодня теряет путь — добавить хелпер `requireAuthWithReturn(path)` для QR-страниц). Сотрудник = пользователь сессии; руководитель (`isManagementRole`) может выбрать другого сотрудника (список показывается только ему). Запись идёт с реальной сессией: аудит от имени пользователя, `formFillTiming.source: "qr-journal-auth"`. Лимитер остаётся.
- Mini App: в режиме `auth` сканер Mini App, распознав `/journal-fill/…`, открывает форму внутри приложения (`/mini/open?href=`), сессия там уже есть — вход не нужен.
- Для смены режима у плакатов ничего перепечатывать не надо: адрес тот же, различается только поведение страницы.

### Где взять QR
- `/settings/qr-posters?kind=journals`: плакат хаба «Все журналы» + плакат на каждый включённый журнал (`loadQrPosters` для `kind=journal`), обе раскладки (плакат/наклейки).
- На странице списка журнала (`JournalTopBar`, слот рядом с `createSlot`) кнопка «QR для заполнения»; в меню документа (`DocumentActionsBar menuItems`) пункт «QR: заполнить с телефона» → превью `QrFillPreview kind="journal"` (через `/api/qr-fill/journal/<orgId>:<code>`).
- Mini App: те же клиенты; ссылка из QR открывается во внешнем браузере (форма публичная — ок).

## 2. Температура по блюду + память номенклатуры с миграцией

- `NameSuggestion.meta Json?` (`dish`: `{ productTemp?: string }`). `GET /api/name-suggestions` → `{values, meta}`; `POST` принимает `meta` (пустую температуру не затирает). Хук: `remember(values, meta?)`, `metaFor(name)`.
- Бракераж (`finished-product-document-client.tsx`) и QR-форма: при выборе блюда (чип, список, точное совпадение без учёта регистра) и видимой колонке `temp` и поле пустое **или подставлено автоматически** → `productTemp = metaFor(name).productTemp`, флаг `productTempAuto`; ручной ввод снимает флаг; подпись под полем «по прошлой записи». Fallback без сети — по строкам текущего документа. При сохранении `remember([name], {[name]:{productTemp}})`.
- Миграция `scripts/backfill-name-suggestions.ts` (шаблон `scripts/migrate-journal-rooms-to-directory.ts`: dry-run по умолчанию, `--apply`, идемпотентно): все документы `finished_product`, `intensive_cooling` → `dish`; `perishable_rejection`, `incoming_control`/`acceptance`/`incoming_raw_materials_control` → `product`; `lastUsedAt` = дата строки (иначе `updatedAt` документа, не позже «сейчас»), `useCount` = вхождения, `meta.productTemp` из самой свежей строки с непустой температурой; upsert по `(organizationId, scope, value)` с `lastUsedAt = max`. Отчёт по организациям.
- Порядок на проде: dry-run через туннель → по SSH `pg_dump -Fc -t '"NameSuggestion"' -t '"JournalDocument"' > backups/name-suggestions-<дата>.dump` → `--apply` на сервере → повторный dry-run = 0 изменений.

## 5. Дополнительные улучшения (продуманы отдельно)

**Включаю в эту задачу** (дёшево, сильно упрощает ввод):
- **Третий режим QR — «PIN»** (`qrFillMode: "public" | "pin" | "auth"`): сотрудник выбирает имя и вводит личный 4-значный PIN (`User.qrPin`, bcrypt, задаётся в карточке сотрудника и в Mini App «Профиль»). Достовернее публичной формы, проще пароля на чужом телефоне; 5 ошибок — блокировка на 15 минут. Руководитель выбирает любой из трёх режимов.
- **«Отметиться во всех» после сохранения**: экран результата показывает список ежедневных журналов сотрудника на сегодня (per-employee адаптеры) с галочками «✓ отмечено / ○ ещё нет» и кнопкой «Дальше →» к следующему неотмеченному — один скан хаба закрывает всю смену. Считается по сегодняшним `JournalDocumentEntry`/строкам через существующую логику «Сегодня осталось».
- **QR из документа ведёт сразу в документ**: subject `journal:<orgId>:<code>:<documentId>` (плакат из меню документа) — без экрана выбора; QR журнала/хаба — с выбором.
- **Отклонение — сразу комментарий**: если числовое поле вне нормы (`min/max` схемы), под ним раскрывается «Что сделали» (обязательное), значение подсвечено красным — как в кабинете, чтобы инспектор не видел «заметили и проигнорировали».
- **Поиск сотрудника** в публичном режиме при ростере > 12: строка поиска, последний выбор первым, группировка по должности.
- **Применить ко всем выделенным** — вторая кнопка рядом с «Изменить по очереди»: окно с полями и галочками «менять это поле» (время снятия, проверяющий, оценка…); типичный кейс «поправить время у восьми блюд» за одно окно. Реализация — тот же `rowFields`/диалог строки с режимом `applyFields`.
- **Повторить строку** в полосе выделения бракеража/скоропорта: копия строки с временем «сейчас» — для повторной выпечки одного блюда.
- **Память контрагентов**: scope `partner` (производители/поставщики приёмки и скоропорта) — в тот же `NameSuggestion` и в миграцию; поле поставщика получает подсказки по организации.
- **Экран результата** — «Записано в <журнал> · <точка> · 12:40» с кнопкой «Открыть в приложении» (deep link в Mini App) и «Добавить ещё» для строчных журналов.

**Следующим этапом** (отдельные задачи, в план не входят):

- Уведомление руководителю об отклонении из QR-формы для журналов, где адаптер сам его не шлёт (сейчас так делают только холодильники/климат).
