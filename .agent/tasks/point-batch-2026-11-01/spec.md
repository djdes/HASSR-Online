# Партии и CAPA по точкам (2026-11-01)

Решение владельца: «исправь ссылки проверяющего на одну точку и т. д.» — у партий
и CAPA появилась точка (`Batch.buildingId`, `CapaTicket.buildingId`, схема PR #97;
null — общая запись на всю организацию).

## Критерии приёмки

- AC1. Списки и счётчики партий и CAPA — точка из шапки (её записи и общие) и только
  доступные человеку точки; в «Вся организация» — все, с подписью точки.
- AC2. Карточка, правка, «Подсказать», массовое закрытие записи другой точки —
  «не найдено» / не трогается.
- AC3. Новая партия: из строки приёмки — точка документа приёмки; иначе — точка из
  шапки (явная — только доступная). Новая CAPA: точка из шапки; исполнитель — человек
  этой точки.
- AC4. Автоматические CAPA (IoT-тревога, 3 дня вне нормы, отклонение в журнале,
  аномалия задачи) — точка события; ответственный за «3 дня вне нормы» — руководитель
  точки оборудования. Партия из приёмки Меркурия — точка приёмки.
- AC5. Выбор партии в журнале прослеживаемости, партии в новом документе списания и
  поставщики металлопримесей — точки документа.
- AC6. Отчёты: «Остальное», «Отчёты», ИИ-отчёт за период, архив для проверки, Telegram
  /capa и /batches — по точке.
- AC7. Тесты правил; typecheck 0 ошибок.
