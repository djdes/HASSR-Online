## «Определение по ИНН» — какой метод

`СБИС.ИнформацияОКонтрагенте` (справка Saby: «возвращает информацию о контрагенте, в том числе идентификатор участника
документооборота»; https://saby.ru/help/integration/api/all_methods/companyinfo, https://saby.ru/help/integration/api/sequence/iduserdoc).
Страница метода рендерится JS-ом, поэтому форма взята из: (1) руководства СБИС SDK 1.3.6 (`ReadContragentInfo`, вход
`Контрагент{Идентификатор|СвЮЛ{ИНН,КПП,Название}|СвФЛ{ИНН,Фамилия,Имя,Отчество}}`, выход с `Идентификатор` участника,
пустой — «контрагент отказался/не подключён»); (2) функционального теста библиотеки magdv/sbis против живого Saby:
`params = {"Участник": {"СвЮЛ": {...}, "ДопПоля": "СписокИдентификаторов"}}` → `result.Идентификатор` = массив ящиков
`{ИдентификаторУчастника, Основной, Роуминг, Оператор{Идентификатор,Название}, СостояниеПодключения{Код,Описание}}`.
Разбор защитный (строка/массив/объект), на -32602 — один повтор без `ДопПоля`. Побочный эффект по справке: если
контрагента нет в кабинете, Saby добавляет его в список контрагентов. На нашем кабинете не проверено.

## УПД: PDF, а не XML 5.03

Генератор DocsFlow (`upd-edo-xml.ts` 673 строки + `upd-html.ts` 621 + nds/шаблоны) не переносился: он не проходил ФЛК
Saby (нулевые ID операторов в `ИдФайл`, живой цепочки с УПД не было), а у БФС статус 2 (УСН, без НДС) — это передаточный
документ без счёта-фактуры, для него формализованный XML не обязателен; подписанный КЭП PDF — законный первичный документ.
Цена решения: покупатель не загрузит УПД в 1С автоматически. УПД уходит типом `ДокОтгрИсх` с одним PDF-вложением —
принимает ли Saby неформализованное вложение в «Реализации», нужно проверить на живом кабинете (тестовый документ на 10 ₽).
