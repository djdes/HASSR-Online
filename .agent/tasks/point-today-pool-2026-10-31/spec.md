# Задачи дня по точке: «Сегодня», «Проверка записей», панель заведующей, уведомления

Дата: 2026-10-31. Ветка `fix/point-today-pool` от `origin/master` 39d9d990.

## Откуда

Владелец, 2026-10-31: «проверь похожие проблемы в других местах» после жалобы
партнёра «в журналах темп. режима — всё оборудование организации», «чтобы ТТ
не своё просто не видела». Аудит нашёл, что задачи дня строятся без точки:

- `/api/mini/today` («Сегодня» сотрудника на сайте и в Mini App) зовёт
  `generatePoolForDay` без `buildingId`: повар точки А видит холодильники,
  УФ-лампы и помещения точки Б и берёт документ гигиены любой точки.
- В `journal-task-pool.ts` холодильники, фритюрницы, УФ-лампы и
  оборудование не учитывают точку, даже когда она передана.
- `/api/verifications` и `/api/control-board` — подборка без точки, работы
  и сотрудники всех точек; «Напомнить» с панели — всем.
- Крон «Не отметились по QR» — один список на всю сеть ответственному
  произвольной точки.
- Утренняя сводка руководителю в Telegram — общий итог сети и
  руководителю одной точки.

## Правило

Точки для задач дня (`poolBuildingsFromContext`): точки выключены — вся
организация как раньше; человек смотрит на торговую точку — только она;
руководство в режиме «Вся организация» — каждая точка отдельно, у задачи
название точки; сотрудник офиса — офис. Оборудование точки — цехов этой
точки и цехов без точки (`equipmentBuildingWhere`); сотрудники точки —
отмеченные на ней или без точек (`staffAtBuildingWhere`).

## Критерии

- AC1. `poolBuildingsFromContext` (чистая функция) с тестами: точка, «Вся
  организация», офис, точки выключены.
- AC2. Подборки холодильников, фритюрниц, УФ-ламп и оборудования
  (`journal-task-pool.ts`) при переданной точке — только её оборудование и
  общих цехов.
- AC3. `mergePointPools` / `generatePoolForPoints`: одна точка — подборка как
  есть; несколько — у задач название точки, общий объект один раз; тест.
- AC4. «Сегодня» (`/api/mini/today`) — по точкам из AC1: повар точки А не
  видит холодильник, УФ-лампу и склад точки Б.
- AC5. «Проверка записей» (`/api/verifications`) на точке: работы на
  проверке, в работе и история — сотрудников точки (и «все точки»), «не
  взято» — подборка точки, отключённые журналы — точки. «Вся организация» —
  всё, как раньше, плюс задачи каждой точки.
- AC6. Панель заведующей (`/api/control-board`) на точке: задачи и
  сотрудники точки; «Напомнить» (`/remind`) — только сотрудникам точки.
- AC7. Крон «Не отметились по QR»: по документу гигиены каждой точки —
  свой список (люди точки), свои получатели (ответственные документа),
  ссылка на документ точки, название точки в заголовке; ключ повтора — на
  документ. Организация без точек — как раньше.
- AC8. Утренняя сводка: руководитель одной (живой) точки получает сводку
  этой точки («Компания · Точка»); руководство на всю сеть и висящие id
  удалённых точек — общая сводка; тест.
- AC9. `npx tsc --noEmit --skipLibCheck` — 0 ошибок; eslint изменённых
  файлов; затронутые тесты зелёные; проверка на e2e-базе (не прод):
  `raw/http-check.txt` ALL PASS.

## Не входит

- Состав документов точек, TasksFlow «Отправить всем», «Сетап помощник»,
  бот Max — отдельные PR (параллельно).
- Решения владельца: точка у документов ЭДО / iiko / 1С, ответственные за
  журналы по точкам, общие документы (`buildingId = null`) при включённых
  точках, отчёты и выгрузки.
- `JournalTaskClaim` без точки: на точке работы фильтруются по сотруднику;
  у сотрудника «все точки» работы видны на каждой точке.
