## Что сделано

**1. Блок по ссылке в любой момент.** `src/lib/nps-data.ts` → `npsVisibilityFor()` возвращает
`{ eligible, ask }`: `eligible` — руководитель, которому опрос задают вообще (как раньше: management, не ROOT,
не демо-организация), `ask` — прежние правила 14/90 дней. Оба layout'а (`(dashboard)/layout.tsx`, оболочка
мини-приложения `mini-app-shell.tsx` + `mini-shell-data.ts`) передают в `NpsBanner` `ask` и `canPreview`.
Блок читает `?nps=1` через `useSearchParams` (обёрнут в `Suspense`, как `CompleteProfileNudge`) и
показывается, если `ask || (canPreview && nps=1)`. Просмотр не считается вопросом: крестик без оценки шлёт
«не сейчас» (`npsAskedAt`) только тем, кого спросили по правилам; `npsAskedAt` ставит только ответ — как было.
`/mini?nps=1`: экран входа мини-приложения переносит метку на главную (`withNpsPreview`), на самом экране
входа блок не мелькает. Ссылка работает на любой странице кабинета, не только на `/dashboard`.

**2. «Оставить отзыв» при 4–5.** Одно поле «Сообщение» (текст по умолчанию можно поправить) и два действия:
«Отправить коллеге» (прежний `POST /api/nps/recommend`, без изменений в логике) и «Оставить отзыв» — новый
`POST /api/nps/review` → `src/lib/nps-review.ts` → существующий `submitReview` из `src/lib/balance/reviews.ts`:
оценка ответа — в `rating`, текст — тот же, согласие — галка с текстом из «Баланс и бонусы» (включена по
умолчанию, как там), `consentPublic`, `kind = text`, статус `pending`, модерация ROOT, баллы — только при
одобрении по правилам программы (не менялись), показ на главной — по согласию и тумблеру модератора.
Автор и заведение — как в «Баланс и бонусы»: имя из профиля и название организации ответа; почту или
название организации вместо имени не публикуем (подпись «Руководитель») — там человек видит подпись и
может её поправить, здесь нет. Пока у организации есть отзыв на проверке — 409 «У вашей организации уже
есть отзыв на проверке — дождитесь решения» (свой — «Ваш отзыв уже на проверке…»), второй не создаётся;
проверка и создание — под advisory-замком организации (двойной клик не проходит проверку дважды).
Итог — «Спасибо! Отзыв отправлен на проверку, после одобрения начислим баллы». Модератору — то же
уведомление, что у формы баланса, с пометкой «из опроса». Текст по умолчанию стал общим для письма и
отзыва: без «Привет!» и «ссылка ниже» (в письме приветствие и кнопка уже есть, на главной они лишние).

**3. Связь с отзывами без изменения схемы.** Строка `AuditLog` `nps.review` (сущность `NpsResponse`,
`entityId` — ответ, в деталях `customerReviewId` и `npsScore`, без текста). По ней `/root/nps` пишет у ответа
«оставил отзыв» (ссылка на модерацию), модерация `/root/reviews` — «из опроса». В журнале действий
организации — «Отзыв о WeSetup из опроса», id отзыва скрыт. На `/root/nps` — подсказка, как открыть блок.

**4. Телефон.** Кнопки блока на телефоне — 48 px: «Отправить коллеге», «Оставить отзыв», «Отправить» (1–3) и
крестик (иконка на прежнем месте); на широком экране — прежние 44/36 px, действия — одной колонкой справа.

## Как повторить
1. Своя база и dev-сервер (см. шапку), `node .agent/tasks/nps-reviews-2026-09/raw/e2e-nps-reviews.cjs`.
2. Прогон создаёт свою организацию и пользователей (`nps-rv-<run>@example.com`, пароль для входа
   прописывается в базе), ROOT — из `.env`. Настоящие письма не уходят: `SMTP_HOST` пуст, адреса — `example.com`;
   Telegram-токен фиктивный. Данные прогонов остаются в `wesetup_wt_nps2`, поэтому проверка `/root/nps`
   сверяет пометки с базой, а не считает их «ровно одну».

## Открытые вопросы
- **Найдено попутно, не относится к задаче:** в dev после захода в `/mini` (регистрируется `/mini-sw.js`)
  жёсткая перезагрузка `/dashboard` в оболочке при мобильной эмуляции уходит в цикл перезагрузок (событие
  `load` не наступает, «Failed to sync build state» в консоли). То же на базовом коммите 7941f785 (правки
  задачи временно убраны `git stash`, проверено тем же скриптом), без захода в `/mini` (кука оболочки
  поставлена напрямую) — цикла нет. Похоже на воркер + нехешированные dev-чанки; на проде не проверял.
  e2e поэтому открывает форму в мини-приложении новым входом через `/mini?nps=1`, без перезагрузки.
- **Решения, которые стоит подтвердить владельцу:**
  - текст по умолчанию стал общим: «Мы ведём журналы ХАССП и СанПиН в WeSetup — заполняем с телефона по QR,
    проверки проходим спокойно. Советую!» — меняет и письмо коллеге (раньше «Привет! … Посмотри, ссылка ниже.»);
  - после одного действия блок закрывается (как было с письмом): письмо и отзыв за один раз не отправить,
    второе остаётся в «Баланс и бонусы». Можно оставлять второе действие открытым после первого;
  - галка согласия включена по умолчанию — как в «Баланс и бонусы»; юридически чище снятая;
  - подпись «Руководитель», если в профиле нет имени (или там почта / название организации);
  - отзыв привязан к организации ответа опроса (домашней), у владельца нескольких точек «Баланс и бонусы»
    берёт активную — для одной организации это одно и то же;
  - замок против второго отзыва — только у опроса; одновременная отправка из формы баланса и опроса в одну
    миллисекунду теоретически даст два отзыва на проверке.
- Уведомление модератору в Telegram не проверено вживую (фиктивный токен, чат админа не задан) — код тот
  же, что у формы баланса. Production-сборка не запускалась (место на диске): `useSearchParams` в обоих
  layout'ах обёрнут в `Suspense` (как в репозитории), layout'ы динамические, PPR/cacheComponents не включены.
