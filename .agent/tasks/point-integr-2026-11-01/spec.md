# Датчики и интеграции — данные в журнал своей точки (2026-11-01)

Источник: детальный аудит изоляции точек (запрос владельца «поищи ещё такие
проблемы, детальнее»), группа «integr». Без изменений схемы.

## Acceptance criteria

- **AC1. Датчики Tuya (крон `tuya-pull`).** Показание оборудования точки А
  пишется только в активные документы точки А или общие: где оборудование
  есть в строках (`config.equipment` / `config.rooms`), иначе свой документ
  точки, иначе общий. Документ другой точки не выбирается. Запись
  подписывает человек точки документа (руководитель, без него — сотрудник);
  на точке никого — организация, как раньше. Значение пишется в строку
  этого холодильника, а не мимо неё (`temperatures[<id строки>]`),
  отметки «обсл»/«рем» не перетираются.
- **AC2. Внешний API датчиков (`POST /api/external/sensors`).** Те же
  правила выбора документа и подписанта; влажность в журнал холодильников
  не пишется.
- **AC3. `tuya/collect`.** Автор записи — руководитель точки оборудования,
  а не первый руководитель организации.
- **AC4. `tuya/device`.** Живые показания оборудования чужой точки
  человеку недоступны: 404.
- **AC5. Внешний API записей (`POST /api/external/entries`).** Точка
  документа: `buildingId` из запроса (точка этой организации, сотрудники
  строк на ней работают), иначе единственная общая точка сотрудников строк.
  Сотрудники разных точек — 400. Несколько возможных точек: подходит
  только живой общий документ, иначе 400 «укажите buildingId». Новый
  документ при включённых точках создаётся на точку (с названием точки в
  заголовке), общий — никогда. Помещения климата и люди конфига — точки
  документа. Без точек — как раньше.
- **AC6. Меркурий.** Приёмка по ВСД пишется в журнал входного контроля
  точки площадки ВСД; без точки у ВСД — точки из шапки; без точки вовсе
  (точки включены) — понятный отказ. Оформить приёмку ВСД чужой точки
  нельзя (403). Список ВСД (страница и API) — по точке из шапки, «Вся
  организация» — все. Напоминание о просроченном гашении — по точкам,
  людям точки и офису.
- **AC7. TasksFlow «Отправить всем» из сессии.** С точкой в шапке —
  документы и задачи только этой точки; `force` стирает связи только
  документов этой точки; сообщения о пропущенных журналах — с точкой.
  Крон, внутренний триггер и ключ TasksFlow — как раньше (все точки).
  Транспорт задач не меняется (П-13/П-15/П-19).
- **AC8. CSV списаний для 1С.** У организации с точками — колонка «Точка»
  последней (своя точка записи, иначе точка цеха); без точек файл прежний.
- **AC9. Исходящие вебхуки.** `journal.deviation` и `journal.entry`
  дополнительно несут `buildingId` и `buildingName` (поля добавлены,
  прежние не менялись); точка считается, только если есть подписки.

## Вне группы / вопросы владельцу

- Сопоставление площадок Меркурия с точками: в интерфейсе и API его нет
  (`MercuryEnterprise` никто не создаёт) — нужен экран настройки.
- `journal.deviation` из `api/journals/route.ts` — файл группы docs.
- Партии (`Batch`) из ВСД без точки — нужна колонка в схеме.
