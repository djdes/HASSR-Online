# Spec (frozen 2026-11-20): серия D — надёжность обмена и сеть организаций

Владелец 20.11.2026 после серий A–C2 (#272, #273, #275, #276): «Сделай все кроме 6, 7, 8, 9» из предложенных 12
улучшений. Берём пункты 1, 2, 3, 4, 5, 10, 11, 12.

## Решения

### Р1. Безопасный откат C2 (п. 1)
Скрипт `scripts/directory-exchange-hash-downgrade.ts`: для связей помещений и должностей с отпечатком `v2` пересчитать
отпечаток записи по составу полей v1 (account/foreign как у связи) и записать его. По умолчанию — пробный прогон (только
отчёт: сколько связей по кабинетам), `--apply` — запись в одной транзакции на кабинет под замком обмена. Связи
надгробий и связи, чью запись не найти, не трогаются. Порядок отката описан в `docs/directory-exchange-rollback.md`:
скрипт с `--apply`, затем revert на master.

### Р2. Здоровье обмена в ROOT (п. 2)
Таблица `DirectoryExchangeRun`: кабинет, повод (вручную / по расписанию / сохранение / подтверждение), начало, конец,
длительность, создано / обновлено / пропущено, итог (готово / занято / ошибка) и текст ошибки. Пишется на каждом обмене
(и в фоне). Страница ROOT «Обмен справочниками» (`/root/directory-exchange`, доступ как у клиентских разделов ROOT):
последние обмены, кабинеты с ошибкой или без успешного обмена за сутки, фильтр «только ошибки». Строки старше 90 дней
удаляются при плановом обмене.

### Р3. Ночной прогон сквозных сценариев (п. 3)
Рабочий процесс GitHub Actions `nightly-e2e.yml` (ночью и вручную): PostgreSQL как сервис, `npm ci`, `prisma db push`,
сиды шаблонов журналов, прогон сценариев обмена, баланса, отмены переноса, кода кабинета, компаний, меню, версий и
новых списков (без браузерных). Сценарии переносятся в `scripts/e2e/` (одна копия, задачи ссылаются на неё). Сбой —
сообщение в Telegram тем же ботом и чатом, что сбой выката. На прод ничего не пишется.

### Р4. Сводка по сети для владельца аккаунта (п. 4)
Страница «Сеть» (`/settings/network`, пункт меню рядом с «Мастер-кабинетом»; только владелец аккаунта, 2+ организации):
по каждой организации — журналы за сегодня (сделано / всего, как на главной), баланс, тариф и свои 14 дней (в силе /
закрыта / нет), последний обмен справочниками, ссылка «Перейти» (переключение активной организации). Итог: общий
баланс, сколько организаций без заполненных журналов сегодня.

### Р5. История обмена по организации (п. 5)
Таблица `DirectoryExchangeChange`: что обмен создал или изменил у организации (вид записи, запись, группа, источник,
название, поля до и после, когда, какой обмен). В карточке «Обмен справочниками» — «История» за 30 дней: что, откуда
(своя организация — по названию; у компании другого аккаунта — только «мастер-кабинет «…»»), когда. «Отменить»:
созданное — по правилам отмены переноса (используемое и правленное остаётся) и надгробие, чтобы не создать снова;
изменённое — вернуть прежние значения только у этой организации, связь получает отпечаток вернувшейся записи (правка не
уходит обратно к остальным; следующая правка источника придёт снова). «Журналы» — вернуть прежние настройки. Повтор
отмены — 409. Строки старше 30 дней удаляются.

### Р10. Отмена переноса «Журналов» (п. 10)
Перенос сохраняет снимок настроек получателя до переноса (`createdJson`); отмена возвращает их, если после переноса
настройки не менялись (отпечаток совпадает с перенесённым), иначе — «правили после переноса».

### Р11. Узбекские переводы (п. 11)
Проверка всех ключей uz, добавленных в сериях A–D: грамматика, единая терминология с уже существующими uz-текстами
(«мастер-кабинет», «справочник», «журнал», «точка», «тариф»), латиница, кавычки «». Исправления — в `uz.json`; список
изменённых ключей — в evidence. Проверка носителем языка остаётся рекомендацией.

### Р12. Напоминание в колокольчике и «Добавить точку» (п. 12)
Напоминания за 3 и 1 день до конца своих 14 дней организации дублируются в колокольчик владельца аккаунта (в его
домашней организации). Кнопка «Добавить точку» (письмо, Telegram, колокольчик) ведёт на
`/settings/subscription?addPoints=1`: страница тарифа сразу открывает смену тарифа с числом точек +1 к текущему (оплата
— как обычно).

## Критерии приёмки
- AC1. Скрипт отката: пробный прогон ничего не пишет; `--apply` переводит связи v2 в v1, после чего код до C2
  (проверяется пересчётом отпечатка по v1) считает записи неизменёнными; повторный запуск — 0 изменений.
- AC2. Каждый обмен (успех, занято, ошибка, фон) оставляет строку; страница ROOT показывает их; доступ — по правилу
  ROOT; очистка старых.
- AC3. Рабочий процесс проходит синтаксическую проверку; сценарии из `scripts/e2e/` проходят локально тем же набором
  команд, что в процессе.
- AC4. Сводка: суммы и статусы сходятся с данными; не владелец — 403/нет пункта меню; одна организация — пункта нет.
- AC5. История: создание и правка записываются; отмена правки возвращает значения только у этой организации и не
  уходит к остальным; отмена создания — по правилам; компания другого аккаунта не видит названий организаций владельца.
- AC6. Отмена переноса «Журналов» возвращает прежние настройки; после правки — остаётся с причиной.
- AC7. uz — исправления внесены, `i18n:check` проходит.
- AC8. Колокольчик при напоминании (без повтора); ссылка открывает смену тарифа с +1 точкой.
- AC9. Схема — только добавления (`DirectoryExchangeRun`, `DirectoryExchangeChange`); typecheck, test:gate, eslint;
  сквозные проверки прежних серий зелёные; живой прогон.
