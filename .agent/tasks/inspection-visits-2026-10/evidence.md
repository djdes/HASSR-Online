## Что сделано в этой сессии (поверх работы прошлого агента)

- **Предел тела запроса.** Proxy (`src/proxy.ts`) буферизует тело и обрезает его на
  `proxyClientMaxBodySize = 27mb`; прежний предел 5×10 МБ (50,5 МБ) давал битую
  форму. Теперь файлы одного запроса — до 25 МБ вместе (`INSPECTION_VISIT_MAX_TOTAL_BYTES`),
  тело — до 25,5 МБ; проверка суммы и на сервере (запрос без Content-Length), и в
  обеих формах. Тест сверяет предел с `next.config.ts`.
- **Вложения проверяющему:** отозванный/истёкший токен — теперь 404, как велит AC3
  (было 410); общий ответ `inspectionVisitNotFound()` с `no-store`/`nosniff`;
  открытие скана пишется в журнал действий (`visit_file`, текст «Открыл основание
  проверки» уже был).
- Имя файла при сохранении очищается от управляющих символов.
- Ошибки типов (Prisma 7 `Bytes` = `Uint8Array<ArrayBuffer>`, readonly `orderBy`) —
  исправлены; `message-contract.d.ts` перегенерирован (новые ключи не были в контракте).
- `uz`: `inspectionDay.visits.count` переведён в plural — иначе `i18n:check` падал.

## Решения по ходу

1. **Сумма файлов 25 МБ** вместо 5×10 МБ в одном запросе — ограничение proxy (выше).
   Каждый файл по-прежнему до 10 МБ, фото в браузере сжимаются до JPEG.
2. **Лимит посещений на токен** — 10 записей за скользящие сутки (429 с объяснением
   «попросите руководителя добавить запись в кабинете»), плюс 10 запросов за 10 минут
   на токен+IP.
3. **`Cache-Control`.** Маршрут ставит `private, no-store`, но общий `headers()` в
   `next.config.ts` для всех не-статических путей подменяет его на
   `no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0` (видно в e2e).
   Это строже: `no-store` запрещает хранить ответ любому кэшу. Общий конфиг не
   трогал; e2e проверяет наличие `no-store` и `nosniff`.
4. **POST по токену** оставляет 404/410 (AC2), а **GET вложения** на любой отказ даёт
   404 (AC3) — подсказки «ссылка была действующей» в файловом маршруте нет.
5. Серверные тексты ошибок API — на русском и в EN/UZ-кабинете (как у остальных
   API проекта); подписи интерфейса — RU/EN/UZ.
6. `viewer-name-form.tsx` удалён: ссылок в `src/` нет (осталась только в старом
   артефакте `.agent/tasks/inspector-qr-2026-09/e2e/smoke.ts`). Маршрут `/sign` и
   `InspectorVisit` не тронуты.

## Безопасность (чек-лист everything-security-review по новым маршрутам)

- Секреты: нет. Сырые токены стенда в `smoke-result.json` заменены на `<token:…>`,
  `e2e/state.json` не коммитится.
- Ввод: zod для полей, `fileId`/`id`/токен — regex до БД, тип файла по содержимому
  (`validateOrderScanFile`: HEIC/чужое — отказ, PDF открывается, картинка встраивается),
  размер файла и суммы — до чтения содержимого.
- SQL: только Prisma.
- Права: кабинет — `canUseInspectionVisits` + организация из сессии; портал —
  организация только из токена; файл — `inspectionVisitFileAccessible`
  (организация файла = организации посещения = зрителя; токен = токен записи).
- XSS: React экранирует; файлы отдаются только как `application/pdf|image/jpeg|image/png`
  (тип из проверки содержимого), `nosniff`, имя в `filename*=UTF-8''…`;
  загруженные KnowledgeDocument — inline только для PDF/JPG/PNG.
- Лимиты: 429 на запись (токен+IP и сутки), 300/мин на файлы, 20/мин на PDF.
  Кабинетные маршруты — под сессией, без отдельного лимита (как остальные).
- Утечки: в логах — id токена/организации/записи, без ФИО и сырых токенов; IP/UA
  записи в списки не отдаются; медкнижки — два числа; чек-листы — без ФИО.
- Остаётся как в проекте: CSRF-токенов нет (сессия SameSite=Lax). IP для лимитов
  после ревью — только от nginx (см. ниже).
