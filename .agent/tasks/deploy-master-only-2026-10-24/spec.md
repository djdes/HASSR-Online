# Деплой на прод — только из master (24.10.2026)

Зафиксировано до реализации.

## Запрос

Удалить ветку `codex/mobile-first-release-2026-10`. Автодеплой — только из
master. Пароли и доступы не менять: деплоить по-прежнему могут все, но в
правилах прописать, что только из master. Обязательные PR — только если это
не навредит.

## Почему

Анализ 24.10: CI сам не откатывал прод (300 прогонов 10.09–22.10, каждый
выкатывал коммит новее предыдущего). Старый код приходил на прод мимо master
(ручные выкладки из локальных копий и «релизных снимков», 19.10 и 22.10).
Кроме того, CI позволяет выкатить старый код:

- «Run workflow» на другой ветке берёт `deploy.yml` этой ветки. У
  `codex/mobile-first-release-2026-10` (−86 коммитов от master) там
  `prisma db push --accept-data-loss`: откат кода и удаление таблиц и колонок,
  добавленных после 01.10.
- «Re-run» старого прогона выкатывает его старый коммит.

## Критерии приёмки

- **AC1.** Ветка `codex/mobile-first-release-2026-10` удалена на GitHub. Её 4
  коммита, которых нет в master, сохранены патчами в
  `raw/codex-mobile-first-release-2026-10/` вместе с tip и base, чтобы их можно
  было восстановить через `git am`.
- **AC2.** `deploy.yml`, запуск не на `refs/heads/master`:
  - ничего не выкатывает: gate, upload и deploy пропускаются;
  - отдельный job падает с понятной причиной;
  - запуск не попадает в очередь `production-deploy` и не вытесняет ожидающий
    деплой master.
- **AC3.** `deploy.yml` не выкатывает коммит старше сборки, которую сейчас
  отдаёт прод (`/api/build-info`), если эта сборка есть в master (типичный
  случай — Re-run старого прогона). При этом:
  - откат через `git revert`, через перезапись master или деплой master поверх
    сборки не из master проходят;
  - недоступность сайта или GitHub API деплой не блокирует, только даёт
    предупреждение.
- **AC4.** `scripts/deploy.sh` (ручной деплой) отказывается работать, если HEAD
  не совпадает с origin/master или в рабочей копии есть незакоммиченные или
  неотслеживаемые файлы. Деплой из чистой копии master, в том числе из
  `git worktree` с detached HEAD, работает как раньше.
- **AC5.** Правила записаны в `AGENTS.md` (Deployment), `.cursorrules`,
  `docs/THREAD_WESETUP.md` («Правила деплоя») и `docs/SESSION_HANDOFF.md`
  («Деплой»):
  - деплой только из master, деплоить могут все;
  - старые прогоны не перезапускать (Re-run);
  - ручной деплой — только из чистой копии origin/master;
  - откат — через `git revert`.

  Удалён `deploy-remote.sh`: он выкатывал архив из `/tmp` с фиктивным
  `.build-sha`.
- **AC6.** Не меняются:
  - пароли, секреты и SSH-доступ;
  - кто может пушить и запускать деплой;
  - автодеплой при push в master;
  - шаги сборки и выкладки на сервере.
- **AC7.** Проверки:
  - YAML разбирается, actionlint не находит ошибок;
  - сценарии AC2–AC4 прогнаны на имитации;
  - `scripts/check-secrets.sh` проходит чисто.

## PR

Обязательные PR не вводим. Сейчас агенты и люди пушат прямо в master, и
обязательный PR остановил бы их работу. Причина откатов не в отсутствии PR, а в
выкладках мимо master. Эта правка идёт через PR, потому что меняет конвейер
деплоя.

## Вне рамок

Не входят в задачу, сообщаются пользователю:

- запись `.build-sha` до сборки;
- брошенные сборки после отмены прогона;
- ответы 429 при прогреве;
