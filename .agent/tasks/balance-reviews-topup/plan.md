# План: «Баланс и бонусы» — поля отзыва, анонимный отзыв (−20 %), пополнение баланса деньгами

Ветка `feat/balance-topup-2026-09-30`, рабочая копия `d:/wt/balance`, база `wesetup_wt_balance`, порт 3194.
Спека — `spec.md` рядом (заморожена 2026-09-30).

## Что выяснено до кода

- Партнёрская комиссия считается от `PaymentOrder.amountRub` — это деньги ПОСЛЕ списания баллов
  (`accrueForPaidOrder` → `splitOrderAmount`). Подписка, закрытая баллами целиком, имеет `amountRub = 0`
  и начисления не даёт; частично баллами — начисление только на денежную часть. Значит пополнение
  (деньги) даёт комиссию один раз, а трата этих баллов на подписку — ноль. В `accruals.ts` ничего не
  меняем (его же читает задача orgsw) — пополнение просто проходит через тот же `accrueForPaidOrder`.
- Реферальная награда клиент→клиент (`accrueReferralReward`) считает базу «подписка деньгами + баллы»
  и выдаётся один раз на приглашённую организацию. Без правки первое пополнение съело бы её (30 % от
  пополнения до 300 000 ₽). Решение: пополнение реферальную награду не запускает; она придёт, когда
  приглашённый оплатит подписку (в т.ч. баллами из пополнения — база учитывает баллы).
- УПД (закрывающий документ) по правилам 2026-09-09 выпускается на деньги за оказанную услугу
  (период подписки). Пополнение — аванс, услуги ещё нет: выпускать на него УПД «подписка за период»
  было бы неправдой. Решение: у пополнения УПД не выпускается (причина `advance`), счёт на оплату —
  да; что нужно по закону для аванса — в отчёте (не выдумываем документ).
- Чеки 54-ФЗ: переключатель `ROBOKASSA_SEND_RECEIPT` не трогаем. Строка чека пополнения (если
  чеки включат) — «аванс» + предмет «платёж»; подробности в отчёте.
- Отзыв «Как вас подписать» после мгновенной регистрации предзаполнялся ПОЧТОЙ (имя пользователя =
  почта), а заведение — «Моя организация». Технические значения не предзаполняем.

## Задачи

1. **Ядро без БД + константы** (TDD).
   - `src/lib/balance/constants.ts`: `ANONYMOUS_REVIEW_FACTOR = 0.8`,
     `reviewRewardFor(kind, anonymous = false)` (округление вниз до рубля, целочисленно),
     `TOPUP_MIN_RUB = 500`, `TOPUP_MAX_RUB = 300_000`, `TOPUP_PRESETS_RUB = [1990, 5000, 10000]`,
     `parseTopupAmount(value)`, вид транзакции `topup` («Пополнение»).
   - `src/lib/balance/review-rules.ts` (client-safe): `reviewPrefill({ userName, organizationName, city })`,
     `publicReviewAuthor(...)`, `reviewSignature(...)`.
   - `src/lib/balance/topup-core.ts`: `TOPUP_TARIFF_KEY = "balance_topup"`, `isTopupOrder`,
     `topupCreditDedupeKey`, `creditTopupOrder(store, order)` (идемпотентно по `topup:<orderId>`),
     `settleOrderPayment(store, input)` (pending → paid и зачисление пополнения одной транзакцией).
   - Тесты: `review-rules.test.ts`, `topup-core.test.ts` (границы суммы, идемпотентность: повтор
     уведомления, повтор «Оплата поступила», гонка двух уведомлений; сумма — из заказа),
     `topup-accruals.test.ts` (комиссия с пополнения, ноль при оплате подписки баллами, частичная
     оплата — только деньги, бонус считает денежные платежи), `constants.test.ts` (240/600/1592).

2. **Поля отзыва и анонимный отзыв.**
   - Схема: `CustomerReview.anonymous Boolean @default(false)`.
   - `reviews.ts`: `submitReview({ …, anonymous })` — анонимный хранит пустые имя/заведение;
     `approveReview` — сумма `reviewRewardFor(kind, review.anonymous)` из БД, клиенту не верим;
     `toView` — `anonymous`, `organizationSphere`; `listPublicReviews` — «Анонимный отзыв» + сфера.
   - `POST /api/balance/reviews` — `anonymous`, для анонимного имя/заведение не обязательны; лог и
     сумма в уведомлении ROOT.
   - `overview.ts` — `reviewPrefill` (имя пользователя; название организации + город из адреса).
   - UI `balance-client.tsx`: подписи над полями, чекбокс «Оставить отзыв анонимно (без имени и
     заведения)», зачёркнутые суммы на плитках и в «Будет начислено», другой текст согласия.
   - ROOT `/root/reviews`: пометка «анонимно», сумма с учётом −20 %, аудит одобрения/отклонения.
   - Лендинг: `testimonials.tsx` — без имени, значок вместо инициалов; JSON-LD — без анонимных.

3. **Пополнение: сервер.**
   - `src/lib/balance/topup.ts`: `createTopupCardOrder`, `settlePaidOrder` (БД-обёртка ядра),
     `completeTopupOrder` (комиссия партнёру, письмо и колокольчик руководству, живое событие
     `balance`, заметка ROOT, аудит `balance.topup.paid`, лог `[balance] topup paid org=… rub=… order=…`).
   - `POST /api/balance/topup { amountRub, method: "card" | "invoice" }` — руководитель, не «войти как»,
     не приложение WeSetup; сумма только с сервера; лимит попыток; аудит `balance.topup.create`.
   - ResultURL `/payment` и `markInvoicePaid` — через `settlePaidOrder`; `completePaidOrder` уводит
     пополнение в `completeTopupOrder` (подписку не продлевает, скидку навсегда не привязывает).
   - Счёт: `createTopupInvoiceOrder` (один действующий счёт на пополнение, как у подписки),
     строка счёта «Пополнение баланса…», письмо со счётом — текст про пополнение.
   - Подписочные места не путаются с пополнением: `hasPendingInvoice`, действующий счёт на подписку,
     УПД (`closingEligibility` → `advance`), реферальная награда.
   - `GET /api/payments/robokassa/status` → `purpose: "topup" | "subscription"` для страницы возврата.

4. **Пополнение: интерфейс.**
   - `src/components/balance/balance-ui.tsx` — общие примитивы раздела (вынесены из balance-client).
   - `src/components/balance/topup-section.tsx` — блок «Пополнить баланс»: 1 990 / 5 000 / 10 000 ₽ и

     «Выставить счёт» (подтверждение, PDF), действующий счёт, подсказки. В приложении WeSetup не
     рендерится (решает сервер).
   - `/order` (возврат с кассы): для пополнения — «Баланс пополнен», ссылка на баланс.
   - `/settings/subscription` и ROOT → организация: пополнение не считается счётом на подписку,
     без УПД, подпись «пополнение баланса», «Оплата поступила» с правильными последствиями.
