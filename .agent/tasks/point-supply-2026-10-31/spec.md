# Поставки по точкам: ЭДО-приёмка с выбором точки, склады iiko → точки, журнал маркировки

Дата: 2026-11-01. Ветка `feat/point-supply` от `origin/master` 9583b7b9.

## Откуда

Аудит «точка видит только своё» (2026-10-31). Владелец ответил «да» на вопросы:
- ЭДО: точку для приёмки выбирать явно;
- iiko: склады связать с точками.

Найдено в коде:
- `POST /api/edo/documents/[id]/accept` пишет приёмку в журнал `getActiveBuildingId(session)`. В режиме «Вся организация» это офис или первая точка, а форма точку не показывает.
- `SupplyDocument` без точки; «Входящие накладные» (`/edo`) показывают документы всей организации.
- iiko: склад документа не разбирается, накладные всех складов идут в общие входящие, акты списания — в `LossRecord` без места.
- Журнал маркировки (`LabelPrint`) без точки; `/settings/print-agent/labels` — вся организация.
- `EdoCabinet`/`EdoDocument` — исходящие документы платформы клиентам (договоры, счета), к точкам не относятся: не трогаем.

## Правило

Точки включены, если `buildingTargets(org)` ≠ `[null]`. Если выключены, всё как раньше: точки нет, фильтров нет, выбора нет.

## Критерии

- **AC1.** `SupplyDocument.buildingId`, `LossRecord.buildingId`, `LabelPrint.buildingId` — необязательные, связь с `Building`, `onDelete: SetNull`. Изменение только аддитивное.
- **AC2.** УПД: разбирается грузополучатель (`ГрузПолуч`). При сохранении накладной точка ставится сама, если КПП грузополучателя (иначе покупателя) совпадает с КПП ровно одной точки организации. Иначе точки нет — её выберут при приёмке. Тест.
- **AC3.** Форма приёмки при включённых точках:
  - блок «Точка приёмки» — точки, доступные человеку;
  - по умолчанию выбрана точка накладной, иначе просматриваемая точка из шапки, иначе ничего;
  - без выбора «Принять» не отправляет и подсказывает выбрать точку.
- **AC4.** `POST …/accept`:
  - `buildingId` из тела;
  - при включённых точках точка обязательна, принадлежит организации и доступна человеку (сотрудник с точками принимает только на свои);
  - приёмка ложится в журнал приёмки этой точки (`ensureActiveDocument`), точка сохраняется в накладной;
  - при выключенных точках — `null`, как раньше.
- **AC5.** «Входящие накладные»:
  - на торговой точке — её накладные и накладные без точки;
  - «Вся организация» — все, у каждой пометка точки;
  - страница накладной другой точки для привязанного к точкам человека — 404.
- **AC6.** iiko: склад накладной (`defaultStore`, иначе склад строки) и склад акта списания (`storeId`) разбираются. Тест на разбор.
- **AC7.** iiko, склады → точки:
  - в настройках iiko «Загрузить склады» берёт склады и подразделения сервера;
  - у каждого склада выбирается точка, «Без точки — выбрать при приёмке» или «Не загружать»;
  - сопоставление хранится в `SupplyConnection.storePoints` (не секрет, без шифрования).
- **AC8.** Синхронизация iiko:
  - накладная склада получает его точку, акт списания — `LossRecord.buildingId`;
  - склад «Не загружать» пропускается;
  - склад без сопоставления — без точки, как раньше.
  - Тест на `syncIikoData` с подменённым клиентом.
- **AC9.** Журнал маркировки:
  - этикетка получает точку, если сотрудник телефона работает ровно на одной точке;
  - `/settings/print-agent/labels` на торговой точке показывает её этикетки и этикетки без точки.
- **AC10.** Потери (`/losses`) на торговой точке: записи этой точки (по `buildingId` или цеху точки) и записи без места.
- **AC11.** Проверки:
  - ru/en/uz для новых ключей, `npm run i18n:check`;
  - `npm run typecheck`, eslint изменённых файлов, затронутые тесты;
  - e2e-база (не прод): приёмка накладной на выбранную точку, фильтр входящих, отказ на чужую точку.

## Не входит

- Номенклатура iiko остаётся общей на организацию (у `Product` нет точки).
- Меркурий (ВетИС) — отдельная приёмка, проверить и упомянуть в отчёте.
- Несколько подключений iiko на организацию (по серверу на точку) — модель `@@unique([organizationId, provider])` не меняем.
