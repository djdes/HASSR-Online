# MAX: всё через бота, без мини-сайта (2026-10-26)

## Запрос владельца

> Сделай интеграцию в MAX без мини-сайта, только через бота чтобы работало.
> Продумай логику работы по кнопкам, чтобы было просто и понятно для
> сотрудников и управляющих

## Что есть сейчас

- Бот MAX (`src/lib/max/bot.ts`) — только «вход на сайт»: каждая кнопка
  журнала создаёт одноразовую ссылку `/max#ticket=…` и открывает сайт
  (мини-приложение `/max`, `/max/journals`, `/max/open/[code]`,
  `/api/max/session`). Мини-приложение требует включения в бизнес-консоли
  MAX, без него сотрудник уходит в браузер — «через бота» ничего не
  заполняется.
- Сотрудника можно подключить только через сайт: войти, нажать значок MAX,
  открыть бота, вернуться на сайт и подтвердить. У линейных сотрудников
  часто нет пароля от сайта.

## Решения

### Без мини-сайта

- Убираем мини-приложение и вход по ссылкам из бота: страницы `/max`,
  `/max/journals`, `/max/open/[code]`, API `/api/max/session`, проверку
  `initData`, разрешение показывать `/max` во фрейме MAX. Модель
  `MaxSessionHandoff` в схеме остаётся (не удаляем таблицу на проде —
  `db push` без потери данных), код её больше не создаёт.
- Сайт остаётся только для личной привязки руководителя (`/max/connect`)
  и настроек организации (`/settings/integrations/max`) — это кабинет, не
  мини-сайт.
- Все кнопки бота — callback-кнопки. Ссылка-кнопка остаётся только там, где
  без сайта нельзя: «Подключить аккаунт» для неподключённого человека.

### Кнопки: сотрудник

Главное сообщение (`/start`, `/menu`, «Меню»):

```
Анна Петрова · Кафе «Ромашка»
Сегодня 26.10.2026: заполнено 2 из 4.
Осталось: Гигиенический журнал, Бракераж…

[✍️ Заполнить: Гигиенический журнал]   ← следующий незаполненный
[📋 Мои задачи на сегодня]
[📚 Все журналы]
[❓ Как это работает]  [🏢 Организация] (если их несколько)
```

- «Мои задачи» — журналы на сегодня: ⏳ не заполнен (кнопка), ✅ заполнен.
  Источник — обязательства дня (`JournalObligation`), как в мини-приложении
  Telegram.
- «Все журналы» — журналы, которые сотруднику разрешено заполнять сегодня
  (ACL, право `journals.fill`, отключённые журналы, есть документ на
  сегодня или его можно продолжить новым периодом). Журналы объектов
  (холодильники, склады, УФ-лампы) — в конце с пометкой «по наклейке»:
  нажатие объясняет, что их заполняют по QR на объекте.

### Кнопки: заполнение журнала

Один вопрос — одно сообщение; навигация редактирует то же сообщение.

1. Документ: один на сегодня — выбирается сам; несколько (точки) — кнопки.
2. Строка: журналы со строками (уборка помещений и т.п.) — кнопки строк,
   сначала свои.
3. Поля формы адаптера по одному: «Шаг 2 из 5».
   - да/нет — `[✅ Да] [❌ Нет]`;
   - список — кнопка на каждый вариант (текущий/по умолчанию отмечен ✓);
   - число — «Напишите число в ответ», быстрые кнопки по норме (мин/сред/макс),
     у показаний объектов `[Выключено / нет показания]`; вне нормы — вопрос
     «Что сделали?» с готовыми ответами;
   - текст — ответ сообщением; готовые варианты/недавние наименования
     кнопками; необязательное — `[Пропустить]`;
   - дата — `[Сегодня] [Вчера]` или ответ «ДД.ММ.ГГГГ»; время — `[Сейчас]`,
     `[−15 мин] [−30 мин] [−1 ч]` или ответ «ЧЧ:ММ»;
   - подпись — `[✍️ Подписать: Анна Петрова]`;
   - фото — необязательное `[Пропустить]`; обязательное — объяснение, что
     такой журнал заполняется по QR.
   - Под каждым шагом `[‹ Назад] [✖ Отменить]`; значение по умолчанию —
     кнопкой `[Оставить: …]`.
4. Проверка: список «поле — значение», `[✅ Сохранить]`, `[✏️ Изменить]`
   (выбор поля → после правки снова проверка), `[✖ Отменить]`.
5. Сохранено: «✅ Записано в …», для строчных журналов `[➕ Добавить ещё]`,
   `[✍️ Следующий: …]` если остались задачи, `[🏠 Меню]`.

Запись — через то же ядро `submitJournalFill`, что QR-формы: блоки
отключённых/объектных журналов, проверка схемы, отметки «Выключено»,
комментарий к отклонению, память наименований, аудит, уведомления.
Устаревшие кнопки (из старых сообщений) не пишут в журнал: бот показывает
текущий шаг.

### Кнопки: руководитель

В главном меню дополнительно:

```
[📊 Сводка за сегодня]
[🔔 Напомнить не заполнившим]
[👥 Подключить сотрудника]
```

- «Сводка» — заполнено/осталось по организации и список сотрудников с
  незаполненными журналами (до 15 строк), кто из них в MAX.
- «Напомнить» — подтверждение «Отправить N сотрудникам в MAX?» → личные
  сообщения подключённым сотрудникам со списком журналов и кнопкой
  «Заполнить». Не чаще раза в 30 минут на организацию.
- «Подключить сотрудника» — список сотрудников без MAX (по 8, листание) →
  нажатие выдаёт личную одноразовую ссылку `https://max.ru/<бот>?start=inv_…`
  (7 дней) и текст для пересылки. Сотрудник нажимает ссылку → бот сразу
  привязывает его и показывает меню; руководителю приходит «Анна
  подключилась». Повторная выдача заменяет прежнюю ссылку.

### Безопасность

- Приглашение — 24 случайных байта, в базе только SHA-256, одноразовое
  (атомарная отметка), срок 7 дней, только активный неархивный сотрудник
  своей организации, выдаёт руководитель (роль управления или ROOT в этой
  организации). Если у сотрудника уже есть другой MAX или этот MAX привязан
  к другому человеку — отказ с объяснением, ничего не перепривязывается.
- Каждое действие заново проверяет привязку, активность аккаунта,
  организацию (включён ли MAX), ACL журнала и право `journals.fill`.
- Заполнение — только в своей (домашней) организации: ядро записи пишет
  от имени сотрудника этой организации. В других организациях руководитель
  видит сводку, напоминания и приглашения.
- Состояние диалога — в `MaxIdentity.botState` (JSON) с отметкой времени,
  живёт 2 часа. Лимит записи — на пользователя MAX, а не на общий IP вебхука.
- Групповые чаты по-прежнему не получают личных меню.

## Изменения схемы (аддитивные, `prisma db push`)

- `MaxIdentity.botState Json?`, `MaxIdentity.botStateAt DateTime?`.
- `MaxOrganizationIntegration.lastReminderAt DateTime?`.
- Новая модель `MaxInvite` (tokenHash unique, userId, organizationId,
  createdByUserId, expiresAt, usedAt).

## Критерии приёмки

- **AC1** — мини-сайта нет: удалены `/max`, `/max/journals`,
  `/max/open/[code]`, `/api/max/session`, проверка initData, браузерный
  handoff и CSP-фрейм для `/max`; бот не создаёт ссылок входа; документация и
  `setup-max` не упоминают мини-приложение.
- **AC2** — главное меню сотрудника и руководителя по схеме выше; «Мои
  задачи», «Все журналы», «Как это работает», смена организации.
- **AC3** — пошаговое заполнение любого поддерживаемого журнала кнопками и
  ответами: все типы полей DSL, «Назад», «Отменить», «Выключено», отклонение
  от нормы с комментарием, проверка перед записью, «Изменить», выбор
  документа и строки, «Добавить ещё», защита от устаревших кнопок.
- **AC4** — запись идёт через `submitJournalFill` (канал MAX: сотрудник
  подтверждён привязкой, лимит на пользователя), ошибки ядра показываются
  в чате и возвращают к шагу.
- **AC5** — сводка, напоминания (с подтверждением и ограничением частоты)
  и подключение сотрудника по личной ссылке-приглашению.
- **AC6** — безопасность приглашений и проверок доступа по разделу выше.
- **AC7** — юнит-тесты на чистые части (разбор нажатий, шаги формы и разбор
  ответов, приглашения, тексты сводки), `npm run typecheck`,
  `npm run test:gate`, ESLint по изменённым файлам — без ошибок.

## Вне рамок

- Загрузка фото в журнал из чата.
- Холодильники/склады/УФ-лампы из чата (решение 33d8559b: по наклейке).
- Ежедневные автоматические рассылки по расписанию (ручная кнопка
  «Напомнить» есть).
