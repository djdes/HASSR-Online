# Найдено при проверке и исправлено

1. Телефон: первая строка ниже первого экрана (y=799 при высоте 664).
   Причина — описание страницы в 4 строки, переключатель фильтров
   разъехался на 2 ряда (общее правило телефона `globals.css` превращает
   `grid-cols-3` в две колонки), длинные кнопки автоперевода.
   Исправлено: описание на телефоне скрыто, фильтры — `flex` с шириной по
   подписи, кнопки автоперевода на телефоне — «EN · N / UZ · N» под
   подписью «Автоперевод», подсказка про русский исходник перенесена в
   окно строки. Теперь первая строка на y=502.
2. Счётчик «Строки 1–100 из N» при смене запроса на мгновение показывал
   старое N со старыми строками (страница сбрасывалась раньше ответа).
   Исправлено: смещение берётся из ответа сервера (`offset`).
3. Плавная прокрутка к началу списка после смены страницы не доезжала
   за время подмены 100 строк. Исправлено: мгновенная прокрутка.
4. «Без перевода» обрезалось в переключателе на телефоне — см. п. 1.
5. Длинный ключ переносился посреди слова («items.toda|y») — перенос по
   точкам (`<wbr>`).
6. Поиск без кэша нормализации — 50–90 мс сверху на запрос в dev;
   кэш нормализованного текста → ~25 мс.
7. Ревью (независимый субагент): запрос длиннее 200 символов (лимит API)
   давал 400, а на экране оставались прежние строки. Исправлено: клиент
   обрезает запрос до `MAX_SEARCH_LENGTH` (общая константа с API), при
   ошибке список очищается. e2e: запрос в 299 символов → 200.
8. Ревью: окно строки, открытое до прихода новых результатов (во время
   загрузки или паузы поиска), закрывалось само — строки не было в новой
   странице. Исправлено: открытая строка хранится снимком, сохранение
   обновляет и его; листание скрыто, если строки на странице уже нет.
   e2e: окно остаётся открытым.
