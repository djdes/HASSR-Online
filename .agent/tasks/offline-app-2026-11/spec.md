# Spec (frozen 2026-11-10, утверждена владельцем): приложение WeSetup без интернета

Запрос владельца: «приложение WESETUP apk должно работать без интернета. При появлении подключения нужно
синхронизировать все данные, дату, время записи что сделаны в офлайне и остальную информацию, авторизация
сохраняется вечно и интернет ей не нужен. QR при сканировании должен перебрасывать в приложение и понимать,
какой журнал: я открываю apk на планшете, где ранее вошёл на сайт, сканирую QR обычной камерой или из
приложения в авиарежиме — и код читается и определяется, что я ввожу температуру по холодильной камере».

Утверждение владельца (2026-11-10, третье): «Границы времени расширь до 1 месяца, без сети делаем просмотр и
правку старых записей и при появлении их как бы мерджим если возможно. Делай сайт и apk, я проверю на андроид
планшете. Скажешь откуда апк скачать».

Уточнение владельца (2026-11-10, второе): «авторизации по pin коду сотрудников хранить, пропускать в
приложении в офлайне» — выбор сотрудника и проверка его ПИН работают без сети.

Уточнение владельца (2026-11-10): вариант «А» — запуск без сети, QR-сценарии, журналы с простой формой,
синхронизация со временем; обязательно бракеражи, уборки и остальные часто используемые обязательные журналы.

## Исходное состояние (master 9e6e6e8a)

- APK (`mobile/`, Capacitor 8) — оболочка: грузит `https://wesetup.ru/mini?src=app` с сервера, локально лежит
  только экран «Нет связи с интернетом» (`mobile/www/offline.html`, `server.errorPath`).
- Service worker кабинета `public/mini-sw.js` (scope `/mini`) кеширует только статику с хешем; авторизованный
  HTML не кешируется никогда (общий телефон на три смены). **В приложении воркер снят намеренно**
  (`mini-sw-register.tsx`): запросы из воркера идут без приписки `WeSetupApp/…` в User-Agent, и сервер
  переставал узнавать приложение.
- Очереди отправки есть (`src/app/mini/_lib/journal-queue.ts` — с автором записи, фото и ключом
  идемпотентности; `src/lib/offline-queue.ts` — общая), но работают только на уже открытой странице.
- Страницы журналов и QR-страницы (`/equipment-fill/…`, `/room-fill/…`, `/journal-fill/…`, `/qj/…`) рисует
  сервер; `/mini/journals/<код>` перенаправляет на страницу кабинета. Без сети ни одна не открывается.
- Дату и время записи ставит сервер в момент получения (`todayKeyFor(org.timezone)`, `new Date()`).
- Простые формы журналов уже описаны данными: адаптеры `src/lib/tasksflow-adapters/*` отдают
  `TaskFormSchema` (поля text / number / boolean / select / date / time …), запись делает
  `submitJournalFill`. На этом работает QR-хаб «Все журналы» (`listHubJournals`, `resolveJournalFillRows`,
  `loadJournalFillForm`).
- Ссылки `wesetup.ru` с QR приложение уже перехватывает (App Links, `APP_LINK_PATHS`), событие
  `appUrlOpen` принимает `native-app-bridge.tsx`.
- Сессия NextAuth: JWT, 1 год, продлевается при заходах онлайн (`updateAge` 1 сутки).

## Решение в двух словах

1. **Офлайн-экран** — статическая, одинаковая для всех страница сайта (`/offline-app`, без данных человека
   в HTML). Service worker сохраняет её и её скрипты на устройстве и отдаёт вместо любой страницы, которую не
   удалось загрузить из сети.
2. **Офлайн-пакет** — данные человека для работы без сети, скачиваются при каждом заходе с сетью и лежат в
   IndexedDB устройства: кто вошёл, организация, точка, сотрудники, журналы с документами, строками и
   формами, оборудование и помещения с нормами.
3. **Разбор QR на устройстве** — чистая функция по адресу из QR определяет вид (оборудование, помещение,
   журнал, хаб) и id; объект ищется в пакете, сразу открывается нужная форма.
4. **Очередь с настоящим временем** — запись хранит время устройства; сервер при синхронизации записывает
   её тем днём и временем и помечает «внесено без связи».

Правило «авторизованный HTML не кешируется» сохраняется: в кеш воркера попадает только обезличенная
страница, данные человека — только в IndexedDB и стираются при выходе.

## Что работает без сети (объём)

- Запуск приложения, экран «Работаем без связи» со списком журналов и объектов из пакета.
- QR оборудования: температура (и влажность, где настроена), УФ-лампа («включил / выключил»), фритюр
  (начало и окончание жарки). QR помещения. QR журнала и хаба «Все журналы».
- Все журналы, у которых есть простая форма адаптера (то, что показывает QR-хаб), в том числе названные
  владельцем: бракераж готовой продукции (`finished_product`), бракераж скоропортящейся продукции
  (`perishable_rejection`), уборка (`cleaning`), генеральная уборка (`general_cleaning`), чек-лист уборки и
  проветривания (`cleaning_ventilation_checklist`), гигиена (`hygiene`), здоровье (`health_check`),
  холодильное оборудование (`cold_equipment_control`), климат (`climate_control`), приёмка, списание,
  дезсредства, УФ-лампы, фритюрный жир и остальные журналы с адаптером.
- Фото к записи (шаги уборки с обязательным фото): снимок хранится на устройстве и уходит при синхронизации.
- Список «Ждёт отправки / Не ушло» с причиной и кнопкой «Повторить».

## Что НЕ входит (второй этап или не делаем)

- Таблицы журналов целиком, печать, отчёты, настройки, сотрудники. (Просмотр и правка записей за
  последний 31 день в виде формы строки — входит, см. AC17–AC18.)
- Создание документов журналов, подписи комиссии бракеража, закрытие дня.
- Взятие задач, начало и передача смены — правило проекта: задним числом их не делаем.
- Первый вход в аккаунт и смена аккаунта устройства без сети. Проверка подлинности QR без сети (проверяет
  сервер при синхронизации).
- Выдача, смена и запрос ПИН без сети («Запросить доступ» — только с сетью).
- iOS: в WKWebView service worker для этого домена не гарантирован; iPhone остаётся как сейчас.
- Нативные правки APK. Если проверка на устройстве покажет, что без них не работает запуск по ссылке из
  системной камеры, — отдельная задача с новой версией приложения.

## Критерии приёмки

- **AC1. Офлайн-экран сохраняется на устройстве.** После одного захода в кабинет с сетью воркер хранит
  страницу `/offline-app` и все её скрипты и стили. В HTML страницы нет имени, организации и других данных
  человека (тест на ответ сервера). После выката новой сборки сохранённая копия обновляется при следующем
  заходе с сетью; старая работает, пока новая не скачана целиком.
- **AC2. Запуск без сети.** Сеть выключена, открываем `/mini?src=app` (и `/mini`, `/mini/today`,
  `/journals/<код>`): вместо «Нет связи с интернетом» открывается офлайн-экран с именем вошедшего,
  организацией, отметкой «данные от <дата, время>» и списком доступных журналов и объектов. Если пакета на
  устройстве нет — прежний экран «Нет связи» с пояснением «откройте приложение один раз с интернетом».
- **AC3. Воркер работает в приложении и не ломает его.** В приложении воркер регистрируется; сервер узнаёт
  приложение и его версию и по User-Agent, и по метке в cookie (ставит страница из User-Agent) — оплата,
  проверка версии и мобильная оболочка ведут себя как раньше. С сетью все навигации идут в сеть, как
  сейчас; авторизованный HTML в кеш не попадает (тест на воркер).
- **AC4. Офлайн-пакет.** `GET /api/offline/pack` (только с сессией, организация — `getActiveOrgId`) отдаёт:
  пользователя, организацию с часовым поясом, точку, журналы с простыми формами (с учётом прав на журналы и
  отключённых журналов), их документы, строки и схемы форм, оборудование (вид: температура / УФ / фритюр,
  нормы) и помещения. Клиент сохраняет пакет в IndexedDB с привязкой к пользователю, обновляет при каждом
  открытии кабинета с сетью и не чаще раза в 15 минут; при выходе пакет стирается. Чужих организаций и
  недоступных человеку журналов в пакете нет (тест).
- **AC5. Разбор QR.** Чистая функция разбирает адреса всех печатаемых QR: `/equipment-fill/<id>?token=…`,
  `/room-fill/<id>?token=…`, `/journal-fill/<orgId>/<код>?…` (в том числе хаб `all`, QR документа и QR
  точки), `/qj/<orgId>/<код>/<подпись>`; чужой домен, мусор и неизвестный путь — «не наш QR». Тесты на
  каждый вид, на адреса с `www.`, с лишними параметрами и в кодировке URL.
- **AC6. QR без сети открывает нужную форму.** Сеть выключена. (а) Переход по адресу QR оборудования
  открывает офлайн-экран сразу на форме этого объекта: название, норма, поле температуры. (б) То же через
  сканер внутри приложения. (в) Событие `appUrlOpen` приложения с таким адресом ведёт туда же. УФ-лампа —
  «Я включил / Я выключил», фритюр — начало и окончание, помещение — его форма, QR журнала — выбор строки и
  форма, хаб — список журналов. Объекта нет в пакете — понятный экран «Этого объекта нет в сохранённых
  данных» с переходом к списку журналов. QR чужой организации — отказ.
- **AC7. Формы журналов без сети.** Из списка офлайн-экрана открывается любой журнал пакета: строка →
  форма по `TaskFormSchema` (все типы полей, обязательность, границы, подсказка нормы, отклонение с «что
  сделали») → «Сохранено на устройстве». Проверено в браузере для `finished_product`,
  `perishable_rejection`, `cleaning`, `hygiene`, `cold_equipment_control`. Оформление — по дизайн-системе
  проекта, тексты русские (и en/uz через словари).
- **AC8. Очередь.** Запись хранит: ключ идемпотентности, аккаунт устройства (`ownerUserId`), сотрудника-автора
  (`employeeId`) и способ подтверждения (ПИН без связи / выбор из списка / сам вошедший), время устройства
  (`recordedAt`, ISO с поясом), журнал, документ, строку, значения, фото. Очередь переживает закрытие
  приложения. Запись чужого автора не отправляется под текущей сессией (правило `queue-owner.ts`).
- **AC9. Синхронизация.** При появлении сети и при открытии кабинета очередь уходит сама; повтор одной и той
  же записи не создаёт дубль (ключ идемпотентности, тест на сервер). Отправленная запись появляется в
  журнале так же, как введённая онлайн тем же человеком.
- **AC10. Дата и время записи.** Сервер кладёт запись в день `recordedAt` по часовому поясу организации (не
  в день синхронизации) и сохраняет при записи `recordedAt`, время получения и признак «внесено без связи»;
  признак виден руководителю в журнале аудита. Время в будущем более чем на 10 минут и запись старше 31 дня
  сервер не принимает — она остаётся в «Не ушло» с причиной («проверьте время на устройстве», «запись
  старше 31 дня — внесите через руководителя»). Тесты: полночь на границе пояса, будущее, старше срока.
- **AC11. Конфликты и отказы.** Событийные журналы (бракеражи, приёмка и т. п.) — запись всегда
  добавляется. Журналы «одна строка в день» — запись сливается с тем, что уже есть в журнале, по правилам
  AC18. Документ
  закрыт, строки больше нет, нет прав — запись не пропадает молча, а остаётся в «Не ушло» с причиной.
- **AC12. Вход без сети.** Без сети приложение пускает аккаунт, вошедший на устройстве последним, без запроса
  к серверу. Сессия истекла или вошёл другой аккаунт — записи, сделанные при прежнем, ждут его входа и не
  уходят через чужой аккаунт. Выход стирает пакет; неотправленные записи остаются и видны автору после его входа.
- **AC13. Состояние на экране.** В кабинете с сетью — строка «Готово к работе без связи · данные от …» (или
  «Не готово: …»). На офлайн-экране — «Работаем без связи», счётчик «Ждёт отправки: N»; при появлении сети —
  «Отправляем…», затем переход в обычный кабинет.
- **AC15. Сотрудник и ПИН без сети.** Офлайн-экран повторяет режим организации (`qrFillMode`):
  «по списку» — выбор сотрудника из списка точки; «по ПИН» — выбор сотрудника и ввод его ПИН; «только
  вошедший» — автор тот, кто вошёл на устройстве. Список — те же люди, что на QR-странице онлайн (точка,
  допущенные к объекту). Для проверки ПИН в пакете лежит не сам ПИН и не хеш из базы, а отдельный
  проверочный код (PBKDF2 со случайной солью, выпускается сервером для этого пакета). Верный ПИН
  пропускает к форме; неверный — отказ, 5 ошибок подряд — блок сотрудника на этом устройстве на 15 минут
  (как онлайн). Знакомое устройство помнит выбранного сотрудника, как онлайн; ПИН спрашивается заново по
  тем же правилам, что онлайн (пропуск на 30 минут). У сотрудника нет ПИН — «ПИН не выдан, обратитесь к
  руководителю». ПИН в очереди и где-либо на устройстве в открытом виде не хранится.
- **AC16. ПИН при синхронизации.** Запись уходит под сессией аккаунта устройства с автором-сотрудником и
  отпечатком ПИН, по которому она подтверждена. Сотрудник активен, из этой организации и его ПИН не менялся
  — запись принимается за его подписью с пометкой «ПИН проверен на устройстве без связи». ПИН сменён или
  отозван, сотрудник уволен или не из этой организации — запись остаётся в «Не ушло» с причиной; после
  ввода действующего ПИН с сетью она уходит. Тесты на каждый исход.
- **AC17. Просмотр и правка прошлых записей без сети.** Для журналов «строка в день» пакет хранит
  сохранённые значения строк за последний 31 день (в пределах периода документа). На офлайн-экране у строки
  выбирается день; форма открывается с сохранёнными значениями (или пустой, если записи нет), их можно
  посмотреть и изменить. Правка ложится в очередь с днём записи, временем правки и исходными значениями, с
  которых она начата. Неотправленные правки и новые записи этого устройства видны в форме сразу.
- **AC18. Слияние при синхронизации.** Сервер сравнивает три набора: исходные значения (из пакета), правку
  с устройства и то, что сейчас в журнале. Поля, которые менялись только на устройстве, записываются; поля,
  которые менялись только на сервере, остаются серверными; одинаковые изменения совпадают. Если одно и то же
  поле изменено по-разному — в журнале остаётся серверное значение, остальные поля сливаются, а запись
  остаётся в «Не ушло» с перечнем таких полей и кнопками «Оставить как в журнале» и «Записать моё». Ничьи
  данные молча не затираются. Тесты: без пересечений, одинаковые правки, конфликт, запись появилась на
  сервере, пока устройство было без сети.
- **AC19. APK.** Владелец получает APK для проверки на планшете и инструкцию, откуда его скачать и как
  проверить (в `evidence.md` и в ответе). Нативный код меняется только если без этого сценарий не работает.
- **AC14. Ничего не сломано.** `npm run typecheck` и `npm run test:gate` зелёные; `src/lib/app-links.test.ts`
  и тесты воркера проходят; онлайн-сценарии кабинета, QR-страниц и сайта в браузере работают как раньше.

## Как проверяем

- Модульные тесты (`node:test`): разбор QR, сборка пакета и права, правила времени, идемпотентность,
  конфликты, владелец очереди, правила кеша воркера.
- Браузер (Playwright, Chromium, production-сборка, демо-организация): вход → пакет скачан → «без сети» →
  AC2, AC6, AC7 → сеть включена → AC9, AC10 по записям в базе. Снимки экранов — в `raw/`.
- **На устройстве проверить из этой среды нельзя** (нет эмулятора Android). После выката владелец проверяет
  на планшете: авиарежим → запуск приложения; авиарежим → QR системной камерой; авиарежим → QR сканером
  приложения; включить сеть → записи в журнале с правильным временем. Результат записывается в `evidence.md`
  отдельной строкой «проверено на устройстве».

## Известные ограничения (сообщаем владельцу)

- Системная камера открывает приложение только у APK, подписанного ключом из `assetlinks.json`; у отладочной
  сборки ссылка уйдёт в браузер. Сканер внутри приложения работает всегда.
- «Вечный» вход: без сети — без ограничений; для отправки записей сессия должна быть действующей (год,
  продлевается при каждом заходе с сетью). Истекла — войти заново, записи после этого уйдут.
- Новые объекты, журналы и сотрудники появляются на устройстве только после захода с сетью.
- Данные пакета лежат на устройстве; при выходе из аккаунта стираются.
- ПИН из 4–6 цифр на устройстве защищён только проверочным кодом: тот, кто технически извлечёт данные
  приложения с планшета, сможет подобрать ПИН перебором. ПИН защищает от подписи «за коллегу» в обычной
  работе, а не от взлома устройства. В пакете — только сотрудники своей организации (точки).

## Что меняет выкат

- Новые маршруты `/offline-app`, `/api/offline/pack`, приём `recordedAt` в записи журналов.
- Service worker кабинета получает более широкую область действия и включается в приложении.
- Схема базы: по возможности без изменений (метка «без связи» — в существующих JSON-полях записи и в
  `AuditLog`); если понадобится колонка — только nullable, через `prisma db push`.
- Новая версия APK не требуется.
