# Принтер своей точки (2026-11-01)

Решение владельца: «печать на принтер своей точки». Журнал, отправленный на
печать на точке А, печатается принтером точки А, никогда — принтером точки Б.
Схема уже в master (PR #97): `PrintAgent.buildingId`, `PrintJob.buildingId`.

## Критерии приёмки

- AC1. Правило маршрутизации — чистая функция с тестами (`src/lib/print-point-routing.ts`):
  агент точки X — задания X и общие; агент без точки — общие и задания точек без
  своего подключённого принтера; задание точки со своим принтером чужой агент не берёт.
- AC2. Очередь агента (`/api/print/agent/poll`) отдаёт задания по правилу AC1.
- AC3. Постановка задания (`POST /api/print/jobs`): `PrintJob.buildingId = document.buildingId`;
  «принтер на связи» — только принтер, который возьмёт это задание.
- AC4. Подключение программы (`/api/print/agents/auth`): точка по человеку (руководитель
  точки — его точка, руководство компании — вся организация); необязательное поле
  `buildingId` в запросе — только точка в пределах человека. Контракт агента не меняется.
- AC5. Смена точки принтера: `PATCH /api/print/agents/<id>` `{ buildingId | null }`;
  руководитель точки — только свои принтеры и только на свои точки; отключение
  (`revoke`) — только принтеры своих точек.
- AC6. Страница «Онлайн-принтер»: у принтера выбор точки (когда журналы по точкам) и
  подсказка; руководитель точки видит только принтеры своих точек и свои точки, без
  «Вся организация». Карточка на дашборде и `/api/print/status` — по точке из шапки,
  у принтера подписана точка.
- AC7. Тесты, typecheck 0 ошибок, eslint по изменённым файлам 0.
