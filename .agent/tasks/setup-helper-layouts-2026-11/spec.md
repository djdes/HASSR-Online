# «Сетап помощник» 1.6.0: изменение макетов этикеток прямо на телефоне (05.11.2026)

## Запрос

> Настроить в APK изменение макетов для печати с телефона. Учесть, что авторизацию
> убрали из кода, чтобы пройти ревью приложения.

## Контекст

- С 1.5.0 (`f3b20d13`, спека `.agent/tasks/setup-helper-no-auth-2026-11/spec.md`) в
  приложении нет входа и сети (вариант `play` — без `INTERNET`). Значит, макеты нельзя
  получать с сайта: правка и хранение — только на телефоне, без аккаунта.
- Шаблоны — JSON в `assets/templates`, разбираются `TemplateParser`, раскладываются
  `LayoutEngine` (мм шаблона → точки принтера).

## Решения

1. **Хранение.** Изменённый встроенный макет и свои макеты — JSON того же формата в
   `filesDir/layouts/<id>.json` (внутреннее хранилище приложения, никаких разрешений и
   сети). Встроенный с тем же `id` подменяется изменённым; «Вернуть как было» удаляет
   файл. Свои макеты (`id` = `my-…`) идут после встроенных; их можно удалить.
2. **Ядро (чистая Java, тесты на JVM):** `TemplateWriter` (шаблон → JSON, круговой
   разбор без потерь), `TemplateDraft` (изменяемая копия: поля и элементы, проверка
   через запись+разбор), `LayoutEditing` (попадание пальцем в элемент, перенос и
   размер с шагом 0,5 мм в границах этикетки, список вставок `{{…}}` с человеческими
   названиями).
3. **Экраны.**
   - «Макеты этикеток» (`LayoutsActivity`): список всех макетов с мини-превью и
     пометками «Изменён» / «Свой»; «Новый макет» (копия любого или пустой); у
     пункта меню: изменить, копия, вернуть как было / удалить (с подтверждением).
     Вход — меню ⋮ главного экрана и кнопка «Изменить макет» на экране печати.
   - Редактор (`LayoutEditorActivity`): живое превью этикетки ровно теми точками,
     что уйдут на принтер; нажатие выбирает элемент (синяя рамка), перетаскивание
     двигает, уголок — меняет размер (у линии — конец); стрелки сдвигают на 0,5 мм.
     Панель выбранного элемента: текст со вставками полей, кегль −/+, жирный,
     выравнивание, «белым по чёрному», толщина линии / заливка, дублировать, удалить.
     «Добавить»: текст, линия, прямоугольник, чёрная плашка. Вкладка «Поля»: подпись,
     обязательность, умолчание; добавить текстовое поле или дату; удалить поле.
     Название и размер макета (мм). «Отменить» (история шагов), «Сохранить»;
     выход с несохранённым — вопрос «Сохранить изменения?».
4. **Печать** берёт макеты из того же репозитория: после сохранения изменённый макет
   сразу виден в ленте шаблонов и на пробной этикетке. История печати открывает
   макет по `id`.

## Критерии приёмки

- **AC1. Ядро.** `TemplateWriter` + `TemplateParser` дают тот же шаблон для всех 12
  встроенных (разметка совпадает по `DrawOp`); `TemplateDraft` правит поля/элементы и
  не пропускает неразбираемый результат; `LayoutEditing` — попадание, перенос, размер,
  границы и шаг 0,5 мм. Тесты `:core:test` проходят.
- **AC2. Хранение.** `TemplateRepository` подменяет встроенный изменённым, добавляет
  свои, «вернуть как было» и удаление работают, битый файл пропускается без падения
  (Robolectric-тест).
- **AC3. Экраны.** Список макетов и редактор открываются без сети и входа; правка
  текста, перенос, добавление элемента и поля, сохранение — изменённый макет виден на
  экране печати (Robolectric-тест экранов). Скриншоты экранов — в `raw/`.
- **AC4. Без авторизации и сети.** В новом коде нет обращений к сети, аккаунту и
  новых разрешений; итоговый манифест `play` по-прежнему без `INTERNET` и
  разрешений установки; README и «что нового» (release-notes) обновлены, версия
  `1.6.0` (`versionCode = 9`).
- **AC5. Сборка.** Проходят `:core:test`, `:app:testSiteDebugUnitTest`,
  `:app:testPlayDebugUnitTest`, собираются `assembleSiteDebug` и `bundlePlayRelease`.
