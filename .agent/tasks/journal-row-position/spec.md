# journal-row-position — должность под фамилией в строках журналов

Источник: баг-репорт владельца (скриншот журнала микроклимата: Акулинина
подписана «Заведующий производством», эта должность только у Репешко).
План: `C:\Users\Oleg\.claude\plans\peppy-pondering-backus.md`.

## Правило
Должность человека в строке журнала = `getUserDisplayTitle(user)`
(jobPosition.name → positionTitle → лейбл роли). Сохранённая в строке копия —
только если человека нет в списке. Должность документа в строку другого
человека не подставляется. Хелпер: `getRowEmployeeTitle(user, stored)`.

## Критерии приёмки
- AC1 Микроклимат, сетка: под фамилией — должность этого сотрудника;
  должность документа не подставляется.
- AC2 Микроклимат, диалоги: префилл и сохранение по выбранному человеку;
  смена сотрудника обновляет ту же строку (entryId), без дубля.
- AC3 PDF микроклимата печатает те же должности, что экран.
- AC4 Автозаполнение не пишет должность документа в строку другого сотрудника.
- AC5 Серверная перештамповка и `findTaskEmployee` берут `jobPosition`;
  ненайденный человек не получает должность документа.
- AC6 Охлаждение, дезинсекция, прослеживаемость, СИЗ: экран и PDF — должность
  человека строки.
- AC7 Чек-лист проветривания, бракераж, металлопримеси, дезсредства: верная
  должность на показе/записи.
- AC8 Мойка оборудования, медкнижки, обучение, списание: должность из
  справочника вместо лейбла роли / «Управляющий».
- AC9 `npm run typecheck`, `npm run lint`, `npm run test:gate` зелёные.
