2. К «Гигиеническому журналу (сотрудники)» добавить загрузку скана приказа о назначении ответственного и т. п. — чтобы он печатался и показывался вместе с журналом.
3. То же для БЖГП (бракераж готовой продукции) — приказ о бракеражной комиссии, с выводом на печать и в просмотр вместе с журналом.

## 1. «Допущен» только после ответа о здоровье
- Найти, где заведующий/руководитель ставит «Допущен» по сотруднику в гигиеническом журнале (сайт: документ гигиены, окно допуска/QR «Допуск» — `HYGIENE_VERIFY_SUFFIX` в `src/lib/journal-qr-target.ts`, QR-страницы `journal-fill`, TasksFlow-адаптер гигиены, API записей документа) и откуда берутся ответы сотрудника на вопросы о здоровье (что именно считается «ответом»: вопросы гигиены/здоровья за этот день у этого сотрудника).
- Правило: допустить сотрудника за день можно, только если у него за этот день есть ответ хотя бы на один вопрос о здоровье. Проверка — на СЕРВЕРЕ во всех путях, где ставится «Допущен» (API сайта, QR, TasksFlow, массовые действия «допустить всех», автозаполнение), плюс в UI кнопка недоступна с понятной причиной: «Сотрудник ещё не ответил на вопросы о здоровье». Отказ сервера — 400/409 с тем же текстом.
- Чистая функция правила (например `canAdmitEmployee(...)`) с тестами; не ломать «не допущен»/отстранение — их можно ставить всегда.
- Автоматика, которая сама ставит допуск (автозаполнение, «Закрыть день» и т. п.), тоже не должна ставить «Допущен» без ответа — найти и учесть; если такая логика есть — описать в evidence, что изменилось.

## 2–3. Сканы приказов к журналу (гигиена и БЖГП)
- Уровень привязки — журнал организации (организация + код журнала), а не отдельный документ периода: приказ действует, пока его не заменят, и должен идти со всеми документами журнала, в том числе будущих периодов. Несколько файлов на журнал (например, приказ о назначении ответственного + приказ о комиссии), у каждого — название (по умолчанию имя файла, можно переименовать), дата загрузки, кто загрузил.
- Форматы: PDF, JPG, PNG (+HEIC → если нет конвертера, отказать с понятным текстом); до 10 МБ на файл, до 10 файлов на журнал. Хранение — тем же способом, что уже используется в проекте для загружаемых файлов (найти: фото записей `JournalEntryAttachment`, логотипы партнёров и т. п.; не изобретать новое хранилище без нужды). Доступ к файлам — только своей организации (и сессиям проверяющего/партнёра, если они видят журнал), по прямой ссылке без сессии — нет.
- Где управлять: в документе журнала (гигиена и БЖГП) блок/кнопка «Приказы к журналу»: загрузить, переименовать, удалить (ConfirmDialog), просмотреть. Права — как на настройки документа журнала (руководство); сотрудникам — только просмотр, если журнал им доступен.
- Где показывать: на странице документа журнала (сайт) — список приказов с просмотром (картинка — лайтбокс, PDF — просмотр); на странице проверяющего (портал инспектора / QR для РПН, если он показывает журналы) — тоже.
- Печать: PDF документа журнала (`generateJournalDocumentPdf` в `src/lib/document-pdf.ts` — через него идут все печати) после страниц журнала добавляет страницы приказов: PDF-сканы — страницами как есть (склейка), картинки — каждая на своей странице A4 с полями, по размеру. Порядок — по дате загрузки. QR-штамп на страницы сканов не ставить. Если склейка PDF требует библиотеку — можно добавить `pdf-lib` (или растеризовать страницы через имеющийся `pdfjs-dist` + `@napi-rs/canvas` — выбрать и обосновать в evidence).
- Сделать механизм общим (журнал задаётся кодом), включить для `hygiene` и `finished_product`; остальные журналы — без изменений.
- Аудит: загрузка/удаление/переименование приказа — `AuditLog`.

## Критерии приёмки
- AC1: заведующий не может поставить «Допущен» сотруднику без ответа хотя бы на один вопрос о здоровье за этот день — ни кнопкой на сайте, ни через API/QR/TasksFlow/массовые действия; кнопка показывает причину; с ответом — допуск работает как раньше; «не допущен» ставится всегда (тесты + e2e).
- AC2: к гигиеническому журналу и к БЖГП загружаются сканы приказов (PDF/JPG/PNG), видны в документе и у проверяющего, переименовываются и удаляются; чужая организация получить файл не может (тест доступа).
- AC3: печать документа гигиены и БЖГП содержит после журнала страницы приказов (PDF-страницы и картинки), без QR-штампа на них; без приказов печать как раньше.
- AC4: typecheck, `npm test` (новые тесты правила допуска, доступа к файлам, сборки PDF с приложениями), `npm run build` — зелёные; e2e на своей базе со скриншотами 1440 и 390.
