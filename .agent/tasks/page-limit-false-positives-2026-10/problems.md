# Найдено проверкой и исправлено

## Production-сборка (e2e, первый прогон — `raw/e2e-limits.txt`)
1. **AC3 не работал: `_rsc` до proxy не доходит.** 200 запросов `?_rsc=` от
   старого iOS: 100×200 и 100×429 — посчитались страницами. Next 16.1.6 убирает
   `_rsc` (и заголовок `RSC`) в адаптере до proxy (`next/dist/server/web/adapter.js`,
   `stripInternalSearchParams`); unit-тест вызывал `proxy()` напрямую, мимо
   адаптера. Проба заголовков на сборке: `rsc: 1` — тоже не виден.
   Исправлено: признак по `Accept` — браузер без `Sec-Fetch-Dest`, не просящий
   `text/html` (RSC-запрос Next не задаёт `Accept`, браузер шлёт `*/*`), —
   фоновый; инструменты и объявленный `Sec-Fetch-Dest` — страницы.
2. Попутно (не наша правка, есть и на проде): запрос с `next-router-prefetch: 1`
   без `RSC` висит дольше 10 с (локально и на wesetup.ru). В эту задачу не
   входит — сообщено владельцу отдельно.

## Независимое ревью (свежий агент)
1. **Блокер: Google Cloud VM как Googlebot.** `googleusercontent.com` в списке
   доменов: PTR любой ВМ GCE — `*.bc.googleusercontent.com` с совпадающей
   прямой записью. Исправлено: только `googlebot.com`, `google.com`; тест.
2. **Блокер AC3** — то же, что п. 1 выше.
3. Квадратичная регулярка `platformOf` на длинном UA (≈5 мс на 8 КБ на каждый
   запрос). Исправлено: две линейные проверки + UA обрезается до 512 символов;
   тест на 14 КБ.
4. Отклонённый запрос посетителя тратил общий потолок адреса. Исправлено:
   сначала свой бюджет, потом потолок; тест (50 повторов во время паузы не
   мешают соседу).
5. Скрипт с cookie получал свой бюджет (адрес ×4 для curl). Исправлено:
   инструментам cookie не выдаётся и не учитывается; потолок ×3 теперь
   общий для всех гостей адреса (без cookie — ×1, как раньше).
6. Заполненная таблица посетителей не чистилась, пока стучатся только новые.
   Исправлено: `admits()` подметает полную таблицу; тест.
7. Мелочи: форма `instrumentation.ts` как в документации Next; убраны
   неиспользуемые `droppedPageLimitBuckets` и `limitedBySubject`; `orderBy`
   для `take`; лишний `@@index([day])` удалён (уникальный индекс уже
   начинается с `day`); подмена DNS для теста подтверждённого робота
   (`setPageCrawlerVerifierForTests`).
   Не меняли: второй PrismaClient в бандле instrumentation (ленивый, одно
   соединение раз в минуту — безвредно).
