# Ограничитель переходов: меньше ложных срабатываний

Запрос владельца: «сделай всё (пункты 1–7), главное не сделать хуже».

## Общее правило «не хуже»
Каждое новое послабление включается только при выполненном условии и при
любом сбое возвращает нынешнее поведение (ключ — IP гостя / ID пользователя,
пороги из `PAGE_NAVIGATION_LIMITS`):
- нет `NEXTAUTH_SECRET` → нет cookie посетителя;
- DNS не ответил или ответил не то → робот считается обычным клиентом;
- таблица посетителей заполнена → запрос считается по IP;
- база или запись статистики упала → сайт работает, счётчики теряются;
- неверное значение переменной окружения → обычные пороги.
Ни одна правка не добавляет запросов к базе или сети на пути обычного
пользователя (DNS — только для UA, назвавшегося поисковым роботом).

## Пункты и критерии приёмки
1. Статистика 429 без IP и ID.
   - AC1.1. Proxy считает в памяти процесса каждую проверенную страницу:
     итог (прошла/429), причина 429 (всплеск, минута, фон, пауза,
     переполнение), субъект (пользователь/посетитель/IP/неизвестный),
     клиент (браузер, автоматика, приложение WeSetup, проверенный робот),
     платформа (старый iOS < 16.4, iOS, Android, компьютер, прочее), тип
     (страница/фон), есть ли `Sec-Fetch-Dest`, раздел (первый сегмент пути
     из имён маршрутов; для прошедших — без раздела). IP, ID, cookie, полный
     путь и query не сохраняются.
   - AC1.2. Раз в минуту счётчики переносятся в таблицу `PageLimitStat`
     (сутки по Москве, атомарный `increment`), строки старше 90 дней
     удаляются. Сбой записи не валит процесс; размер буфера ограничен.
   - AC1.3. `/root/page-limit` (только ROOT): 7 суток — страницы, 429, доля
     по дням и по субъектам; разбивки 429 по причине, клиенту, платформе,
     метаданным, разделу; текущие настройки (пороги, режим, множитель,
     cookie посетителя, проверка роботов). Пункт в меню «Платформа»,
     тексты ru/en/uz.
2. Вошедшие пользователи — бюджет ×3 (страницы и фон). Полного исключения
   нет: регистрация открыта, и аккаунт не должен снимать защиту.
   - AC2. Для `user:<id>`: 300 страниц за 10 с, 1200 в минуту, фон 3600.
3. Старые браузеры без Fetch Metadata.
   - AC3. Запрос без `Sec-Fetch-Dest` (и без `RSC: 1`) от браузера, не
     просящий `text/html` в `Accept`, — фоновый: так выглядит RSC-запрос
     Next.js в iOS до 16.4 и старых WebView, а загрузка страницы всегда
     просит `text/html`. Инструменты (curl тоже шлёт `*/*`) и запросы с
     объявленным `Sec-Fetch-Dest` остаются на бюджете страниц. Подмена даёт
     только фоновый бюджет — то же, что подмена Fetch Metadata сейчас.
     (Первый вариант — параметр `_rsc` — production-сборка не доносит до
     proxy: Next убирает его и заголовок `RSC` раньше; проверено e2e.)
4. Гости за общим IP.
   - AC4.1. Proxy выдаёт гостю-браузеру cookie `wesetup.visitor` (случайный
     ID + HMAC из `NEXTAUTH_SECRET`; HttpOnly, SameSite=Lax, Secure на https,
     30 дней) на странице и на 429. Инструментам (curl, скрипты) cookie не
     выдаётся, а их cookie не учитывается.
   - AC4.2. Гость с верной cookie считается по `visitor:<id>` (обычные
     пороги), без cookie или с неверной — по `ip:<ip>`, как сейчас. Все
     гости одного адреса вместе — не больше ×3 (`ipcap:<ip>`); отклонённый
     запрос потолок не тратит.
   - AC4.3. Посетители — в отдельной таблице на 20 000 записей; если она
     заполнена и не освобождается очисткой, запрос считается по IP (как
     сейчас), а не ждёт.
5. Поисковые роботы.
   - AC5. UA Googlebot/Google-InspectionTool/GoogleOther/AdsBot/bingbot/
     YandexBot и др. проверяется обратным DNS (googlebot.com, google.com —
     не googleusercontent.com, под ним любая ВМ Google Cloud;
     yandex.ru/.net/.com; search.msn.com) и прямым
     подтверждением IP. Подтверждённый робот не ограничивается. Кэш
     5000 адресов (24 ч / 1 ч), не больше 16 одновременных проверок,
     запросы DNS через c-ares (не `dns.lookup`, который занимает общий
     пул потоков), 1 с на запрос и не больше 2 с на проверку; IPv6 в
     любой записи; при сбое — обычный клиент.
6. Экран паузы.
   - AC6. По окончании отсчёта страница открывается сама, если вкладка
     видима; не чаще 3 автоповторов подряд (sessionStorage), не раньше
     3 с; кнопка «Продолжить» остаётся.
7. Аварийный выключатель.
   - AC7. `PAGE_NAVIGATION_LIMIT=off` — ограничитель не отвечает 429
     (статистика пишется); `PAGE_NAVIGATION_LIMIT_SCALE=<0.25…100>` —
     множитель всех порогов; неверные значения игнорируются. Порядок
     включения на сервере описан в `docs/page-navigation-guard.md`.

## Проверка
- AC8. Unit-тесты на каждый пункт; `npm run typecheck`, `npm run test:gate`.
- AC9. Локальная production-сборка (`next build` + `next start`) за
  заглушкой: каждый пункт вживую (в т. ч. `_rsc`, cookie, статистика в
  базе, страница `/root/page-limit`, автопродолжение).
- AC10. Независимое ревью свежим агентом; найденное — исправлено или
  обосновано.
- Деплой меняет схему: новая таблица `PageLimitStat` (только добавление).
