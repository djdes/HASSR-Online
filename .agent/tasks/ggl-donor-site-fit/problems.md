# Проблемы первого прогона

Проверка трёх площадок из слота и отраслевого контрольного сайта вернула четыре пустых результата. У контрольного сайта есть профильные статьи. Выборка не обходила рубрики «Менеджмент» и «Проблемы и рекомендации», а при повторных ссылках на материал могла сохранять анонс вместо заголовка. Расширены названия тематических рубрик и уточнён отбор по заголовку и тексту статьи.

Первая попытка npm ci установила зависимости, однако npm запустил POSIX-скрипт prepare через cmd.exe. Prisma сгенерирована отдельно; для повторной установки используется Git Bash в качестве script-shell.

На Windows начальная проверка типов стартовала до генерации Prisma. Повтор запущен после генерации. Проверка каталога i18n требует LF в производных файлах даже при core.autocrlf=true, поэтому для локальной проверки они оставлены в том виде, в котором их записал генератор. Различия ограничены окончаниями строк и не добавляются в коммит.

Также тест переименования объектов на Windows сканировал собственный исходник из-за разных разделителей путей. Нормализован путь для списка исключений, сам тест по-прежнему проверяет весь остальной код.

Прямая выборка на Windows не смогла разрешить адрес отраслевого контрольного сайта через отдельный DNS-резолвер. Проверка использует системное разрешение имени с общим таймаутом, а HTTPS-соединение по-прежнему открывается только к уже проверенным публичным IPv4. После этого контрольный сайт подтвердил две публикации для аудитории слота.

Свежая проверка типов обнаружила передачу числового траста в строковый параметр перевода. В карточке траст преобразован в строку, после этого проверки перезапущены.
