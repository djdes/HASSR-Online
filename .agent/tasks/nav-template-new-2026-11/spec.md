# Spec (frozen 2026-11-09): шаблон меню «Новый» — два уровня слева, остальное сверху

Запрос владельца: «сделай вариант D только как вариант шаблона „Новый“, чтобы опционально можно было из
меню кликнуть и, если что, вернуться к стандартному. Нужно максимально понятно и легко всё сделать».
Вариант D — эскиз на холсте «WeSetup — новая навигация, 4 варианта»: слева разделы и раскрывающийся под
разделом список, уровни глубже — горизонтальное меню над страницей с выпадающим подменю, над страницей —
строка «Назад + хлебные крошки».

## Исходное состояние (master b1747297)

- Меню кабинета — одно дерево `NAV_SECTIONS` (`src/lib/app-nav.ts`): разделы главного меню → пункты меню
  раздела (среди них вложенные разделы со своим меню: «Моя компания → Торговые точки → Журналы») → вкладки
  пункта. Права и адреса считает `visibleNav`, клиент получает готовую `NavModel`.
- Сайдбар (≥1024px, `app-sidebar.tsx`) при входе в раздел целиком меняется на его меню (лента из двух
  панелей, «стопка уровней» сверху). Вкладки пункта — над страницей (`SectionTabs`). В разделе с меню крошек
  нет, на глубоких страницах — ссылка «‹ пункт» (`SectionFrame`).
- Настройки устройства — кука `wesetup-view` (`src/lib/view-prefs.ts`), сервер ставит атрибуты на `<html>`.

## Границы

- Меняется только кабинет на компьютере (≥1024px). Телефон, мини-приложение, лист меню, ⌘K — без изменений.
- Дерево меню, права, адреса и подписи пунктов не меняются: шаблон — другое представление той же `NavModel`.
- По умолчанию — стандартное меню; у тех, кто ничего не нажимал, не меняется ничего.
- Схема БД не меняется.

## Критерии приёмки

- **AC1. Выбор шаблона на устройстве.** В `ViewPrefs` — поле `navLayout: "classic" | "new"` (ключ куки `n`,
  по умолчанию `classic`), атрибут `<html data-view-nav>`. Разбор и запись куки — туда и обратно, мусор — по
  умолчанию; тест.
- **AC2. Переключатель в меню.** Внизу сайдбара в обоих шаблонах — переключатель «Вид меню: Стандартный /
  Новый». Нажатие меняет меню сразу, без перезагрузки; выбор переживает перезагрузку страницы; вернуться к
  стандартному — то же одно нажатие.
- **AC3. Слева — два уровня.** В шаблоне «Новый» сайдбар показывает разделы главного меню; под разделом, в
  котором человек находится, раскрыт список его пунктов (с подписями групп). Нажатие на другой раздел
  открывает его корень и раскрывает его список; нажатие на раскрытый раздел сворачивает список. Глубже
  второго уровня слева ничего нет. Текущий пункт подсвечен (`aria-current`). «Пришла проверка» — внизу.
- **AC4. Уровни 3–5 — горизонтальное меню над страницей.** Когда текущий пункт второго уровня — вложенный
  раздел, под шапкой стоит строка с его пунктами; у пункта с подменю (вложенный раздел со своим меню или
  пункт с вкладками) — стрелка и выпадающая панель: пункты следующего уровня, под пунктом — его вкладки.
  Когда пункт второго уровня — обычный пункт с вкладками, строка показывает эти вкладки (и `SectionTabs`
  над страницей на компьютере не дублируются). Текущее место подсвечено. Расчёт — чистая функция
  `buildNewNav` с тестами на реальной модели меню.
- **AC5. Хлебные крошки.** В шаблоне «Новый» на компьютере над страницей — кнопка «Назад» и цепочка
  «раздел › вложенные разделы › пункт › вкладка › страница»: каждое звено, кроме последнего, — ссылка;
  повторы подряд убираются. Ссылка «‹ пункт» на компьютере не показывается (её заменяют крошки). Страницы
  журнала (`/journals/<код>/…`) рисуют свои крошки сами — там строка не добавляется.
- **AC6. Стандартный шаблон не изменился**, кроме переключателя внизу сайдбара. Телефон не изменился.
- **AC7. Проверки.** `npm run typecheck`, `npm run test:gate`, `npm run lint` по изменённым файлам — без новых
  ошибок; подписи есть на ru, en, uz (`i18n:types` перегенерирован).

## Что меняет деплой

Только код интерфейса. Миграций и новых переменных окружения нет.
