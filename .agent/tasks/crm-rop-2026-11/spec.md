## Готовые решения (GitHub) — вывод

Отдельную CRM (Twenty, Chatwoot, Krayin, EspoCRM) не ставим: это второй сервер, вторая
база и вторая авторизация, а все обращения уже лежат в нашей PostgreSQL. Берём идеи и
библиотеки:
- **imapflow** (postalsys/imapflow, MIT, автор nodemailer) — IMAP-клиент;
  **mailparser** (nodemailer/mailparser, MIT) — разбор письма.
- Отсев автоответов — по RFC 3834 и практикам `is-autoreply` / arp242 «How to detect
  automatically generated emails»: `Auto-Submitted`, `X-Autoreply`, `X-Autorespond`,
  `X-Auto-Response-Suppress`, `Precedence`, `List-Id`/`List-Unsubscribe`, bounce.
- Из Chatwoot/Pipedrive: единая лента переписки по контакту, статус «ждёт нашего
  ответа», у каждого живого лида есть «следующий шаг» с датой.

## Модель данных (только добавления — `apply-safe-schema` пропускает)

- `User.platformSalesHead Boolean @default(false)` — роль РОП.
- `CrmContact` — человек/компания: имя, компания, email (lower), телефон + `phoneKey`
  (последние 10 цифр), `telegramChatId`, `userId`/`organizationId` (если узнали),
  `stage` (new | in_work | won | lost | spam), `ownerId` (ответственный), `source`
  (канал первого обращения), `lastInboundAt`, `lastOutboundAt`, `lastActivityAt`,
  `awaitingSince` (с какого входящего ждём нашего ответа), `nextActionAt` +
  `nextActionNote` (следующий шаг), `note`.
- `CrmInteraction` — запись ленты: `channel`, `direction` (in | out | note | event),
  `subject`, `body` (до 4000 символов), `externalKey @unique` (идемпотентность:
  `email:<message-id>`, `chat:<id>`, `service:<id>` …), `href` (ссылка на точечный
  инструмент), `fromAddress`, `filteredReason` (отсеянное письмо, без контакта),
  `authorUserId`/`authorName`, `occurredAt`.
- `CrmMailbox` — ящик для сканирования: хост/порт/SSL/логин/пароль (AES-GCM), папки
  «Входящие» и «Отправленные», `uidValidity`/`lastUid` по каждой, `lastSyncAt`, `lastError`.
- `CrmSenderRule` — `pattern @unique` (адрес или `@домен`), `action` block | allow.
- `CrmReminderLog` — `dedupeKey @unique`: «забрали, потом отправили» — напоминание
  уходит не больше одного раза даже при двух одновременных прогонах.
- Курсоры внутренних источников — `PlatformSetting` `crm:cursor:<source>`.

## Логика

**Сбор (раз в 5 минут, `/api/cron/crm` + кнопка «Обновить сейчас»).**
1. Внутренние источники → записи ленты; первый прогон подтягивает 90 дней истории,
   дальше — от курсора с нахлёстом 10 минут; дубли отсекает `externalKey`.
   Рассылки поддержки «всем» (`broadcastId`) не считаются ответом клиенту.
2. IMAP: каждый включённый ящик, «Входящие» (входящие письма) и «Отправленные»
   (наши ответы — только к уже известным контактам). Первый проход — 30 дней,
   дальше по UID; смена `UIDVALIDITY` — проход заново по окну. До 200 писем за прогон,
   письмо читается до 256 КБ.
3. Склейка контакта: email → телефон → Telegram chat id → пользователь платформы;
   по email/телефону подтягиваются пользователь и организация (клиент или лид).

**Отсев писем (по порядку, первое совпадение):** allow-правило → принять;
block-правило → «стоп-лист»; нет отправителя; наш домен (wesetup.ru) — «внутреннее»;
bounce (mailer-daemon/postmaster, multipart/report, «Undelivered…») — «недоставка»;
автоответ (`Auto-Submitted`≠no, `X-Autoreply`, `X-Autorespond`,
`X-Auto-Response-Suppress`, тема «Автоответ/Out of office») — «автоответ»; спам-метки
(`X-Spam-Flag: YES`, `X-Spam-Status: Yes`, `X-Yandex-Spam: 4`) — «спам»; рассылки
(`List-Id`, `List-Unsubscribe`, `Precedence: bulk|list|junk`) — «рассылка»; адреса роботов
(noreply, no-reply, do-not-reply, notifications, mailer, bounce, robot) — «робот».
Отсеянное хранится (без контакта) во вкладке «Отсеяно»: «Вернуть» и «Вернуть и всегда
пропускать». Из карточки — «Спам: в стоп-лист».

**Состояние контакта** (пересчёт после каждой записи): ответом считается `out` или
отметка «Ответ не нужен»; `awaitingSince` — первое `in` после последнего ответа.
События (`event`: регистрация, бланк, счёт) ответа не ждут.

**Напоминания** (только 09:00–21:00 по Москве, иначе ждут утра; `spam`/`lost` — никогда):
- нет ответа клиенту 30 мин → ответственному (нет ответственного — РОП); для онлайн-чата
  этот шаг пропускаем (там свой сигнал поддержке через 15 минут);
- нет ответа 4 часа → эскалация РОП (и ответственному);
- старше 7 дней — больше не пингуем, остаётся в сводке и дайджесте;
- клиент молчит 3 дня после нашего ответа и нет следующего шага → «напомните о себе»;
- наступил срок следующего шага → ответственному (нет — РОП);
- новое письмо из почты: новый лид → РОП; ответ по контакту с ответственным → ему;
- ежедневная сводка РОП в 09:00 по Москве (Telegram + почта).
Получатели: все РОП + ответственный; если РОП нет — администраторы платформы.
Канал: Telegram, если привязан, иначе почта.

**Заявки РОП.** Новая аудитория уведомлений `sales` = администраторы + РОП. На неё
переводятся «заявочные» уведомления: показ за 15 минут, заявка на услугу, счёт по ИНН,
заявка партнёра, регистрация.

## Экраны (раздел «Продажи», верхний пункт меню «CRM»)

- `/root/crm` — сводка по гайду дашбордов: «Что сделать сейчас» (ждут ответа,
  следующие шаги на сегодня/просрочены), «Требует внимания» (просрочено > 4 ч, молчат
  после нашего письма), цифры за 30 дней по каналам и по стадиям, «Инструменты» —
  ссылки на чаты, заявки на услуги, КП, рассылки, счета, воронку, клиентов, партнёров,
  ЭДО, «Мою почту», «Почта и фильтры». Состояние ящиков и последнего сбора.
- `/root/crm/contacts` — все контакты: поиск, очередь (ждут ответа / ждём клиента /
  шаг на сегодня / все), стадия, канал, «мои»; последняя реплика в строке.
  «Добавить лид» — вручную из WhatsApp, VK, MAX, звонка и т. п.
- `/root/crm/contacts/[id]` — карточка: стадия, ответственный, следующий шаг, данные;
  инструменты: письмо (через личную почту `sendStaffEmail`), Telegram (если писал боту),
  записать звонок, заметка, «Ответ не нужен», ссылки tel:, WhatsApp, Telegram,
  чат поддержки, организация, КП, счета; лента всей переписки по всем каналам.
- `/root/crm/mail` — ящики IMAP (добавить/изменить/проверить — только владелец),
  правила block/allow, отсеянные письма.

## Роль РОП

- В «Команде и доступах» в окне доступа — переключатель «РОП»; требует раздел «Продажи»
  (окно отмечает его само, сервер отклоняет несогласованный запрос). Снятие доступа
  снимает и РОП. В списке команды — метка «РОП». Назначение пишет аудит и оповещает
  человека (Telegram/почта).
- Одноразовый сид `prisma/seed-crm-rop-2026-11.ts` (маркер `once:crm-rop:alexey:v1`):
  alexey@wesetup.ru — РОП (раздел «Продажи» у него уже есть), шаг деплоя после
  `seed-platform-admin-2026-11`.

## Критерии приёмки

- **AC1** Схема: новые модели и колонка из раздела «Модель данных»; `prisma validate`
  проходит; `additiveSchemaSql` на диффе от текущей схемы не находит разрушающих
  операций (проверка на локальной PostgreSQL).
- **AC2** Доступ: `/root/crm*` и `/api/root/crm*` — раздел `sales`; изменение ящиков
  (`POST/PUT/DELETE /api/root/crm/mailboxes*`) — только владелец; крон — `CRON_SECRET`;
  `platform-access.test.ts` (обход всех страниц/маршрутов) зелёный; пункт «CRM» в меню.
- **AC3** Отсев писем: чистая функция с тестами на каждое правило и порядок
  (allow бьёт эвристику, block бьёт всё остальное, обычное письмо клиента принимается).
- **AC4** Склейка и состояние: нормализация email/телефона, правила allow/block по адресу
  и домену, расчёт `awaitingSince`/last*/«ответ не нужен» — тесты.
- **AC5** Источники: преобразование строк всех внутренних источников в записи ленты
  (канал, направление, ссылка, ключ, контактные данные) — тесты; повторный прогон не
  создаёт дублей (уникальный `externalKey`, проверено на локальной БД).
- **AC6** IMAP: синхронизация через подменяемый клиент — новые письма по UID, смена
  UIDVALIDITY, письма из «Отправленных» только к известным контактам, отсеянное
  сохраняется с причиной, курсор двигается — тест; адаптер на imapflow + mailparser;
  пароль ящика хранится зашифрованным и не отдаётся в API.
- **AC7** Напоминания: план напоминаний (30 мин / 4 ч / 7 дней, чат без первого шага,
  молчит 3 дня, следующий шаг, тихие часы, spam/lost) и тексты — тесты; отправка
  «забрали, потом отправили» через уникальный `dedupeKey`; ежедневная сводка — один раз в день.
- **AC8** Роль РОП: API команды принимает `salesHead`, требует раздел «Продажи»,
  снятие доступа снимает РОП; аудитория `sales` = администраторы + РОП (тест);
  заявочные уведомления идут на `sales`; окно доступа и список команды показывают РОП;
  сид для alexey@wesetup.ru однократный и подключён в деплой.
- **AC9** Экраны работают на живом сервере с локальной БД: сводка, список, карточка
  (смена стадии/ответственного/шага, заметка, «ответ не нужен»), «Добавить лид»,
  «Почта и фильтры» — скриншоты на телефоне и компьютере, без ошибок в консоли.
- **AC10** `npm run typecheck`, `npm run test:gate`, `npm run lint` (по изменённым файлам),
  `npm run i18n:check` — зелёные; документация `docs/crm.md` со строкой crontab и
  настройкой почты.
