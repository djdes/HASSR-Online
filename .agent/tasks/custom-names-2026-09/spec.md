# Spec (frozen 2026-09-25): свои названия разделов и журналов у организации

Правка владельца: «Сделать в разделе настроек возможность переименовать разделы и стандартные названия журналов — кому не нравятся наши. Продумать хотя бы минимально, индивидуально за организацией.»

## 1. Что можно переименовать
- **Журналы**: любое включённое в организации название журнала (сейчас название берётся из шаблона журнала/каталога — `src/lib/journal-catalog.ts` и т. п.; найти единый источник отображаемого названия).
- **Разделы меню кабинета**: пункты навигации (`Журналы`, `Сотрудники`, `Отчёты` и т. д. — найти конфигурацию меню, `MENU_*` в `src/components/layout/*`/`src/lib/*`). Служебные пункты (Настройки, Выход) — не переименовываются.

## 2. Где задаётся
- Настройки → «Названия» (новая страница `/settings/names` + пункт в списке настроек; права — как у настроек журналов). Два списка: «Разделы меню» и «Журналы» (поиск по журналам). У каждого: стандартное название серым, поле своего названия, «Вернуть стандартное». Пустое поле = стандартное. Ограничение 2–80 символов, обрезка пробелов. Сохранение одной кнопкой, `AuditLog` (что было → что стало).

## 3. Где действует
- Своё название показывается везде, где пользователи организации видят журнал/раздел: меню, главная (карточки журналов, «Обязательные журналы»), список журналов, страница документа журнала, задачи/напоминания в кабинете, QR-страницы заполнения (сотрудник видит привычное название), мини-приложение, уведомления в Telegram — где название журнала подставляется из общего источника.
- **Печать (PDF), проверяющий (`/inspector`), образцы на сайте и отчёты для надзорных органов — официальное название** (так требуют проверки). На странице документа под своим названием мелко: «Официальное название: …», чтобы не путались.
- Поиск по журналам (командная палитра и т. п.) находит и по своему, и по официальному названию.

## 4. Хранение
- Разрешено одно добавление в схему: `Organization.customNamesJson Json @default("{}")` вида `{ "journals": { "<code>": "Своё" }, "sections": { "<key>": "Своё" } }`. Порядок, чтобы не сломать соседние копии, которые используют тот же node_modules: сначала `prisma db push` в КАЖДУЮ локальную базу копий — `wesetup_wt_ui`, `wesetup_wt_pdf`, `wesetup_wt_qrforms`, `wesetup_wt_blanks` (строка подключения — как в `.env` этой копии, меняется только имя базы), и только потом `prisma generate`. Больше схему не трогать.
- Один помощник на сервере (например `resolveJournalDisplayName(org, code)` / `resolveSectionName(org, key)`) и один способ передать названия на клиент — без дублирования логики по страницам. Кеширование — как у остальных настроек организации.

## Не делать
- Не переименовывать коды журналов, URL и данные. Не менять названия в печати/у проверяющего.
- Не править whats-new/CHANGES; не писать в `D:/www/Wesetup.ru`; не пушить.

## Критерии приёмки
- AC1: в `/settings/names` можно задать и сбросить свои названия разделов и журналов; аудит.
- AC2: своё название видно в меню, на главной, в списке журналов, на странице документа (с подсказкой официального), на QR-странице заполнения и в мини-приложении.
- AC3: в PDF и у проверяющего — официальное название.
- AC4: у другой организации названия стандартные (изоляция).
- AC5: typecheck, `npm test` (тесты помощника названий и API), e2e на своей базе со скриншотами 390 и 1440.
