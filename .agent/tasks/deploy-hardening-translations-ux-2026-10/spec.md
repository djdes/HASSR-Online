# Деплой: повтор SSH, честная версия, авто-откат. Переводы: ссылки, «устарели», автоперевод раздела, «далее», история (2026-10-25)

## Запрос владельца

> сделай 1, 4, 5 и все пункты по переводам, обнови промпт

Пункты из предложений:
1. Повтор SSH-подключения в `deploy.yml` (деплой #2029 упал на разовом
   `dial tcp …: i/o timeout`).
4. `/api/health` показывает `.build-sha`, который деплой пишет в начале, —
   при упавшем деплое там была чужая версия.
5. Проверка после рестарта и автоматический откат на `.next-previous`.
8. Ссылки на состояние редактора переводов (`?q=`, `?section=`, `?page=`,
   `?key=`), кнопка «Назад».
9. Фильтр «Исходник изменился».
10. Автоперевод на весь раздел/поиск, а не только 100 строк страницы, с
    прогрессом.
11. «Сохранить и далее» и переход по строкам с клавиатуры.
12. История правок строки из AuditLog с возвратом версии.
+ обновить промпт для других репозиториев.

## Решения

- SSH: повторяем только то, что безопасно повторить. Шаг 1 деплоя
  распаковывает и удаляет архив, шаг 3 меняет БД и перезапускает сайт —
  их не повторяем. Перед выгрузкой и перед шагом 1 — ожидание SSH-порта
  (TCP, до ~2 минут). «Prepare app directory» (`mkdir -p`) и SCP —
  вторая попытка после паузы, таймаут подключения 60 с.
- `/api/health`: `buildSha` — вшитая версия (как `/api/build-info`), файл
  `.build-sha` — отдельным полем `buildShaOnDisk`, только если отличается.
- Авто-откат: шаг 3 до переключения запоминает обслуживаемую версию;
  после рестарта и прогрева `scripts/post-deploy-check.sh` ждёт, пока
  `/api/build-info` отдаст выкатываемый коммит, а `/` и `/login` ответят
  без 5xx. Не дождался — `scripts/deploy-rollback.sh` возвращает
  `.next-previous`, `.build-sha`, перезапускает сайт и проверяет прежнюю
  версию; деплой падает (уведомление в Telegram уже есть). `.next-previous`
  удаляется только после успешной проверки. Схема БД не откатывается
  (применяются только добавляющие изменения — прежняя сборка с ними
  работает).
- Ссылки: состояние в адресе (`q`, `section`, `filter`, `page` с 1, `key`);
  раздел, страница и открытая строка — новая запись истории, поиск и
  фильтр — замена текущей. «Назад» закрывает окно строки (на телефоне —
  жест «назад»). Через `history.pushState` (Next.js синхронизирует его со
  своим роутером без запроса к серверу). Открытая по ссылке строка
  догружается `GET /api/translations?key=`. В окне строки — «Скопировать
  ссылку».
- «Устарели»: фильтр `filter=stale` (правка есть, русский исходник
  изменился после неё). На телефоне фильтры — одна прокручиваемая строка.
- Автоперевод раздела: сервер отдаёт число кандидатов на весь раздел или
  поиск и по запросу — все их ключи (`?candidates=en`). Клиент переводит
  пачками по 30 с прогрессом, на 429 ждёт и продолжает, можно остановить.
  Результат — черновики, как раньше; строки с ручной правкой не трогаются.
- «Сохранить и далее»: кнопка в окне строки; Ctrl/⌘+Enter — сохранить и
  к следующей, Alt+↑/↓ — соседняя строка; на краю страницы — переход на
  соседнюю страницу.
- История: `GET /api/translations/history?key=` — записи AuditLog
  (`entity = "translation"`, все языки строки, новые сверху, до 50).
  Правки переводов общие для платформы, поэтому история не режется по
  организации; доступ — только ROOT и переводчикам. В окне строки —
  сворачиваемый блок «История правок»: кто, когда, язык, было → стало,
  «Вернуть эту версию» / «Вернуть прежний текст» — ставят черновик.

## Вне объёма

- Пункты 2, 3, 6, 7 из предложений (лог причины остановки схемы, сторож
  версии, права Actions, защита ветки).
- Откат схемы БД; повтор неидемпотентных шагов деплоя.

## Критерии приёмки

- AC1. `deploy.yml`: ожидание SSH-порта перед выгрузкой и перед шагом 1;
  вторая попытка «Prepare app directory» и SCP после неудачи первой;
  неидемпотентные шаги без повтора. Файл — валидный workflow
  (actionlint или разбор YAML), логика ожидания проверена локально.
- AC2. `/api/health.buildSha` = вшитая версия; `buildShaOnDisk` — только
  когда файл отличается. Unit-тест на функцию выбора версии.
- AC3. Проверка после рестарта и откат — скрипты в `scripts/`, вызов в
  шаге 3, удаление `.next-previous` после успешной проверки. Тест с
  заглушкой сервера и pm2: верная версия → 0; неверная → откат, прежняя
  сборка на месте, код ≠ 0.
- AC4. Адрес отражает `q/section/filter/page/key`; открытие ссылки
  восстанавливает вид и открытую строку; «Назад» закрывает окно и
  возвращает прежнюю страницу/раздел; «Скопировать ссылку» копирует адрес
  со строкой. Unit-тест разбора/сборки адреса.
- AC5. Фильтр «Устарели» показывает только строки со `stale`. Unit-тест
  предиката фильтра.
- AC6. Кнопки автоперевода показывают число кандидатов на весь раздел;
  перевод идёт пачками по всем страницам с прогрессом, 429 → пауза и
  продолжение, «Остановить» работает; черновики появляются и на других
  страницах раздела.
- AC7. «Сохранить и далее», Ctrl/⌘+Enter, Alt+↑/↓; на последней строке
  страницы «далее» открывает первую строку следующей страницы.
- AC8. История: API отдаёт записи всех языков строки, без доступа — 403;
  в окне строки видно правку и «Вернуть» ставит черновик.
- AC9. Тексты UI в ru/en/uz, `i18n:types` перегенерированы штатно;
  `npm run typecheck`, `npm run test:gate`, `i18n-types --check`, eslint
  по изменённым файлам — зелёные.
- AC10. e2e (телефон и компьютер) на AC4–AC8 + прежние проверки
  редактора; скриншоты в `raw/` (локально).
- AC11. Промпт для других репозиториев обновлён под сделанное.
