# pages-points-2026-10 — решения по ходу

1. **Модель меню.** У группы — `source?: NavMenuSourceKey` (`"buildings"`); описание источника —
   `NAV_MENU_SOURCES.buildings = { icon: "Store", hrefBase: "/settings/buildings", access: FULL_ACCESS }`.
   Пункты из данных (`sourceMenuItems`) — id `buildings:<id>`, адрес `<hrefBase>/<id>`, подпись — название точки
   (поле `label` у видимого пункта, не через i18n). Подставляются в `visibleNav(actor, facts, data)` перед
   обычными пунктами группы, только если человеку открыта страница точки (`navAllows` по `hrefBase` и `access`).
   `buildNavModel({ …, menuData })`, данные — `loadNavMenuData(session)` (запрос в БД только руководству).
   Статическая модель (`PATH_OWNERS`, `sectionForPath`) не менялась: динамических сегментов в ней нет.
2. **Какие точки в меню.** `listPersonBuildings(session)` (`active-building.ts`): все точки организации в порядке
   переключателя (`sortOrder`, имя) с правилом `User.buildingIds` в домашней организации — как у
   `loadBuildingContext`, но независимо от тумблера «журналы по точкам». При включённом тумблере список
   совпадает со списком переключателя; при выключенном шапка показывает «Все: N», а меню всё равно учитывает,
   на каких точках работает человек. Та же функция — проверка страницы точки (вне списка — 404) и ссылки
   «Открыть точку» на обзоре (у недоступной точки её нет).
3. **Активный пункт** — чистая `activeMenuItemId(path, itemIds)`: `/settings/buildings/<id>` (и глубже) — пункт этой
   точки, если он есть в меню человека; иначе — как раньше (`sectionForPath`). `useSectionPlace` берёт пункт через
   неё; сайдбар, лист телефона, Mini App и шапка страницы не менялись.
4. **Подписи групп** — свои: «Мои точки» (`myPoints`) и «Все точки» (`allPoints`), а не `directories`
   («Справочники»): в группе — обзор всех точек и справочники всех точек.
5. **Иконки:** пункт точки — `Store`, «+ Добавить точку» — `Plus` (добавлена в `nav-icons.ts`).
6. **Шапка без точек** («+ Добавить точку» руководителю) ведёт сразу в мастер `/settings/buildings/new`;
   подсказка обновлена: «Откроется мастер: название и адрес, помещения, оборудование». Пункт «Настроить точки»
   в выпадающем списке переключателя по-прежнему ведёт на обзор.
7. **Обзор `/settings/buildings`:** в шапке — «+ Добавить точку» (мастер), у карточки точки — «Открыть точку».
   Прежняя форма «Новая точка» внизу заменена кнопкой-ссылкой на мастер — один способ завести точку.
   Тумблер «Вести журналы отдельно по точкам» не тронут. Перевод на `SectionPageHeader` и i18n остального
   текста обзора — вне задачи (страница по-прежнему на русском, кроме новых подписей).
8. **Страница точки:** блоки 1–5 и удаление. Блок 1 — окно (PATCH существующего API) с подписью «идёт в сведения
   для документов этой точки». Блок 2 — помещения точки, добавление (POST `/api/settings/rooms`), «Настроить» —
   существующее окно помещения (название, вид, уборка, ответственные), удаление — `confirmAsync` с последствиями
   с сервера (как на обзоре), копирование из другой точки — существующий `copy-rooms`. Чтобы не дублировать
   разбор помещения для окна, `roomEditorInitial` вынесен из клиента обзора и используется обоими.
   Блоки 3–4 — серверные списки; правка/удаление — существующие `EquipmentDialog` / `DeleteButton`;
   у окна оборудования два необязательных свойства: `defaultType` (блок УФ-ламп открывает окно с типом
   «УФ-лампа») и `triggerLabel`. Блок 5 — существующая страница QR с параметрами `kind=equipment&layout=sheet&ids=…`
   (наклейки оборудования точки) и `kind=rooms&ids=…` (плакаты помещений точки).
9. **Мастер:** четыре шага с номером и полосой; создание — существующими API по очереди (точка → помещения или
   `copy-rooms` → оборудование с `roomId`, сервер сам заводит цех точки). Ошибка отдельного помещения или единицы
   не останавливает остальное: после создания — страница точки и тост «не добавилось: …». Новая точка получает
   `sortOrder` = последний + 1 — в меню и переключателе она последняя. Названия оборудования — «Холодильник N» со
   свободным номером в организации; нормы — холодильник 2…6 °C, морозильник −24…−18 °C (как в демо-справочнике);
   УФ-лампа — модель «Лампа ДБ…», ресурс 8 000 ч (правится на странице точки). Названия типовых помещений —
   на языке интерфейса.
10. **Страница точки не переключает текущую точку журналов** в шапке: шапка — выбор точки для журналов, открытие
    страницы точки не должно молча менять фильтр журналов.
11. Существующие окна (оборудование, помещение, удаление записи справочника) — как были, на русском; все новые
    тексты — next-intl RU/EN/UZ (`settingsManagement.points`, `navigation.shell.menus.points`, `navigation.shell.point`).

## Наблюдения (не исправлялось)

- В оболочке Mini App вне Telegram React пишет предупреждение гидратации про `style` у `<html>`
  (`--tg-viewport-height`, ставит скрипт Telegram WebApp). Есть и на нетронутой `/settings/areas` — к задаче не относится.
- Удаление точки оставляет её цеха «Без точки» вместе с оборудованием (так задумано в points-model). Если потом
  завести точку с теми же названиями помещений, правило зеркала (`pickMirrorArea`: цех этой точки, иначе одноимённый
  цех без точки) отдаст новой точке старые цеха с оборудованием. Это прежнее поведение модели; стоит решить владельцу,
  нужно ли при удалении точки предлагать удалить и её оборудование.
