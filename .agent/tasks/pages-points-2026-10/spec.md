- Группа «Мои точки» (`myPoints`): по пункту на каждую точку, доступную человеку (название точки, иконка `Store`,
  адрес `/settings/buildings/<id>`), затем **«+ Добавить точку»** `/settings/buildings/new`.
- Группа «Все точки» (`directories`… или своя подпись): Точки (обзор) `/settings/buildings`, Цеха и помещения,
  Оборудование, QR-наклейки и плакаты — как сейчас.
- «Ещё» — без изменений.

## Критерии приёмки

### AC1. Пункты меню из данных
1. Модель меню расширена источником пунктов из данных: у группы `NavMenuGroup` поле вроде
   `source?: "buildings"` (статическая часть группы — обычные пункты). `href` в статической модели без
   динамических сегментов (тест остаётся).
2. Пункты точек подставляются на сервере при сборке модели (`buildNavModel` или layout) из того же списка
   точек, что получает переключатель точки в шапке (с учётом точек, доступных человеку); подпись — название
   точки (не через i18n). Сайдбар, лист бургера, Mini App и ⌘K показывают их без отдельного кода.
3. Активный пункт: на `/settings/buildings/<id>` подсвечена именно эта точка (не «Точки»); на `/settings/buildings/new` — «+ Добавить точку»; на остальных путях — как раньше (`useSectionPlace` в `section-tabs.tsx`).
4. Нет точек — в группе только «+ Добавить точку». Чужая точка в меню не попадает.
5. Тесты: чистая функция подстановки пунктов (порядок как у точек, фильтр доступных, пусто), `menuShape("points")` для статической части, активный пункт по пути.

### AC2. Страница точки `/settings/buildings/[id]`
1. Guard — `hasFullWorkspaceAccess(` (как у `/settings/buildings`); точка другой организации или недоступная человеку — 404.
2. Заголовок — название точки (`SectionPageHeader title`), пояснение — адрес. Блоки-карточки по эскизу:
   1) **Название и адрес**: название, наименование для журналов, адрес, КПП, телефон; правка окном/формой через существующий API точек; подпись «идёт в сведения для документов этой точки»;
   2) **Цеха и помещения**: помещения точки (`Room`) с видом (включая «Основное производство»), добавить/переименовать/удалить существующими окнами и API; пустое состояние;
   3) **Оборудование**: оборудование точки (через `Area.buildingId`), кроме УФ; добавить — окно оборудования с этой точкой по умолчанию;
   4) **УФ-лампы и установки**: оборудование типа УФ: модель, ресурс, наработка (как на «Оборудовании»);
   5) **QR-наклейки и плакаты**: сколько наклеек у оборудования точки, кнопки печати листа/плакатов этой точки (существующие страницы/листы с параметром точки, если поддерживают; иначе — ссылка на `/settings/qr-posters`).
3. Удаление точки — в конце страницы, `ConfirmDialog` с `typeToConfirm` и последствиями; по существующему API.
4. Телефон 390 — блоки в одну колонку, без горизонтальной прокрутки.

### AC3. Мастер «+ Добавить точку» `/settings/buildings/new`
1. Guard — `hasFullWorkspaceAccess(`. Пошагово (pipeline с номером шага): 1) название и адрес; 2) помещения — типовой набор галочками (Кухня/горячий цех, Холодный цех, Основное производство, Склад, Мойка, Зал…) и «как в точке …» (копирование помещений из существующей точки, если есть); 3) оборудование из типового набора с количеством (холодильник, морозильник, фритюрница, УФ-лампа…), с выбором помещения; 4) итог «что будет создано» → «Создать».
2. Создание — через существующие API (точка, помещения, оборудование); ошибки — тостом, частично созданное не теряется (после ошибки можно продолжить со страницы точки).
3. После создания — переход на страницу новой точки, точка появляется в меню (обновление модели меню).
4. Кнопка «+ Добавить точку» есть и в шапке `/settings/buildings` (вместо/в дополнение к кнопке внизу).

### AC4. Обзор `/settings/buildings`
