# Spec (frozen 2026-09-28): акции с зачёркнутой ценой и промокоды на подписку

Задача владельца: «Сделать акцию и в админке настройку акций с датой и временем, периоды, которые зачёркивают
цену в процентном соотношении. Придумать промокоды для снижения цены». Решения оркестратора — ниже.

Сейчас (master bc243840): цена подписки — `PlatformTariff` (ROOT `/root/tariffs`), расчёт — `quoteSubscription`
в `src/lib/subscription-pricing.ts` (одна функция на лендинг, `/pricing`, кабинет, ROOT), промокоды уже есть:
`src/lib/promo/rules.ts` (percent/fixed, даты, лимит оплат, «только новым»), `src/lib/promo/service.ts`
(`resolvePromo`), ROOT `/root/promo-codes`; оплата — Robokassa (`src/app/api/payments/*`, `PaymentOrder`,
`src/lib/payment-fulfillment.ts`), страница заказа `/order`. Параллельная задача `billing` меняет лимиты
(бесплатно 1 сотрудник, подписка до 10) и делает окно перехода — её файлы (`plan-limits*`, `plan-catalog`
константы, окно перехода) не трогать, кроме необходимого для цены.

## Сделать
1. **Акции.** Новая модель (например `PricePromotion`: название, процент 1–90, начало и конец — дата и время,
   включена, заметка). ROOT — раздел «Акции» (`/root/promotions`, ссылка в меню ROOT): список (идут сейчас /
   будущие / прошедшие), создать, изменить, выключить, удалить; время вводится и показывается в МСК; проверка
   (конец позже начала, процент в пределах). Пересечение периодов допустимо — действует наибольший процент.
2. **Одна серверная функция цены** (например `getSubscriptionOffer(now)`): базовая цена из `PlatformTariff`,
   действующая акция (или null), цена со скидкой (целые рубли), конец акции. Скидка акции — на всю сумму подписки
   (база + доплата за сверх лимита). Клиенту — пропсами (client-safe модуль расчёта, как `quoteSubscription`).
3. **Зачёркнутая цена везде, где показана цена подписки:** лендинг (блок тарифов), `/pricing`,
   `/settings/subscription`, `/order`, мобильные/мини-экраны с ценой (найти поиском) — старая цена зачёркнута,
   рядом новая и плашка «−N % до <дата>». Один компонент на все места. Без акции — как сейчас.
4. **Оплата:** сумма к оплате = цена с акцией − скидка промокода (промокод считается от цены с акцией,
   `computeDiscountRub`). Сумму считает только сервер. В `PaymentOrder` сохранить базу, акцию (id/процент) и
   промокод со скидкой (для отчёта ROOT). Чек Robokassa — итоговая цена.
5. **Промокоды.** Проверить весь путь: ROOT создаёт → клиент вводит на оплате → проверка (сроки, лимит, «только
   новым») → скидка поверх акции → учёт использований после оплаты. Починить, если что-то не работает.
   Придумать стартовый набор (3–4 кода с назначением, сроком и лимитом: например переход после бесплатного
   периода, первый месяц новым, код для партнёров/продаж) — описать в evidence и сделать скрипт
   `scripts/seed-promo-codes.ts` (идемпотентный, создаёт их ВЫКЛЮЧЕННЫМИ; включает ROOT). Коды — латиница/цифры
   (`isValidPromoCodeFormat`).
6. Логи (`console.info("[promo] …")`), аудит изменений акций в ROOT.

## Проверка (обязательно)
- Юнит-тесты: выбор действующей акции (нет / одна / пересечение / граница времени), цена с акцией, промокод
  поверх акции (percent/fixed, не ниже 0), сумма заказа.
- E2E (Playwright, headless, Chromium из `%LOCALAPPDATA%\ms-playwright`, 390 и 1280): ROOT создаёт акцию на
  «сейчас» → на лендинге, `/pricing`, `/settings/subscription`, `/order` зачёркнутая цена и новая; промокод на
  `/order` уменьшает сумму; акция в прошлом — обычная цена. Скриншоты.
- `npm run typecheck`, `npm test` зелёные.

## Не делать
- Не включать боевую оплату, не трогать прод и env; не менять лимиты/тарифы/окно перехода (задача `billing`);
  не писать в `D:/www/Wesetup.ru`, не пушить, не править whats-new / CHANGES; не запускать `npm run dev` /
  `npm run build`.

## Критерии приёмки
- AC1: ROOT «Акции» с датой и временем, процентом, списком.
- AC2: во всех местах цены — зачёркнутая старая и новая в период акции; к оплате — цена с акцией.
- AC3: промокод работает поверх акции от ROOT до оплаты; стартовый набор кодов (выключены) + скрипт.
- AC4: тесты и e2e зелёные.
