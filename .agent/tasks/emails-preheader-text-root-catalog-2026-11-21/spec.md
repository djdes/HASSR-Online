## Факты (разбор)

- Во входящих рядом с темой почта показывает начало текста письма: сейчас это «wesetup.ru» из шапки
  и повтор темы (заголовок полосы). Прехедер есть только у рекламных рассылок (`EmailLayoutExtras.preheader`).
- `sendEmail` шлёт текстовую часть, только если её передали: из ~20 писем `email.ts` — у приветственного;
  у писем пробного периода и опроса — свой текст. Остальные — только HTML.
- Подсказка поля «Название компании или ИП (в шапку журнала)» на 390 px обрезается («…(в шапку ж»).
- Цели Метрики в окне скачивания есть: `blank_download_click`, `blank_download_done`,
  `blank_quick_register_done`; когда сервер просит «Я не робот» — цели нет.
- В ROOT есть образец: «Письма обмена справочниками» шлёт письмо на почту нажавшего
  (`sample-letters.server.ts`).

## Решения

- Р1. Прехедер у каждого письма через общий шаблон: явный `extras.preheader` главнее; иначе — первая
  содержательная фраза тела письма (без приветствия «Здравствуйте…», «Hello…», «Assalomu alaykum…»), до
  ~110 знаков по границе слова; после неё — невидимое заполнение, чтобы почта не дописывала «wesetup.ru».
- Р2. Текстовая версия у каждого письма: `sendEmail` собирает её из HTML, если вызывающий не дал своей
  (абзацы через пустую строку, ссылки «текст: адрес», пункты списков, без скрытого прехедера, `<style>`).
- Р3. Подсказка поля компании короче во всех языках: ru «Компания или ИП (в шапку журнала)», en/uz —
  того же смысла и длины; не обрезается на 360–430 px.
- Р4. Цель `blank_download_challenge`, когда сервер попросил проверку (полное окно и короткое окно
  запомненной почты). Как сравнить долю скачиваний до и после отмены капчи — `docs/blank-download-analytics.md`.
- Р5. ROOT → «Платформа» → «Письма» (`/root/emails`, раздел доступа «Мониторинг»): каталог писем сайта
  клиентам — каждое собрано настоящими функциями на примерах (письма `email.ts` — через перехват
  отправки без доставки; письма из `compose*/build*` — тем же шаблоном, что настоящая отправка), язык
  ru/en/uz там, где письмо переведено, ширина «телефон / компьютер», тема, строка во входящих, текстовая
  версия. «Прислать мне» — это письмо на рабочую почту нажавшего с темой «[Образец] …»; ответ: доставлено /
  записано в журнал (почта не настроена) / ошибка.

## Критерии приёмки

- **AC1. Прехедер.** Любое письмо через `layout()` начинается со скрытой строки: явная — как есть,
  иначе первая содержательная фраза без приветствия, ≤ 110 знаков, экранирована; за ней невидимое
  заполнение. Тест: текст письма по порядку начинается с этой строки, приветствие пропущено, явная
  строка главнее, HTML-спецсимволы экранированы.
- **AC2. Текстовая версия.** `sendEmail` передаёт транспорту `text`: свой — если дан, иначе собранный из
  HTML (абзацы, «текст: адрес» у ссылок, без прехедера, стилей и разметки, сущности раскодированы).
  Тест на преобразование и на то, что транспорт получает текст у писем без своего.
- **AC3. Подсказка поля компании** короче в ru/en/uz (`npm run i18n:types`), не обрезается на 360, 390 и
  430 px (снимок).
- **AC4. Цель Метрики** `blank_download_challenge` при запросе проверки в обоих окнах (тест по коду);
  `docs/blank-download-analytics.md` — цели и порядок сравнения до/после 20.11.2026.
- **AC5. ROOT «Письма».** Страница и API под правилом доступа «Мониторинг»; пункт меню «Письма»
  (ru/en/uz). Каталог: каждое письмо собирается на всех своих языках с непустыми темой, HTML (общий шаблон)
  и текстом, без настоящей отправки; id уникальны. «Прислать мне» шлёт выбранное письмо только на почту
  нажавшего, неизвестное письмо — 404, без рабочей почты — понятный отказ. Тексты интерфейса — ru/en/uz.
  Снимки страницы (компьютер и телефон).
- **AC6. Проверки.** `npm run i18n:types`, typecheck, test:changed / test:gate, eslint по изменённым
  файлам — зелёные.
