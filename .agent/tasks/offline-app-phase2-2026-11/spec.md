# Spec (frozen 2026-11-10): работа без связи, второй этап

Запрос владельца (2026-11-10, после выката первого этапа, PR #165): «Сделай все, кроме iPhone. То есть разные
языки, подписанные APK, вот это вот все, все пункты, кроме 10» — в ответ на список из 12 предложений.

Первый этап: `.agent/tasks/offline-app-2026-11/` (экран `/mini-offline`, пакет `/api/offline/pack`, очередь,
заголовки `x-offline-*`, слияние по записям форм).

## Исходное состояние (master 299b0f9c)

- Фото без сети не делается: форма с обязательным фото и организация с «фото показания обязательно» отправляют
  человека ждать интернет.
- Слияние и история строк видят только записи, сделанные через формы (аудит `journal.qr_fill`); правка той же
  строки в таблице кабинета не видна, запись с устройства ложится поверх.
- Фритюрница — «только с интернетом». Ежедневная уборка и климат помещений в браузере не проверялись.
- Данные на устройстве обновляются сами при открытии кабинета; кнопки и предупреждения о давности нет.
- Отметка «без связи» есть в журнале аудита, отдельного экрана для руководителя нет; сервер не знает, какие
  устройства работают без связи.
- На главном офлайн-экране не видно, что сегодня уже заполнено. Задач смены на нём нет.
- Тексты офлайн-экрана только русские.
- `https://wesetup.ru/.well-known/assetlinks.json` отдаёт `[]`: переменная `ANDROID_CERT_SHA256` на сервере не
  задана, поэтому Android не отдаёт ссылки с QR приложению ни у какой сборки.

## Критерии приёмки

- **AC1. Фото показания без сети.** У холодильника и помещения на офлайн-экране есть кнопка «Фото» (камера или
  галерея), если фотофиксация в организации включена; при «фото обязательно» без снимка запись не сохраняется.
  Снимок хранится на устройстве в очереди вместе с записью, при синхронизации сначала загружается
  (`/api/qr-fill/reading-photo` с заголовками `x-offline-*`), затем уходит запись со ссылкой на него. Запись
  видна в журнале с фото. Снимок больше 5 МБ или не картинка — отказ сразу, на устройстве.
- **AC2. Фото в формах журналов без сети.** Поле формы типа «фото» принимает снимки (до 3 на поле); они хранятся
  в очереди и при синхронизации загружаются через `/api/mini/attachments`, в запись уходят ссылки. Обязательное
  поле «фото» больше не блокирует форму. Фото шагов инструкции (уборка) по-прежнему не требуется — как на
  QR-странице с интернетом.
- **AC3. Потерянное или отклонённое фото не теряет запись.** Сервер не принял снимок или снимка в очереди нет —
  запись остаётся в «Не ушло» с причиной; без снимка в журнал не уходит.
- **AC4. Слияние видит правки из кабинета.** Для гигиены, здоровья и чек-листа уборки и проветривания «что сейчас
  в журнале» читается из самой записи журнала (а не только из аудита форм): история в пакете и слияние при
  синхронизации показывают и учитывают значения, внесённые в таблице кабинета. Тесты: правка в кабинете после
  скачивания пакета → расхождение показано человеку, не затёрто. Для остальных журналов «строка в день»
  поведение прежнее (аудит форм) — это явно указано в evidence.
- **AC5. Фритюрница без сети.** Наклейка фритюрницы открывает форму: «Начало жарки» (жир, продукция, оценка 1–5)
  или «Окончание жарки» (оценка, остаток, утилизация); списки жира и продукции — из пакета. Время записи — с
  устройства. Окончание без начала сервер не принимает — запись остаётся в «Не ушло» с причиной.
- **AC6. Уборка и климат помещений проверены.** В демо-данных сквозного сценария есть помещения, ежедневная
  уборка с уборщиками и климат; сценарий заполняет их без сети и проверяет запись в журнале.
- **AC7. «Обновить данные сейчас» и давность.** В профиле кабинета и на офлайн-экране (когда сеть есть) —
  кнопка обновления данных; результат виден сразу (новое время). Данные старше 24 часов — предупреждение на
  офлайн-экране и в строке профиля.
- **AC8. Что заполнено сегодня — на главном офлайн-экране.** У каждого объекта и журнала — отметка: заполнено
  сегодня (кем и когда, если известно), ждёт отправки, или ещё нет. Учитываются и данные пакета, и
  неотправленные записи этого устройства. Сверху — сводка «заполнено N из M».
- **AC9. Задачи смены без сети — только просмотр.** Пакет хранит задачи на сегодня вошедшего сотрудника
  (журнал, что сделать, состояние на момент скачивания). Офлайн-экран показывает их списком с пометкой «на
  момент …»; задача, чей журнал есть в пакете, открывает его форму. Взять, завершить или передать задачу без
  сети нельзя (правило проекта) — это написано на экране.
- **AC10. Устройства и записи без связи — экран руководителя.** Кабинет: «Настройки → Работа без связи»
  (только руководству). Список устройств (кто вошёл, приложение/браузер, когда выходило на связь, насколько
  свежи данные, сколько записей ждёт и не ушло по последнему отчёту устройства) и список записей, сделанных без
  связи, за 31 день (кто, что, когда сделано, когда получено, задержка, как подтверждён автор). Чужих
  организаций нет (тест).
- **AC11. Уведомления.** (а) Устройство вышло в сеть, а часть записей не принята (отказ или расхождение) —
  автор и руководство получают уведомление в колокольчик и push «Не ушло записей: N» со ссылкой на список; не
  чаще раза в сутки на устройство. (б) Устройство, с которого приходили записи без связи, не выходило на связь
  больше 24 часов — руководство получает одно уведомление «Устройство не на связи». Тесты на правила.
- **AC12. Языки.** Все тексты офлайн-экрана, строки готовности в профиле и экрана руководителя — на русском,
  английском и узбекском через словари проекта (`offlineApp`); `npm run i18n:check` зелёный. Причины отказа с
  кодами `offline-*` переводятся на устройстве. Названия журналов, полей и объектов — как в журналах.
- **AC13. Подписанный APK.** Запустить workflow из этой среды нельзя (нет права — 403), поэтому владельцу дана
  точная инструкция: как собрать подписанный APK, где взять отпечаток ключа и куда его вписать на сервере, чтобы
  системная камера открывала приложение. В репозитории — проверка, которая замечает пустой список ключей.
- **AC14. Ничего не сломано.** `npm run typecheck`, `npm run test:gate`, `npm run i18n:check` зелёные; сквозной
  сценарий первого этапа проходит; обычная работа с сетью не изменилась.

## Что НЕ входит

- iPhone (решение владельца).
- Фото шагов инструкции уборки (на QR-странице с интернетом их тоже нет).
- Чтение сохранённых значений из журнала для всех журналов «строка в день» — только три самых частых (AC4).
- Локальные уведомления на выключенном из сети устройстве: без нового нативного плагина приложение не может
  напомнить о себе, пока закрыто. Напоминание приходит руководству с сервера (AC11б).
- Взятие и завершение задач без сети.

## Что меняет выкат

- Новая таблица `OfflineDevice` (применяется `prisma db push`, данных не трогает).
- Новые маршруты: `/api/offline/heartbeat`, `/settings/offline`; проверка «устройство не на связи» вызывается
  из существующего крона (новых записей в расписании сервера не требуется).
- Новая версия APK не требуется; подписанную сборку запускает владелец.

## Как проверяем

Модульные тесты, production-сборка и сквозные сценарии в Chromium (как в первом этапе), `e2e/` и `raw/` этой
задачи. На настоящем планшете — проверка владельца.
