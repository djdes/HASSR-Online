## Композиция листа: A или B

Обе композиции — на одних данных и одной типографике (Manrope, токены сайта), бок о бок в цвете и ч/б:
`compare/compare-a-b-cafe.png`, `compare/compare-a-b-cafe-bw.png` (кафе, промокод 10 %),
`compare/compare-a-b-education.png`, `compare/compare-a-b-education-bw.png` (детский сад, без промокода).

- **A — сверху вниз:** шапка → заголовок и обращение → «Как это работает» тремя карточками → «Что получит
  ваше…» и «Журналы для…» в две колонки → панель предложения во всю ширину (цена крупно, зачёркнутая цена,
  плашка скидки, QR с промокодом) → контакты и реквизиты.
- **B — две колонки:** основная колонка 118 мм (заголовок, шаги списком, преимущества, журналы) и панель
  предложения 60 мм справа на всю высоту.

**Выбрана A.** Почему:
1. Порядок A совпадает с логикой продажи: сначала «как это работает» и польза, потом журналы, в конце цена и
   действие (QR, промокод, оплата). Взгляд заканчивает лист на кнопке-QR, а не начинает с неё.
2. Лист заполнен ровно. У B при коротких текстах в панели справа остаётся 20–25 % пустоты, а при длинных
   (столовая, производство) панель переполняется раньше основной колонки.
3. Читаемость: узкая колонка B рвёт заголовок на три строки («…ХАССП и / СанПиН для школы, детского / сада и
   лагеря»), тексты в панели 60 мм идут по 7–8 строк мелким кеглем. В A заголовок — две строки, абзацы короче.
4. Цена и QR в A — самые крупные элементы нижней трети: 17 pt цена, QR 36–38 мм рядом с промокодом.
   В B цена и QR сжаты шириной панели.
5. Ч/б печать: у A серая заливка — только панель предложения (~70 мм), у B — полоса на три четверти листа.
6. Письмо и веб-версия выстроены в том же порядке, что A, — КП одинаково во всех трёх каналах.

Код B удалён отдельным коммитом (4a94c05c); сравнение воспроизводится скриптом `compare-variants.ts` на
`pdf.ts` из 8bda0995.

## PDF

- Матрица `verify-pdf.ts`: **все 16 сфер × {без промокода, 10 % навсегда, 10 % до даты} × {короткое, 80 знаков}
  = 96 PDF — все на одной странице**, весь текст внутри полей 14/12 мм (координаты текста pdf.js с учётом
  выносных элементов шрифта), все обязательные тексты на месте (заголовки строк предложения, цена, промокод,
  обязательные журналы, название компании).
- QR каждого PDF снят растром 150 и 300 dpi: чистый, ч/б, «ч/б принтер», «телефон» (перспектива, поворот 7°,
  размытие, JPEG) и «ч/б + телефон» — **jsQR и zxing-cpp читают правильный адрес во всех 960 снимках**
  (`https://wesetup.ru/promo/<CODE>?s=<сфера>` с промокодом, нишевая страница сферы без него).
- Плотность вёрстки 0,906–0,981 (кегли уменьшаются, только когда не влезает), размер PDF 88,7–91,4 КБ

## Интерфейс для соседних задач (`src/lib/proposal/index.ts`, по спеке без изменений)

```ts
export type ProposalPromo = { code: string; kind: "percent" | "fixed"; value: number; lifetime: boolean; endsAt: Date | null };
export type ProposalSender = { name: string; phone?: string | null; email?: string | null; telegram?: string | null };
export type ProposalVars = { sphere: OrgSphere; companyName?: string | null; recipientName?: string | null;
  promo?: ProposalPromo | null; ctaUrl?: string | null; sender?: ProposalSender | null };
export const PROPOSAL_SPHERES: Array<{ sphere: OrgSphere; label: string }>;
export async function renderProposalPdf(vars: ProposalVars): Promise<Buffer>;
export async function renderProposalEmail(vars: ProposalVars, opts?: { webUrl?: string | null;
  unsubscribeUrl?: string | null; trackUrl?: (url: string) => string }): Promise<{ subject: string; preheader: string; html: string; text: string }>;
export function proposalWebUrl(vars: ProposalVars, baseUrl?: string): string; // `<база>/kp/<токен>`
```

- `renderProposalEmail`: `webUrl` не передан — своя подписанная ссылка на `NEXTAUTH_URL`; `null` — без ссылки
  «Открыть в браузере». PDF-ссылка добавляется, если `webUrl` — наш `/kp/<токен>`. `trackUrl` применяется ко
  всем ссылкам письма (включая `mailto:`/`tel:`/`t.me`), кроме `unsubscribeUrl`.
- Действующий промокод → в КП «−N % навсегда» (`lifetime`), «−N % до <дата>» (`endsAt`) или «−N % по промокоду»;
  истёкший (`endsAt` в прошлом) — цена без скидки, пометка, CTA на нишевую страницу.
- Для рассылки полезно: `buildProposalContent` + `loadProposalContext` (один раз на кампанию) и
  `renderProposalEmailHtml` — чтобы не читать базу на каждого получателя.

## Зависимости от соседей и ограничения

- **promo-personal:** адрес CTA/QR `https://wesetup.ru/promo/<CODE>?s=<сфера>` — их контракт (маршрута в этой
  ветке нет — до слияния QR с промокодом ведёт на 404). Поле `PromoCode.lifetime` читается без типа
  (`lifetimeOf` в `root.server.ts`) — после слияния коды «навсегда» в ROOT подхватятся сами.
- **Регистрация со сферой:** регистрация сферу из адреса не принимает, поэтому без промокода CTA ведёт на
  нишевую страницу сферы (`/dlya-…`, у «Другое» — `/register`). Если promo-personal научит регистрацию
  сфере — поменять одну функцию `proposalCta` (`src/lib/proposal/cta.ts`).
- **mailing:** отписка, учёт кликов, заголовки List-Unsubscribe и отправитель рекламы — их; тестовое письмо
  генератора уходит через `sendRawEmail` (только HTML, без вложения PDF).
- **next.config.ts:** `/kp/:token/pdf` — `X-Frame-Options: SAMEORIGIN` (иначе DENY блокирует встроенный
  просмотр в ROOT), `api/kp/qr/` — вне глобального no-store.
- **Шрифт:** в `src/lib/pdf-fonts` добавлены статические Manrope Regular/SemiBold/ExtraBold (~95 КБ каждый) из
  уже лежащего в репозитории `manrope-variable.ttf` (jsPDF не умеет вариативные шрифты), лицензия OFL —
  `LICENSE-Manrope.txt`. Новых npm-зависимостей нет.
