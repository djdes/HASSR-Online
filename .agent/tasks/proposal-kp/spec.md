# Spec (frozen 2026-09-29): коммерческое предложение (КП) — А4 PDF, письмо и веб-версия по сферам

Задача владельца: «создание коммерческого предложения — на А4 листе показать преимущества платформы + специальное
предложение по деньгам. Например: предлагаем бесплатно полный доступ к электронным журналам на 1 сотрудника, ваша
заведующая сканирует QR и заполняет температуру, бракераж и т. д. Если сотрудников до 10 (с журналами будут помогать и
повара и т. д.), то тариф такой-то, но для вас со скидкой 10 % навсегда — перечёркнутая цена; доступна оплата по QR-коду
или введите на сайте персональный промокод, и скидка заработает. Таким макаром для разных сфер — ресторан, кафе, детский
сад, отель и т. д., чтобы я мог разослать по почте точечно». И: «разработать email-письмо с этим КП — PDF А4, но
адаптированное под почтовики, с вёрсткой и под мобильные».

Ветка `feat/proposal-kp-2026-09-29`, рабочая копия `d:/wt/kp`, порт 3192. Соседи: `promo-personal` делает маршрут
`/promo/<CODE>?s=<sphere>` и персональные коды, `mailing` — рассылку. Их код в этой ветке не появится, опирайся на
контракты ниже.

## Сделать
1. **Модуль `src/lib/proposal/`** (без БД-моделей; цены — из тарифа и акций на момент отрисовки):
   ```ts
   export type ProposalPromo = { code: string; kind: "percent" | "fixed"; value: number; lifetime: boolean; endsAt: Date | null };
   export type ProposalSender = { name: string; phone?: string | null; email?: string | null; telegram?: string | null };
   export type ProposalVars = {
     sphere: OrgSphere;                 // ORG_SPHERES из src/lib/org-profile.ts
     companyName?: string | null;       // «Кафе «Ромашка»»
     recipientName?: string | null;     // «Анна Сергеевна»
     promo?: ProposalPromo | null;      // нет — без скидки
     ctaUrl?: string | null;            // нет — по умолчанию (см. ниже)
     sender?: ProposalSender | null;    // нет — из настройки ROOT
   };
   export const PROPOSAL_SPHERES: Array<{ sphere: OrgSphere; label: string }>;
   export async function renderProposalPdf(vars: ProposalVars): Promise<Buffer>;
   export async function renderProposalEmail(
     vars: ProposalVars,
     opts?: { webUrl?: string | null; unsubscribeUrl?: string | null; trackUrl?: (url: string) => string },
   ): Promise<{ subject: string; preheader: string; html: string; text: string }>;
   export function proposalWebUrl(vars: ProposalVars, baseUrl?: string): string; // /kp/<подписанный токен>
   ```
   - **CTA и QR по умолчанию:**
     - есть промокод → `https://wesetup.ru/promo/<CODE>?s=<sphere>`. Этот контракт реализует соседняя задача, URL не менять;
     - промокода нет → страница регистрации с подставленной сферой, если регистрация это умеет, иначе публичная страница сферы (`/dlya-kafe` и т. п. — найти соответствие).
   - `trackUrl` — рассылка оборачивает ссылки для учёта кликов. Применять ко всем ссылкам письма, кроме отписки.
2. **Содержание** — одна страница А4, честно и конкретно:
   - Заголовок с именем адресата/компании, если есть: «Электронные журналы ХАССП и СанПиН для <сферы>».
   - «Как это работает» в 3 шага: QR на холодильнике/складе → заведующая сканирует телефоном → вводит показание.
     Плюс бракераж, гигиена, уборка с телефона; проверяющему — журналы по форме СанПиН на печать.
   - 3–5 преимуществ под сферу. Детсад: бракераж, С-витаминизация, суточные пробы. Отель: завтраки, склады.
     Ресторан/кафе: холодильники, бракераж, гигиена и т. д.
   - Обязательные журналы сферы: из `src/lib/sphere-public-content.ts` / `sphere-journal-rules.ts`, 6–8 названий и «и ещё N».
   - **Блок предложения:**
     - «Бесплатно: все журналы для 1 сотрудника»;
     - «Команда до 10 сотрудников: <цена> ₽/мес» — цена из `PlatformTariff` с действующей акцией. С промокодом — старая
       цена зачёркнута, новая крупно, «скидка 10 % навсегда» (если `lifetime`) или «до <дата>»;
     - «Отсканируйте QR — промокод применится сам, или введите <CODE> на wesetup.ru»;
     - оплата картой или по счёту для юрлиц — проверить, что так и есть.
   - Контакты отправителя и реквизиты (как на `/root/requisites`) внизу.
   - **Каждое утверждение сверить с продуктом по коду.** Фото термометра распознаётся только на платном тарифе — так и
     писать. Приложения в сторах ещё НЕТ — не упоминать. Никаких выдуманных цифр и отзывов. Число журналов — из констант.
   - Слова «бланк» про наши журналы нет.
3. **PDF (А4, одна страница).**
   - Стек проекта — jsPDF и зарегистрированные шрифты; новые зависимости — только если без них никак, с обоснованием.
   - Фирменные цвета сайта; при ч/б печати всё читается.
   - Длинные названия компаний (до 80 знаков) и все сферы влезают на одну страницу без обрезки.
   - QR крупный и читаемый.
4. **Письмо.**
   - Табличная вёрстка 600 px, все стили инлайн, адаптив под телефон (медиазапросы + резиновые таблицы).
   - Кнопка-CTA «пуленепробиваемая», прехедер, `alt` у картинок, тёмная тема не ломает контраст, текстовая версия.
   - Все ссылки абсолютные. Картинки (логотип, QR) — по абсолютному адресу с сайта: `data:` в Gmail режется. Если нужен
     маршрут для PNG QR — только для адресов `/promo/…` своего домена, не для произвольного текста.
   - HTML не больше 100 КБ.
   - Внизу: реквизиты и ссылка отписки (`unsubscribeUrl`, если передан).
   - Тема письма короткая, без спам-слов и капса.
5. **Веб-версия** `/kp/[token]` и PDF `/kp/[token]/pdf`:
   - токен — подписанный (HMAC на секрете приложения с контекстом `kp:`) набор переменных;
   - `noindex`, адаптив;
   - кнопка «Скачать PDF».
6. **ROOT `/root/proposals` — генератор:**
   - форма: сфера, компания, имя, промокод (выбор из действующих `PromoCode` или ввод), отправитель;
   - отправитель по умолчанию хранится в `PlatformSetting` `proposal.sender`, правится здесь же;
   - предпросмотр: PDF в iframe и письмо в iframe с переключателем 390/600;
   - кнопки: «Скачать PDF», «Скопировать ссылку на веб-версию», «Отправить мне тестовое письмо» (на почту текущего ROOT;
     в рабочей копии SMTP выключен — там отправка пишет лог);
   - ссылка на раздел — в меню ROOT, как у соседних разделов.

## Проверка
- **PDF:** все сферы × {без промокода, промокод 10 % навсегда, промокод до даты} × {короткое и длинное название}.
  - Ровно одна страница, ничего не вылезает за поля (проверка по координатам текста).
  - QR декодируется (jsQR / zxing, как в прошлых задачах) в правильный URL.
  - PNG первой страницы при 150 dpi — для 4–5 сфер в папку задачи.
- **Письмо:** скриншоты в Chromium при 375 и 600 px, светлая и тёмная схема, для 3 сфер. Размер HTML, абсолютные ссылки,
  текстовая версия.
- **Веб-версия и ROOT-генератор:** e2e 390 и 1280, скриншоты.
- Юнит-тесты: подпись и проверка токена, расчёт цены со скидкой (навсегда / до даты / фикс), выбор CTA.
- `npm run typecheck`, `npm test`.

## Критерии приёмки
- AC1: КП на одну страницу А4 для каждой сферы, честное, с зачёркнутой ценой и промокодом/QR.
- AC2: письмо с тем же предложением адаптировано под почтовики и телефоны.
- AC3: веб-версия и PDF по подписанной ссылке; ROOT-генератор с предпросмотром и тестовой отправкой.
- AC4: интерфейс модуля — по сигнатурам выше (им воспользуется рассылка), с тестами.
