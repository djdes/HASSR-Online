## Запрос владельца (21.11.2026)

«Проверь ещё раз и письма деплой на проде? Что ещё предложишь?»

## Факты

- Выкат #2383 (`3114684`, письма) упал в job `Upload tarball`, шаг `Wait for SSH`: 8 попыток за 3 мин
  (06:28:30–06:31:35 UTC) — «порт сервера не отвечает». Код до прода не дошёл, `/api/health` → `bb1f3a2`.
- Запустить выкат из этой сессии нельзя: `run_workflow` → 403 «Resource not accessible by integration».
- Сайт в это время работал, но из зарубежных дата-центров соединения с сервером (79.137.237.2, сеть
  DINETHOSTING-NEXT, RU) проходят через раз: из этой сессии `wesetup.ru` 5 из 15, `ya.ru` 10 из 10,
  `mail.ru` 8 из 8 (прокси: «tunnel … closed before the exchange completed»). GitHub Actions — тоже
  зарубежный дата-центр.

## Решение

- Р1. `scripts/wait-for-port.sh`: по умолчанию 20 попыток вместо 8 (≈8 мин вместо ≈3) — тот же скрипт
  ждёт порт и в выгрузке, и в выкате. Окно ограничено сверху 10 мин, чтобы job выгрузки (30 мин: два
  ожидания и скачивание) успевал.
- Р2. Влить в master — выкат запустится сам и заберёт письма (#283) вместе с этой правкой.

## Критерии приёмки

- **AC1.** Окно ожидания по умолчанию 8–10 мин (тест `deploy-scripts.test.ts` разбирает значения
  скрипта); прежние тесты скрипта (явные попытки/пауза) — зелёные.
- **AC2.** typecheck, test:changed — зелёные.
- **AC3.** После влития: выкат master завершился успешно, `/api/health` → новый `buildSha`; письма с
  новым шаблоном на проде (новый HTML-шаблон из `src/lib/email.ts` в сборке — проверка по
  `buildSha`, т. к. настоящее письмо с прода без побочных эффектов не отправить).
