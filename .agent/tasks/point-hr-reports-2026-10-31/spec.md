# 1С:ЗУП по точкам; отчёты, выгрузки и экраны руководителя по точке

Дата: 2026-10-31. Ветка `feat/point-hr-reports` от `origin/master` 9583b7b9.

## Откуда

Аудит «точка видит только своё» (после #76–#79), решения владельца
2026-10-31: «по решениям на все вопросы да».

- 1С:ЗУП (#73): новые сотрудники из 1С создаются без точек
  (`buildingIds = []` — «все точки») и видны в журналах, списках и QR всех
  точек; подразделение сотрудника из 1С не читается.
- Выгрузка журнала PDF/Excel (`report-export-data.ts`) сливает документы
  всех точек; список участков на «Отчётах» — вся организация; графики
  «Отчётов» в режиме «Вся организация» считаются по офису / первой точке.
- Архив для проверки (`compliance-bundle`) — документы всех точек, в том
  числе руководителю точки.
- Дашборд: «ждут подтверждения» и «записи за 48 ч» — вся организация.
- Чек-листы: результаты и назначения других точек видны на точке.
- Потери (`/losses`) — вся организация.
- Мониторинг игнорирует точку в шапке, по умолчанию «Все точки».

## Правило

Точка — торговая точка из шапки (`viewedPointId`): у руководителя точки —
всегда его точка; «Вся организация» / офис / точки выключены — `null`, всё
как раньше. Цех точки — `Area.buildingId = точка` или цех без точки (общий);
документ точки — `buildingWhere` (свой и общие без точки).

## Критерии

1С:ЗУП
- AC1. OData: читается текущее подразделение сотрудника
  (`ТекущееПодразделение_Key` регистра текущих кадровых данных) и
  справочник подразделений (`Catalog_ПодразделенияОрганизаций`); API
  обработки 1С принимает необязательные `departmentId` / `department`.
- AC2. Настройка «1С: кадры»: список подразделений, встреченных при
  последнем прогоне, у каждого — выбор «точка / все точки / не выбрано»;
  сохраняется в подключении. Блок виден, только когда точки включены.
- AC3. Чистое правило `planHrPoints` (тесты): принятый из 1С получает точки
  по подразделению; у связанного из 1С сотрудника точки обновляются, только
  если их ставила 1С (последние поставленные 1С хранятся в связи), или они
  пустые и ещё не ставились; точки, заданные руководителем вручную, не
  меняются; подразделение без сопоставления — «проблема» с подсказкой
  «сопоставьте подразделение с точкой», точки не трогаем. Увольнения — как
  раньше.
- AC4. Прогон «Проверить» показывает, кому какие точки поставит, «Применить»
  ставит их и запоминает в связи.

Отчёты и экраны
- AC5. Выгрузка PDF/Excel: на точке — документы точки и общие, легаси-записи
  её цехов и без цеха; «Вся организация» при включённых точках — колонка
  «Точка» у каждой строки. Список участков на «Отчётах» — цеха точки.
  Графики и счётчики «Отчётов» — по точке из шапки (в «Вся организация» — по
  всей организации, а не по офису).
- AC6. Архив для проверки: на точке — только её документы (и общие),
  в описи — строка «Точка: …».
- AC7. Дашборд: «ждут подтверждения» и «записи за 48 ч» на точке — записи
  её цехов/оборудования и без цеха.
- AC8. Чек-листы: «Результаты» и «Назначение» на точке не показывают
  назначения на другую точку и на сотрудника другой точки.
- AC9. Потери: на точке — записи её цехов и без цеха.
- AC10. Мониторинг без `?point=` открывается на точке из шапки; «Все точки» —
  явный выбор (`?point=all`).
- AC11. `npm run typecheck` 0 ошибок, eslint изменённых файлов, тесты,
  `npm run i18n:check`; проверка на e2e-базе (не прод).
