## 2. Причины и что сделано

### AC1 — тема до первой отрисовки
Причины (по замеру и коду):
1. Скрипт темы `SiteThemeBootstrap` стоял **перед** `<div class="app-shell">` в `(dashboard)`, `/root`, `/partner`,
   `/master`: когда браузер его выполнял, оболочки ещё не было, `querySelectorAll('.app-shell')` пуст — скрипт ничего
   не делал. Первый кадр каждой загрузки рисовался в теме профиля (`User.themePreference`), тему устройства
   применял эффект после гидрации — 0,5–1,5 с чужой темы.
2. Сервер рисовал тему профиля, а она у многих не совпадает с устройством: профиль поменяли с телефона,
   «как на устройстве» у ноутбука и телефона разное, «смена по времени суток» не пишет тему в профиль при загрузке.
   Отсюда и `router.refresh()`: если профиль сменился, React переписывал атрибут темой профиля.
3. При клиентском переходе в новую оболочку (вход, публичная страница ↔ кабинет, экраны мини-приложения ↔
   страницы кабинета в оболочке) скрипт до гидрации не выполняется, а эффект провайдера срабатывал после кадра.

Сделано:
- `src/lib/theme-cookie.ts`: кука `wesetup-theme` = действующая тема ЭТОГО устройства; `pickInitialTheme(кука, профиль)`.
  Пишут куку скрипт до гидрации и `applyThemeToDOM` сайта; читают layout'ы `(dashboard)`, `/root`, `/partner`,
  `/master` (`src/lib/site-theme.server.ts` → `readInitialTheme`). Первый кадр, `router.refresh()` и ремаунт
  оболочки — сразу в теме устройства.
- `SiteThemeBootstrap` — первый ребёнок `.app-shell` (красит `document.currentScript.parentElement`), правит кадр,
  если кука устарела (сменилась системная тема, перевалил 7:00/19:00); цвет строки браузера теперь и для светлой.
- `SiteThemeProvider`, `usePublicAutoTheme`, `MiniThemeProvider`: применение темы при монтировании —
  `useLayoutEffect` (до отрисовки кадра). Логика выбора и ключи localStorage не менялись.
- Мини-приложение: первый кадр уже красил скрипт внутри `#mini-root`; моргало только пересоздание оболочки —
  исправлено третьим пунктом.
- Логи: браузер — `[theme] до отрисовки: сервер light → устройство dark` (только когда скрипт правит кадр);
  сервер — `[theme] профиль user=… → dark` (`POST /api/me/theme`).

### AC2 — «Что нового»
Причины: окно открывал `useEffect` после гидрации по localStorage — оно всплывало через 1,2–1,8 с поверх
нарисованной страницы и заново после ремаунта кабинета; версия считалась по тексту, отфильтрованному под
организацию (`notesWithoutPartnerProgram`) — у организации со скрытым консультантом своя «версия», и смена
организации «обновляла» заметки.

Сделано (`src/lib/whats-new-seen.ts`, `whats-new-modal.tsx`, `(dashboard)/layout.tsx`):
- версия — хэш **полного** текста заметок, одна на все организации (показываются по-прежнему заметки организации);
- закрытая версия — в куке `wesetup-whats-new`; layout решает до рендера: `show` — окно в серверной разметке сразу
  открытым; `hide` — компонента в разметке нет вовсе (ни при загрузке, ни при переходах, ни после `router.refresh`);
- `legacy` (куки ещё нет — первый заход после выката): один раз по старой отметке localStorage; новичку окно
  по-прежнему не показывается; видевшему прошлую версию — показывается, и дальше сервер рисует его сам до закрытия;
- закрытие → кука + localStorage; логи `[whats-new] окно в разметке сразу открыто …` (сервер),
  `[whats-new] окно закрыто, версия …`, `[whats-new] отметка перенесена в куку …` (браузер).

### AC3 — скелетоны в едином стиле
- Общий `PageSkeleton` (`src/components/ui/skeleton.tsx`): шапка как у `PageHeader`, плитки (2/4 в ряд),
  тело — карточки / список / таблица / панель-форма; цвета — токены `--app-skeleton-*` (светлая и тёмная).
- Выбор скелета по адресу (`src/components/ui/skeleton-routes.ts`) во вложенных `loading.tsx`: подстраницы настроек —
  общий скелет вместо хаба с тёмным баннером; журнал / документ / новая запись — свой скелет с первого кадра
  (раньше каталог → список → документ); «Догнать пропущенное», «Аудит» — не скелет дашборда; отчёт по сотруднику —
  не скелет сводных отчётов; проверка документа — не сетка документа.
- Клиентские страницы, которые после серверного скелета показывали пустой блок с крутилкой: панель контроля,
  команда, прогресс журналов, проверка задач — пока грузятся, показывают тот же скелет, что `loading.tsx`
  (смена незаметна). Прогресс журналов больше не пишет «Все журналы на сегодня готовы» до ответа сервера.
  Идеи — скелет карточек вместо строки «Загружаем…».
- Новые `loading.tsx` (страницы читают по несколько списков из базы или грузят данные на клиенте): `/batches`,
  `/bonuses`, `/losses`, `/verifications`, `/root/*`. Быстрым страницам (одна выборка — `/capa`, `/changes`,
  `/plans`…) скелет не добавлял: React держит показанный скелет минимум 300 мс, и он только замедлил бы их.
- Мини-приложение: «Открываем кабинет…» — только на входе `/mini`, вкладкам — скелет списка мини (как «Сегодня»).
- `/settings/balance`, `/settings/organization` и переключатель организаций не трогал (параллельные задачи): они
  получают общий скелет настроек через `settings/loading.tsx`.

## 5. Найдено, но не правил
1. **Анонс бесплатного периода** (`BillingAnnouncement`, `/dashboard`, `/control-board`, `/journals`) — рисуется
   после гидрации (`useState(true)` → эффект читает localStorage «закрыт сегодня») и сдвигает страницу вниз: на
   телефоне CLS 0.178 (`/dashboard`) и 0.152 (`/journals`) в замере «до». Не правил — зона тарифов (параллельные
   задачи). Решение — как у «Что нового»: отметку «закрыт сегодня» в куку, решение на сервере.
2. `AnnouncementBanner` (объявления ROOT) устроен так же — при активном объявлении будет тот же сдвиг. Не
   замерялось (объявления не было).
3. «Назад» на `/journals` с компьютера — CLS 0.909: общие элементы смещаются при смене страницы (история
   восстанавливает другую по высоте страницу), не мигание темы. Проверить на проде глазами.
4. Мини-приложение: `template.tsx` проигрывает въезд экрана 200 мс на каждом переходе — решение дизайна, не трогал.
5. У организаций со скрытым консультантом окно «Что нового» после выката покажется один лишний раз: раньше их
   версия считалась по урезанному тексту, теперь — по полному. Если к выкату меняются заметки — незаметно.
