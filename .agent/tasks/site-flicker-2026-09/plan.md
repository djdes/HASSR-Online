## 0. Что уже видно по коду (до замера)

- **Тема кабинета.** `SiteThemeBootstrap` (скрипт до гидрации) стоит в `(dashboard)/layout.tsx`,
  `root/layout.tsx`, `partner/layout.tsx`, `master/layout.tsx` ПЕРЕД `<div class="app-shell">`.
  Когда браузер выполняет скрипт, `.app-shell` ещё не разобран — `querySelectorAll` пуст, скрипт ничего
  не делает. Первый кадр рисуется в теме из профиля (`User.themePreference`), а выбор устройства
  (localStorage: светлая/тёмная, «как на устройстве», смена по времени) применяет только эффект после
  гидрации. Если они расходятся — кадры чужой темы при каждой полной загрузке.
- Смена по времени суток и «как на устройстве» не пишут действующую тему в профиль при загрузке, поэтому
  расхождение профиля и устройства — обычное дело (днём профиль «тёмная» с вечера → мигание на каждой
  загрузке).
- Сервер отдаёт в `data-app-theme` тему профиля и при `router.refresh()`/переходе в другой layout: если
  профиль поменялся с другого устройства — React перепишет атрибут, эффект вернёт обратно → кадр чужой темы.
- Публичные страницы: тема ставится `useEffect` → при клиентском переходе на публичную страницу первый кадр
  без темы.
- «Что нового»: решение показывать принимается в `useEffect` после гидрации (localStorage), окно
  всплывает после отрисовки страницы; версия считается по тексту заметок, а текст зависит от организации
  (`notesWithoutPartnerProgram`) — у разных организаций разные «версии».
- Скелетоны: общие примитивы уже есть (`src/components/ui/skeleton.tsx`), `loading.tsx` — 11 штук.
  `settings/loading.tsx` (скелет хаба с тёмным hero) служит запасным для ВСЕХ `/settings/*` —
  у подстраниц показывается чужая раскладка.

## 2. Исправления

### 2.1 Тема (AC1)
- `src/lib/theme-cookie.ts` (новый, без React): `THEME_COOKIE = "wesetup-theme"`,
  `parseThemeCookie(value): "light" | "dark" | null`, `themeCookieString(theme): string`.
- Кука = действующая тема ЭТОГО устройства. Пишут: скрипты до гидрации (сайт, мини, публичные) и
  `applyThemeToDOM` (сайт и мини). Сервер (`(dashboard)`, `root`, `partner`, `master`) берёт
  `кука ?? User.themePreference ?? light` — первый кадр уже в теме устройства, `router.refresh()` и
  ремаунт отдают то же самое.
- `SiteThemeBootstrap` — первым ребёнком внутри `.app-shell` (как `MiniThemeBootstrap` у мини):
  корректирует кадр до отрисовки, если кука устарела (сменилась системная тема, перевалил час).
- `SiteThemeProvider`, `usePublicAutoTheme`: применение темы при монтировании — `useLayoutEffect`
  (до отрисовки кадра при клиентском переходе); логика выбора и ключи localStorage не меняются.
- Мини-приложение: проверить замером; править только если найдены кадры чужой темы.

### 2.2 «Что нового» (AC2)
- Решение — на сервере до первой отрисовки: кука `wesetup-whats-new` = версия, которую человек закрыл.
  Совпала с текущей — окна нет в разметке вовсе; не совпала — окно рендерится сразу открытым в SSR.
- Версия считается по ПОЛНОМУ тексту заметок (`whatsNewVersion(WHATS_NEW_NOTES)`), а показываются
  отфильтрованные для организации — смена организации не «обновляет» заметки.
- Перенос старого флага: localStorage `wesetup.last-seen-build-sha` → кука (один раз, без показа).
- Не менять тексты заметок (`whats-new-notes.ts` — только если нужна функция, без правки текста).

### 2.3 Скелетоны (AC3)

- `loading.tsx` только для медленных разделов по замеру (порог — серверный ответ заметно > 150 мс или
