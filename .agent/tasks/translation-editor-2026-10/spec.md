# Редактор переводов интерфейса (2026-10-24)

## Запрос владельца

У администратора платформы (ROOT, admin@wesetup.ru) — отдельная настройка,
где выведены все переводы интерфейса (журналы, меню и т.д.) одним списком,
сгруппированным по категориям. Каждую строку можно поправить вручную, при
необходимости — автоперевод по кнопке. Делать переводы можно разрешить
конкретному пользователю (alexey@wesetup.ru). Начать с одного журнала,
дальше дорабатывать постепенно.

## Решения

- Источник — каталоги `src/i18n/messages/{ru,en,uz}.json` (≈16 000 строк ×
  3 языка). Правки хранятся в БД (`TranslationOverride`, ключ
  `locale + key`) и подмешиваются поверх JSON в `loadMessages()` — тем же
  путём идут страницы, письма, бот, PDF. Деплой правки не нужен.
- Кэш правок в памяти процесса: TTL 30 с, сброс сразу после записи в том же
  процессе. Без правок — исходный объект каталога без копирования. Ошибка БД
  не роняет страницу: каталог отдаётся как есть. В тестах (`node --test`)
  и без `DATABASE_URL` БД не трогаем.
- Правка не может сломать ICU: аргументы (`{name}`, plural/select, теги)
  обязаны совпасть с русским исходником (`messageArguments`). Ключ должен
  существовать в каталоге. Значение, равное исходнику, или пустое — сброс.
- Категории — реестр префиксов ключей. Первая курируемая категория —
  журнал «Гигиенический журнал» (`hygiene` + поля, инструкции, печать,
  уведомления). Плюс «Меню и навигация» (`navigation`) и «Общее» (`common`).
  Всё, что не попало в курируемые категории, — в группе «Прочие разделы»,
  по пространству имён: так все строки доступны с первого дня.
- Автоперевод — через очередь AI-диспетчера (`enqueueAndWait`, тип
  `wesetup_translate`, сайт к модели не ходит). Пачка до 30 строк, ответ —
  JSON; результат подставляется в поля как черновик, сохраняет человек.
  Строки с несовпавшими аргументами отбрасываются.
- Доступ: ROOT или пользователь с `User.canEditTranslations = true`
  (активный, не в архиве). Проверка по БД на каждом запросе, не по JWT.
  Выдаёт/снимает право только ROOT на `/root/translations`.
- Переводчик открывает редактор по `/translations` (вне `/settings`, чтобы
  `proxy.ts` не уводил линейную роль), пункт «Переводы интерфейса» — в меню
  профиля. ROOT — пункт «Переводы» в навигации платформы.
- Каждая запись пишет `AuditLog` (`translation.update`) со старым и новым
  значением.
- Право alexey@wesetup.ru выдаётся однократно в `prisma/seed.ts` (маркер
  `PlatformSetting translators_bootstrap_2026_10`), дальше управляет ROOT.

## Вне объёма (следующие итерации)

- Каталоги `pricing/`, `errors/`, `confirm/`; названия журналов на русском
  (берутся из шаблона в БД, не из каталога).
- Курируемые категории для остальных журналов и разделов.
- История версий строки (есть в AuditLog).

## Критерии приёмки

- AC1. Схема: модель `TranslationOverride` (`locale`, `key`, `value`,
  `updatedById`, даты; уникальность `locale+key`) и
  `User.canEditTranslations Boolean @default(false)`; `prisma validate` ok.
- AC2. `loadMessages(locale)` возвращает каталог с применёнными правками;
  без правок — тот же объект; ключ вне каталога игнорируется; ошибка
  источника правок не ломает загрузку. Покрыто unit-тестами.
- AC3. Валидация правки: неизвестный ключ, неизвестная локаль, несовпадение
  аргументов ICU, невалидный ICU — отказ с понятной причиной; пустое или
  равное исходнику значение — сброс. Unit-тесты.
- AC4. Реестр категорий: журнал `hygiene`, `navigation`, `common`, «Прочие»
  покрывают все ключи каталога; ключ курируемой категории не дублируется в
  «Прочих». Unit-тест.
- AC5. API: список категорий с количеством, строки категории с фильтрами
  (поиск, изменённые, без перевода) и пагинацией, сохранение/сброс,
  автоперевод, управление переводчиками. Не-root без права — 403/404;
  управление переводчиками — только ROOT.
- AC6. UI: `/root/translations` (ROOT, + блок переводчиков) и
  `/translations` (переводчик); одна клиентская таблица: категории слева,
  строки ru/en/uz с редактированием, отметка «изменено», сброс, автоперевод
  строки и пачки, «Сохранить всё». Тексты UI — в каталогах ru/en/uz.
- AC7. Пункты навигации: «Переводы» в меню платформы, «Переводы интерфейса»
  в меню профиля только тем, у кого есть доступ.
- AC8. Seed однократно выдаёт право alexey@wesetup.ru.
- AC9. `npm run typecheck`, `npm run test:gate`, `npm run i18n:check`
  (часть про типы), `npm run lint` по изменённым файлам — зелёные.
- AC10. Сквозная проверка на локальной БД: правка en-строки журнала
  `hygiene` видна в `loadMessages("en")`, сброс возвращает исходник; вход
  переводчика открывает `/translations`, обычный пользователь — нет.
