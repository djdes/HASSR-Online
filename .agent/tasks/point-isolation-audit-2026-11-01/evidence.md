## Не исправлено (без визуального подтверждения или на решение владельца)

**На решение владельца:**
1. ППК/ХАССП (`/production-control/*`): документ компании — руководитель точки видит людей всех точек в
   выборе команды и может править общий документ. Если ППК — документ компании, закрыть ему запись; если точки —
   нужны отдельные документы по точкам.
2. Колонки журналов бракеража «применить ко всем документам» меняют документы всех точек — зона исключения
   «бракераж настраивается отдельно», не трогал.
3. Бумажные журналы без точки (`PaperJournalDocument` без `buildingId`) — нужна схема.
4. «Закрыть день» в режиме «Вся организация» закрывает день только офису: закрывать все точки или
   требовать выбрать точку.
5. «Оплата» и приказы компании: `closing-documents` (УПД) и `orders` (приказы) открыты руководителю точки.

**По коду подтверждено, вживую в этой среде не проверить (нет Telegram/Max/TasksFlow/iiko/Tuya):**
утренняя сводка руководителя (офис — только офис, 2+ точки — вся сеть); события без офиса уходят руководителю
точки; «датчик молчит» — одно обязательство на сеть; эскалация TasksFlow 2-го уровня; TasksFlow «Связи» и журнал
событий; склады iiko; датчик Tuya по чужому id устройства; старый `/api/tuya/collect`.

**Низкая важность, вживую не подтверждал (следующий заход):** история партии (`traceability`), фильтр
выгрузки отчётов и тепловых карт для записей без документа, бонус по чужому обязательству, шаблон уборки
компании, автопоиск CAPA, сотрудник другой точки в строке документа, «Сегодня» в Mini App при «Вся
организация», запрос PIN с УФ-лампы, `journal-fill?daily=1`, привязка группы MAX, inline Telegram для
непривязанных, хаб Max, MCP `list_journals`, влажность с QR холодильника, ППК в портале проверяющего,
результаты чек-листов от авторов других точек, счётчик посещений на «Пришла проверка», откат автозаполнения
по всем точкам.
