# Spec (frozen 2026-11-25): старые мелочи после проверок спецрежима и ППК

Запрос владельца: «Исправь старые мелочи, предложи что ещё можно улучшить».

«Старые мелочи» — замечания, которые свежие проверки последних задач оставили как неблокирующие:
- `special-mode-past-days-2026-11-25/verdict.json`: `delete-by-employee-and-date-ignores-date`, `MV12-future-source-move`,
  `local-env-breaks-site-locale-proxy-tests`; ESLint тех же файлов журналов (1 ошибка, 4 предупреждения — были и до задачи);
- `ppk-diff-drafts-spheres-2026-11-25/verdict.json`: V2 (сравнение читает текст всех редакций), V3 (текст редакции и её
  отпечаток читаются раздельно, сбой чтения текста молча глотается), V5 (ошибки новых API ППК только по-русски);
- `ppk-overview-spheres-2026-11-24/verdict.json`: V10 (скрепка карточки объекта одна в средней строке на 320–375 px).

Не делаем (проверки приняли как осознанные решения, исправлять нечего): V1 (устаревшие строки доказательств), V4
(пробелы в тексте редакции — поведение как задумано), V6 и V9 (прокрутка, формат даты и стрелки в радиогруппах),
перевод строки «Файл: … КБ · отпечаток …» — это содержимое уже утверждённых редакций: смена формата дала бы ложные
различия при сравнении со старыми редакциями.

## Критерии приёмки

- **AC1 — удаление по сотруднику и дню.** `DELETE /api/journal-documents/[id]/entries` с `{ employeeId, date }`
  проверяет закрытые дни и удаляет только строку этого сотрудника за этот день (раньше в документе автоматики
  проверялись все его строки — одна старая закрытая строка запрещала удалить строку в окне). `{ ids }` — ровно эти
  строки, `{ employeeId }` — все строки сотрудника, как было; неверная дата — 400. Одно чистое правило выбора строк с
  тестами; на стенде: в документе автоматики с окном прошлых дней удаление вчерашней строки по сотруднику и дню — 200,
  строки за окном — 403.
- **AC2 — перенос строки из будущего дня.** Руководство снова может перенести строку с будущего дня на разрешённый
  день (до спецрежима так и было); клетка-источник проходит запреты прошлых дней, но не правило «будущее никто не
  заполняет» (оно — о том, куда пишут). Сотруднику по-прежнему нельзя (не его день). Запись в будущий день — 403, как
  было. Чистая функция с тестами; на стенде: руководитель переносит строку с послезавтра на сегодня — 200; сотрудник —
  403; в будущий день — 403.
- **AC3 — ESLint журналов.** В `journals/[code]/documents/[docId]/page.tsx`, `climate-document-client.tsx`,
  `journal-entry-write.ts` нет замечаний ESLint: ссылка «Настройки журналов» — `Link`, неиспользуемые импорты убраны.
  Поведение не меняется.
- **AC4 — тест прокси не зависит от `.env`.** `src/site-locale-proxy.test.ts` проходит и без `.env`, и с загруженным
  `.env` (секрет авторизации): проверяет то, о чём тест, — что предзагрузка не ставит куку языка.
- **AC5 — сравнение редакций читает только нужное.** Текст читается только у двух сравниваемых редакций; история
  по-прежнему знает, у какой редакции текст есть. Результат сравнения не меняется (тесты).
- **AC6 — текст утверждённой редакции соответствует её отпечатку.** Если документ изменился во время утверждения, оно не
  проходит (409 «Документ изменился — утвердите ещё раз»), ничего не сохраняется; сбой чтения текста — повтор, затем
  запись в лог сервера (утверждение проходит без текста, как раньше, но не молча). Тесты.
- **AC7 — ошибки ППК на языке интерфейса.** Ответы с ошибкой API сравнения редакций и черновика ИИ-помощника несут
  `code`; интерфейс показывает текст по коду на ru/en/uz, неизвестный код — текст сервера. Тексты во всех трёх языках,
  `npm run i18n:types`.
- **AC8 — скрепка остаётся рядом с названием объекта.** На карточке объекта («Объекты») на 320–639 px значок,
  название и скрепка — одна строка (длинное название переносится внутри неё), сфера/«Офис» — ниже; с 640 px порядок как
  раньше: название, сфера, скрепка. Снимки 320/360/375/390/430/700/1280.
- **AC9 — качество.** typecheck, `test:gate`, ESLint изменённых файлов без новых замечаний, `i18n:check`, проверки на
  стенде, свежая независимая проверка, слияние в master и выкладка (схема БД не меняется).

## Уточнение при реализации (2026-11-25)

- AC6 добавляет пользователю новое сообщение (409 «Документ изменился…»), а по правилам репозитория видимые тексты идут
  через переводы — поэтому коды получил и API утверждения редакции (`doc_not_found`, `doc_empty`, `doc_changed`,
  `bad_request`, `kb_forbidden`) и общий доступ ППК (`forbidden`, `choose_point`); окно утверждения переводит их так же,
  как сравнение и черновик (AC7).
- AC8 (после второй проверки): скрепка на телефоне идёт вместе с последним словом названия — одним блоком
  (`inline-block max-w-full`), в строке занимает 28 px при зоне касания 48×48. Если последнее слово вместе со скрепкой
  шире строки (слово почти во всю ширину карточки), скрепка переходит на следующую строку: иначе пришлось бы рвать
  слово. Критерий проверки — нет разрывов слов, которых нет в master, ничего не вылезает, одна скрепка на карточку,
  с 640 px порядок прежний.
