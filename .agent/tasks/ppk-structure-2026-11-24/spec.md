# Spec (frozen 2026-11-24): структура ППК из документа владельца на `/production-control`, пункты — ссылки, окна для данных

## Запрос владельца (2026-11-24)

Документ «Электронная программа производственного контроля, основанная на принципах ХАССП» (docx, копия
текста — `raw/source.md`): разделы 1.1–1.9, 2.1–2.10, 3.1–3.7 и приложения №1–6, у пунктов в скобках —
откуда брать данные. Задача: «на `/production-control` сделай структуру как в документе, с нумерацией, как
гиперссылки; по нажатию — всплывающие окна в нужные разделы для загрузки, редактирования и добавления данных.
Где в скобках сказано, откуда брать, — подтягивать; где не указано и не к чему привязать — пустые окна с
произвольными данными («заполню потом»). У пользователей, у которых уже что-то создано, данные — в
соответствующих разделах: ничего не убирается, только добавляется и видоизменяется. Окно — стандартное: на ПК
всплывающее, на телефоне шторка снизу, стиль переиспользовать».

Ответ владельца на вопрос об объёме: **вариант (а)** — сейчас страница, окна и данные; печатный ППК/PDF по новой
структуре (сканы с колонтитулом и сквозной нумерацией) и «подпись пальцем по экрану» — следующим шагом.
«Делай, сразу в прод, доделай до конца».

## Исходное состояние (master `4f93950aa`)

- `/production-control` (обзор): шапка с прогрессом блоков, два документа (свой файл ППК/ХАССП-плана или
  сборка), мастер «типовыми за 10 минут», «Следующий шаг», «Разделы программы» — карта блоков реестра
  (`src/lib/ppk/registry.ts`) карточками со ссылками на страницы блоков.
- Блоки с данными в `PpkRecord` (`src/lib/ppk/records.ts`): team, policy, products, hazards, control-points,
  flowchart, floor-plan, pest-plan, lab-plan, norms, doc-versions, team-meetings. Папки файлов —
  `KnowledgeDocument.folder` (`src/lib/ppk/folders.ts`). ППК ведётся на точку (`PpkScope`), первое открытие
  точки копирует ППК организации (`scope.server.ts`).
- Окно `Dialog` (`src/components/ui/dialog.tsx`) уже: на ПК — по центру, на телефоне (< 640px) — шторка снизу со
  свайпом вниз.
- Нет: реестра договоров, оргструктуры, сведений о производстве, текстов «принципы ХАССП», «понятия»,
  «методика ККТ», «положение о руководителе группы», таблиц ПОПМ (3.1, 3.2, 3.4), правки аварийных ситуаций
  (они константой в `program-content.ts`), ознакомления с самой программой, приложения «график потоков».

## Решения (владелец может поправить)

1. **Каждый пункт — ссылка `/production-control/item/<id>`** (`1-1` … `3-7`, `app-1` … `app-6`; без точек в
   адресе — точка в пути мешает прокси и статике). С обзора ссылка открывается окном поверх страницы (перехват
   маршрута Next.js: слот `@modal`, `(.)item/[id]`); по прямой ссылке или в новой вкладке — та же панель
   отдельной страницей. Закрыть окно — крестик, фон, Esc, свайп вниз на телефоне, кнопка «Назад» браузера.
2. **Окно — стандартный `Dialog`** (без своей вёрстки шторки), ширина на ПК до 920px, шапка с номером и
   названием пункта, подсказка «откуда берутся данные». Данные пункта читаются на сервере — теми же
   загрузчиками, что у страниц блоков; редакторы блоков — те же клиентские компоненты (одна правда на блок).
3. **Существующие данные не переносятся в БД, а показываются в пунктах**: продукция → 1.5, план помещений → 1.6,
   нормативка → 1.7, политика → 2.1, блок-схемы → 2.5, опасности → 2.6–2.8, ККТ и рабочие листы → 2.10 и
   прил. №2, лаборатория → 3.6, процедуры → прил. №5, инструкции базы знаний → прил. №6. Папка «Подписанные
   документы группы» (`team-signed`) показывается в 2.2 и 2.4. Договоры лаборатории и дезслужбы (папки
   `lab-contract`, `pest-contract`) показываются в 1.3. Страницы блоков, меню раздела и их адреса остаются.
4. **Новые данные — тем же реестром `PpkRecord`** (новые блоки, zod-схема на каждое сохранение):
   - `org-chart` — схемы оргструктуры (схема блок-схемы: этапы и связи), редактор — общий конструктор схем
     (`/production-control/org-chart/[id]`), печать — как у блок-схем; кнопка «Собрать из должностей» строит
     черновик: руководитель → должности руководства → должности персонала (моё решение: связей подчинения в
     системе нет, черновик правится в редакторе);
   - `contracts` — договоры: наименование, контрагент, номер, дата, «видно проверяющему»; файлы договоров и
     актов — папка `contracts`; отмеченные договоры видны на портале проверяющего (раздел «Производственный
     контроль», списком без файлов);
   - `production-info` (одиночный) — сведения о производстве по шаблону;
   - `text-haccp-principles`, `text-terms`, `text-team-regulation`, `text-team-leader`, `text-ccp-method`,
     `text-flow-schedule` (одиночные) — текст пункта;
   - `prp-infections`, `prp-disinfection`, `prp-emergencies`, `prp-medical` — строки таблиц ПОПМ.
   Новые папки: `contracts`, сканы `policy-scan`, `team-regulation-scan`, `team-leader-scan`,
   `team-order-scan`, `flow-schedule`. У пунктов, где документ не просит скан (1.8, 1.9, 2.9), папки нет.
5. **Пункты по видам:**
   - 1.1 — форма реквизитов организации (те же поля и тот же `PATCH /api/settings/organization`, что
     «Моя компания → Реквизиты»; значения — действующие, из правок и ЕГРЮЛ). Обязательные для ППК: полное
     наименование, ИНН, КПП (не у ИП), ОГРН/ОГРНИП, юридический и фактический адрес, телефон, руководитель и
     его должность. Не хватает — плашка «Ваши документы могут быть заполнены не полностью, не хватает
     сведений» со списком; сохранить с пропусками можно после подтверждения «Пропустить». Править может
     только руководитель с правом `admin.full`, остальным — просмотр.
   - 1.4 — шаблон: наименование и адрес объекта, вид деятельности (подтягиваются из сведений об объекте —
     `Building`, у ППК организации — из организации; меняются там, ссылка рядом), численность персонала
     (считается по сотрудникам объекта), режим работы, посадочные места, мощность (порций в смену), площадь,
     водоснабжение, водоотведение, вентиляция, отопление, форма обслуживания, дополнительно. Обязательные:
     режим работы, мощность, водоснабжение, водоотведение (+ подтягиваемые название и адрес). Пропуск — с тем же
     предупреждением.
   - 1.5 — редактор продукции + «Загрузить из справочника»: готовая продукция и полуфабрикаты справочника
     (`Product.kind` `finished`/`semi`, активные) добавляются в описание продукции; уже добавленные по
     названию не дублируются; лимит блока (300) соблюдается.
   - 1.8, 2.2, 2.3, 2.9 — текст по шаблону: пока своего текста нет, в поле — шаблон (2.2 — из нынешнего
     положения о группе с составом группы); «Сохранить» фиксирует текст, «Вернуть шаблон» — заново. 1.9 и
     прил. №3 — пустое поле для своего текста (шаблона нет).
   - 2.1–2.4 и прил. №3 — «Скан своего документа» (папка): загружен скан — пункт заполнен (в собранный
     документ скан пойдёт на следующем шаге).
   - 2.4 — приказ из «Приказов» (шаблон `haccp-team`, с предзаполнением из группы): последний приказ —
     номер и дата со ссылкой, кнопка «Оформить приказ», плюс скан.
   - 2.7 — значимые опасности (вероятность × тяжесть ≥ порога `isSignificantHazard`) таблицей; 2.8 — матрица
     4×4 «вероятность × тяжесть» с числом опасностей в клетках и шкалы баллов. Правка — в 2.6 (ссылка).
   - 2.10 — редактор ККТ + «Рабочие листы плана управления опасностями» (ссылка на печать всех листов);
     прил. №2 — список рабочих листов ККТ/ОПП с печатью.
   - 3.1, 3.2, 3.4 — таблицы с «Добавить строку», правкой, удалением и «Заполнить типовыми» (3.1 — по МР
     2.3.6.0233-21 и принципам ХАССП, 3.2 — объекты дезинфекции, 3.4 — по Приказу Минздрава № 29н; пометка
     «проверьте по документу»). 3.3 — аварийные ситуации: пока своих нет, показан типовой перечень (он же
     идёт в программу); «Взять за основу» превращает его в свои строки; программа (`/program`, PDF) берёт
     свои строки, если они есть.
   - 3.5 — должности объекта и сотрудники на них (из «Сотрудников»): медосмотр, гигиеническая подготовка и
     аттестация — «да» у всех должностей производства (решение: в общепите это все работники), ссылка на
     сотрудников и медкнижки.
   - 3.6 — редактор плана лабораторных исследований с папками договора, протоколов и актов.
   - 3.7 — должностные лица (группа ХАССП и ответственные за журналы) и лист ознакомления: сотрудники объекта
     с отметкой «Ознакомлен и согласен» (дата). Отметка — сам сотрудник в кабинете (`/acknowledge/ppk`) или
     PIN-код сотрудника на устройстве руководителя (тот же PIN, что для QR-форм, 5 ошибок — блок 15 минут).
     Версия: номер утверждённой версии ППК (`doc-versions`), нет — «1»; новая версия — отметки заново.
   - Прил. №1 — оборудование объекта (из «Оборудования»: название, тип, цех, заводской номер, режим);
     прил. №4 — включённые журналы объекта; прил. №6 — рабочие инструкции базы знаний (список со ссылками).
     Ссылки «Изменить в …» ведут в источник.
6. **Статус пункта** (точка как в меню: заполнен / начат / пусто): по фактам из базы, чистая функция
   `ppkItemStatuses(facts)`. Прогресс в шапке обзора — по пунктам структуры («Заполнено N из 32 пунктов»);
   «Сегодня» и меню раздела считают блоки, как раньше.
7. **Обзор сверху вниз:** шапка с прогрессом и «Заполним за вас»; мастер «типовыми за 10 минут» (как было);
   структура документа — три раздела и «Приложения», пункты с номерами-ссылками и точкой статуса; два главных
   документа (свой файл / собрать / заказать); «Заказать индивидуально». Карта «Разделы программы» заменена
   структурой; «Следующий шаг» — первый незаполненный пункт структуры, открывается окном.
8. Права — как у раздела: страницы и API — полный доступ к кабинету (`requirePpkAccess`/`ppkPageScope`);
   реквизиты — `admin.full`; PIN-ознакомление — только сотрудники этой организации/точки.
9. Тексты интерфейса, включая названия пунктов, — ru/en/uz (`productionControl.structure`). Шаблоны документов
   (принципы ХАССП, положения, методика, типовые строки таблиц) — только по-русски, как печатные формы раздела.

## Не делаем сейчас (следующий шаг)

Сборка печатного ППК и PDF по новой структуре со сканами, колонтитулом и сквозной нумерацией; подпись пальцем
по экрану; отдельный «Реестр договоров» вне ППК; перенос файлов `team-signed` по видам документов.

## Критерии приёмки

- **AC1.** `/production-control` показывает структуру документа: 1 «Первичная информация…» (1.1–1.9), 2 «План
  ХАССП» (2.1–2.10), 3 «Программы обязательных предварительных мероприятий (ПОПМ)» (3.1–3.7), «Приложения»
  (№1–№6) — названия и нумерация как в документе; каждый пункт — ссылка `<a href="/production-control/item/<id>">`
  с точкой статуса; прогресс по пунктам; два документа, мастер и «Заказать индивидуально» на месте.
- **AC2.** Нажатие на пункт открывает окно поверх обзора (адрес меняется на `/production-control/item/<id>`);
  на ширине ≥ 640px — окно по центру, на 390px — шторка снизу во всю ширину без горизонтальной прокрутки;
  крестик/Esc/«Назад» закрывают окно и возвращают обзор; прямой заход по адресу — страница пункта.
- **AC3.** Каждый из 32 пунктов открывается без ошибок и даёт описанное в решении 5: правку/добавление
  (записи сохраняются через API и видны после повторного открытия), загрузку файлов в свою папку,
  подтягивание данных из указанных источников, пустые окна там, где источника нет.
- **AC4.** Данные, созданные до изменения (записи блоков, папки), видны в соответствующих пунктах; ни одна
  запись и ни один файл не удаляются; страницы блоков и меню раздела работают как раньше.
- **AC5.** 1.1 и 1.4: не хватает обязательного — предупреждение «Ваши документы могут быть заполнены не
  полностью, не хватает сведений» со списком; сохранение с пропуском — после подтверждения.
- **AC6.** Новые блоки проверяются zod-схемой на сервере (битые данные → 400), лимиты записей соблюдаются,
  одиночные блоки — одна запись на область (точку/организацию), копия ППК на точку переносит новые блоки.
- **AC7.** 1.5 «Загрузить из справочника» добавляет готовую продукцию и полуфабрикаты без дублей; 1.2
  «Собрать из должностей» создаёт схему и открывает редактор; 3.3 программа берёт свои строки аварийных
  ситуаций, если есть; 3.7 PIN-отметка проверяет PIN (неверный → ошибка с остатком попыток) и записывает
  ознакомление; отмеченные договоры видны на портале проверяющего.
- **AC8.** Права: повар не открывает ни страницу пункта, ни API (403/forbidden); чужая организация и чужая точка
  недоступны.
- **AC9.** Все новые тексты интерфейса — в ru/en/uz, `i18n:check` зелёный; `npm run typecheck`,
  `npm run test:changed` (с новыми тестами: структура, статусы, схемы, шаблоны), `eslint` по изменённым файлам и
  `npm run build` — зелёные.
- **AC10.** Проверено вживую на локальном стенде (Postgres + сборка): снимки обзора, окна на ПК и шторки на
  телефоне, сохранение в окне; изменения в master, выкладка прошла.

## Поправки после проверки (fresh verifier, раунд 1)

- **Решение 5, пункт 3.7 — версия для ознакомления.** Было: «нет утверждённой версии — «1»». Стало: версия —
  номер утверждённой версии ППК; без утверждения — дата загруженного файла ППК (новый файл — отметки заново); нет
  ни того ни другого — лист ознакомления закрыт с подсказкой «утвердите версию или загрузите файл». Причина: с
  версией «1» по умолчанию документ «Программа производственного контроля» ушёл бы на ознакомление сотрудникам
  всех организаций, включая тех, у кого ППК не заведён, — подписывать пустую программу. Сотрудник открывает саму
  программу со страницы ознакомления (загруженный файл или собранный PDF).
- **Решение 5, пункт 1.4.** «Вид деятельности» — необязательное поле (в списке обязательных его не было).
