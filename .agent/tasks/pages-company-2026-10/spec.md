## Критерии приёмки

### AC1. Сведения для документов `/settings/organization/documents`
1. Guard — `"admin.full"` (как у Реквизитов); пункт `access: ADMIN`.
2. Две карточки: «Об организации» (поля секции `#documents`: полное наименование, ОГРН, КПП, юр. адрес, руководитель и должность; подсказки «Берётся из ЕГРЮЛ», «Вернуть из ЕГРЮЛ», «Сокращённое название для журналов») и «О торговой точке» (выбор точки, если их несколько; название для журналов, адрес, КПП, телефон точки; правка — ссылкой на страницу точки или формой через API точек).
3. Живой предпросмотр шапки журнала и строк блока — те же функции, что у PDF (`journalHeaderOrgText`, `documentOrgRows`), обновляется при вводе и при смене точки.
4. Сохранение — тот же `PATCH /api/settings/organization`; ошибки КПП/ОГРН — у поля.
5. Секция переезжает из формы Реквизитов (без дублирования полей); на Реквизитах остаётся короткая ссылка «Сведения для документов →».

### AC2. Логотип и цвета `/settings/organization/branding`
1. Guard — `"admin.full"`. Загрузка/замена/удаление логотипа (`org-logo-upload.tsx`), фирменный цвет с проверкой контраста.
2. Предпросмотр: как логотип и цвет выглядят в шапке журнала PDF и на QR-плакате (миниатюры; без генерации PDF на каждый ввод). Подпись: интерфейс кабинета не перекрашивается.
3. Секция `#branding` уходит из формы Реквизитов; все ссылки на `/settings/organization#branding` (в т. ч. «Добавить логотип» в шапке меню) ведут на новую страницу.

### AC3. Контакты и уведомления `/settings/organization/contacts`
1. Guard — `"admin.full"`. Поля организации, которые уже есть в модели: телефон, почта бухгалтера (`accountantEmail`), регион/часовой пояс, язык документов/кабинета (`locale`) — что из этого сейчас правится на Реквизитах, переезжает сюда (без новых полей схемы).
2. Блок «Уведомления»: куда приходят уведомления (Telegram, почта) и ссылка на существующую страницу настроек уведомлений.
3. Сохранение — существующими API; на Реквизитах эти поля больше не дублируются.

### AC4. Реквизиты `/settings/organization`
1. Страница остаётся рабочей: ИНН и «Найти», название, реквизиты, смены, подписка, бейдж, особый режим (ссылка на «Пришла проверка»), удаление — всё, что не переехало. Ни одно поле не потеряно (список полей до/после — в evidence).
2. Демо-база не падает на неполном `legalProfileJson` (нормализация в `readLegalProfile`, замечание evidence sections-menu п. 15).

3. Тесты `app-nav.test.ts` и соседние — зелёные.
