# Spec (frozen 2026-11-23): 11 правок владельца — план помещений, оборудование, списки, шапка, тексты

Запрос владельца (скриншоты: план помещений `production-control/sanitation/floor-plans/…`, окна
«Редактировать / Добавить оборудование», выпадающий список «Тип», `settings/organization`):

1. План: двери и дверные проёмы; серая линия — «грязная посуда/инвентарь»; ещё 2 потока — «Вода» и «Канализация».
2. Оборудование: поля по выбранному типу; у «Другого» мин./макс. температура — по галочкам (использовать или нет).
3. «Кто заполняет по QR»: в офисе — офисные сотрудники, на другом объекте — его сотрудники.
4. Выпадающие списки по сайту на ПК — ровнее; на телефоне — удобно.
5. Глобальный поиск сверху на ПК.
6. Убрать кнопку «Выйти» слева от профиля (выход — в меню профиля).
7. Язык в меню профиля — внизу слева, «Выйти» — внизу справа.
8. Строка «подпись | поле» на ПК — не на весь экран.
9. Убрать определение нагрузки сотрудников.
10. TasksFlow → «Программный модуль», со словом «сервис» и ссылкой на сайт.
11. Убрать жаргон («пушится» и т. п.) — человеческий язык, во всех переводах.

## Исходное состояние (master 6f95d7c6a)

- План помещений — `DiagramData {title, nodes, edges}` в `PpkRecord.data` (блок `floor-plan`), схема
  `src/lib/ppk/records.ts`; редактор `diagram-editor.tsx`, отрисовка `diagram-svg.tsx` (редактор, превью,
  печать `floor-plans/[id]/print`). Дверей нет. Потоки `raw|ready|waste|staff|dishes`; `dishes` = «Грязная посуда»
  (серый пунктир).
- Окно оборудования (`settings/equipment-dialog.tsx`): мин./макс. температура и Tuya — у всех типов, кроме
  УФ-лампы; у «Металлодетектора» (тип «Другое») просит температуру. «Кто заполняет по QR» (`filler-picker.tsx`)
  показывает всех сотрудников без учёта выбранного объекта (QR-страница при этом пускает только людей точки
  оборудования — `filterByQrPoint`).
- Radix Select (`ui/select.tsx`) открывается под кнопкой-триггером; в полях с подписью внутри рамки
  (`FloatingLabelField` + `JOURNAL_DIALOG_FIELD_TRIGGER_CLASS`, 17 мест) триггер — узкая строка внутри рамки, и
  список съезжает вправо, налезает на рамку и не совпадает с ней по ширине (скриншот «Тип»). Список шире поля
  при длинных пунктах, высота — до края экрана. На телефоне — тот же маленький список под полем.
- `settings/organization`: `FormRow` = `md:grid-cols-[200px_1fr]` — поле и нативный `<select>` во всю ширину
  (≈1400px), системный список с синей подсветкой.
- Шапка (классический вид): поиск (Ctrl+K) есть только в «Новой» теме; есть отдельная кнопка «Выйти» рядом
  с аватаром; в меню профиля язык — первой строкой сверху, «Выйти» — отдельной строкой снизу. В «Новой» теме
  язык — в середине меню.
- «Нагрузка сотрудников»: `/settings/workload-balance`, `/settings/journal-difficulty` (+ API), пункт меню
  «workload», карточки и блоки нагрузки в «Ответственных за журналы».
- TasksFlow упоминается в 168 строках словарей (ru) и в серверных сообщениях; жаргон («пушатся», «pipeline»,
  «пресет», «дашборд», «legacy», «custom-шаги», «IoT», адреса `/settings/...` в тексте и т. п.) — сотни строк.

## Критерии приёмки

- **AC1. Двери и проёмы на плане.** Инструмент «Дверь» в редакторе плана помещений; при нём — выбор «Дверь» /
  «Проём». Клик ставит элемент; рядом со стеной помещения (≤ 24 единиц) он встаёт на стену по её направлению,
  иначе — горизонтально в точке клика. Выбранный элемент: перетаскивание (с тем же прилипанием к стене), панель —
  вид (дверь/проём), ширина (20–200, шаг 10), «Повернуть» (90°), «Отразить» (сторона петель, у двери), подпись;
  удаление — «Удалить»/Delete, «Отменить» работает. Отрисовка: разрыв стены и короткие откосы; у двери — полотно
  и дуга открывания. Видно в редакторе, превью списка схем и печати (оба режима); в обозначениях — «Дверь» /
  «Проём», если они есть на плане. Данные — `doors` в записи плана (необязательное поле: старые планы
  открываются и сохраняются как были), сервер проверяет (≤ 150, координаты и ширина в пределах), у блок-схемы
  дверей нет. Тесты: схема записи, прилипание к стене (чистая функция), геометрия значка.
- **AC2. Потоки.** Добавлены «Вода» (голубой, штрих-пунктир) и «Канализация» (фиолетовый, свой штрих); серый
  поток называется «Грязная посуда и инвентарь». Есть в редакторе (выбор потока и панель линии), обозначениях,
  печати «по потокам», PDF; сервер принимает новые виды. ru/en/uz.
- **AC3. Поля оборудования по типу.** Холодильник, морозильник, датчик температуры — мин./макс. температура и
  Tuya всегда (подсказки-примеры по типу: холодильник 2…6, морозильник −25…−18). УФ-лампа — как сейчас (блок
  лампы, без температуры и Tuya). Термометр, печь, фритюрница, посудомоечная машина, «Другое» и неизвестные типы
  — галочки «Мин. температура» и «Макс. температура»: снята — поля нет и норма сохраняется пустой; стоит — поле
  видно. При правке галочки стоят, если норма записана. Поле Tuya у этих типов — только при включённой
  температуре или уже записанном Device ID. Логика — чистая функция с тестами.
- **AC4. «Кто заполняет по QR» по объекту.** Список сотрудников — по выбранному в окне «Объекту»: офис —
  сотрудники офиса, точка — сотрудники точки (правило `worksAtBuilding`: без точек — везде), «Без объекта» — все;
  отмеченные люди видны всегда. При смене объекта из выбора убираются люди, которые там не работают. Страница
  точки отдаёт всех сотрудников своей области с их объектами, окно фильтрует само. Тест функции фильтра.
- **AC5. Списки Radix Select ровные.** Поле с подписью внутри рамки открывает список ровно под рамкой: левый край
  совпадает, ширина = ширине рамки, список не налезает на рамку (кнопка-триггер — сама рамка; все 17 мест).
  Везде: ширина списка = ширине поля (не меньше 12rem у узких), длинные пункты переносятся, высота — не больше
  ≈ 22rem с прокруткой. Телефон (< 640px): список — лист снизу во всю ширину, затемнение фона, пункты ≥ 48px,
  высота ≤ 70vh, отступ под жест «домой». Проверка браузером: координаты списка и рамки (ПК), лист на телефоне.
- **AC6. Нативные списки на ПК.** В кабинете на ПК (мышь) в браузерах с `appearance: base-select` (Chrome/Edge/
  Яндекс ≥ 135) нативные `<select>` полей формы открывают такой же список, как Radix (скругление, тень, подсветка,
  галочка), по ширине поля; в таблицах/ячейках журналов и на телефоне — системный список, как был. Два списка
  `settings/organization` («Сфера», «Тип организации») — на Radix Select.
- **AC7. Поиск сверху на ПК.** В классическом виде в шапке есть поиск: на ≥ 640px — кнопка-значок, на ≥ 1024px —
  поле «Поиск» с подсказкой Ctrl K; открывает общий поиск (Ctrl+K). «Новая» тема — без изменений.
- **AC8. Нет кнопки «Выйти» в шапке.** В классическом виде отдельной кнопки выхода рядом с профилем нет; выход —
  в меню профиля.
- **AC9. Низ меню профиля на ПК.** В меню профиля (классика и «Новая») последняя строка: слева — выбор языка,
  справа — «Выйти». Языка вверху/в середине меню больше нет. Телефон — без изменений.
- **AC10. Ширина строк настроек.** На ПК поле в строке «подпись | поле» не шире 560px (`FormRow`
  организации и такие же строки настроек), подпись — слева; на телефоне — как было.
- **AC11. Нет «нагрузки сотрудников».** Удалены страницы «Распределение задач» (`/settings/workload-balance`) и
  «Сложность журналов» (`/settings/journal-difficulty`, API), пункты меню, карточки, переходы и заголовки
  маршрутов, блоки/прогнозы нагрузки в «Ответственных за журналы» и их данные; старые адреса ведут на
  «Ответственных за журналы». Столбцы БД не удаляются. Тесты обновлены.
- **AC12. «Программный модуль».** Во всех текстах, которые видит клиент (ru/en/uz словари кроме `root*`, и
  серверные сообщения кабинета), вместо TasksFlow — «программный модуль» (en «software module», uz «dasturiy
  modul») в правильных падежах. В точках входа (страница подключения, раздел «Сотрудники», подсказка меню,
  промо-подсказка) — пояснение «сервис задач для сотрудников» со ссылкой на https://tasksflow.ru. Тест: в
  клиентских ключах словарей нет «TasksFlow».
- **AC13. Без жаргона.** Клиентские строки ru/en/uz переписаны простым языком: нет «пуш(ится)», «синк», «фичи»,
  «юзер», «дефолт», «дашборд», «пресет», «pipeline/пайплайн», «legacy», «custom-», «pinned», «override», «scope»,
  «toggle», «fallback», «cron/крон», «resync», «маппинг», «IoT», адресов `/settings/…` в тексте, кодов ролей
  (`head_chef`, `admin`) и т. п.; плейсхолдеры ICU и теги — те же. Технические термины остаются только там, где
  их надо ввести/скопировать (ключ API, вебхук для программистов, Device ID, GUID), с пояснением. Тест-сторож по
  списку слов (ru/en/uz, клиентские ключи).
- **AC14. Ворота.** `npm run typecheck`, `npm run test:gate`, `npm run i18n:check`, eslint изменённых файлов —
  зелёные; `next build` собирается; браузер (локальный запуск): план с дверью и новыми потоками, окно
  оборудования («Другое» с галочками, сотрудники по объекту), список «Тип» ровно под рамкой (ПК) и листом
  (телефон), шапка с поиском без «Выйти», низ меню профиля; PR влит в master (squash), выкладка прошла,
  `/api/build-info` показывает коммит.
