# Журналы точки — без чужих строк внутри документов (2026-10-31)

Владелец, 2026-10-31: «проверь похожие проблемы в других местах» — после
жалобы партнёра «в журналах темп. режима — всё оборудование организации»,
«чтобы ТТ не своё просто не видела». Аудит журналов нашёл, где документ
точки ещё получает или показывает строки других точек.

## Правило точки (как раньше)

- Точка документа — `JournalDocument.buildingId`, если точки включены
  (`documentRowsPointId` / `pointForRows`); иначе фильтра нет.
- Оборудование точки — цеха точки и цеха без точки (`equipmentBuildingWhere`).
- Помещения точки — `Room.buildingId = точка`.
- Сотрудник «чужой» — в его `buildingIds` есть живые точки, и точки
  документа среди них нет. Без точек, только удалённые точки, неизвестный
  (уволен/удалён) — не чужой.
- Закрытые документы и общие документы (без точки) не трогаем.

## Критерии приёмки

- AC1. График генуборок (`general_cleaning`) входит в автоочистку
  `point-document-rows-sync`: в активном документе точки строки помещений
  других точек убираются; строки без помещения, удалённые помещения и
  строки с отмеченными уборками (`cleanings[].done`) остаются — отметки не
  теряем.
- AC2. Журнал уборки: автоочистка убирает чужих сотрудников из
  `selectedCleanerUserIds`, `cleanerByRoomId`, `cleaningResponsibles`,
  `controlResponsibles`, `responsiblePersons`, сторон `responsiblePairs`,
  `controlUserId` и `schedule.*.responsibleUserId`; коды уборщиков
  (`cleanerCodeByUserId` / имена) остаются — это история подписей.
  Окно «Создать документ» уборки предлагает только сотрудников активной
  точки; `POST /api/journal-documents` отбрасывает чужих из переданных
  ответственных.
- AC3. Журнал холодильников, «Добавить оборудование → Выбрать из
  справочника»: только оборудование точки документа и общих цехов
  (`GET /api/equipment?documentId=…`, фильтр на сервере).
- AC4. Климат и генуборки: окно выбора помещений и «Связать» — только
  помещения точки документа; новое помещение из окна по умолчанию — на
  точке документа.
- AC5. Оборудование, созданное из журнала точки (новая строка холодильников,
  «Добавить в справочник» в ППР / поверке / поломках), попадает в цех этой
  точки (если цеха нет — создаётся «Основной цех» точки); поиск дубля по
  названию — только среди оборудования точки.
- AC6. Страница документа точки: списки выбора людей (`users`/`employees`
  журналов) — сотрудники точки плюс все, на кого документ уже ссылается
  (`employeeId` записей, id или ФИО в конфиге и данных записей), чтобы
  выбранные значения не пропали. «Заполнить за сегодня» в табличных
  журналах создаёт строки только сотрудникам точки.
- AC7. Ручное создание документа точки: значения по умолчанию, собранные из
  сотрудников (комиссия, выдающий СИЗ, ответственные и т. п.), берутся из
  сотрудников точки. Форма записи `/journals/[code]/new`: цеха, оборудование
  и сотрудники — выбранной в шапке точки (`getViewedPointId`).
- AC8. Тесты на чистые функции (AC1, AC2, AC6-отбор), `tsc` без ошибок,
  eslint по изменённым файлам без новых ошибок, проверка на e2e-базе (не
  прод): старый документ генуборок и уборки точки чистится, справочник
  холодильников отдаёт только оборудование точки.

## Не входит (решения владельца)

- Общие документы (`buildingId = null`) при включённых точках.
- Ответственные за журналы по точкам (`journal-responsibles-cascade`).
- Строки `glass_items_list` (хранят только названия).
- «Сегодня», пул задач, проверка записей, панель заведующей, кроны,
  TasksFlow, Сетап помощник, Max — другие PR.
