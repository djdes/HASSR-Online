# Spec (frozen 2026-11-12): свежие данные сразу после смены организации/точки и единый тост смены

Запрос владельца (скриншоты «Баланс и бонусы», iPhone, тёмная тема): «При смене организаций баланс показывается
прошлой, после обновления страницы обновляется нормально. Сделать чтобы было актуально сразу. Проверить эту
проблему по всему сайту глобально. А так же оповещение сверху о смене должно показываться стандартно по всему
сайту как 3 секунды с таймером и крестиком закрытия справа сверху, должна быть единая логика и дизайн, в идеале
всегда с компактной кнопкой вернуться.»

## Исходное состояние (master e28d552b)

Смена организации/точки — запрос (`/api/me/active-organization`, `/api/me/active-building`) и `router.refresh()`
в общем переходе (`content-transition.tsx`): сервер присылает новую страницу, но клиентские компоненты НЕ
монтируются заново (`SectionFrame` намеренно держит страницу смонтированной). Корни устаревших данных:

1. **Страницы копируют серверные данные в `useState` один раз.** `BalanceClient`: `useState(initial)` — после
   смены остаётся баланс прежней организации (скриншот: 10 000 ₽ вместо 0 ₽), после перезагрузки — верно. Тот
   же приём в сотнях клиентских компонентов страниц (`useState(initial…)`, загрузка в `useEffect(…, [])`).
2. **Клиентская сессия не догоняет серверную.** `SessionProvider` next-auth 4.24.15 берёт `session` из пропса
   только при первом рендере; смена перевыпускает куку, layout получает новую сессию, а `useSession()` до
   перезагрузки отдаёт прежние организацию, роль и права. На этом — `JournalControlsProvider` (настройки
   журналов прежней организации), проверки прав в клиенте (`hasCapability`, `isPointScoped`), профиль
   мини-приложения.
3. **Оболочка кабинета держит состояние прежней организации:** AI-помощник (переписка и карточки действий
   прежней организации), окно перехода на тариф (закрыто для прежней — скрыто и для новой), логотип (ошибка
   загрузки / только что загруженный — от прежней), анкета, баннер новой организации, отмена правок журнала.
4. **Мини-приложение `/mini/*`:** смена организации в профиле — `router.refresh()` без общего перехода; список
   торговых точек в профиле остаётся от прежней организации; тост — до прихода данных.

Тосты смены — разные:
- организация (меню профиля, лист профиля на телефоне, пилюля навигации) — стандартный `toast.success`
  «Переключено: {name}», 4 с, без крестика и без «вернуться» (скриншот);
- торговая точка (шапка, лист, автосмена по разделу) — `showPointSwitchToast`: 3 с, кольцо-отсчёт вокруг
  крестика, «Вернуться на «…»» текстовой ссылкой, но не всегда (после возврата и при восстановлении — без неё);
- «Перейти на точку объекта» (`PointMismatchNotice`), «Выбрать всю организацию» (`PointModeUnavailable`) — без
  тоста; выход из демо — `toast.success` до прихода данных; вход в демо — два тоста (`toast.success` «Демо-
  организация готова» + приветствие с описанием); создание организации — `toast.success` до прихода данных;
  мини-приложение — `toast.success` «Вы работаете в «…»» / «Торговая точка: …».

## Критерии приёмки

- **AC1. Страница — сразу с данными новой организации/точки.** Layout считает ключ области данных
  (пользователь + организация; при журналах по точкам — плюс активная точка и режим «Вся организация»;
  `src/lib/cabinet-scope.ts`), `SectionFrame` монтирует страницу заново при его смене — и на сайте, и в оболочке
  мини-приложения. Ожидание (скелет) — как раньше. Проверка: тест ключа; браузер: «Баланс и бонусы» в
  организации A (10 000 ₽) → смена на B → 0 ₽ без перезагрузки; «Вернуться» → снова 10 000 ₽; DOM страницы
  после смены — новый (старый узел отсоединён).
- **AC2. Оболочка без состояния прежней организации.** При смене ОРГАНИЗАЦИИ шапка, меню, баннеры и плавающие
  виджеты (AI-помощник, поддержка, окно тарифа, ⌘K, «Что нового» и др.) монтируются заново — как после
  перезагрузки; при смене ТОЧКИ шапка и меню остаются (заново — только страница). Переход (скелет, крутилка) и
  тост после него это переживают (провайдер перехода и `<Toaster>` — выше границы). Сайт, оболочка
  мини-приложения, `/mini/*` (AI-помощник). Проверка: браузер — узел шапки после смены организации новый,
  после смены точки — тот же; тест ключа.
- **AC3. Клиентская сессия догоняет серверную.** Когда layout прислал сессию с другой организацией/ролью/правами,
  `useSession()` перечитывает её без перезагрузки и без состояния «загрузка» (тот же приём, что
  `adoptCookieSession`: событие `storage` для next-auth) — сайт, `/root`, мини-приложение. Без смены — ни
  одного лишнего запроса. Проверка: тест ключа сессии; браузер — после смены организации запрос
  `GET /api/auth/session`, затем `/api/settings/journal-controls`.
- **AC4. Один тост смены на весь сайт.** Один компонент (`src/components/layout/switch-toast.tsx`): сверху, живёт
  3 с, справа сверху крестик «Закрыть» с кольцом-отсчётом (пауза при наведении, без анимации при «Уменьшить
  движение»), сообщение с галочкой, под ним компактная кнопка-пилюля «↶ Вернуться …» в одну строку (длинное
  название — с многоточием); светлая/тёмная/«Новая» темы — через токены `--app-*`. Проверка: SSR-тест разметки
  (крестик с подписью, кольцо `--toast-life: 3000ms`, кнопка возврата и её отсутствие), браузер — скриншот
  тоста, через ~3 с его нет.
- **AC5. Единая логика: все смены — через этот тост и всегда с возвратом, когда есть куда.** Один помощник
  (`switchWithReturn`): смена в общем переходе → после прихода новой страницы тост → «Вернуться …» — та же смена
  обратно (с тем же скелетом), и её тост снова предлагает вернуться. Места: организация (меню профиля, лист
  профиля, пилюля навигации), торговая точка (шапка, лист на телефоне), автосмена точки по разделу (кроме
  страницы точки, которая сама держит свою точку), «Перейти на точку объекта», «Выбрать всю организацию», выход
  из демо и вход в демо (один тост вместо двух), создание организации (тост «Организация «…» создана» с
  возвратом в прежнюю), мини-приложение — организация и точка (общий переход и в `/mini/*`). Тексты смены
  организации едины: «Организация: {name}» и «Вернуться в «{name}»». Прежних `toast.success` о смене в этих
  местах нет. Проверка: тест помощника (порядок: запрос → тост → возврат → тост с обратным возвратом); браузер:
  смена организации → тост с «Вернуться в «A»» → нажатие → организация A и её данные.
- **AC6. Переводы.** Все новые/изменённые подписи — в `ru/en/uz.json` одним коммитом, `npm run i18n:types`
  перегенерировал `message-contract.d.ts`; ставшие ненужными ключи удалены. Проверка: i18n-тесты, поиск
  ключей.
- **AC7. Проверки зелёные.** `npm run typecheck`, `npm run test:changed`, eslint по изменённым файлам.

## Вне объёма

Смены с полной перезагрузкой страницы (данные и так свежие, тост до перезагрузки не виден): вход ROOT «как
организация» и выход из него, открытие мастер-кабинета, кабинет партнёра, принятие приглашения,
`OpenAtPointButton`. Сообщения, которые не о смене (сохранение, ошибки), не меняются.
