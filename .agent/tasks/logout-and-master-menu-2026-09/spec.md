# Spec (frozen 2026-09-26): выход работает везде; мастер-кабинет — в разделе «Кабинет», а не в списке организаций

Правки владельца: «Исправить выход из мастера и вообще выход — был баг с выходом из мини, вроде починили, но походу это везде, чини везде, разберись что не так»; «Мастер-кабинет в списке организаций — норм? Как будто должно быть иначе, в разделе кабинета».

## Причина (разбор оркестратора — проверить и уточнить)
- Сессия живёт в РАЗНЫХ куках: next-auth в проде — `__Secure-haccp-online.session-token` (`src/lib/auth.ts`), а свои входы (`src/lib/issue-session.ts`: вход в мини-приложении, по личному QR, мгновенная регистрация и т. п.) ставят `CUSTOM_SESSION_COOKIE` = `haccp-online.session-token` (`src/lib/auth-cookies.ts`). `src/proxy.ts` берёт токен сначала из `CUSTOM_SESSION_COOKIE`, потом из legacy-имён.
- «Выйти» в мастер-кабинете (`src/components/master/master-shell.tsx`) и партнёрском (`src/components/partner/partner-shell.tsx`) — `signOut()` next-auth: гасит только куку next-auth. Оставшаяся кука держит сессию → proxy для сессии мастер-кабинета (`evaluateDirectoryRequest`) уводит обратно в `/master`, человек не может выйти. После входа другим аккаунтом прокси может читать старую куку (одна личность у proxy, другая у страниц).
- Сайт (`header.tsx`/`profile-sheet.tsx`) и мини-приложение уже зовут `POST /api/auth/logout` (чистит все имена) — проверить, что и там всё уходит (атрибуты/домен куки при удалении совпадают с установкой).

## 1. Выход везде
- Один клиентский помощник полного выхода (есть `signOutOnThisDevice` в `src/app/mini/_lib/signed-out-mark.ts` — обобщить/переиспользовать): `POST /api/auth/logout` → `signOut({ redirect: false })` → переход на нужный экран входа. Им пользуются ВСЕ кнопки «Выйти»: сайт (шапка, лист профиля), мастер-кабинет, партнёрский кабинет, мини-приложение, киоск (если там есть выход), «Выйти на всех устройствах» (`/api/security/logout-all`) — тоже гасит все имена.
- `POST /api/auth/logout` гасит все имена сессии с атрибутами, совпадающими с установкой (`__Secure-`/`__Host-` требования), включая вариант с доменом, если где-то кука ставится с `domain`.
- Вход любым путём (next-auth и `issue-session.ts`) ставит одну актуальную куку и гасит остальные имена сессии — двух аккаунтов одновременно не бывает. `proxy.ts` читает ту же куку, что и `getServerSession`/обёртка сессии (без приоритета устаревшей), legacy — только как запасной вариант, если основной нет.
- Проверить все пути: вход по паролю на сайте, вход в мини-приложении по телефону/почте, по личному QR, принятие приглашения в мастер-кабинет; выход из каждого места; смена аккаунта A → B.

## 2. Мастер-кабинет — в «Кабинет»
- В листе профиля (телефон), выпадающем меню профиля (компьютер) и переключателе организаций мини-приложения организации `kind = "directory"` не показываются в «Организациях». В разделе «Кабинет» — строка с названием мастер-кабинета (например «Мастер-кабинет Школы»), значок справочника; нажатие переключает на него и открывает `/master` (как сейчас при выборе из списка). Несколько мастер-кабинетов — несколько строк. Внутри `/master` — ссылка/пункт «Моя организация» обратно, если у человека есть обычные организации.

- AC1: e2e — для каждого пути входа и каждой кнопки «Выйти»: после выхода нет ни одной куки сессии, `/login` открывается, защищённые страницы требуют входа; из мастер-кабинета выход работает.
