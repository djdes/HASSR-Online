# Выкат без входящего SSH: сервер сам забирает master, если выкат из GitHub не дошёл

- **Task ID:** `deploy-pull-agent-2026-11-21`
- **Base:** `origin/master` `3bd9cb247` (#285)
- **Branch:** `claude/hopeful-euler-lb6cie` (перезапущена от master)
- **Frozen:** 2026-11-21, before implementation.

## Запрос владельца (21.11.2026)

«Сделай все кроме 1» — пункт 7: «выкат без входящего SSH: сервер сам забирает новый master с GitHub (в эту
сторону связь быстрая и стабильная), выкаты перестанут зависеть от обрывов».

## Факты

- Выкат идёт так: GitHub Actions по SSH заходит на сервер: сервер скачивает код коммита с GitHub
  (`Server downloads the commit from GitHub`), затем три шага `Deploy step 1/3 … 3/3` — встроенные скрипты в
  `.github/workflows/deploy.yml`, они зависят только от `${{ env.APP_DIR }}` и `${{ github.sha }}`.
- Из зарубежных дата-центров (GitHub Actions — тоже) сервер принимает соединения через раз: выкат #2383 упал на
  ожидании SSH, прод остался на прежней сборке до ручного запуска. Сервер → GitHub — быстро (10–40 с на коммит).
- Деплой ставит на сервере строки crontab (`install-crm-cron.sh`, `cron-gogetlinks.sh`): крон пользователя есть.
- С 2026-11-03 выкат не ждёт гейта (typecheck/тесты): гейт только сигналит в Telegram.

## Решения

- Р1. Агент на сервере (`scripts/deploy-agent.mjs`, крон раз в 5 минут через `scripts/deploy-agent.sh`):
  сравнивает сборку сайта (`/api/build-info` → `fullBuildId`) с головой master (GitHub API). Выкатывает сам,
  только если: master впереди сборки сайта (сравнение GitHub), выкат этого коммита в GitHub закончился
  (неуспешно) больше 2 минут назад или вовсе не начался за 20 минут; не больше 2 попыток на коммит. Пока выкат
  в GitHub идёт — ждёт.
- Р2. Те же шаги, что у GitHub: код коммита с codeload.github.com, `deploy.tar` скриптом коммита
  (`deploy-tarball.sh`), затем скрипты шагов 1/3–3/3 **из `deploy.yml` того же коммита** (единственный источник:
  подставляются только `APP_DIR` и SHA, любое другое `${{ … }}` — отказ). Шаг упал — остановка (сайт остаётся на
  прежней сборке; шаг 3 сам проверяет новую сборку и откатывает).
- Р3. Один выкат за раз: общий замок (каталог `~/.wesetup-deploy.lock.d`, `scripts/deploy-lock.sh`) — берут шаги
  выката в GitHub (скачивание кода и шаги 1–3, ждут до 25 минут) и агент; замок старше 45 минут — от упавшего
  выката, снимается. Агент обновляет замок перед каждым шагом.
- Р4. Установка — сам деплой (шаг 3, как крон CRM, без падения выката): строка crontab и снимок окружения
  сеанса деплоя (`PATH`, язык, пояс), чтобы крон запускал node и pm2 так же. Выключатель — файл
  `~/.wesetup-deploy-agent-off`.
- Р5. Telegram администратору платформы (`TELEGRAM_BOT_TOKEN`, `PLATFORM_ADMIN_TELEGRAM_CHAT_ID` из `.env`,
  `TELEGRAM_FORCE_IP`): начал / выкатил / не смог; отказ по сравнению и «попытки кончились» — один раз на коммит.
  Журнал каждого выката — `~/.wesetup-deploy-agent/runs/`, последние 10.

## Критерии приёмки

- **AC1. Решение.** Чистая функция `decide` (тест): совпадает — ничего; выкат в GitHub идёт — ждать; закончился
  неуспешно < 2 мин — ждать, ≥ 2 мин — выкатывать; нет выката < 20 мин — ждать, ≥ 20 — выкатывать; master не
  впереди (позади, совпадает, разошёлся, неизвестно) — не выкатывать (+ одно сообщение); попытки кончились —
  стоп (+ одно сообщение); нет сведений о master или сайте — ждать.
- **AC2. Шаги из deploy.yml.** Из настоящего `deploy.yml` извлекаются скрипты шагов 1/3, 2/3, 3/3 и скачивания;
  после подстановки нет `${{`; неизвестное выражение — ошибка (тест).
- **AC3. Выкат агентом.** Порядок: скачать → `deploy.tar` → шаги 1–3 с `WESETUP_DEPLOY_LOCKED=1`, стоп на первом
  упавшем шаге, замок держится и снимается, сообщения «начал / выкатил / не смог» (тест на заглушках шагов, без
  сети и pm2).
- **AC4. Замок.** `deploy-lock.sh`: второй не берёт, ждёт и берёт после освобождения, старый снимается,
  `WESETUP_DEPLOY_LOCKED=1` — без замка (тест). В `deploy.yml` шаг скачивания и шаги 1–3 берут замок (тест по
  файлу).
- **AC5. Установка.** `install-deploy-agent-cron.sh` идемпотентно ставит строку и снимок окружения (тест с
  заглушкой crontab); шаг 3 вызывает его без падения выката, после проверки новой сборки (тест по файлу);
  `docs/deploy-agent.md` — как работает, где журнал, как выключить.
- **AC6. Проверки.** typecheck, test:changed / test:gate, eslint по изменённым файлам, `bash -n` по скриптам —
  зелёные.
