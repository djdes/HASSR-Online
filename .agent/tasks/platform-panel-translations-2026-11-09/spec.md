# Переводы — в панель платформы, панель с разрешёнными вкладками, ссылки на localhost

Задача владельца 09.11.2026 (скриншоты меню alexey@wesetup.ru и адреса `https://localhost:3002/root/crm`):

1. «Перенеси переводы в панель платформы».
2. «Если мы дали роль админа другому пользователю — у него открывается просто панель платформы с вкладками,
   которые разрешили».
3. «Сейчас при заходе в панель платформы ошибка — localhost-ссылки. Исправить и поискать, где ещё может быть
   такая проблема в коде».

## Что найдено до правок

- `GET /api/me/platform-panel` (вход в панель для всех, кроме владельца; на него же ведёт кнопка письма
  «Открыть панель») отвечает `NextResponse.redirect(new URL(path, request.url))`. Next 16 собирает
  `request.url` обработчика из адреса, который слушает сервер (`localhost:3002`), и `x-forwarded-proto`;
  Host запроса не учитывается (`next/dist/server/lib/router-utils/resolve-routes.js`). На проде:
  `curl -I https://wesetup.ru/api/me/platform-panel` → `307 location: https://localhost:3002/login`;
  с сессией — `https://localhost:3002/root/crm` (скриншот). Помощник `lib/relative-redirect.ts` для этого
  уже есть (2026-09-11), маршрут написан позже без него. Редиректы `proxy.ts` Next делает относительными сам.
- В меню кабинета (выпадающее меню на компьютере, лист на телефоне, профиль мини-приложения) отдельный пункт
  «Переводы интерфейса» — владельцу ведёт в `/root/translations`, переводчику (`User.canEditTranslations`) —
  в отдельную страницу кабинета `/translations`.
- Вкладка «Переводы» в панели (`/root/translations`) открыта по разделу `translations`, а API редактора
  (`/api/translations*`) пускает только владельца и флаг `canEditTranslations`: человеку с ролью, где есть
  «Переводы» (например «SEO и контент»), вкладка открывается, но строки не грузятся и не сохраняются (403).
- В мини-приложении строка «Панель платформы» есть только у владельца.

## Решения (сказать в отчёте)

- Право переводчика (`User.canEditTranslations`) = вкладка «Переводы» панели: эффективные разделы человека —
  выданные разделы плюс `translations`, если он переводчик. Колонку и данные не меняем, миграции нет.
- «Переводы интерфейса» из меню кабинета убираем везде; переводы — только вкладка панели
  («Сайт → Переводы»). Старый адрес `/translations` ведёт в панель на «Переводы» (закладки не ломаются).
- Назначать и снимать переводчиков (`/api/root/translators`, блок «Переводчики») — только владелец: теперь это
  выдача доступа к панели, а доступы раздаёт владелец (как «Команда и доступы»). Иначе переводчик мог бы сам
  назначать переводчиков.
- Куда открывается панель — как сейчас: владелец — «Организации», остальные — первая разрешённая вкладка
  (порядок разделов не меняем).
- Поиск «где ещё»: проверяем все места, где сервер собирает абсолютный адрес из запроса; что уже защищено
  (`NEXTAUTH_URL`) — не трогаем, перечисляем в доказательствах. Тест-сторож не даёт вернуть редирект на адрес
  из `request.url`.

## Критерии приёмки

- AC1. `/api/me/platform-panel` отвечает только относительным `Location`: без входа — `/login?next=…` (после входа
  человек возвращается в панель), без доступа — `/dashboard`, с доступом — первая разрешённая вкладка или
  `?next=` (только страница `/root…`, которую человеку можно открыть; иначе — первая вкладка). Claim разделов в
  сессии обновляется, как раньше. Проверка: запрос с `Host: wesetup.ru` и `x-forwarded-proto: https`
  к собранному приложению не даёт `localhost` в `Location`.
- AC2. Тест-сторож: ни один обработчик в `src/app` и `src/lib` (кроме `proxy.ts`) не вызывает
  `NextResponse.redirect` / `Response.redirect` с адресом из `request.url`, `req.url` или `nextUrl`; на коде до
  исправления тест падает. Комментарий `relative-redirect.ts` описывает настоящую причину (адрес сервера, а не
  Host). Результат поиска «где ещё» — в доказательствах.
- AC3. Пункта «Переводы интерфейса» нет в меню кабинета на компьютере и телефоне и в профиле мини-приложения;
  неиспользуемые строки удалены из ru/en/uz (контракт перегенерирован).
- AC4. «Панель платформы» в меню кабинета и в профиле мини-приложения есть у владельца, у человека с разделами
  и у переводчика; владельцу ведёт в `/root`, остальным — через `/api/me/platform-panel`.
- AC5. Переводчик без других разделов попадает в панель на вкладку «Переводы» и видит только её; человек с ролью
  видит только вкладки своей роли (плюс «Переводы», если он переводчик). Proxy и `requireRoot()` пускают
  переводчика на `/root/translations`, но не в другие разделы.
- AC6. API редактора (`/api/translations`, `/auto`, `/categories`, `/history`) пускает владельца, переводчика и
  человека с разделом «Переводы»; остальных — 403.
- AC7. Назначение переводчиков (`/api/root/translators`) — только владелец; блок «Переводчики» на вкладке
  «Переводы» видит только владелец; описание блока говорит, что переводчик открывает «Переводы» в панели
  платформы (ru/en/uz).
- AC8. `/translations` → 307 с относительным `Location` на вход в панель с `next=/root/translations`.
- AC9. Тесты на новые чистые функции и обновлённые правила; `npm run typecheck`, `npm run test:gate`,
  `npm run i18n:check` и eslint по изменённым файлам — зелёные; живая проверка (локальная БД, Playwright):
  владелец, администратор с ролью, переводчик, человек с ролью «SEO и контент» без флага переводчика.
