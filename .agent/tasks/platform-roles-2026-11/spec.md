## Что есть сейчас

- Доступ к панели — разделы (`User.platformSections`) и шесть жёстко заданных в коде наборов
  («Администратор», «Продажи», …). Флаг РОП (`User.platformSalesHead`), РОП может быть сколько угодно.
- Видимость данных не ограничена: кто видит «Клиентов» или CRM — видит всех клиентов и все лиды.
- Подпись КП: в карточке клиента — «Моя почта» (`position`) → `User.positionTitle`; в генераторе
  `/root/proposals` — один общий отправитель по умолчанию без должности.

## Решение

### 1. Роли — в базе, их настраивает владелец

`PlatformRole`: название, описание, разделы, **охват данных** (`all` — все клиенты и лиды; `own` —
только закреплённые за человеком + свободные лиды), **РОП** (все заявки, эскалации, утренняя сводка),
**должность в подписи** (пусто — название роли), порядок, `system` (встроенная: нельзя удалить).

Роль у человека — `User.platformRoleId`. Разделы и флаг РОП из роли **копируются** человеку
(`platformSections`, `platformSalesHead`): все проверки доступа, прокси, уведомления и сессия
работают как сейчас. Изменил роль — обновились все её люди. «Свой набор» (без роли) — как раньше:
разделы и РОП задаются человеку напрямую, охват — «все».

Встроенные роли (создаются, если их нет; правки владельца не перезаписываются):

| Роль | Разделы | Охват | РОП | Подпись |
|---|---|---|---|---|
| Администратор | все | все | — | Администратор |
| Коммерческий директор | все | все | да | Коммерческий директор |
| РОП | клиенты, CRM, продажи, партнёры, ЭДО | все | да | Руководитель отдела продаж |
| Менеджер по продажам | клиенты, CRM, продажи | **свои** | — | Менеджер по работе с клиентами |
| Поддержка / SEO и контент / Бухгалтерия / Аналитика | как прежние наборы | все | — | название |

### 2. Отдельный раздел «CRM»

CRM уходит из «Продаж» в свой раздел `crm` — менеджеру можно дать CRM без промокодов и рассылок.
Миграция: всем, у кого есть «Продажи», добавляется «CRM» (доступ не меняется ни у кого).

### 3. Закрепление клиентов и лидов

- Клиент (организация) — `Organization.accountManagerId`: «Ответственный менеджер» в карточке клиента.
  Назначают люди с охватом «все» (РОП, директор, админ). При назначении лиды CRM этой организации без
  ответственного или со старым менеджером переходят новому.
- Лид CRM — `CrmContact.ownerId` (уже есть). Новый контакт клиента с менеджером сразу получает его.
- Охват «свои»:
  - список клиентов — только закреплённые; карточка, её API (счета, КП, договор, баланс…) чужого
    клиента — 404 (проверка в `requireRoot` по адресу, одна на все маршруты);
  - CRM — свои контакты и свободные (без ответственного) с кнопкой «Взять себе»; назначить чужого
    нельзя; карточка чужого контакта — 404; «Почта и фильтры», «Здоровье клиентов», «Воронка» — нет.
- РОП и охват «все» видят и распределяют всех.

### 4. Должность в подписи

Подпись КП и писем: личная должность (задаёт владелец в окне доступа) → «Моя почта» → должность из
роли → должность в кабинете. Генератор КП подставляет подпись того, кто его открыл (имя, должность,
телефон, почта), и показывает поле «Должность».

### 5. alexey@wesetup.ru

Однократный сид: роль «Коммерческий директор», личная должность «Коммерческий директор».

### 6. Экран «Команда и доступы» (только владелец)

- Блок «Роли»: список (название, разделы, охват, РОП, сколько людей), «Новая роль», изменение,
  удаление (кроме встроенных и ролей с людьми).
- Окно доступа: выбор роли или «Свой набор», личная должность в подписи; в списке команды — роль,
  метка РОП, охват «свои».
- Владельцу платформы — личная должность и РОП (разделы ему не нужны).

## Критерии приёмки

- **AC1** Схема только добавляет: `PlatformRole`, `User.platformRoleId`, `User.platformTitle`,
  `Organization.accountManagerId` (`additiveSchemaSql`, локальная PostgreSQL).
- **AC2** Роли: CRUD владельцем (API + экран); изменение роли переписывает разделы и РОП всех её людей;
  встроенную и занятую роль удалить нельзя; назначение роли и «свой набор» — тесты и живой прогон.
- **AC3** Раздел `crm`: страницы и API CRM — `crm`; обход всех маршрутов (`platform-access.test.ts`)
  зелёный; миграция добавляет `crm` всем, у кого `sales`; администраторы остаются администраторами.
- **AC4** Охват «свои»: список клиентов, карточка и API чужого клиента, CRM (список, сводка, карточка,
  действия, назначение), закрытые страницы — тесты чистых правил и живой прогон под менеджером
  (свой клиент виден, чужой — 404, свободный лид — «Взять себе»).
- **AC5** Закрепление клиента: назначение менеджера в карточке (только охват «все»), перенос лидов
  организации, новый контакт клиента получает менеджера.
- **AC6** Подпись: порядок источников должности — тест; генератор КП подставляет подпись текущего
  человека с должностью; КП alexey — «Коммерческий директор» (живой прогон).
- **AC7** Сид: встроенные роли, миграция `crm`, привязка прежних наборов к ролям, alexey — коммерческий
  директор; однократно, повтор — без изменений (локальная БД).
- **AC8** `npm run typecheck`, `npm run test:gate`, `npm run i18n:check`, eslint по изменённым файлам —
  зелёные; `docs/crm.md` дополнен.

## Вне рамок

Охват «свои» для разделов кроме клиентов и CRM (заявки, чаты, счета гостей видят все, у кого раздел),
массовое переназначение клиентов, права на отдельные действия внутри раздела.
