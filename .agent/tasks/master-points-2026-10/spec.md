# Мастер-кабинет: подключение точек по отдельности

Запрос владельца (2026-10-28): «Не могу подключить к мастер-кабинету ещё одну
школу. Подключает, видимо, всю организацию сразу. Логика должна быть: каждая
точка имеет свой уникальный ID журнала бракеража, независимо от организации.
Именно по ним объединяется выгрузка».

Решения владельца:
- старые подключения «организация целиком» — перевести на точки;
- точки одной организации могут быть в разных кабинетах;
- «выгрузка» = «Добавить в журналы на дату» (+ история и исправления).

## Причина

«Код журнала объекта» в настройках БЖГП — код организации
(`Organization.serviceCode`). Подключение по нему ставит
`Organization.linkedServiceCode`, кабинет видит организацию одним объектом и
пишет в первый документ организации без учёта точки. Вторая школа той же
организации даёт тот же код → «уже подключён».

## Критерии

- AC1. У торговой точки организации с журналами по точкам свой код журнала
  (`Building.serviceCode`, уникальный, не совпадает с кодами организаций);
  настройки журнала на точке показывают код этой точки.
- AC2. Код точки в «Подключённых объектах» подключает только эту точку
  (`Building.linkedServiceCode`); код организации с ≥2 точками не подключает
  её целиком, а объясняет, что нужен код точки.
- AC3. Организация с журналами по точкам, подключённая целиком, в кабинете —
  это её точки отдельными объектами (без миграции данных); выгрузка на дату
  идёт в документ каждой точки.
- AC4. Точка, подключённая своим кодом к другому кабинету, не показывается в
  кабинете организации; точка организации, целиком состоящей в другом
  кабинете, не подключается молча.
- AC5. «Отключить» у объекта с подтверждением: точка организации-целиком —
  организация выходит, остальные её точки остаются своими привязками.
- AC6. Исправления прошлых выгрузок проверяют подключение точки и для точек
  «в составе организации».
- AC7. Тексты ru/en/uz, «Что нового», `npm run i18n:types`, tsc, тесты.
