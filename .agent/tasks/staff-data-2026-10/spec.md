## Критерии приёмки

### AC1. Штатная численность должностей
1. `JobPosition.plannedHeadcount Int?` — необязательное поле («по штатному
   расписанию»); `prisma db push` на `wesetup_staff` проходит.
2. Чистая функция `src/lib/staffing.ts` считает по должности: занято (активные,
   не в архиве), план, вакансии, перебор, подпись «занято N из M»; итоги по
   организации. Покрыта unit-тестами.
3. `GET /api/positions` отдаёт для каждой должности `plannedHeadcount`,
   `occupied`, `vacancies`, `overstaffed`, `staffingLabel` и итоги `totals`.
4. `POST /api/positions` и `PATCH /api/positions/[id]` принимают
   `plannedHeadcount` (целое 0…999 или `null` = «не задано»); неверное значение — 400.
5. `PUT /api/positions/order { ids: string[] }` задаёт порядок (`sortOrder`)
   должностей; только руководитель; чужие и неизвестные id — 400/404; порядок
   сохраняется.
6. На `/settings/users` в окне создания/правки должности есть поле
   «Штатная численность», а в строке должности — пилюля «занято N из M».

### AC2. Пресет прав на конкретного человека
1. `GET /api/users/[id]/access` дополнительно отдаёт `permissionPreset`
   (явный или `null`) и `effectivePreset`.
2. В окне доступа сотрудника (`StaffAccessDialog`) — блок «Набор прав»: выбор
   «По должности (автоматически)» или одного из пресетов, у каждого — что он даёт
   (описание и список возможностей). Сохранение вызывает
   `POST /api/staff/[id]/preset` только при изменении.
3. `POST /api/staff/[id]/preset` не даёт руководителю снять с себя «Администратора»
   (защита от самоблокировки) и сбрасывает кэш ACL журналов человека.
4. Тексты окна — в `ru/en/uz` (тесты локализации и каталога проходят).

### AC3. Пресет «Контроль-группа»
1. В `permission-presets.ts` новый пресет `control_group` «Контроль-группа»:
   видит журналы, сотрудников, отчёты и статистику, подтверждает
   (`tasks.verify`), назначает задачи (новая возможность `tasks.assign`), сам не
   заполняет. `tasks.assign` есть и у `admin`. Списки пресетов и возможностей
   (`/api/settings/role-presets`, `/settings/role-presets`) берутся из одного места.
2. ACL журналов: у `control_group` чтение всех журналов, запись и закрытие
   документа запрещены — даже при роли руководителя.
3. `POST /api/journal-task-claims/assign`: можно `admin.full` или `tasks.assign`;
   без `admin.full` — только сотрудникам из `ManagerScope` назначающего и только
   журналы из `assignableJournalCodes`; назначить задачу участнику контроль-группы
   нельзя (он не заполняет).
4. Контроль-группа не может менять «Иерархию» (`/api/manager-scope` POST/DELETE) —
   иначе расширила бы себе видимость.
5. `GET /api/staff/control-group` — участники контроль-группы с кратким описанием
   их `ManagerScope` (кого видят, какие журналы назначают) и кандидаты для «Добавить».
6. Тесты: возможности пресета, правило ACL, правило назначения по `ManagerScope`,
   видимость разделов меню для контроль-группы с ролью руководителя и с линейной ролью.

### AC4. Бракеражная комиссия у скоропортящейся продукции
1. `perishable_rejection` входит в журналы с комиссией: окно «Комиссия»
   (`commission-dialog.tsx`, `/api/settings/brakerage-commission/perishable_rejection`)
   назначает состав и копирует его в активные документы, новый документ получает состав.
2. Старые копии состава в документах скоропорта (до решения 2026-09-22) не оживают:
   состав действует только с меткой `commissionEnabled`, которую ставит сервер.
3. Документ скоропорта на сайте: кнопка «Комиссия · N», строка состава, итог
   «Сегодня: …», статус строки «Ждёт подписи комиссии» / подписи, «Подписать
   выбранные» для члена комиссии; закончить журнал с неподписанными строками
   нельзя (и на сервере, и в окне закрытия).
4. QR журнала: член комиссии входит по PIN, видит список за сегодня и подписывает
   строку; подпись появляется в документе.
5. Тесты бракеража обновлены (`isCommissionJournalCode`, метка, незакрытые строки).

### AC5. Общий список «Проверяющие и аудиторы»
1. `src/lib/inspectors-auditors.ts`: внешние — ссылки и QR портала проверяющего
   (`InspectorToken`: вид, метка, срок, активность, кто выпустил, открытия) с их
   визитами (`InspectorVisit`); внутренние — люди с ролями: проверяющий журнала
   (`_verifier`), проверяющий документа (`JournalDocument.verifierUserId`),
   проверяющий помещения (`Room.verifierUserIds`), аудитор журналов `audit_*`,
   аудитор прослеживаемости. Сборка внутреннего списка — чистая функция с тестами.
2. `GET /api/staff/inspectors-auditors` — руководителю; без хэшей токенов.

### AC6. Почта сотрудника в карточке
