# Чек-лист «Контроль температуры готовых блюд на раздаче» + вид продукции, сроки и условия хранения

Задача руководителя (05.11.2026), пункты 1 и 5.

## Решения
- Чек-лист, а не журнал (так просил руководитель). Движок расширяется минимально:
  категория чек-листа может брать строки из данных (`rowsSource: "serving_dishes"`).
  При старте проверки сервер записывает в снимок список блюд (`rows`), а
  `expandChecklistDefinition` разворачивает категорию в карточку на каждое блюдо —
  как уже разворачиваются повторяемые категории. Остальной движок (проверка
  ответов, баллы, нарушения, PDF, файлы) работает без изменений.
- Блюда: готовая продукция справочника (вид «Готовая продукция») + блюда из
  сегодняшних строк «Журнала бракеража готовой пищевой продукции» (точка проверки
  и общие документы). Сначала бракераж, без повторов, до 60 блюд.
- На блюдо: «Как подаётся» (горячее / первое блюдо или горячий напиток / холодное /
  сегодня нет на раздаче) и два замера по выбранной группе: «в начале раздачи» и
  «через час после начала». Нормы — те же, что в типовом СанПиН-чек-листе кода
  (`src/lib/checklist-templates/sanpin.ts`): горячее не ниже +65 °C, первое и горячие
  напитки не ниже +75 °C, холодное не выше +14 °C. Пороги — обычные условия
  нарушения вопросов: руководитель меняет их в конструкторе своей копии шаблона.
- Вид продукции: `Product.kind` = raw | semi | finished, по умолчанию `raw`
  («Продукты (сырьё)»): справочник до сих пор служил приёмке и входному контролю.
- Срок годности: значение + единица (часы / сутки): новое `shelfLifeHours`,
  `shelfLifeDays` остаётся. Условия хранения: `storageTemp` (режим) + новое
  `storageConditions` (текст). У готовой продукции — `servingTemp` (как подаётся),
  им предзаполняется «Как подаётся» в чек-листе.

## Критерии
- AC1. Схема Prisma: только аддитивные поля `Product.kind @default("raw")`,
  `shelfLifeHours Int?`, `storageConditions String?`, `servingTemp String?`.
- AC2. Справочник: вкладки-фильтр «Все / Продукты (сырьё) / Полуфабрикаты /
  Готовая продукция» со счётчиками; столбец вида; срок показывает «N ч» или «N сут»;
  хранение — режим + условие. Диалог: выбор вида, срок с единицей, режим, условие,
  у готовой продукции — подача. API POST/PUT принимают и проверяют новые поля.
- AC3. Импорт: колонка «Вид»/«Тип» (сырьё/полуфабрикат/готовая), срок с единицей
  («12 ч», «3 сут»), «Условия хранения» отдельно от температуры; для строк без вида —
  вид, выбранный в диалоге импорта (по умолчанию сырьё).
- AC4. Движок: категория с `rowsSource` разворачивается по `rows` снимка; без
  `rows` (шаблон) — как есть; `rows: []` — пустое состояние с подсказкой «добавьте
  готовую продукцию в справочник / проведите бракераж». Старые снимки не меняются.
- AC5. Типовой шаблон «Контроль температуры готовых блюд на раздаче» в списке
  «Добавить типовой шаблон»; проходит схему; ответы в норме — 100 % и без нарушений;
  значения вне нормы — нарушения с требованием комментария.
- AC6. Старт проверки по такому шаблону подтягивает блюда (справочник + бракераж
  сегодня), предзаполняет «Как подаётся» по справочнику; в черновике кнопка
  «Обновить список блюд» добавляет новые блюда, ответы сохраняются.
- AC7. В форме проверки число вне нормы подсвечивается сразу («Вне нормы»).
- AC8. PDF проверки показывает каждое блюдо, оба замера и отметку нарушения.
- AC9. Тексты UI в ru/en/uz, типы i18n обновлены; тесты рядом с изменениями и
  typecheck проходят; экран проверен на 1440 и 390.
