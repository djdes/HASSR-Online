# Ускорение деплоя (2026-10-01)

## Проблема

Деплой (push в master → новый код на wesetup.ru) идёт 13–15 минут;
8 сентября было ~7.5. Замер прогона 36856042048 (f5ce3d4f), 899 с:

| Шаг | Сек | Причина |
|---|---|---|
| Install + prisma (CI) | 49 | |
| Type-check | 95 | последовательно перед тестами |
| Tests (baseline gate) | 268 | 415 файлов (было 102), каждый — отдельный процесс с tsx; на 4 ядрах раннера — по 3 за раз; ждёт конца type-check |
| Upload | 38 | ждёт гейт, хотя сам ничего не меняет |
| Server: setup | 24 | |
| Server: build | 274 | рост проекта; type-check в сборке уже выключен |
| Server: db push + seeds + restart | 136 | 8 сидов не закрывают `pg.Pool` → процесс ждёт idle-таймаут 10 с |

Прогон тестов в одном процессе (`--test-isolation=none`) отвергнут: 14 тестов
падают — тесты рассчитаны на свежий процесс на файл (глобальный `window`,
мок `db` через `globalThis`). Шардирование сохраняет изоляцию.

## Критерии приёмки

- **AC1.** Сиды, которые ждали 10 с, закрывают пул (`await pool.end()`)
  так же, как уже делают быстрые.
- **AC2.** `scripts/test-with-baseline.sh` при `TEST_SHARD=i/N` гоняет
  только i-ю часть файлов; без переменной — как раньше (pre-commit не меняется).
  Объединение шардов 1..4 = весь набор тестов.
- **AC3.** В `deploy.yml` type-check, тесты (4 шарда) и выгрузка архива
  идут параллельными job'ами; шаги на сервере стартуют, только когда
  type-check и все шарды зелёные. Сервер до зелёного гейта не трогается
  (выгрузка лишь кладёт `deploy.tar` и копию `.env`).
- **AC4.** Уведомление в Telegram о падении срабатывает при падении любого
  job'а, включая type-check и тесты.
- **AC5.** Реальный деплой после правки зелёный и заметно короче
  (цель — ≤ 10 минут против 13–15).
