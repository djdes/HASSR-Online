# Plan — billing-cutover-2026-09

Spec: `spec.md` (frozen). Ветка `feat/billing-2026-09-28` (от origin/master bc243840). Схема БД не меняется.

## Решения до кода
- **Состояние аккаунта — чистая функция** (`src/lib/billing-period.ts`): вход — настройки периода, тариф
  аккаунта, `subscriptionEnd` (max по аккаунту и его организациям), число активных; выход — `paid | legacy |
  free_period | free | needs_decision | exempt`, грейс, лимит мест, платные возможности. Маркер «решения» не
  нужен: после «бесплатного» / автоперехода активных ≤ 1 → `free`; после оплаты `subscriptionEnd` в будущем → `paid`.
- **«Реально оплачено»** = `subscriptionEnd > now` (оплата Робокассой / счёт / ROOT), не пауза. `paid` + `null` —
  тестовый автоперевод. Причина окна: «Бесплатный период подписки закончился», а «Подписка закончилась» — только
  если оплаченный срок кончился позже конца бесплатного периода. Грейс = max(конец периода, конец оплаты) + N дней.
- **Настройки** — `PlatformSetting["billing.free-period"]` (JSON): начало 2026-10-01 00:00 МСК, конец 2026-10-11
  00:00 МСК, грейс 7 дней, «Переход на оплату включён» = да. Флаг выключен → после периода всё как раньше.
- **BILLING_TEST_MODE не трогаем.** Переходом управляют даты и флаг; надписи «тестовый режим, оплата не
  списывается» показываем только до конца периода (после — это была бы неправда).
- **Оплата**: `fulfillPaidOrder` продлевает и аккаунт (тариф живёт там; иначе после перехода на бесплатный оплата
  оставляла бы аккаунт «Бесплатным»). Робокассу/env не трогаем.
- **Лимит**: одна проверка `checkSeatsForActivation(orgId, n)` до создания/активации на всех путях (список ниже);
  комиссия и демо/мастер-кабинет не считаются. Ответ 402 + `code: "billing_free_limit"` + ссылка на оплату.
- **Переход на бесплатный** (руководитель / грейс / тихий ≤ 1): одна функция в транзакции с advisory-lock аккаунта:
  остальные → `isActive=false, archivedAt, sessionVersion+1`, тариф `free` (аккаунт + зеркала, пауза не
  снимается), аудит в каждую затронутую организацию, Telegram владельцу (+ письмо при автопереходе).
- **Возврат из архива**: на `/settings/users` блока «Архив» нет (есть только снятие увольнения) — добавить короткий
  список архивных с «Вернуть» (DELETE `/api/staff/[id]/archive` с проверкой лимита). Без этого обещание «вернуть
  после оплаты» было бы неправдой.
- **Окно**: сайт и оболочка Mini App, только `hasFullWorkspaceAccess` и не ROOT-«войти как» / не партнёр; на
  `/settings/subscription` вместо окна — карточка решения. В приложении WeSetup (правила сторов) — без кнопки
  оплаты и не блокирует. Поварам — тонкая плашка «Руководитель выбирает тариф».
- **Ежедневная задача** `/api/cron/billing-transition` (CRON_SECRET, `?dryRun=1`): тихий `free` для ≤ 1 (одно
  уведомление), одно предупреждение «выберите до …» для > 1, автопереход по истечении грейса.

## Пути создания/активации (проверка до записи)

/api/join/[token]; /api/users/invite; /api/users/invite/tg; DELETE /api/staff/[id]/archive;
DELETE /api/staff/schedules/dismissals/[id]; PUT /api/users/[id] (isActive→true); POST /api/staff/[id]/credentials
(пароль активирует); POST /api/invite/[token]/accept; бот `/start inv_…`. Неактивные заготовки (TasksFlow,
онбординг, партнёр) проверяются при активации.
