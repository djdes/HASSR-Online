## Сделать — тип «КП»
Шаблон, компонент полей `src/components/mailing/fields/kp.tsx`, регистрация в `kinds/index.ts`.

**Payload:**
```ts
{
  defaultSphere: OrgSphere;          // для получателей без сферы; по умолчанию "restaurant"
  promo: {
    mode: "none" | "existing" | "personal";
    code?: string | null;            // для existing — код из «Промокодов»
    kind: "percent" | "fixed"; value: number;  // для personal; по умолчанию percent 10
    lifetime: boolean;               // по умолчанию true
    validDays: number;               // срок кода в днях, по умолчанию 14; конец — 23:59 МСК последнего дня
  };
  attachPdf: boolean;                // по умолчанию false — вложения повышают риск спама, в письме и так есть «Скачать PDF»
}
```

**Поведение по полям:**
- `validate`:
  - `existing` — код существует и действует (`readPromoForOffer` ≠ null);
  - `personal` — value 1–100 для процента, срок 1–90 дней.
- `prepare` (один раз при старте, идемпотентно по id получателя: уже есть код в payload получателя — не создавать заново):
  - `personal`:
    - получатели-пользователи (есть `organizationId`) → код привязан к организации (`{ key: recipient.id, email: null, organizationId, companyName }`);
    - загруженные контакты → `{ key, email, companyName, unlocked: true }`;
    - `options`: `{ kind, value, lifetime, endsAt, note: "Рассылка «<название>»", campaignId }`;
    - вернуть `{ [recipientId]: { promoCode } }`.
  - `existing` — один код всем, через payload.
- `render`:
  - сфера — `ctx.sphere ?? payload.defaultSphere`;
  - компания и имя — из ctx;
  - промокод — из `ctx.personal.promoCode` (для personal) или payload (для existing), с параметрами из payload/`readPromoForOffer`. Кэшируй на время рассылки, чтобы не читать базу на каждое письмо;
  - письмо — `renderProposalEmail(vars, { webUrl: proposalWebUrl(vars), unsubscribeUrl: ctx.unsubscribeUrl, trackUrl: ctx.trackUrl })`;
  - `attachPdf` → вложение `КП WeSetup — <компания или сфера>.pdf`.
  - Колокольчик, push и Telegram — коротко и честно, со ссылкой на веб-версию через `trackUrl`:
    - заголовок «Предложение WeSetup для вашей команды»;
    - текст «Команда до 10 сотрудников — <цена> ₽/мес со скидкой <N %> <навсегда | до даты> по промокоду <CODE>. Бесплатно — все журналы для 1 сотрудника».
- **Предпросмотр и тест себе** (там `prepare` не вызывается): для personal показать пример кода `suggestPersonalCode(company, value)` с пометкой «пример — настоящий код создастся при отправке».
- **Поля формы:**
  - сфера по умолчанию, с подсказкой «каждый получит КП своей сферы: пользователи — по организации, контакты — по колонке «сфера»»;
  - промокод — радио «без промокода / выбрать код / персональные коды» с полями;
  - галочка «Вложить PDF»;
  - ссылка «Отправитель и реквизиты — ROOT → Коммерческие предложения».

**Генератор КП** (`/root/proposals`) — маленькая добавка: кнопка «Создать персональный код для этой компании»:
- `unlocked`, процент, «навсегда», срок — как в полях выше;
- `createPersonalPromoCodes`, аудит;
- созданный код сразу подставляется в форму и в PDF.

## Уточнения исполнителя (решения по неоднозначным местам)

1. **Срок персонального кода.** `validDays = N` — код действует N дней после создания: конец — 23:59:59 по Москве
   дня «сегодня (МСК) + N». Создан 29.09, N = 14 → действует до 13.10 включительно. Так даже при N = 1 у получателя
   есть целые сутки. Одна функция на рассылку и генератор КП — `promoEndsAfterDays(now, days)` в `src/lib/promo/valid-days.ts`.
2. **Идемпотентность `prepare`.** Шаблон получает у каждого получателя его текущие персональные данные
   (`recipient.personal`); у кого `promoCode` уже есть — код не создаётся. Коды создаются одной транзакцией
   (`createPersonalPromoCodes` — все или ни одного). Коды получают только получатели, которым есть что отправлять
   (статус «в очереди»): отписавшимся и адресам из стоп-листа коды не нужны.
3. **Персональные данные получателя:** `{ promoCode, promoEndsAt }` — срок сохраняется, чтобы письмо, ушедшее через
   сутки (лимит 300 писем в сутки), показывало тот же срок, что у кода в базе, без чтения базы на каждое письмо.
4. **Расширения точки расширения (обратно совместимы):**
   - `validate` может быть асинхронной (`existing` проверяет код в базе);
   - `prepare(campaign: { id, title, payload }, recipients)` — у кампании есть название (для заметки «Рассылка «…»»),
     у получателя — `personal` (для идемпотентности);
   - `MailingRecipientContext.mode: "live" | "test" | "preview"` — шаблон отличает настоящую отправку от предпросмотра
     и теста себе (там `prepare` не вызывается);
   - `RenderedMailing.notes?: string[]` — пометки для ROOT: показываются в предпросмотре, в результате «теста себе» и
     плашкой вверху тестового письма; настоящим получателям не уходят.
5. **Нет персонального кода при настоящей отправке** (подготовка не дошла) — письмо не уходит с «примером», получатель
   помечается ошибкой «нет персонального промокода». 
6. **`existing`:** код должен действовать (`readPromoForOffer` ≠ null) и быть общим — персональный код (с почтой или
   организацией) сработает только у одного клиента, `validate` его не пропускает. Код перестал действовать уже после
   запуска — КП уходит без промокода (честные цены), в логе `[mailing] kp …` предупреждение.
7. **«Навсегда» + срок кода.** У персонального кода «навсегда» есть срок активации (14 дней). Чтобы не обещать скидку
   по коду, который через две недели не примут, КП (письмо, PDF, веб-версия, генератор) пишет в пояснениях
   «Промокод X действует до D: при оплате до этого дня скидка остаётся навсегда», а колокольчик, push и Telegram —
   «… по промокоду X (код действует до D)». Проверка «КП на одном листе» дополнена этим случаем.
8. **Тексты каналов** — из того же расчёта, что и КП (`buildProposalContent`): заголовок «Предложение WeSetup для
   вашей команды», текст «Команда до 10 сотрудников — <цена>/мес со скидкой <N %> <навсегда | до даты> по промокоду
   <CODE>. Бесплатно — все <N> журналов для 1 сотрудника.» (строки предложения КП дословно, число журналов — из констант).
9. **Вложение PDF:** имя «КП WeSetup — <компания или сфера>.pdf», символы, запрещённые в именах файлов, заменяются.
10. **Генератор КП:** кнопка «Создать персональный код для этой компании» — `unlocked`, процент, «навсегда»; размер
    скидки и срок — два маленьких поля рядом (по умолчанию 10 % и 14 дней, как в рассылке). Нужна компания (из неё
    основа кода и заметка «Генератор КП · <компания>»). Аудит — `promo.create` (как у «Промокодов») с `source: kp-generator`.
11. **Тип по умолчанию.** Новый черновик «КП»: сфера «Ресторан», персональные коды 10 % навсегда на 14 дней, без PDF.
12. **Ограничение, не трогаем:** веб-push на устройствах Mini App открывает `/mini` (так устроен `public/mini-sw.js`
    для любых ссылок) — КП открывается из письма, колокольчика и Telegram.
