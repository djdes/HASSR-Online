# Spec (frozen 2026-09-25): блок «Посоветуете WeSetup коллегам?» — шкала 1–5, рекомендация коллеге по почте

Правка владельца: «Блок "порекомендуете" — текста поменьше, чтобы в 1 строку уместилось. Давай сделаем 5-балльную шкалу в одну строку. И если выбирают выше 3 — сразу поле ввода почты и текстовое поле произвольный текст, и отправку рекомендации с этим текстом».

Сейчас: `src/components/layout/nps-banner.tsx` (показ решает сервер: `src/lib/nps-data.ts`, `src/lib/nps.ts`), `POST /api/nps` (`src/app/api/nps/route.ts`), модель `NpsResponse { score 0–10, comment }`, отчёт `/root/nps` (`src/app/root/nps/page.tsx`).

## 1. Вопрос и шкала
- Заголовок в одну строку на 390 px, например «Посоветуете WeSetup коллегам?»; подпись убрать или сократить до нескольких слов.
- Шкала 1–5 в одну строку, крупные кнопки (≥ 44–48 px), подписи краёв можно одним словом («нет» … «да») или без них.

## 2. Хранение
- Разрешено одно добавление в схему: `NpsResponse.scale Int @default(10)` (старые ответы остаются 0–10, новые пишутся со `scale = 5`). Порядок, чтобы не сломать соседние копии, которые используют тот же node_modules: сначала `prisma db push` в КАЖДУЮ локальную базу копий — `wesetup_wt_ui`, `wesetup_wt_pdf`, `wesetup_wt_qrforms`, `wesetup_wt_blanks` (строка подключения — как в `.env` этой копии, меняется только имя базы), и только потом `prisma generate`. Больше схему не трогать.
- `/root/nps`: считать по обеим шкалам. Для 1–5: 5 — промоутер, 4 — нейтральный, 1–3 — критик; для 0–10 — как сейчас. Показать распределение по каждой шкале отдельно и общий NPS.
- API принимает `{ score, scale: 5, ... }`; старый формат (0–10 без `scale`) продолжает работать.

## 3. Оценка 4–5 → рекомендация коллеге
- Сразу под шкалой (без перехода): поле «Почта коллеги», поле «Сообщение» с разумным текстом по умолчанию, который можно поправить (например: «Привет! Мы ведём журналы ХАССП и СанПиН в WeSetup — заполняем с телефона по QR, проверки проходим спокойно. Посмотри: …»), кнопка «Отправить». Можно не заполнять почту и просто закрыть — оценка уже сохранена.
- Письмо коллеге — через существующую почту (`src/lib/email.ts`, новая функция рядом с остальными `send*Email`): от сервиса, в теме и тексте — имя и организация рекомендующего, его текст (экранированный), ссылка на регистрацию. Если у организации есть реферальный код (`src/lib/balance/referral.ts`, клиентская программа «порекомендуй другу») — ссылка реферальная, чтобы бонус начислился; иначе — обычная ссылка на регистрацию. Reply-To — почта рекомендующего.
- Ограничения: валидация почты; не на свою почту и не на почту сотрудников своей организации; не больше 5 рекомендаций в сутки на пользователя (и разумный лимит на организацию); текст ≤ 1000 символов; `AuditLog` о каждой отправке (кому, без текста письма целиком). Понятные сообщения об ошибках.
- После отправки — «Спасибо! Письмо отправлено» и блок скрывается, как сейчас после ответа.

## 4. Оценка 1–3 → «Что улучшить?»
- Под шкалой поле «Что улучшить?» и «Отправить» — сохраняется в `comment` этого ответа (как сейчас комментарий), плюс уходит туда же, куда сейчас уходят отзывы/комментарии NPS (найти; если никуда — только сохранение).

## Не делать
- Не трогать шапку кабинета, общие компоненты `src/components/ui/*` и мини-приложение `src/app/mini/*` — ими параллельно занимаются другие.
- Не менять правила, когда показывать блок (раз в квартал и т. п.), кроме нужного для новой шкалы.
- Не править whats-new/CHANGES; не писать в `D:/www/Wesetup.ru`; не пушить. Реальные письма не отправлять (в копиях SMTP пуст — письмо проверять через лог/тестовый транспорт).

## Критерии приёмки
- AC1: на 390 px заголовок в одну строку, шкала 1–5 в одну строку (скриншоты 390 и 1440).
- AC2: 4–5 → поля почты и сообщения, отправка создаёт письмо коллеге с текстом пользователя и (реферальной) ссылкой; лимиты и запрет своей почты работают; `AuditLog` (e2e на своей базе).
- AC3: 1–3 → «Что улучшить?», комментарий сохранён.
- AC4: `/root/nps` считает обе шкалы; старые ответы 0–10 не сломаны (тест).
- AC5: typecheck и `npm test` зелёные.
