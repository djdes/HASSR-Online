## Что сделано
- **Схема**: `NpsResponse.scale Int @default(10)` — единственное изменение. Порядок: правка схемы →
  `prisma db push` в `wesetup_wt_ui`, `wesetup_wt_pdf`, `wesetup_wt_qrforms`, `wesetup_wt_blanks` → `prisma generate`
  (`raw/schema-push.log`). `db push` в каждой базе заодно снимал частичный индекс
  `PartnerClient_one_active_per_org` (Prisma его не описывает, приложение создаёт лениво в
  `src/lib/partners/schema-extras.ts`) — сразу после push он восстановлен тем же SQL (`CREATE UNIQUE INDEX IF NOT
  EXISTS …`), итог в каждой базе: колонка `scale integer NOT NULL DEFAULT 10` + индекс на месте (проверка в том же логе).
- **Правила и расчёт** — `src/lib/nps.ts` (client-safe): шкалы 5/10, `npsCategory` (1–5: 5 промоутер, 4 нейтральный,
  1–3 критик; 0–10 как раньше), `computeNpsReport` (общий NPS + по каждой шкале со средней и распределением),
  `computeNps` для старых вызовов без изменений, разбор тел `POST`/`PATCH /api/nps`, лимиты опроса, текст по умолчанию,
  константы AuditLog `nps.recommend`.
- **API** `src/app/api/nps/route.ts`: `POST { score, scale: 5 }` — новый ответ (в ответе `id`), `POST { score, comment? }`
  без `scale` — старый формат 0–10 как раньше, `POST { dismiss: true }` — «не сейчас»; новый `PATCH { id, score?, comment? }`
  — свой ответ в течение суток (смена оценки 4→5, «Что улучшить?»).
- **Приглашение коллеги — одна функция** `inviteColleague` (`src/lib/balance/invite-colleague.ts`, по просьбе
  оркестратора вместо параллельной реализации). Ею пользуются оба входа: `POST /api/balance/referrals`
  (source `balance`) и `POST /api/nps/recommend` (source `nps`). Общее ядро — то, что было в маршруте баланса:
  адрес уже зарегистрирован → 409, MX-проверка домена, ≤ 20 приглашений в сутки на организацию, один адрес — раз в
  сутки, `ensureReferralCode` (ссылка **всегда** реферальная), одно письмо, запись `ReferralInvite` после отправки
  (рекомендация из опроса видна в «Баланс и бонусы» со статусом). Новое для обоих: проверка лимитов, отправка и
  запись — под advisory-замком организации (`withAdvisoryTryLock`, ключ `referral-invite:<org>`), чтобы параллельные
  запросы не проходили лимит; снаружи это не видно. Добавки опроса поверх ядра: только после своей оценки 4–5 по
  шкале 1–5 (`src/lib/nps-recommend.ts`), текст ≤ 1000 символов (у формы баланса — 500, как было), своя почта — и
  логин, и контактная, запрет почты сотрудников/участников своей организации, ≤ 5 рекомендаций в сутки на человека,
  AuditLog `nps.recommend` (сущность `NpsResponse`, детали `{ colleagueEmail, npsScore, delivery }` — без текста письма),
  понятные ошибки с полем (`field`).
- **Форма «Баланс и бонусы» — прежнее поведение**: те же проверки и порядок, те же тексты ошибок и коды
  (400 «Укажите корректный адрес электронной почты» — и для сообщения длиннее 500, 400 «Это ваш собственный адрес»,
  409 «…бонуса не будет», 400 «Такого почтового домена не существует…», 429 «Не больше 20 приглашений…», 429 «На этот
  адрес уже отправляли приглашение сегодня», 502 «Письмо не ушло…»), тот же ответ `{ ok, invites }`. Отличия: к
  ошибкам про адрес добавлено поле `field: "email"` (клиент его не читает); письмо — общее, с Reply-To и
  `?email=` в ссылке; в dev без SMTP приглашение теперь «уходит в лог» и записывается (раньше — 502), на проде без изменений.
- **Одно письмо** — `buildReferralInviteEmail` / `sendReferralInviteEmail` в `src/lib/balance/emails.ts` (лучшее из
  двух шаблонов): от WeSetup (`SMTP_FROM`), в теме и тексте — имя и организация пригласившего («Денис Управляющий из
  «…» рекомендует WeSetup — электронные журналы СанПиН»; имя-заглушку не пишем — «Коллега из «…»»), личный текст
  экранирован (`escapeHtml`, `pre-wrap`) с подписью, про бонус рекомендателю, кнопка и ссылка `/r/<код>?email=…`
  (почта подставится в регистрацию), Reply-To — контактная почта или логин пригласившего (служебные `*.local`
  пропускаются). Отправка — через `src/lib/email.ts`: `sendRawEmail` получил `replyTo`, транспорт — тоже; в dev
  письмо целиком пишется в лог вместе с Reply-To; `isEmailDeliveryConfigured()` отличает «записано в лог» от сбоя.
  Дубль шаблона из первого коммита (`buildColleagueRecommendationEmail` в `email.ts`) удалён.
- **Блок** `src/components/layout/nps-banner.tsx` (и сайт, и Mini App): «Посоветуете WeSetup коллегам?» в одну строку,
  подпись убрана, шкала 1–5 кнопками 48 px в одну строку с краями «нет»/«да»; оценка сохраняется по клику;
  4–5 — «Почта коллеги», «Сообщение» (текст по умолчанию, можно править), «Отправить», подсказка «Письмо придёт от
  WeSetup с вашим именем…»; 1–3 — «Что улучшить?» + «Отправить» (сохраняется в `comment` этого ответа). После отправки —
  «Спасибо! Письмо отправлено» / «Спасибо! Учтём», блок скрывается. Крестик до оценки — «не сейчас», после — просто
  закрыть (оценка уже сохранена). В `(dashboard)/layout.tsx` блок теперь всегда в дереве (`<NpsBanner ask={askNps} />`):
  после оценки `askNps` становится false, а дашборд делает `router.refresh()` по живым событиям — без этого форма
  пропадала посреди ввода (поймано e2e). Правила показа (`askNpsFor`) не менялись.
- **Куда уходят комментарии NPS**: поиск (`grep -ri nps src`) — только `NpsResponse.comment` и список на `/root/nps`,
  уведомлений нет → «Что улучшить?» только сохраняется, как и раньше.
- **`/root/nps` и `GET /api/root/nps`**: общий NPS по обеим шкалам + отдельно «Шкала 1–5» и «Шкала 0–10 (ответы до
  сентября 2026)» — NPS, средняя, распределение столбиками по каждой оценке; в списке ответов — «5 из 5» / «9 из 10» и
  пометка «письмо коллеге». В JSON `last90`/`allTime` сохранили форму (`NpsSummary`), добавлены `byScale` и `scale` у ответов.
- **Журнал действий**: подписи «Рекомендация WeSetup коллеге», «Почта коллеги», «Оценка», «Доставка».
