## Критерии приёмки

### AC1. Шаблоны `/checklists/templates`
1. Guard — `hasJournalAccess(` к журналу чек-листов (как `/checklists`); пункт `access: CHECKLISTS_FACT`.
2. Блок «Типовые чек-листы»: 6 шаблонов из API (название, разделов/вопросов, критичных, «уже добавлен»); «Добавить в организацию» (при праве на создание шаблонов) → `POST …/typical`; после добавления — «Открыть в конструкторе» / «Начать проверку».
3. Блок «Шаблоны организации»: шаблоны организации (не архив) — «Начать проверку», «Изменить в конструкторе», «Назначить» (руководителю, ведёт в «Назначение» с выбранным шаблоном).
4. Блок «Назначено вам» (если у человека есть назначения на текущий период): шаблон, срок, статус, «Начать проверку» — проверка создаётся с привязкой к назначению.

### AC2. Модель назначения (аддитивно)
1. Prisma: новая модель `ChecklistAssignment` — организация, шаблон, кому (`targetKind`: точка / должность / человек, `targetId`), периодичность (`once` с датой / `daily` / `weekly` с днём недели / `monthly` с числом), срок (время ЧЧ:ММ по часовому поясу организации), кто проверяет результат (`verifierUserId?`), напоминать в Telegram (да/нет), активно/пауза, кто создал, даты, отметка последнего напоминания по периоду. `ChecklistInspection` получает необязательные `assignmentId`, `reviewedAt`, `reviewedById`, `reviewedByName`. Только добавления; `prisma db push` на своей базе без потерь данных.
2. Чистые функции с тестами: текущий период назначения и его ключ, срок периода, статус «ожидает / выполнено / просрочено / не в этот день», кто входит в «кому» (люди точки / должности / человек, только активные).
3. API (guard `admin.full` на изменение, чтение — руководству): `GET/POST /api/checklists/assignments`, `PATCH/DELETE /api/checklists/assignments/[id]`; zod-проверка, организация из сессии, чужие id — 404; запись в журнал действий.
4. Без TasksFlow: никаких задач и вызовов TF API (П-12, П-13 не затрагиваются).

### AC3. Назначение `/checklists/assignments`
1. Guard — `"admin.full"`; пункт `access: ADMIN` («блок администрации», решение раздела 7).
2. Список назначений: шаблон, кому, периодичность и срок, кто проверяет, статус текущего периода, кнопки «Изменить», «Пауза/Включить», «Удалить» (`ConfirmDialog`).
3. Окно «Назначить чек-лист» по шагам: шаблон → кому (точка / должность / человек — групповой выбор как `UserPicker`) → как часто и до скольки → кто проверяет (рекомендуем: руководитель/заведующая) → напоминать в Telegram. Под формой живая подсказка: «Получат: N человек; напоминание придёт …».
4. Предупреждение, если у кого-то из получателей нет доступа к чек-листам или не привязан Telegram (сколько и кто), со ссылкой туда, где это исправить.

### AC4. Напоминания в Telegram
1. Маршрут `/api/cron/checklist-reminders` (`checkCronSecret`, `?dryRun=1`), расписание в комментарии (crontab сервера — строку добавляет S3 с согласия владельца при выкладке).
2. В день срока шлёт каждому получателю с привязанным Telegram одно напоминание на период (повтор вызова не дублирует), с кнопкой открыть чек-лист в Mini App; выполненные — не напоминает.
3. Завершение проверки по назначению — уведомление проверяющему (кто проверяет результат) со ссылкой на результат.
4. Тесты: отбор получателей и дедупликация по периоду (чистая функция); маршрут без секрета — 401.

### AC5. Результаты `/checklists/results`
1. Guard — `hasJournalAccess(` (как `/checklists`). История проверок (вынести из конструктора, в конструкторе — ссылка «Все результаты»): дата, шаблон, кто проводил, балл/нарушения/критическая остановка, статус, назначение (если было), «Открыть», PDF — существующими маршрутами.
2. Фильтры: шаблон, период, только с нарушениями; пустое состояние.
3. «Принять результат» для проверяющего по назначению (или руководителя) → `reviewedAt/By`; отметка в списке.

### AC6. Меню и права
1. `menuShape("checklists")` = `[[null, ["templates","builder","assignments","results"]]]`; подписи RU/EN/UZ; иконки; тесты на корень раздела обновлены.
2. Повар с доступом к чек-листам видит Шаблоны, Конструктор, Результаты, но не Назначение; без доступа — раздела нет.
3. Тесты `app-nav.test.ts` и соседние — зелёные.
