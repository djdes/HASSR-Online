# Spec: автоворонка CRM — письма клиенту, задачи менеджеру, воронка сделок, спец-КП со скидкой

Задача владельца (2026-11-09):

1. Бизнес-логика рассылок, оповещений и задач CRM по лидам и оплатам. Пример: зарегистрировался → пробный → ведёт
   журналы → за 4 дня до конца письмо «что отключится по вашим данным» + предложение продлить со ссылками и счётом
   в письме → не оплатил → задача в CRM у Алексея (прозвон или мессенджер, предложить спец-КП со скидкой по тому,
   как ведётся аккаунт; 100+ человек — супер-скидка на согласовании) → то же за 2 дня (заранее: выходные и
   согласование у директора клиента, B2B) → оплатил и подходит срок → «оплачивать лучше заранее» → не оплатил →
   что пишем клиенту и какой таск Алексею. Продумать по максимуму и эмулировать разные ситуации.
2. Воронка продаж в CRM, колонки: «Зарегистрировался, не подписали договор», «Подписали договор, не оплатили»,
   «Сообщение отправлено», «Был прозвон»; в каждой карточке — переписка (лента контакта из прошлой задачи).
3. Протестировать воронку в разных сценариях и доработать — самостоятельно и агентами Opus.

Frozen: 2026-11-09. Ветка `claude/peaceful-brown-tgkspp` от master `9bd55f4`.

## Модель

### Сделка `CrmDeal` — карточка воронки
Одна на «период решения» аккаунта биллинга: `trial` (пробный → первая оплата) или `renewal` (оплаченный срок →
продление). Ключ `dedupeKey` = `trial:<unit>` / `renewal:<unit>:<день конца срока>`.
Поля: вид, единица биллинга, домашняя организация, контакт CRM владельца, ответственный, колонка, ручная колонка
(флаг), конец периода, рекомендация (тариф, период, точки, скидка, сумма), отметки «договор подписан»,
«сообщение», «прозвон», счёт, «оплачено» / «отказ» с причиной.

Колонки (`stage`), слева направо:
| ключ | колонка | как попадает автоматически |
|---|---|---|
| `registered` | Зарегистрировался, договор не подписан | новая сделка (продление — «Скоро оплата») |
| `contract_signed` | Договор подписан, не оплачено | договор подписан в ЭДО (Saby, код 7) или отмечен руками |
| `message_sent` | Сообщение отправлено | ушло письмо автоворонки, КП или письмо менеджера |
| `called` | Был прозвон | задача «позвонить/написать» закрыта с результатом «дозвонился»/«написал», звонок в ленте |
| `won` | Оплачено | аккаунт оплатил (для продления — срок ушёл дальше конца периода) |
| `lost` | Отказ / бесплатный | ушёл на бесплатный после грейса, или менеджер отметил отказ |

Автодвижение только вперёд (`registered` < `contract_signed` < `message_sent` < `called`); `won`/`lost` —
по событию. Ручной перенос фиксирует колонку: автоматика дальше её не двигает, кроме `won`/`lost`.
Оплата после `lost` возвращает сделку в `won`.

### Задача `CrmTask`
Кому (ответственный), что (звонок / мессенджер / спец-КП / согласование скидки / счёт / своя), срок, контекст и
рекомендация текстом, сценарий, `dedupeKey` (уникальный), итог (код + комментарий), кто и когда закрыл.
Итоги: «Дозвонился», «Не дозвонился», «Написал в мессенджер», «Отправил КП», «Обещали оплатить»,
«Отказ», «Согласовано»/«Отклонено» (согласование); авто — «Оплачено», «Заменена новой», «Неактуально».

### Лимит скидки роли `PlatformRole.discountLimit`
Сколько процентов человек роли даёт без согласования. Владелец платформы (ROOT) — без ограничения.
Встроенные: коммерческий директор 25, РОП 15, менеджер по продажам 10, остальные 0. Правится в редакторе ролей.

### Настройки `PlatformSetting` `crm:lifecycle`
Включено (всё), письма клиентам, счёт во вложении, период счёта (год/месяц), ступени пробного [4, 2], продления
(год [30, 14, 4, 2, 1], месяц [7, 4, 2, 1]), лестница скидок (по сотрудникам: 100+ → 25 %, 30+ → 15 %,
10+ → 10 %), ответственный по умолчанию. Страница «Автоматизация» с переключателями и прогнозом на 7 дней.

## Сценарии (автоворонка)

Срок ступени «за N дней» — московский день (конец − N дней); выходной → предыдущий рабочий день (сб, вс и
праздники РФ из списка). Письма клиенту — с 10:00 МСК рабочего дня ступени, задачи — со сроком в этот день 11:00.
Пропущенные ступени не догоняются пачкой: срабатывает только последняя наступившая. Каждое действие —
один раз (уникальный ключ), повторный прогон ничего не дублирует.

Сегмент аккаунта по данным:
- **один** — в пределах бесплатного (≤ 1 сотрудника и ≤ 1 журнала): ничего не потеряет;
- **не начал** — нет записей в журналах за 14 дней;
- **работает** — остальное. Рекомендация: «Премиум», если сотрудников больше места «Стандарта» (25 на точку)
  или подключены датчики, иначе «Стандарт»; точки — в работе; скидка — по лестнице (только «работает»);
  согласование — если скидка больше лимита ответственного.

| Когда | Клиенту | Задача ответственному |
|---|---|---|
| Регистрация | — (welcome-цепочка уже есть) | сделка «Зарегистрировался»; с телефоном — «Познакомиться» на следующий рабочий день |
| 4-й день пробного, «не начал» | — | «Не начали работать: помочь запустить» |
| Пробный −4 | письмо (+Telegram): что отключится по их данным, рекомендованный тариф и цена, счёт PDF во вложении (если есть ИНН; есть неоплаченный — прикладываем его), «оплатить картой», «другой тариф», подпись менеджера, ответ — менеджеру; «один» — короткое «останется бесплатный» без счёта; «не начал» — «продлим пробный, ответьте» без счёта | «работает»: позвонить/написать, предложить спец-КП со скидкой X % (или согласовать); «не начал»: узнать, продлить пробный |
| Пробный −2 | короткое напоминание, тот же счёт | «работает»: повторный контакт, прошлая открытая задача — «Заменена новой» |
| Пробный кончился (грейс) | (биллинг: «выберите тариф до …») | «Не оплатили, грейс до …: последний шанс» |
| Конец грейса −2 | «через 2 дня в архив уйдут N сотрудников, выключатся M журналов» + счёт | «Срочно: послезавтра отключение» |
| Автопереход на бесплатный | (биллинг: уведомление) | сделка «Отказ»; через 3 рабочих дня «Вернуть: узнать причину, предложить условия» |
| Продление −30 / −7 (год / месяц) | «оплатите заранее: бухгалтерии нужно время» + счёт на продление | — |
| Продление −14 (год) | напоминание + счёт | — |
| Продление −4, −2 | напоминание + счёт | позвонить; помесячным — предложить год |
| Продление −1 | «завтра последний день» (+Telegram) | — |
| Срок кончился (грейс) | как у пробного | как у пробного |
| Счёт выставлен клиентом, не оплачен 2 рабочих дня | — | «Счёт № … не оплачен: уточнить у бухгалтерии» |
| Счёт просрочен | — | «Счёт истёк: выставить новый» |
| Начал оплату картой и бросил (2–72 ч) | (письмо о брошенном заказе уже есть) | «Не завершил оплату: помочь» |
| Оплата | (чек и письмо уже есть) | сделка «Оплачено», открытые задачи — «Оплачено», ответственному — сообщение |

Когда автоворонка включена, ежедневная задача биллинга не шлёт свои напоминания «пробный за 3 дня» и
«оплата за 7/3/1 день» — их заменяет автоворонка (иначе клиент получит два письма). Переход на бесплатный,
«выберите тариф до …» и уведомление об автопереходе остаются у биллинга.

Оповещения ответственному: новые задачи — сообщением (Telegram, без него — почта) после прогона;
в 9:00 — «задачи на сегодня и просрочено»; задача просрочена на рабочий день — эскалация РОП.

## Спец-КП и согласование скидки
Из задачи или сделки: «Отправить КП со скидкой» — тариф, период, точки, скидка, срок кода, счёт во вложении,
кому. Скидка ≤ лимита — сразу: персональный код на организацию (одно использование, до конца срока), КП с
кодом от имени менеджера (его подпись и должность) + счёт со скидкой (если есть ИНН), запись в ленте, сделка
«Сообщение отправлено». Больше лимита — задача «Согласовать скидку X %» тому, чей лимит покрывает
(коммерческий директор, иначе владелец), с расчётом суммы; «Согласовать» (можно поправить %) → менеджеру
задача «Скидка согласована: отправить КП» с кнопкой отправки; «Отклонить» → задача закрыта с комментарием.

## Экраны
- `/root/crm/funnel` — воронка-канбан: колонки выше, карточка (организация, ответственный, сотрудники/точки,
  до какого числа, сумма, значки «договор», «счёт», «письмо», «звонок», «скидка на согласовании», ближайшая
  задача), перетаскивание и выбор колонки, фильтры: вид (новые / продления), ответственный, «закрываются за 7 дней».
  Клик — переписка (карточка контакта) с панелью сделки.
- `/root/crm/tasks` — задачи: просрочено / сегодня / завтра / позже; мои / все (РОП); закрыть с итогом,
  перенести, переназначить, своя задача, спец-КП.
- Карточка контакта — панель сделки (колонка, рекомендация, отметки, «договор подписан», отказ) и задачи.
- `/root/crm/automation` — настройки и прогноз «что уйдёт клиентам и какие задачи появятся за 7 дней».
- Сводка CRM — плитки «задачи сегодня / просрочено» и ссылки на воронку и задачи.
- Охват «свои»: менеджер видит свои сделки и задачи (и свободные), чужие — 404.

## Acceptance criteria
- **AC1 Схема.** `CrmDeal`, `CrmTask`, `PlatformRole.discountLimit` — только аддитивно, `apply-safe-schema` пропускает.
- **AC2 Планировщик.** Чистая функция: по снимку аккаунта, истории и времени — действия. Тесты на все строки
  таблицы сценариев, выходные/праздники, догон только последней ступени, сегменты, рекомендацию и скидку,
  повторный прогон без дублей. Скрипт эмуляции печатает ленту по дням для ≥ 8 персонажей.
- **AC3 Письма клиенту.** Персональные данные (сотрудники, журналы, точки, записи, что отключится), тариф и
  цена, счёт PDF во вложении при ИНН (иначе ссылка «указать ИНН»), ссылки оплаты, подпись и Reply-To
  ответственного, Telegram при привязке; запись в ленте CRM; ровно один раз; только в рабочее время;
  биллинг свои напоминания при включённой автоворонке не шлёт.
- **AC4 Задачи.** Создаются с контекстом, рекомендацией и пометкой о согласовании, ответственному
  (менеджер клиента → по умолчанию → РОП); оповещения (новые, 9:00, эскалация); закрытие с итогом пишет
  в ленту и двигает сделку; перенос, переназначение, своя задача; охват «свои».
- **AC5 Спец-КП и согласование.** В пределах лимита — код, КП, счёт со скидкой, лента; сверх — задача
  согласования, согласовать/отклонить, после согласования — отправка.
- **AC6 Воронка.** Колонки как в задаче; автодвижение (договор ЭДО/руками, сообщение, прозвон, оплата,
  отказ), ручной перенос, фильтры, карточка ведёт в переписку.
- **AC7 Автоматизация.** Настройки сохраняются и действуют; прогноз на 7 дней.
- **AC8 Живая проверка.** Локальная БД, прогон автоворонки с переводом времени по персонажам: письма в SMTP-
  ловушке, задачи, канбан, скриншоты; независимая проверка агентами Opus — найденное исправлено.
- **AC9 Проверки.** `npm run typecheck`, `npm run test:gate`, eslint по изменённым файлам.
