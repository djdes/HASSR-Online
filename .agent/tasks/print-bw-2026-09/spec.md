# Spec (frozen 2026-09-27): печатные документы без цвета — только чёрный, белый и серые

Правка владельца: «Выводить не красным выходные, а серым тоже. Глобально надо без цветного в таблицах — у всех
чёрно-белые принтеры». Решения оркестратора (владелец делегировал) — ниже.

## Сделать
- Во ВСЕХ документах, которые сайт выдаёт на печать, — только чёрный, белый и оттенки серого (текст, линии,
  заливки ячеек, подписи, отметки, легенды): печатные журналы PDF (`src/lib/document-pdf.ts`,
  `pdf-journal-table.ts`, `pdf-page-labels.ts`, `pdf.ts`, `paper-journal-pdf.ts`, чек-листы
  `cleaning-ventilation-checklist-pdf.ts`, `sanitary-day-checklist-pdf.ts`), пакет для проверяющего
  (`regulator-bundle.ts`, `/api/inspector/[token]/pdf`), шаблоны Word (`document-docx.ts`), приказы и прочие
  документы для печати (`src/lib/orders/*` — найти поиском, как они рендерятся: DOCX/PDF/HTML), печатные
  HTML-страницы и `@media print` у таблиц журналов. Найти ВСЁ поиском: `setFillColor/setTextColor/setDrawColor`,
  стили autoTable `fillColor/textColor/lineColor`, цвета в DOCX (`color`, `shading`/`fill`, `highlight`), цвета в
  print-CSS. Счета/закрывающие документы (`invoices/pdf.ts`, `closing-documents/pdf.ts`) и сертификаты — тоже
  проверить и перевести на серое, если там цветные таблицы/текст (логотип-картинку не трогать).
- Выходные и праздники — СЕРЫЕ, не розовые/красные: и в PDF (`PDF_DAY_OFF_FILL` и легенда «Выходной или
  праздник»), и на экране в сетке журналов (`journal-grid.ts` и где ещё розовая заливка выходных/сокращённых
  дней) — одинаково («тоже»). Выходной и сокращённый день должны различаться и на ч/б печати (разная
  светлота серого и/или штриховка), легенда — с теми же образцами.
- Где цвет нёс смысл (красный — отклонение/ошибка/просрочка, зелёный — норма, жёлтый — внимание, синий —
  ссылки/акценты): заменить на серое И сохранить смысл без цвета — жирный шрифт, серая заливка, рамка,
  пометка текстом («!», «откл.») — так, чтобы на ч/б распечатке отклонение было заметно. Список всех таких
  замен — в evidence.
- Экранный интерфейс сайта (кроме сетки выходных выше) не менять.
- Фирменную плитку QR (`brand-qr.ts`, `drawBrandQrTilePdf`) не трогать — её в это же время переделывает
  параллельная задача (`bwqr`); в проверке цвета область QR исключить.

## Проверка (обязательно)
- Скрипт-сканер цвета: для всех бланков (образцы 45 журналов + «длинные» документы + бумажные бланки + чек-листы
  + пакет проверяющего + приказы + Word-шаблоны) до/после: PDF — операторы цвета в контент-потоках
  (`rg/RG/k/K/sc/scn` с неравными компонентами) и растр (доля «цветных» пикселей вне зоны QR); DOCX — XML на
  цветные атрибуты. После — 0 цветных везде вне QR. Таблица в evidence.
- Наборы бланков и входы — те же, что в `.agent/tasks/journal-qr-header-2026-09/` (pages.ts, long-inputs.ts,
  portrait-inputs.ts) и `.agent/tasks/journal-pdf-qr-2026-09/check-qr-overlap.ts` (он должен остаться
  зелёным; страниц нигде не больше).
- Скриншоты до/после (растр PDF): гигиена (выходные), журнал с отклонениями (температура), чек-лист,
  Word-шаблон, экранная сетка журнала с выходными (светлая и тёмная тема).
- `npm run typecheck` и `npm test` зелёные; тесты на цвета (например, «в PDF журнала нет цветных операторов»)
  добавить.

## Не делать
- Не менять данные/тексты документов, схему БД, зависимости проекта (сканер/конвертеры — только в отдельной
  папке проверки). Не править whats-new / CHANGES, не писать в `D:/www/Wesetup.ru`, не пушить; не запускать
  `npm run dev` / `npm run build` (pre-скрипты делают `prisma generate`).

## Критерии приёмки
- AC1: во всех печатных документах вне QR нет цвета (таблица сканера до/после).
- AC2: выходные и праздники серые в PDF и на экране; выходной и сокращённый различимы на ч/б.
- AC3: смысл бывших цветовых отметок виден на ч/б печати (список замен, скриншоты).
- AC4: `check-qr-overlap.ts` зелёный, страниц не больше; typecheck и тесты зелёные.
