# Spec (frozen 2026-10-31): этап «Недели 1–2» плана «как стать №1» — оплата, активация, ответы

Запрос владельца: «делай следующий этап плана и сразу в прод, по окончанию приготовь план в pdf что осталось».
План — документ Claude Docs «WeSetup: как стать №1», раздел «Пошаговый план → Недели 1–2 (2–15 ноября)».
Первые правки (напоминания о продлении, честное автопродление, ответ гостю, горячие лиды, SEO-гигиена,
CLS) уже в проде: задача `growth-quick-wins-2026-10-31`.

## Исходное состояние (master a4481d06)

- /pricing: «Оплата картой через сервис «Робокасса» или по счёту для юрлица. Возврат за неиспользованный
  период — по заявлению…» — про СБП и безусловный возврат 14 дней (оферта п. 5.2, 6.1) ни слова; на /order — тоже.
- Экран «Оплата не прошла» предлагает только /pricing и почту; оплатить по счёту оттуда нельзя.
- Новый клиент после оплаты видит «мы отправили письмо со ссылкой… письма нет — напишите в поддержку»: выслать
  ссылку ещё раз сам он не может.
- Крон `compliance` (3 раза в день) шлёт «Напоминание / Внимание / СРОЧНО: незаполненные журналы» всем
  организациям, включая демо и зарегистрированных вчера.
- Писем новичку после регистрации нет (кроме письма с паролем); активацию никто не подталкивает.
- Сообщение в чате поддержки без ответа никто не напоминает: админ узнаёт о нём один раз.
- MAX на сайте не показан: в коде есть рабочий MAX-бот для сотрудников, но канала поддержки в MAX нет.

## Критерии приёмки

- **AC1. Оплата понятна заранее.** На /pricing под тарифами: оплата картой или через СБП в «Робокассе» либо по
  счёту для юрлица; 14 дней с первой оплаты — возврат всей суммы без вопросов, дальше — за неиспользованный
  период (оферта п. 6.1–6.2). На /order под кнопкой оплаты — та же короткая строка со ссылкой на раздел возврата
  оферты. Тексты не обещают того, чего нет в оферте.
- **AC2. Неудачная оплата не тупик.** Экран «Оплата не прошла»: «Попробовать ещё раз» (как раньше), «Оплатить по
  счёту для юрлица» (раздел счёта в «Настройки → Тариф», для гостя — после входа) и «Связаться с нами» (окно с
  телефоном, Telegram, почтой и чатом) вместо одной почты.
- **AC3. Ссылку на достройку можно выслать ещё раз.** На экране «мы отправили письмо со ссылкой» — кнопка
  «Выслать ссылку ещё раз». Сервер принимает те же доказательства, что и статус заказа (подпись возврата
  Робокассы или подпись запроса оплаты), отвечает одинаково на любой запрос (не выдаёт, есть ли заказ),
  выпускает новый одноразовый токен (старая ссылка перестаёт работать) и шлёт письмо на почту заказа. Не чаще
  раза в минуту и не больше 5 раз на заказ (счётчик и время — в заказе или журнале). Тесты: правило ограничения.
- **AC4. «СРОЧНО» — не новичкам и не демо.** Крон `compliance` пропускает демо-организации и организации младше
  48 часов, в которых ещё нет ни одной записи в журналах. Тест: правило пропуска.
- **AC5. Письма новичку.** Ежедневная задача биллинга (уже работает по расписанию) шлёт владельцу новой
  русскоязычной организации до трёх писем — по одному на шаг, не больше одного в день:
  - день 2+ (48 ч): записей в журналах нет → «Начните с одного холодильника» (кнопка «Распечатать QR-наклейки»);
    записи есть, но активный сотрудник один → «Теперь позовите смену» (кнопка «Пригласить сотрудников»);
  - демо-организация аккаунта удалится в ближайшие 2 суток → «Демо удалится <дата>» (кнопка «Открыть демо»);
  - день 9+: «Что увидит проверяющий» (кнопка «Открыть „Пришла проверка“»).
  Окно — организации, созданные 2–14 дней назад. Не шлются: демо, платформенной, неактивным, адресам из
  стоп-листа рассылок и техническим, если владелец писал в чат поддержки за последние сутки, en/uz-организациям.
  Повтор шага исключён (запись `onboarding.journey` в AuditLog). Тесты: выбор шага и исключения.
- **AC6. Неотвеченный чат напоминает о себе.** Новый крон `/api/cron/support-unanswered` (по секрету, как
  остальные): ветки, где последнее сообщение — клиента, без ответа 15 минут – 24 часа, — одно повторное
  сообщение админу в Telegram на каждое такое сообщение клиента (ключ от повторов). Строка для crontab описана
  в docs; пока её нет на сервере, ничего не меняется. Тест: выбор веток.
- **AC7. MAX рядом с Telegram — по настройке.** Переменная `WESETUP_MAX_URL` (только `https://max.ru/…`)
  добавляет MAX в окно «Свяжитесь с нами»; без неё сайт не меняется. Тест: разбор адреса.
- **AC8. Ворота.** `npm run typecheck`, `npm run test:gate`, `npm run i18n:check` зелёные; PR влит в master
  (squash), выкладка прошла, `/api/build-info` показывает коммит; на проде проверены тексты /pricing и
  ответ нового эндпоинта на запрос без доказательств.

## Вне объёма

Повторная оплата того же заказа одной кнопкой (нужны данные тарифа в статусе заказа), счёт по ИНН для гостя,
автосписания, страница СанПиН 4282-26, сравнения, PDF-пакет проверки, журнал ККТ, ИИ в чате, запись без сети.

## Уточнение (31.10.2026, до реализации AC7)

Адрес MAX — публичное значение, а окно «Свяжитесь с нами» получает Telegram пропом из восьми серверных
страниц. Чтобы не протягивать второй проп через все, AC7 читает переменную сборки
`NEXT_PUBLIC_WESETUP_MAX_URL` (только `https://max.ru/…`): владелец задаёт её в `.env` сервера, и следующая
выкладка показывает MAX в окне на всех страницах. Без переменной окно не меняется.
