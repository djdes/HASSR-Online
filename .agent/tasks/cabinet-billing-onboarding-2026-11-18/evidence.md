### Найдено и исправлено
1. **Потеря замера влажности в журнале климата** (`climate-document-client.tsx`). Температура → Tab → влажность:
   ответ на первое сохранение перезаписывал строку снимком «до влажности», и второе сохранение уходило с
   `humidity: null`. Воспроизведено дважды (запрос `…"humidity":null` после ввода 61), после правки — 62 сохранено.
   Правка: из ответа берём только `id` строки.
2. **Автопродление без года** (`auto-renew.server.ts`): у годовой подписки «17 ноября нужно списать…» читалось как
   вчера. Теперь `formatMskDayAuto` — «17 ноября 2027», если год не текущий.
3. **Пополнение баланса: причина отказа терялась** (`topup-section.tsx`): вместо «уже выставлен счёт № 2 на 5 000 ₽…»
   клиент видел общее «не удалось». Теперь показывается текст сервера.

### Найдено, не исправлено (вне объёма, нужен отдельный заход)
- **Отчёты PDF/XLSX по документным журналам** выводят технические ключи: колонки `measurements`,
  `responsibleTitle`, ячейки вида `room-0: 10:00: humidity: 62; temperature: 20`. У каждого из ~40 журналов своя
  структура данных — нужна раскладка по журналам. PDF самих документов (их печать) — корректные.
- **XLSX внутри архива журналов** — сырой дамп: колонка `_autoSeeded`, JSON в ячейках.

### Удаление тестовых данных
Удалены 3 тестовые организации и всё связанное (Organization 3, User 5, Building 2, Area 1, Equipment 3,
JobPosition 5, JournalDocument 3, JournalDocumentEntry 60, PaymentOrder 2, ClosingDocument 2, BalanceTransaction 3,
Account 3, AuditLog 11, Notification 4, LegalConsent 3, Room 1, OrganizationMember 3), настройки
`org-journal-controls:*`, реквизиты `legal.requisites`, файлы `.data/legal/*.png`. Контроль: поиск почт, id
организаций и названий по всем текстовым/JSON колонкам всех таблиц — `remaining matches 0`; `PaymentOrder` 0,
`ClosingDocument` 0.
