# Ответственные за журналы по точкам

Дата: 2026-10-31. Ветка `feat/point-responsibles` от `origin/master` 9583b7b9.

## Откуда

Аудит «точка видит только своё» (PR #76–#79) нашёл, что ответственные за журналы
одни на всю организацию: выбор на `/settings/journal-responsibles` записывается
во все точки, и человек точки А становится ответственным за журнал точки Б (а её
задачи и уведомления уходят ему). Владелец на вопрос «сделать ответственных по
точкам?» ответил «да».

## Правило

- У точки — своя карта `Building.journalResponsibleUsersJson`
  ({ [journalCode]: { [slotId]: userId } }), null — как у организации.
- Действующие ответственные документа точки (`resolvePointSlots`): своё точки
  по журналу, иначе — организации; человек, который на точке не работает
  (`worksAtBuilding`: без точек и «только удалённые точки» — работает везде),
  — пустой слот, его заполняет авто-подбор из сотрудников точки.
- Документ без точки и организация без точек — карта организации, как раньше.

## Критерии

- AC1. Поле `Building.journalResponsibleUsersJson Json?` (аддитивно).
- AC2. `src/lib/journal-responsibles-points.ts`: `resolvePointSlots`,
  `parseSlotMaps`, `droppedSlotIds`, `withoutUser` (чистые, с тестами);
  `loadEffectiveResponsibleSlots` / `effectiveJournalSlots` — один помощник для
  всех читателей; `savePointJournalSlots`, `removeUserFromPointResponsibles`.
- AC3. Каскад: сохранение точки — в точку и только её документы; сохранение
  организации — в организацию, документы каждой точки получают действующих
  ответственных своей точки (человек другой точки в документ точки не попадает,
  у точки со своими — её люди). `prefillResponsiblesForNewDocument` и
  авто-подбор — по точке нового документа.
- AC4. API `PUT /api/settings/journal-responsibles/<code>` с `buildingId` —
  ответственные точки (только её сотрудники, иначе 400; должности не трогает);
  `DELETE …?buildingId=` — «Как у организации». Руководитель точки (с офисом,
  `pointScope`) — только свои точки, организацию — 403. Proxy открывает
  страницу и сохранение журнала, общие действия (пресеты на всё, resync,
  пересоздание, проставить проверяющих) — по-прежнему только офису.
- AC5. Страница: выбрана торговая точка — баннер «Ответственные точки «…»»,
  в выборе только её сотрудники, у журнала «Своё для точки» / «Как у
  организации», кнопка «Вернуть как у организации» (с подтверждением);
  должности — только просмотр; кнопки на всю организацию скрыты. ru/en/uz.
- AC6. Читатели, работающие с документом точки, берут ответственных точки:
  получатели «Не отметились по QR» (core-journal-keepers), УФ-лампы (документ,
  операторы, уведомления, крон), отклонения температуры, TasksFlow «каждому из
  ответственных», ручное создание документа, автосоздание, rolling-задачи,
  ответственный по умолчанию на странице журнала, мастер бракеража,
  «к кому идти» на QR. Каскад проверяющего в TasksFlow — по точке.
- AC7. Архив и удаление сотрудника снимают его и с ответственных точек.
- AC8. `npm run typecheck` 0 ошибок; eslint изменённых файлов без новых ошибок;
  тесты; проверка на e2e-базе (`raw/check.txt` ALL PASS).

## Не входит

- Страницы «Баланс нагрузки», «Соответствие» и список проверяющих — сводки на
  всю организацию, считают по карте организации.
