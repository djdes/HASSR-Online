## Критерии приёмки

### AC1. Наборы журналов `JOURNAL_SETS`
Новый модуль `src/lib/journal-sets.ts` рядом с каталогом.
- `standard` — 11 пунктов эскиза в его порядке: `finished_product`, `perishable_rejection`,
  `hygiene` (+ `health_check` как связанный журнал того же пункта), `climate_control`,
  `cold_equipment_control`, `uv_lamp_runtime`, `general_cleaning`, `disinfectant_usage`,
  `pest_control`, `med_books`, `staff_training`.
- `haccp` — 18 журналов с флагом ХАССП + `ccp_monitoring` (19).
- `extra` — вычисляется: весь каталог минус `standard` (вместе со связанными) и `haccp`.
- Тест `src/lib/journal-sets.test.ts`: все коды есть в каталоге; у `standard` ровно 11 пунктов
  в порядке эскиза; `extra` не пересекается со `standard` и `haccp`; `standard ∪ haccp ∪ extra`
  = каталог; `extra` равен вычисленному остатку; пересечение `standard ∩ haccp` — только
  задуманное (`climate_control`, `cold_equipment_control`).

### AC2. «Включить весь набор» — API
- Чистая функция `enableJournalSetCodes(disabledCodes, setId)` → новый список выключенных и
  список включённых кодов (дельта, чужие выключения не трогает, идемпотентна).
- Маршрут `src/app/api/settings/journals/sets/route.ts`:
  - `GET` — наборы с пунктами и признаком «включён» для текущей организации;
  - `POST { set: "standard" | "haccp" }` — включает основные коды набора; `extra` и неизвестный
    набор → 400; повторный вызов → `changed: []`; каждое включение — запись `journal.enable`
    в AuditLog с `via: "journal-set"`.
- Guard как у настроек журналов: `requireApiAuth` + `hasFullWorkspaceAccess` (иначе 403).
- Связанный `health_check` набором не включается (решение владельца: журнал здоровья —
  дубль гигиенического, выключен по умолчанию).
