# Spec (frozen 2026-11-20): серия B — контроль (пункты 9–13)

Общий дизайн: `docs/superpowers/specs/2026-11-20-multi-org-followups-design.md`. Серия A — #272.

## Исходное состояние
- Обмен считает пропущенные записи только числами (`skippedLimit`, `skippedConflict`); какие именно записи пропущены,
  нигде не хранится, и пропущенная запись пробуется заново при каждом обмене.
- Баланс — у каждой организации свой (`Organization.balanceRub`, `BalanceTransaction`, `applyBalanceChange`); сводки по
  аккаунту и перевода между своими организациями нет.
- У ROOT нет ни показа, ни правки своих 14 дней организации (`Organization.trialEndsAt`) и счётчика выданных
  (`Account.orgTrialsGranted`); подозрения на повторный пробный период видны только в журнале действий.
- Разовый перенос не запоминает, что создал; отменить его нельзя.
- Код мастер-кабинета для запроса другой компании — это `serviceCode` кабинета, он же код меню и сырья для
  подключённых объектов; сменить его нельзя (а смена сломала бы подключения).

## Решения

### Пункт 9. Разбор пропущенных записей обмена
- Р9.1. Новая таблица `DirectoryExchangeSkip`: кабинет, организация-получатель, вид записи (`entity`), группа
  (`groupId`), организация-источник и её запись, название, причина (`limit` | `conflict`), когда впервые и в последний
  раз пропущена. Уникальна по (кабинет, вид, группа, получатель). Обмен записывает её при пропуске создания и удаляет,
  когда запись у получателя появилась или связана. Только обмен (разовый перенос показывает пропуски в своём итоге).
- Р9.2. Карточка «Обмен справочниками» (владелец аккаунта): «Пропущено: N — Разобрать» → окно со списком по
  организациям: название, список, причина простыми словами («нет свободных мест в тарифе», «такое название уже есть»).
- Р9.3. Действия: «Не переносить» — надгробная связь (`entityId: null`): больше не пробовать, строка уходит;
  «Связать с …» — только для причины `conflict`, если у получателя есть видимая обменом запись того же вида с тем же
  названием (без учёта регистра и пробелов): связь на неё с её собственным отпечатком (её данные не перезаписываются до
  настоящей правки источника); для причины `limit` — ссылка «Открыть тариф», запись пробуется снова при следующем
  обмене. Только свои организации аккаунта; участник из другой компании — не разбирается владельцем кабинета за неё
  (видит свои пропуски в своей карточке только числом).

### Пункт 10. Баланс по аккаунту и перевод между своими организациями
- Р10.1. «Настройки → Баланс» у владельца аккаунта (не «войти как», не руководитель без прав): блок «Баланс по
  аккаунту» — организации аккаунта (кроме демо и кабинетов) с балансами и итог.
- Р10.2. «Перевести»: откуда (по умолчанию — активная), куда, сумма (целые рубли ≥ 1, не больше остатка), комментарий.
  Одна транзакция БД: списание `transfer_out` и зачисление `transfer_in` через `applyBalanceChange`, ключ повтора от
  клиента (`dedupeKey`), журнал действий в обеих организациях. Закрытая организация может и отдавать, и получать.
  Подписи видов — в истории баланса на трёх языках.

### Пункт 11. Инструменты ROOT
- Р11.1. Карточка организации у ROOT (`/root/organizations/[id]`, раздел тарифа): свои 14 дней организации — срок,
  состояние («в своих 14 днях», «закрыта», «нет отметки»), сколько организаций аккаунта получили свои 14 дней
  (`orgTrialsGranted` из 2), подозрения на повторный пробный период по аккаунту (из журнала действий: дата, ИНН/телефон,
  с какой организацией совпало).
- Р11.2. Действия (доступ «billing», как у правки тарифа): продлить свои 14 дней на N дней (1–60; от большего из
  «сейчас» и текущего срока), снять отметку (организация становится обычной и занимает точку тарифа), обнулить счётчик
  выданных. Каждое — запись в журнале действий с «было/стало»; кеш «закрыта ли» сбрасывается сразу.

### Пункт 12. Отмена разового переноса
- Р12.1. Новая таблица `DirectoryTransfer`: откуда, куда, кто, когда, созданные записи по видам (`createdJson`),
  итог, запрос другой компании (если перенос по запросу), когда и кем отменён.
- Р12.2. Отменить может владелец аккаунта получателя в течение 7 дней: карточка «Обмен справочниками» →
  «Последние переносы» → «Отменить». Отменяется только то, что перенос создал и что не используется и не правилось
  после переноса: продукты — выключаются (`isActive: false`); сотрудники — в архив, если по ним нет записей журналов;
  оборудование — удаляется, если нет записей журналов, датчиков и смен работы; помещения, цеха, объекты — удаляются,
  если пусты; должности — если без сотрудников. Остальное остаётся, итог называет, что и почему. Повторная отмена — 409.

### Пункт 13. Новый код мастер-кабинета
- Р13.1. Отдельное поле `Organization.exchangeCode` (уникальное, необязательное) — код для запросов другой компании.
  Пока не задано, действует прежний код (`serviceCode` кабинета) — уже выданные коды не ломаются; при первом показе
  код запоминается в `exchangeCode`.
- Р13.2. «Выдать новый код» в карточке (владелец аккаунта, с подтверждением): новый `exchangeCode`; старый перестаёт
  приниматься для новых запросов (и прежний путь через код меню — тоже); подтверждённые связи, ждущие запросы и
  подключения к меню и сырью не меняются. Журнал действий.

## Критерии приёмки
- AC1 (п. 9). Пропуск пишет строку, появление/связь записи её убирает; «Не переносить» — надгробие, строка ушла,
  следующий обмен не пробует; «Связать с …» — связь на существующую запись, её данные не изменились, дальше правки
  источника доходят; другая компания чужих пропусков не видит. Чистые части — с тестами; сквозная проверка.
- AC2 (п. 10). Сводка и перевод: суммы сходятся, обе строки истории, журнал; отказы: чужая организация (404), не
  владелец (403), больше остатка (409), повтор с тем же ключом не списывает дважды. Сквозная проверка.
- AC3 (п. 11). Показ и три действия у ROOT, журнал «было/стало», закрытая после продления — снова открыта сразу;
  без доступа billing — 404/403 как у остальных маршрутов.
- AC4 (п. 12). Перенос записывает созданное; отмена — используемое и правленное остаётся, остальное отменено; итог
  называет оставшееся; через 7 дней и повторно — отказ; чужой аккаунт — 404. Сквозная проверка.
- AC5 (п. 13). Старый код работает до смены и после первого показа; после смены — только новый; связи и подключения к
  меню и сырью на месте. Сквозная проверка.
- AC6. Схема — только добавления (`DirectoryExchangeSkip`, `DirectoryTransfer`, `Organization.exchangeCode`); тексты
  ru/en/uz; typecheck, test:gate, i18n:check, eslint; сквозные проверки частей 2, 3 и серии A зелёные; живой прогон
  со снимками.
