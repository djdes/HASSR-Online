# Детальный аудит изоляции точек и организаций (2026-11-01)

Запрос владельца: «поищи ещё такие проблемы, детальнее» → «как выявишь все такие
проблемы — в мердж и в прод».

## Как искали

Пять параллельных проверок кода (только чтение) по областям: кроны и уведомления;
страницы кабинета и API людей; Mini App, боты и устройства; документы журналов;
интеграции и настройки. Отдельно — проверка «между организациями» (общие модели
без `organizationId` и чужие id). Около 90 находок; каждую перед правкой
перепроверяли по коду.

## Критерии приёмки

- AC1. Уведомления по точке — PR #88.
- AC2. Настройки журналов (набор, автоматика, комиссия) по точке — PR #89.
- AC3. Датчики и интеграции пишут в журнал своей точки — PR #90.
- AC4. Документы журналов: чужой документ не открыть и не изменить по ссылке;
  «Вся организация» — все точки — PR #91.
- AC5. Руководитель точки — только люди и данные своих точек; общие настройки
  компании — офису — PR #92.
- AC6. Оборудование, цеха, помещения, киоск — только своя точка — PR #93.
- AC7. Боты, ИИ-помощник, Mini App, QR — по точке; сводка офиса в Max — вся
  компания — PR #94.
- AC8. «Распределение» и бонус журнала — свои у организации; ключ повтора
  внешнего API по организации — PR #95.
- AC9. Сборка всех PR вместе: typecheck 0 ошибок, полный набор тестов без новых
  падений, живая проверка на отдельной копии e2e-базы — все проверки PASS.
- AC10. «Что нового» для руководителей.
