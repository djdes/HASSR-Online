# Подпись журнала УКЭП (КриптоПро ЭЦП Browser plug-in)

- **Task ID:** `journal-ukep-signing-2026-11-21`
- **Base:** `origin/master` `6bc5c9b9` (#292)

## Запрос владельца (21.11.2026)

«Сделай все кроме 6,7» — пункт 3: подписание журналов квалифицированной электронной подписью (УКЭП).

## Что есть и что выбрано

- Подписи в WeSetup сейчас — простые: вход в кабинет, PIN киоска, passkey (`SignatureEvent`). УКЭП нет.
- Интеграция со СБИС — только для входящих накладных; подписывать ею журналы нельзя.
- PDF документа журнала строит `generateJournalDocumentPdf` (`/api/journal-documents/[id]/pdf`).
- Загрузки (`/uploads/…`) отдаются без входа — подписанный журнал с ФИО туда класть нельзя; закрытые файлы в
  проекте хранятся в базе (`ChecklistAttachment.content`, `KnowledgeDocument.content`).
- Способ подписи — КриптоПро ЭЦП Browser plug-in (стандарт для УКЭП в браузере): `cadesplugin_api.js` с
  `cryptopro.ru` (проверено 21.11.2026: `window.cadesplugin` — промис, константы `CAPICOM_CURRENT_USER_STORE = 2`,
  `CAPICOM_MY_STORE = "My"`, `CADESCOM_CADES_BES = 1`, `CADESCOM_BASE64_TO_BINARY = 1`). Подпись — откреплённая
  CAdES-BES над байтами PDF.
- На сервере ГОСТ-криптографии нет (OpenSSL без ГОСТ): математику подписи сервер не проверяет. Проверка
  подлинности — на Госуслугах (`https://www.gosuslugi.ru/eds`) или в КриптоАРМ по паре «PDF + .sig».

## Решения

- Р1. «Подпись УКЭП» в меню документа журнала (общая панель `DocumentActionsBar`, руководство): окно со списком
  подписей документа и кнопкой «Подписать». Нет плагина — что поставить (КриптоПро CSP и плагин) и ссылки.
- Р2. Подписание: сервер собирает PDF документа и выдаёт его вместе с подписанным токеном (HMAC: документ,
  пользователь, SHA-256 PDF, срок 15 минут) → браузер подписывает выбранным сертификатом → сервер принимает PDF,
  подпись и токен, сверяет токен и хэш, разбирает подпись и сохраняет PDF и подпись в базе (новая таблица
  `JournalDocumentSignature`).
- Р3. Данные подписанта — из сертификата внутри подписи (ФИО, должность, организация, ИНН, СНИЛС, ОГРН,
  удостоверяющий центр, серийный номер, срок), а не со слов браузера. Отказ: не CMS, подпись не откреплённая,
  нет сертификата подписанта, сертификат не действует на момент подписания. Для SHA-256 сервер ещё сверяет
  хэш PDF с подписанным; для ГОСТ — честная пометка «проверить на Госуслугах».
- Р4. Скачать PDF и подпись (`.sig`) — только своей организации, своей точки и с доступом к журналу; подписывать —
  руководство или право «завершать» журнал.

## Критерии приёмки

- **AC1.** Разбор подписи: из CMS SignedData извлекаются сертификат подписанта и поля (тест на настоящей
  откреплённой подписи, сделанной `openssl cms`), SHA-256 сверяется с PDF; мусор, присоединённая подпись,
  чужой PDF, просроченный сертификат — отказ с понятным текстом.
- **AC2.** Токен подписи: подделка, другой документ/пользователь/PDF и истёкший срок — отказ (тест).
- **AC3.** Обёртка плагина: список сертификатов с закрытым ключом и подпись вызывают API КриптоПро в нужном
  порядке и с нужными константами; нет плагина — понятная ошибка (тест на подставном плагине).
- **AC4.** API: список, подготовка, сохранение, скачивание — с проверкой сессии, организации, точки, доступа к
  журналу, права подписи; запись в журнал аудита (тест по исходнику).
- **AC5.** Окно «Подпись УКЭП» в меню документа, тексты ru/en/uz, `i18n:types`; документация.
- **AC6.** typecheck, тесты, eslint, палитра — зелёные; схема — только добавление таблицы.
