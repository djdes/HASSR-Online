# iiko: приходные накладные, акты списания и номенклатура из iikoServer (2026-10-31)

Заморожено 31.10.2026 (после ЭДО, на его входящих). Запрос владельца (идея № 15): «сделай … 15» —
«iiko: накладные приходуются в iiko — приёмка, списания и номенклатура подтягиваются в WeSetup сами».

## Что уже есть
Входящие накладные и приёмка по ним (`SupplyDocument`, `/edo`), подключения поставщиков (`SupplyConnection`,
ключи зашифрованы), «Потери» (`LossRecord`), справочник продуктов (`Product`). С iiko — только импорт
файлов выгрузки (продукты, сотрудники).

## Решение
1. **Клиент iikoServer** (iiko RMS / Chain REST): вход `GET /resto/api/auth?login&pass=sha1(пароль)`,
   работа одной сессией и обязательный выход `/resto/api/logout` (сессия держит лицензию сервера) — даже при
   ошибке; приходные накладные `documents/export/incomingInvoice` (XML), акты списания
   `v2/documents/writeoff` (JSON), номенклатура `v2/entities/products/list`, единицы
   `v2/entities/list?rootType=MeasureUnit`, поставщики `/resto/api/suppliers`.
2. **Накладные** → «Входящие накладные» (источник «iiko», та же приёмка в журнал, что у УПД; удалённые —
   нет); **акты списания** → «Потери» (категория «Списание», причина — комментарий акта, без дублей по
   `iiko:<акт>:<строка>`, в колонке «Откуда» — «из iiko»); **товары и заготовки** (не блюда и не услуги) →
   справочник продуктов — только недостающие, заведённые руками не трогаем. Что забирать — галочки.
3. **Подключение** `/settings/integrations/iiko`: адрес сервера, логин, пароль; вход проверяется сразу (и
   сразу выход); пароль — только зашифрованным. Адрес вводит клиент, поэтому сайт ходит только на внешние
   адреса: имя разрешается в IP, внутренние сети отклоняются (вне продакшена — localhost для заглушки).
4. Загрузка — кнопкой «Забрать сейчас», «Проверить новые» во входящих и cron `/api/cron/edo-sync`.

## Критерии приёмки
- **AC1** — клиент: SHA1-пароль, выход всегда (и после ошибки), понятные ошибки входа и занятой лицензии
  без пароля в тексте; разбор накладных, поставщиков, номенклатуры, единиц, списаний; тесты.
- **AC2** — перенос: накладная как УПД (поставщик с ИНН, товары с единицами, сумма), удалённые пропускаются;
  списания → строки потерь; товары и заготовки → справочник; тесты.
- **AC3** — синхронизация одной сессией, без дублей при повторе, галочки соблюдаются; тест.
- **AC4** — защита адреса сервера (внутренние сети, протокол, логин в адресе); тест.
- **AC5** — сквозь сайт на заглушке iikoServer: подключение, неверный пароль, внутренний адрес, загрузка →
  накладная во входящих, строки потерь, новые продукты; повтор — без новых; скриншоты.
- **AC6** — `typecheck`, `test:gate`, `eslint` по изменённым файлам, `i18n:check` — зелёные.

## Вне задачи
iikoCloud API (меню доставки), выгрузка из WeSetup в iiko, сопоставление складов и точек, живой сервер iiko
(доступа нет — проверка на заглушке по документированным методам).
