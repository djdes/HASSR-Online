# 1С кадры: сотрудники и увольнения из 1С:ЗУП (2026-10-31)

Заморожено 31.10.2026. Запрос владельца (идея № 17): «сделай … 17» — «1С кадры: принятые и уволенные в
1С появляются и уходят в WeSetup сами».

## Что уже есть
Сотрудники (`User`; без почты и пароля — `createStaffMember`), должности (`JobPosition`), увольнение с
передачей задач преемнику (`performOffboarding`), внешний API организации (`Authorization: Bearer
<токен организации>`), импорт сотрудников файлом.

## Решение
1. **Два пути данных** — одно и то же правило синхронизации:
   - **OData 1С:ЗУП 3.x** (база опубликована на веб-сервере): `Catalog_Сотрудники`,
     `InformationRegister_ТекущиеКадровыеДанныеСотрудников` (приём, увольнение, должность),
     `Catalog_Должности`; Basic-авторизация, адрес — только внешний (как у iiko);
   - **из 1С по API** (база не опубликована): обработка в 1С шлёт список на
     `POST /api/external/hr/employees` с токеном организации.
2. **Правило** (чистая функция): сотрудник 1С связывается с сотрудником WeSetup (`HrEmployeeLink` по
   id в 1С); при первом сопоставлении — по ФИО, только если такой человек в WeSetup один. Принят и
   активен → новый сотрудник (должность — по названию из 1С, иначе должность по умолчанию из настроек;
   нет ни той, ни другой — в «проблемы»); изменились ФИО или должность — обновить; уволен в 1С (дата
   увольнения наступила) → уволить в WeSetup тем же путём, что кнопка «Уволить» (задачи — преемнику);
   уволенного в WeSetup обратно не принимаем — только сообщаем. Никого не удаляем.
3. **Сначала проверка, потом применение**: «Проверить» показывает, кто будет принят, уволен, изменён, и
   проблемы; «Применить» — делает. Галочка «Применять автоматически» — для расписания
   (`/api/cron/hr1c-sync`) и API (без неё API только отвечает, что изменилось бы, — `apply: true` в теле
   применяет явно).
4. **Настройки** «Остальное → 1С: кадры» (`/settings/integrations/1c`): адрес OData, логин, пароль
   (зашифрован), должность по умолчанию, автоприменение; описание API для обработки 1С.

## Критерии приёмки
- **AC1** — правило синхронизации: приём, изменение, увольнение, сопоставление по ФИО только при
  однозначном совпадении, проблемы (нет должности, уволен в WeSetup), повтор ничего не меняет; тесты.
- **AC2** — OData-клиент: Basic-авторизация, кириллица в адресах, постраничная выборка, разбор
  сотрудников, кадровых данных и должностей, понятные ошибки (401, не опубликовано); тесты.
- **AC3** — применение: новый сотрудник через `createStaffMember` + связь, увольнение через
  `isActive=false` + `performOffboarding`, обновление ФИО и должности; только своя организация.
- **AC4** — API для 1С: токен организации, проверка входных данных, `apply` по умолчанию — только
  предпросмотр; тест на разбор тела.
- **AC5** — сквозь сайт на заглушке 1С: подключение, проверка, применение, повтор без изменений,
  увольнение; API; скриншоты.
- **AC6** — `typecheck`, `test:gate`, `eslint` по изменённым файлам, `i18n:check` — зелёные.

## Вне задачи
Выгрузка из WeSetup в 1С, график и табель, медкнижки из 1С, живая база 1С (доступа нет — заглушка по
документированному стандартному интерфейсу OData).
