# Уведомления и кроны по точкам (2026-11-01)

Задача: детальная проверка «точка видит только своё» показала, что часть
уведомлений уходит людям чужих точек или смешивает данные нескольких точек.
Группа «notify» — кроны, напоминания, сводки.

## Критерии приёмки

- **AC1** `listCoreJournalRecipients`: ведущие основных журналов и запасной список
  руководителей отбираются по точке гигиенического документа
  (`filterRecipientsByPlace`). «Не отметились по QR» и «не допущен(а)» точки А
  не уходят заведующей точки Б.
- **AC2** `cron/expiry`: истекающие продукты (по цеху записи / цеху оборудования)
  и документы сотрудников (по точке сотрудника, `placeBuildingOfUser`)
  отправляются отдельным сообщением на каждую точку с `buildingId`; письма —
  только руководителям по месту. Точки выключены — как раньше, одно сообщение.
- **AC3** `cron/tasksflow-escalations` L1: руководитель для пинга выбирается только
  из тех, кому задача по месту (`placeOfEvent({documentId, userId})`).
- **AC4** УФ-лампы (`cron/uv-lamp-running`, `uv-lamp-runs.lampRecipients`): без
  ответственного — руководство точки лампы и офис, не вся сеть.
- **AC5** `cron/weekly-digest`: и в организации без офиса руководитель точки
  получает сводку своей точки, а сводку компании — только те, кто работает на
  всю компанию (`receivesPlaceEvent` с `onlyPlace`).
- **AC6** «Новенький в команде» (`auth.ts`) и «внести в журнал» (`staff-create.ts`)
  — руководителям точки(ек) сотрудника и офису.
- **AC7** Записи журналов по полям (`JournalEntry`) считаются по точке:
  `getTemplatesFilledToday` и `cron/auto-close-shifts` (`journalEntryPointWhere`).
- **AC8** `cron/journal-automation`: подписант по умолчанию — из людей точки
  документа; сводка «Журналы заполнены автоматически» — по точкам с `buildingId`.
- **AC9** Сводки по всей сети (`anomaly-detect`, `predict-alerts`,
  `weekly-ai-digest`) — только тем, кто работает на всю компанию.
- **AC10** `cron/general-cleaning-tasks` учитывает свой набор выключенных журналов
  точки документа.
- **AC11** `receivesPlaceEvent` без офиса: в списке только удалённые точки —
  человек работает везде (как `worksAtBuilding`); `onlyPlace` при включённых
  точках — только люди точки / только «на всю компанию». Тесты.
- **AC12** `npm run typecheck` — 0 ошибок; затронутые тесты зелёные.

## Не входит

- Почта «кто не отметился» в сводке точки по-прежнему считает людей, закреплённых
  за точкой (`buildingIds has`), без «работает на всех точках» — иначе они
  числились бы отсутствующими на каждой точке.
- Mercury, бот Max, массовая отправка задач TasksFlow, автосоздание журналов —
  другие группы.
