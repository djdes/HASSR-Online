# Slow automated page collection — frozen specification

Frozen 2026-10-13 before implementation. ProjectsFlow task: https://projectsflow.ru/projects/5c2c38fa-f022-44b8-b125-f67a8caa0bf4/tasks/093a0d41-c145-434e-84a6-3d5fd616c600 . Request: detect automation signals in user-agent and rapid page visits, then show a timed wait screen.

Scope: a server-side page-navigation limiter in the existing Next.js proxy, after existing access decisions. A self-contained Russian HTTP 429 wait screen uses the existing design tokens and an accessible countdown/retry button. No external provider, schema or dependency changes. Public and permitted authenticated pages are covered. This deters bulk collection; it does not promise to prevent copying delivered assets or distributed/slow scraping.

Policy: rolling 10-second/minute windows, normal clients 20/120 page requests, automation-signalling clients 6/30. User-agent is only a signal for stricter frequency thresholds, never a sole ban or an exemption. Authentic Next RSC prefetch uses a separate bounded budget of 240/minute; prefetch headers on document requests do not skip counting. A block lasts 30 seconds, is enforced server-side and is not prolonged by blocked retries. Changing UA or clearing cookies cannot reset an anonymous IP's budget. Verified session user IDs separate signed-in people behind a shared IP; unverified cookies/headers cannot choose an account bucket. State is bounded and process-local, appropriate to the current single PM2 web process, with documented limitations on restarts/scaling/NAT.

Acceptance criteria:
- **AC1:** Frequency decisions pass deterministic tests for normal use, bursts, sustained rate, suspicious UA, fixed cooldown, reset and independent subjects. Bounded memory and expiry are verified.
- **AC2:** The real proxy enforces limits on GET document and RSC navigation responses before protected page data is served. Existing root concealment, partner/directory/staff access decisions retain precedence. Static assets, API routes, non-GET requests, payment callbacks, invitation and external QR/task-fill/kiosk flows remain outside this new limit.
- **AC3:** Prefetch cannot provide an unlimited bypass. Spoofed UA, session cookies, misleading client headers and malformed addresses cannot reset or arbitrarily select the limiter subject. Prefer the trusted Nginx X-Real-IP; document that the origin must be private and ingress must overwrite client-IP headers. No secrets or raw identities in the wait response/logs.
- **AC4:** A real browser shows a responsive Russian countdown and a retry button enabled after the displayed interval; retry returns to the same URL and is still server-checked. HTTP 429 includes Retry-After/no-store/noindex. No-JS visitors receive a usable explanation and can retry by reloading. Validate document and real Next client navigation, plus assets and normal browsing; capture 320px/desktop evidence.
- **AC5:** Focused behavior/proxy tests, relevant existing proxy tests, lint, typecheck and full repository gate pass. Freeze evidence.md/json, raw outputs and a fresh current-source verification. Preserve unrelated local edits and the previously deployed registration CAPTCHA. No completion claim on failed criteria.

Delivery: implement and verify the task in the repository. Retain a reviewed local commit. GitHub publishing is currently known to be blocked by account permissions; do not bypass access controls or claim a push/deployment. Any external publication must be reported according to actual outcome. Task is not marked done remotely while required publication is unavailable.

Implementation notes: the installed Next 16.1.6 fetch-server-response falls back to a document navigation for a non-OK/non-Flight RSC response. ## Revision 1 — frozen before correcting the real-browser finding

The first real Next 16.1.6 browser pass exposed that `Link prefetch={true}` sends full RSC fetches without any prefetch marker (`segment-cache/cache.js`, `FetchStrategy.Full`). A 30-link page exhausted the document budget despite ordinary browsing. To avoid relying on undocumented router-state heuristics, ALL requests with `RSC: 1` now share the bounded 240/minute background budget (including actual client navigation); document GETs retain 20/120 or 6/30 limits. Both budgets share the same subject and fixed cooldown. Forging `RSC: 1` can select the background budget but cannot remove its limit. Prefetch markers alone still do not exempt documents. AC1–AC5 remain, with their RSC/prefetch policy interpreted according to this revision. Validate ordinary full Link prefetch, real client navigation, and exhaustion of this background budget. Capacity overload may wait up to 60 seconds for cleanup, separately from the normal 30-second subject cooldown.

## Revision 2 — frozen before correcting the framework adapter finding

The real Next 16.1.6 proxy adapter strips Flight headers (including RSC and prefetch) before calling the user proxy (`server/web/adapter.js`), unlike direct NextRequest unit fixtures. Classify browser background GETs by the standard Fetch Metadata `Sec-Fetch-Dest: empty`; accept `RSC: 1` when available, otherwise use the stricter document budget. Real documents carry `Sec-Fetch-Dest: document`. A forged background destination still selects only the bounded 240/minute budget. This replaces revision 1's reliance on visibility of the RSC header; the policy and all other acceptance criteria remain. The actual server RSC-budget test must include the same fetch metadata a browser sends.
