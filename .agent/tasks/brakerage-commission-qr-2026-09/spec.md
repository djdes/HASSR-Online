## Что сделать

1. **Должность без состава.** Сотрудник с должностью категории `commission`, которого нет ни
   в составе документа, ни в составе организации, попадает в список за сегодня **только для
   чтения**.
   - Без радио «Допущено / Не допущено», без полей оценки, без кнопки подписи.
   - Сверху плашка: «Вас нет в утверждённом составе бракеражной комиссии. Попросите
     руководителя добавить вас: журнал → «Комиссия».»
   - Роль: новый флаг, например `viewer`, в `BrakerageQrRole`. `brakerageQrDefaultView` даёт
     `"list"` и для него.
   - POST списка от такого человека — отказ, как у чужого: сервер не доверяет форме.
2. **Запасная проверка по составу организации.** Член `readOrgCommission(org, code)`,
   которого нет в копии документа, — оценщик.
   - Копию документа досинхронизировать под `withDocumentConfigLock` (как делает
     `saveOrgCommission`), иначе `signBrakerageRows` вернёт 403 (L93–96).
   - Синхронизировать только добавлением недостающего члена, чужие правки состава не
     затирать.
3. **«Новый человек» сразу в составе.** `POST …/members` после создания человека добавляет
   его в состав организации через `saveOrgCommission(org, code, [...текущие, { employeeId,
   role: "Член комиссии" }])`. Функция копирует состав в активные документы.
   - Диалог обновляет список из ответа.
   - Toast остаётся правдой.
   - «Сохранить состав» по-прежнему работает, двойного добавления нет.
4. **Смена человека сбрасывает вид.** При выборе другого сотрудника (redirect, скрытые поля
   выбора, ссылка «Сменить») `view` и `bulk` не переносятся. Новый человек получает свой вид
   по умолчанию.
5. **PIN при `commission=1` в режиме «только после входа».** Без сессии PIN обязателен:
   передавать `mode: "pin"` для `commissionOnly` или проверять `sessionVerified` до шортката
   `auth`. Сессионный руководитель со своим входом работает как раньше.

## Критерии приёмки

- AC1. Член утверждённого состава (документа или организации) после скана и PIN видит
  «За сегодня» — тот же список, что у заведующего производством. Ставит «Допущено /
  Не допущено», подписывает, получает «Подписано: N».
- AC2. Человек, добавленный кнопкой «Новый человек», проходит AC1 без «Сохранить состав».
- AC3. Должность «Член бракеражной комиссии» без состава видит список только для чтения и
  плашку. Подписать нельзя ни через UI, ни прямым POST.
- AC4. После «Сменить» новый человек видит свой вид по умолчанию, а не вид прошлого.
- AC5. `commission=1` без сессии в режиме «только после входа» требует PIN.
- AC6. Везде «Доброкачественно / Недоброкачественно». Старые записи готовой продукции
  показываются новыми словами.
- AC6a. При добавлении блюд (сайт: одно и списком; QR: одно и несколько) вводится только
  время изготовления. Бракераж = +N1, разрешение = бракераж + N2 (по умолчанию 5 и 5) —
  сохраняются сразу. Коррекция по QR у неподписанных строк сдвигает цепочку.
- AC7. `npx tsc --noEmit --skipLibCheck` (с `NODE_OPTIONS=--max-old-space-size=8192`),
  `npm run lint` (ошибок нет в изменённых файлах), `npm test` — зелёные. Смоуки
  `smoke-qr.ts`, `smoke-signatures.ts`, `smoke-commission.ts` и новый `smoke-member-list.ts` —
  зелёные на стенде.
