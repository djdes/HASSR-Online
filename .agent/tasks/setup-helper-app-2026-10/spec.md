# «Сетап помощник» — Android-приложение для печати этикеток (25.10.2026)

Зафиксировано до реализации.

## Запрос

Отдельное тестовое Android-приложение (APK) «Сетап помощник» для печати
этикеток на Bluetooth-принтер. Работает и с интернетом, и без него.

1. При первом запуске — вход с учётной записью сайта. Сессия сохраняется:
   дальше приложение не ходит на сервер проверять вход и работает офлайн.
2. Пока одна кнопка «Добавить оборудование»: поиск Bluetooth-устройств
   телефона, подключение принтера **AIYIN IP-802BT** (по спецификации, чтобы
   подключался наверняка).
3. После подключения, если есть интернет, в аккаунте на сайте видно, что
   оборудование подключено.
4. Кнопка «Пробная этикетка» 58×40 мм; печать по шаблонам.

## Спецификация принтера (источники)

База моделей официального драйвера Seagull для AiYin (`AiYin_12.3.0.exe`,
скачан с aiyin.com, раздел «Драйверы»; `AiYin.inf` → `"AiYin IP-802BT"=TSC`,
`ay#tsc_12.3.0.0.ddz/Model.d` → `[AiYin IP-802BT]`):

- язык команд **TSPL2** (`~CommandClass=TSPL2`, семейство драйвера TSC);
- 203 dpi (8 точек/мм), печатная ширина 72 мм, носитель 25,4–78 мм,
  длина 5–250 мм, носитель по умолчанию — этикетки с зазором (Gap),
  поддерживается чёрная метка; прямая термопечать; скорость 2/3/4 дюйм/с;
  плотность по умолчанию 8; носитель центрируется;
- драйвер рисует текст, линии и штрихкоды **картинкой** (`Drawing:IPRT`:
  `Text=false`, все штрихкоды `false`) — встроенные шрифты принтера не
  используются, кириллица печатается только растром;
- служебные команды драйвера: `AUTODETECT` (калибровка), `SELFTEST`,
  `INITIALPRINTER`, `FORMFEED`; резака/отделителя нет, `SHIFT` и
  `SET TEAR` не поддерживаются;
- Bluetooth: по руководству серии IP-802 Android сопрягается с PIN «0000»
  или «1234», iOS — через приложение без PIN (значит, есть и BLE).
- `BITMAP`: бит 0 — чёрная точка, 1 — белая (пример из руководства TSPL/TSPL2
  TSC: байты `00 00 … 07 FF …` дают чёрную стрелку на белом).

## Решения

- **Сессия = ключ устройства, а не кука сайта.** Как у «Онлайн принтера»
  (`PrintAgent`): почта и пароль один раз уходят на сервер, в ответ —
  долгоживущий ключ (32 случайных байта), в БД только sha256. На телефоне ключ
  зашифрован ключом Android Keystore (AES-GCM, ключ не извлекается). Ключ
  открывает только API приложения (не весь кабинет), отзывается с сайта по
  одному телефону и не протухает через год, как JWT-кука NextAuth.
- **Офлайн по умолчанию.** На старте сеть не нужна; печать идёт только по
  Bluetooth; шаблоны лежат в приложении. Сообщения сайту копятся в очереди на
  телефоне и уходят, когда появится сеть.
- **Печать растром.** Этикетка рисуется на телефоне (Canvas, любые шрифты и
  кириллица) в монохромную картинку 8 точек/мм и уходит одной командой
  `BITMAP` — как у официального драйвера.
- Приложение нативное (Java, без Capacitor): ему не нужен сайт в WebView, а
  Bluetooth и Keystore — нативные API.

## Критерии приёмки

- **AC1. Проект и сборка.** `mobile/setup-helper/` — отдельный Gradle-проект
  (Java, AGP 8.13.0, обёртка Gradle 8.14.3, JDK 21, compile/target SDK 36,
  minSdk 24), `applicationId` `ru.wesetup.helper`, название «Сетап помощник»
  (ставится рядом с WeSetup `ru.wesetup.app`, не заменяет его).
  `./gradlew testDebugUnitTest assembleRelease` проходит; release-APK подписан
  (схема v2+), не debuggable; ключ подписи в репозиторий не попадает
  (публичный репозиторий) — берётся из переменных окружения, без них release
  подписывается отладочным ключом. `android:allowBackup="false"`.
- **AC2. Вход и сохранённая сессия.** Первый запуск — экран входа (почта и
  пароль WeSetup) → `POST /api/setup-helper/auth`; включённое подтверждение
  кодом Telegram обрабатывается (`requiresCode` → экран кода →
  `POST /api/setup-helper/auth/code`). Ключ хранится зашифрованным (Keystore
  AES-GCM), профиль (имя, организация, сервер) — рядом; пароль не хранится.
  Следующие запуски открывают главный экран без единого сетевого запроса и
  работают в режиме полёта. «Выйти» стирает данные на телефоне и, если есть
  сеть, отзывает ключ (`POST /api/setup-helper/logout`). Ответ 401 на ключ
  (отключён на сайте) — выход с понятным сообщением.
- **AC3. «Добавить оборудование».** Единственное основное действие главного
  экрана. Запрашивает разрешения по версии Android (12+: `BLUETOOTH_SCAN`,
  `BLUETOOTH_CONNECT`; до 12: геолокация и включённое определение
  местоположения), предлагает включить Bluetooth. Показывает сопряжённые
  устройства + классический поиск + BLE-сканирование, объединённые по адресу;
  похожие на принтер имена (IP-802, AIYIN, Printer…) — сверху. Подключение:
  остановка поиска → сопряжение с автоподстановкой PIN «0000», затем «1234» →
  SPP (UUID `00001101-0000-1000-8000-00805F9B34FB`): защищённый сокет →
  незащищённый → канал 1; если не вышло или устройство только BLE — GATT
  (известные UART-сервисы принтеров или любая записываемая характеристика).
  Подключённый принтер сохраняется на телефоне и появляется на главном
  экране с кнопкой «Пробная этикетка 58×40».
- **AC4. Сайт видит подключение.** События `printer_connected`,
  `printer_printed`, `printer_removed` (UUID, время, адрес, имя, модель,
  транспорт / шаблон и копии) пишутся в очередь на телефоне и уходят сразу,
  если есть сеть, иначе — при появлении сети или следующем открытии.
  `POST /api/setup-helper/sync` (Bearer-ключ) обрабатывает события
  идемпотентно (повтор того же пакета ничего не меняет, событие старее
  записанного не затирает новое), проверяет каждое событие отдельно (битое
  отклоняется само, пакет — нет), отвечает списками `accepted`/`rejected`;
  приложение удаляет их из очереди. Сайт: «Настройки → Онлайн принтер» →
  блок «Принтеры этикеток»: имя и модель, адрес, когда и через какой телефон
  и кем подключён, последняя печать и шаблон; список телефонов с кнопкой
  «Отключить».
- **AC5. Протокол печати.** Задание: `SIZE 58 mm,40 mm`, `GAP 2 mm,0 mm`,
  `DIRECTION`, `REFERENCE 0,0`, `DENSITY 8`, `SPEED`, `CLS`,
  `BITMAP 0,0,58,320,0,<данные>`, `PRINT <копии>,1`; строки через CRLF; числа
  не зависят от локали телефона. Картинка: бит 0 — чёрный, старший бит —
  левая точка, ширина дополняется белыми битами до байта. Ширина картинки не
  больше печатной (72 мм). Поток байтов проверен unit-тестами. В меню принтера:
  «Калибровка» (`AUTODETECT`), «Самотест» (`SELFTEST`), настройки этикетки
  (размер, зазор, плотность, скорость, поворот на 180°, сдвиг).
- **AC6. Шаблоны.** В приложении (JSON в assets): «Пробная этикетка 58×40»
  (рамка, деления через 5 мм, принтер, организация, дата), «Маркировка
  продукта» (название, изготовлено, годен до = изготовлено + срок,
  ответственный), «Вскрытая упаковка», «Произвольный текст». Поля: текст,
  дата-время, срок. Экран печати: выбор шаблона, поля с умолчаниями (сейчас,
  срок, имя пользователя, организация), предпросмотр — та же монохромная
  картинка, что уйдёт на принтер, копии 1–99. Всё работает без интернета.
  Разметка шаблона общая для телефона и JVM-тестов (превью шаблонов PNG
  собираются тестом).
- **AC7. Сервер.** Prisma: `SetupHelperDevice`, `LabelPrinter` + связи в
  `Organization` — только добавление (`prisma db push` без потери данных).
  `POST /api/setup-helper/auth`: лимит попыток, та же проверка пароля, что у
  сайта (`verifyEmailPassword`), только руководство (`isManagementRole`), не
  ROOT, отметка входа (`recordLogin`); `POST /api/setup-helper/auth/code`;
  `POST /api/setup-helper/sync`; `POST /api/setup-helper/logout`;
  `POST /api/setup-helper/devices/[id]/revoke` (сессия сайта,
  `hasFullWorkspaceAccess`, только своя организация);
  `GET /api/setup-helper/download` (APK). Организация берётся из строки
  устройства, клиент её не передаёт. Чистые функции (разбор событий, план
  обновления принтера, адрес, время) покрыты тестами.
- **AC8. Интерфейс сайта.** Новые строки — в ru/en/uz
  (`printAgent.labelPrinters`), `npm run i18n:types` перегенерирован, каталоги
  валидны; тест рисует блок на трёх языках. Отключение — через `ConfirmDialog`,
  уведомления — sonner. Вид — как у соседних блоков страницы.
- **AC9. Проверки.** `npm run typecheck`, `npm run test:gate`,
  `npm run i18n:check`, `npx prisma validate`, eslint изменённых файлов,
  Gradle-тесты и `assembleRelease` зелёные. API проверен на локальной
  PostgreSQL сквозным сценарием: вход → синхронизация (в том числе повтор) →
  принтер в выборке страницы → отзыв → 401. В `mobile-check.yml` — задание,
  собирающее APK приложения.
- **AC10. Документация.** `mobile/setup-helper/README.md`: что внутри, как
  работает офлайн и где хранится сессия, протокол и источники спецификации
  принтера, сборка и подпись, как обновить APK на сайте. В PR — что меняет
  деплой (две новые таблицы через `prisma db push`, файл APK в `resources/`).

## Вне рамок

- iOS-версия.
- Шаблоны с сайта (редактор и синхронизация) — следующий шаг; формат JSON
  шаблонов в приложении для этого и выбран.
- Публикация в Google Play, постоянный ключ подписи (нужны секреты GitHub).
- Штрихкоды и QR на этикетках.
- Фоновая синхронизация при закрытом приложении (WorkManager).
- Проверка на живом принтере: в контейнере нет Bluetooth — проверяются поток
  команд (тесты), сборка и сервер.
