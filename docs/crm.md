# CRM в панели платформы (`/root/crm`)

Рабочее место продаж: все обращения в одном месте, переписка по каждому человеку,
напоминания РОП и ответственным. Код — `src/lib/crm/`, экраны — `src/app/root/crm/`,
задача и доказательства — `.agent/tasks/crm-rop-2026-11/`.

## Что попадает в CRM

| Канал | Откуда | Направление |
|---|---|---|
| Почта | ящики IMAP (рабочая admin@, личная РОП) — «Входящие» и «Отправленные» | входящее / наш ответ |
| Онлайн-чат | `SupportMessage` (рассылки «всем» не считаются ответом) | входящее / наш ответ |
| Обращение с сайта, Telegram-бот | `FeedbackReport` + ответ поддержки | входящее / наш ответ |
| Показ за 15 минут, заявка на услугу | `ServiceRequest` | входящее |
| Заявка партнёра | `Partner` | входящее |
| Счёт по ИНН | `PaymentOrder` (`paymentMethod="invoice"`) | событие |
| Регистрация | `Organization` + владелец | событие |
| Скачал шаблон журнала | `LegalConsent` `source="blank-download"` | событие |
| Звонки рабочей АТС | Телфин: история звонков, запись, расшифровка Whisper (Groq) | разговор / пропущенный / не дозвонились |
| WhatsApp, ВКонтакте, MAX, звонок с мобильного | кнопка «Добавить лид» | входящее |

Контакты склеиваются по почте → телефону (последние 10 цифр) → Telegram chat id →
пользователю платформы. Если почта или телефон есть у пользователя платформы, в карточке
видна его организация. Пишет в поддержку пользователь платформы — стадия «Клиент», иначе
«Новый». Отказ, написавший снова, возвращается «В работу».

## Звонки (Телфин)

Код — `src/lib/crm/telphin.ts` (разбор звонка, под тестом) и `telphin.server.ts` (API, записи,
расшифровка); шаг «звонки» прогона CRM, до напоминаний.

- **Что берём**: история звонков АТС (`call_history`) окнами по 30 дней (больше Телфин не отдаёт),
  первый проход — 90 дней, дальше от курсора `crm:cursor:telphin` с нахлёстом 3 часа (звонок
  попадает в историю после отбоя, а время у него — начала). Дубли отсекает `externalKey`
  `telphin:<call_uuid>`. Внутренние звонки между добавочными пропускаются.
- **К кому**: по номеру клиента (последние 10 цифр). Нет контакта — создаётся; есть пользователь
  платформы с этим телефоном (в профиле он может быть записан как угодно — сравниваем цифры) —
  в карточке его организация, стадия «Клиент». Контакт, у которого первым был звонок, узнаётся и позже.
- **Как в ленте**: разговор — канал `call` (входящий тоже снимает «ждёт ответа»: клиенту уже ответили
  голосом); не взяли трубку — `missed_call`, входящее, ждёт ответа и напоминает; не дозвонились —
  `call_attempt`, событие, ответом не считается. Сотрудник — имя добавочного из кабинета Телфина.
- **Запись** копируется к нам (`CrmCallRecording`, каталог `CRM_CALLS_DIR`, по умолчанию
  `.data/crm-calls`) — не в `uploads`: его отдают всем, а это разговоры с клиентами. Плеер в карточке
  берёт файл через `/api/root/crm/contacts/<id>/calls/<callId>` с теми же правами, что карточка.
  Звонки, переадресованные на мобильный, Телфин не записывает — «Записи нет».
- **Расшифровка**: Groq Whisper (`whisper-large-v3-turbo`, русский), до 6 записей за прогон; короче
  5 секунд и больше 25 МБ — без расшифровки. Сбой повторяется до 5 раз, потом «не получилось».
- **Ключи** (`.env` на сервере): `TELPHIN_CLIENT_ID`, `TELPHIN_CLIENT_SECRET` — приложение «WeSetup CRM»
  (тип Trusted) в кабинете Телфина; `GROQ_API_KEY`, `GROQ_PROXY_URL` (Groq из России напрямую не
  открывается), `GROQ_MODEL`. Нет ключей Телфина — шаг пропускается; нет ключа Groq — записи
  копируются, расшифровка ждёт.

## Отсев писем

Первое совпадение по порядку (`src/lib/crm/mail-filter.ts`):

1. правило «Всегда принимать» (адрес или домен) — принять;
2. правило «Всегда отсеивать» — «Стоп-лист»;
3. нет отправителя; адрес на wesetup.ru — «Внутренняя переписка» (уведомления сайта уже
   собраны из таблиц);
4. недоставка: mailer-daemon/postmaster, `multipart/report`, «Undelivered…»;
5. автоответ: `Auto-Submitted` ≠ no (RFC 3834), `X-Autoreply`, `X-Autorespond`,
   `X-Auto-Response-Suppress`, `Precedence: auto_reply`, тема «Автоответ / Out of office»;
6. спам-метки сервера: `X-Spam-Flag: YES`, `X-Spam-Status: Yes`, `X-Yandex-Spam: 4`;
7. рассылка: `List-Id`, `List-Unsubscribe`, `Precedence: bulk|list|junk`;
8. робот: noreply, no-reply, do-not-reply, notifications, mailer, bounce, robot…

Отсеянное не пропадает: «Почта и фильтры» → «Отсеяно» — «Вернуть» или «Вернуть и всегда
пропускать». Из карточки — «Это спам»: стадия «Спам» и адрес в стоп-лист.

## Напоминания

Только с 9:00 до 21:00 по Москве; ночью ждут утра. По «Спаму» и «Отказу» — никогда.

| Что | Когда | Кому |
|---|---|---|
| Нет ответа клиенту | 30 минут (у онлайн-чата этот шаг — сигнал поддержке через 15 минут) | ответственному, нет его — РОП |
| Эскалация | 4 часа без ответа | РОП и ответственному |
| Хватит пинговать | 7 дней | — (остаётся в сводке) |
| Клиент молчит | 3 дня после нашего ответа, если нет следующего шага (до 14 дней) | ответственному / РОП |
| Следующий шаг | в назначенное время (до 7 дней просрочки) | ответственному / РОП |
| Новое письмо | новый лид → РОП, ответ по контакту → ответственному | |
| Сводка | первый прогон после 9:00 | РОП (Telegram + почта) |

Ответом считается наше письмо (в т. ч. из «Отправленных»), реплика оператора в чате, ответ
поддержки, записанный звонок и отметка «Ответ не нужен». Заметка — не ответ.

Получатели: все РОП + ответственный. Если РОП не назначен — администраторы платформы.
Канал — Telegram, если привязан, иначе почта. Каждое напоминание уходит один раз
(`CrmReminderLog.dedupeKey`, строка пишется до отправки); не дошло ни до кого —
ключ снимается, и следующий прогон пробует снова.

## Роль РОП

«Команда и доступы» (или карточка клиента → «Доступ к панели») → роль с РОП или «Свой набор» с
переключателем «РОП». Нужен раздел «CRM» — окно отметит его само. Владельцу платформы разделы не нужны:
у его строки кнопка «Сделать РОП / Снять РОП» (можно и себе). РОП получает все заявки
(аудитория уведомлений `sales`: показ, услуги, счета, партнёры, регистрации, заполненная
анкета), напоминания CRM и утреннюю сводку.

Однократный сид `prisma/seed-crm-rop-2026-11.ts` при деплое назначает РОП:
alexey@wesetup.ru и владельца/руководителя компании «БФС» (ООО «БФС», ИНН 5018215599 —
по ИНН, названию, юр. названию или снимку ЕГРЮЛ организации) с подключённым Telegram. Совпало больше трёх человек — сид
ничего не выдаёт и пишет об этом в лог деплоя (только id и маска почты).

## Роли панели: менеджер, РОП, коммерческий директор

Роли настраивает владелец в «Команде и доступах» → «Роли» (`PlatformRole`, `src/lib/platform-roles.ts`).
Роль — это разделы панели, **охват данных** и флаг РОП; у человека — роль или «Свой набор».
Изменение роли сразу меняет доступ всех её людей (разделы и РОП копируются им).

| Встроенная роль | Разделы | Охват | РОП |
|---|---|---|---|
| Администратор | все | все | — |
| Коммерческий директор | все | все | да |
| РОП | CRM, клиенты, продажи, партнёры, ЭДО | все | да |
| Менеджер по продажам | CRM, клиенты, продажи | **свои** | — |
| Продажи, Поддержка, SEO и контент, Бухгалтерия, Аналитика | как прежние наборы | все | — |

**Охват «свои»** (менеджер): в списке клиентов — только закреплённые за ним; карточка и любые API
чужого клиента — 404 (проверка в `requireRoot` по адресу). В CRM — его контакты и свободные (без
ответственного) с кнопкой «Взять себе»; назначить другого менеджера, стоп-лист почты, «Почта и
фильтры», «Здоровье клиентов», «Воронка» — нет. РОП может быть сколько угодно.

**Закрепление клиента**: карточка клиента → «Ответственный менеджер» (назначает охват «все»). Лиды
CRM этой организации без ответственного или у прежнего менеджера переходят новому; новый контакт
клиента сразу получает его менеджера.

**Подпись КП и писем**: личная должность (окно доступа, у владельца — «Подпись и РОП») → «Моя
почта» → должность роли → должность в кабинете. Генератор КП подставляет подпись того, кто его
открыл; должность видна в PDF, веб-версии и письме.

CRM — отдельный раздел «CRM» (раньше входил в «Продажи»): сид `prisma/seed-platform-roles-2026-11.ts`
добавил его всем, у кого были «Продажи», привязал прежние наборы к ролям и назначил
alexey@wesetup.ru коммерческим директором.

## Настройка на сервере

1. **Крон** — раз в 5 минут (сбор, почта, напоминания, сводка). Строку ставит сам деплой
   (`scripts/install-crm-cron.sh`, идемпотентно, по метке `# wesetup-crm-cron`; ручную
   строку с `/api/cron/crm` заменяет):

   ```
   2-59/5 * * * * /bin/bash <каталог приложения>/scripts/cron-crm.sh >> $HOME/wesetup-cron-crm.log 2>&1 # wesetup-crm-cron
   ```

   `scripts/cron-crm.sh` берёт `CRON_SECRET` из `.env` приложения и шлёт POST на
   `http://127.0.0.1:3002/api/cron/crm`; в `~/wesetup-cron-crm.log` пишутся только сбои
   (маршрут отвечает 500, если шаг прогона упал). Состояние последнего прогона — на
   сводке («Автосбор») и в `CronRunState` (`job = "crm"`).

2. **Рабочая почта** — «CRM → Почта и фильтры → Подключить ящик» (только владелец
   платформы). Яндекс 360: `imap.yandex.ru:993`, SSL, логин — адрес, пароль — пароль
   приложения (Яндекс ID → Безопасность → Пароли приложений → Почта), в настройках почты
   включён IMAP. Папка отправленных — `Sent`. «Проверить» покажет папки ящика. Первый проход
   читает 30 дней, дальше — новые письма по UID. Ящик открывается только на чтение.

## Почему не готовая CRM

Смотрели Twenty, Chatwoot, Krayin, EspoCRM: это второй сервер, вторая база, вторая
авторизация и синхронизация обращений, которые и так лежат в нашей PostgreSQL. Взяли
библиотеки и идеи:

- [imapflow](https://github.com/postalsys/imapflow) и
  [mailparser](https://github.com/nodemailer/mailparser) (MIT, автор nodemailer) — IMAP и
  разбор писем;
- признаки автоответов — RFC 3834, [is-autoreply](https://github.com/BOOKATIGER/is-autoreply),
  [arp242.net/autoreply](https://arp242.net/autoreply.html);
- из Chatwoot/Pipedrive — единая лента по контакту, «ждёт нашего ответа» и следующий шаг
  с датой у каждого живого лида.

Не сделано (отдельными задачами): слияние дублей контактов вручную, сделки с суммами,
AI-разбор писем (только через очередь диспетчера, `docs/ai-dispatcher.md`), приём WhatsApp
и VK по API, переписка Telegram с рабочего аккаунта (через Telegram для бизнеса — нужен
Premium). Личные переписки MAX API не отдаёт — только вручную.
