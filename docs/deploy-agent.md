# Агент выката на сервере: master доходит до прода, даже если GitHub не достучался

Обычный выкат идёт из GitHub Actions (`.github/workflows/deploy.yml`): GitHub заходит на сервер по SSH, сервер
скачивает код коммита и проходит три шага (установка, сборка, переключение и проверка). Из зарубежных
дата-центров — а GitHub Actions работает именно оттуда — сервер принимает соединения через раз: 21.11.2026 выкат
упал ещё на ожидании SSH, и прод оставался на старой сборке, пока выкат не запустили заново.

В обратную сторону (сервер → GitHub) связь быстрая и стабильная. Поэтому сервер сам проверяет, дошёл ли до него
master, и если выкат из GitHub не дошёл — выкатывает тот же коммит сам, **теми же шагами**.

## Как работает

- Крон раз в 5 минут (`4-59/5`): `scripts/deploy-agent.sh` → `scripts/deploy-agent.mjs`.
- Сравнивает сборку сайта (`http://127.0.0.1:3002/api/build-info` → `fullBuildId`) с головой master (GitHub API).
  Совпадает — ничего не делает.
- Не совпадает — смотрит выкат этого коммита в GitHub:
  - выкат ещё идёт — ждёт;
  - упала выгрузка, ожидание SSH или шаги 1/3–2/3 — через 2 минуты после конца выката выкатывает сам;
  - выката вовсе нет (push не сработал, Actions лежит) — ждёт 20 минут, потом выкатывает сам;
  - упал шаг 3/3 (схема БД, проверка новой сборки, откат) или GitHub выкатил, а сайт другой — **сам не трогает**,
    пишет в Telegram: это повод для человека, а не для повтора;
  - master не впереди сборки сайта (позади или разошёлся) — не выкатывает, пишет в Telegram.
- Не больше 2 попыток на коммит; потом — одно сообщение и тишина до следующего коммита.
- Выкат агентом: код коммита с `codeload.github.com` (до 20 минут: у агента нет таймаута SSH-сессии, а скачивание
  бывает медленным — 21.11.2026 ~0,8 МБ/с), `deploy.tar` скриптом коммита (`scripts/deploy-tarball.sh`),
  затем скрипты шагов `Deploy step 1/3 … 3/3` **из `deploy.yml` этого же коммита** — подставляются только
  `APP_DIR` и SHA; если в шаге появится другое выражение `${{ … }}`, агент такой шаг не выкатывает. Шаг упал —
  остановка: шаги 1–2 живой сайт не трогают, шаг 3 сам проверяет новую сборку и откатывает.

## Один выкат за раз

Замок — каталог `~/.wesetup-deploy.lock.d` (`scripts/deploy-lock.sh`, внутри — кто держит). Его берут шаги выката
из GitHub (скачивание кода и шаги 1–3; ждут до 25 минут) и агент на всё время своего выката (освежает перед каждым
шагом). Замок старше 45 минут — от упавшего выката, снимается сам. Каталог, а не `flock`: его не унаследует демон
pm2, если шаг 3 запустит его заново.

## Где смотреть

- `~/wesetup-deploy-agent.log` — решения агента (только когда меняются: «ждём», «выкатываю», «не смог»).
- `~/.wesetup-deploy-agent/runs/*.log` — полный вывод каждого выката агентом, последние 10.
- `~/.wesetup-deploy-agent/state.json` — коммит, попытки, какие сообщения уже отправлены.
- Telegram администратору платформы (`TELEGRAM_BOT_TOKEN`, `PLATFORM_ADMIN_TELEGRAM_CHAT_ID` из `.env`, с
  `TELEGRAM_FORCE_IP`): «🚚 выкатываю», «✅ выкатил», «❌ не смог», «⚠️ сам не трогаю», «⛔ попытки кончились».

## Установка и выключение

- Ставит сам деплой: шаг 3 вызывает `scripts/install-deploy-agent-cron.sh` (как крон CRM; сбой не роняет
  выкатку). Скрипт пишет строку crontab с меткой `# wesetup-deploy-agent` и снимок окружения сеанса деплоя
  (`~/.wesetup-deploy-agent/env`: `PATH` с node, язык, пояс) — у крона PATH пустой.
- Выключить на время (ручной откат на сервере, разбор): `touch ~/.wesetup-deploy-agent-off`. Включить —
  `rm ~/.wesetup-deploy-agent-off`. Пока агент выключен, он ничего не скачивает и не выкатывает.
- Правильный откат по-прежнему — `git revert` в master (AGENTS.md); агент выкатит его так же, как обычный коммит.
