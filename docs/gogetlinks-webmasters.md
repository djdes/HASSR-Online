# Заявки вебмастеров GoGetLinks

Рабочее место: `/root/seo/links` → **Заявки вебмастеров**. Доступ имеют ROOT и сотрудники с делегированным разделом SEO. Используется подключённый кабинет GoGetLinks; пароль, cookie и баланс для анализа диспетчеру не передаются.

- Список включает все страницы входящих предложений кампании wesetup.ru. Оплаченные и принятые обзоры остаются в существующем реестре закупок.
- Клик по домену открывает карточку: все характеристики, доступные сервису, цены каталога и примеры размещения. Неизвестные показатели не заменяются нулями. Владельцы и история сотрудничества не выдумываются.
- **Анализ всех площадок** последовательно загружает карточки партиями до 20, сохраняет прогресс и передаёт данные каждой заявки диспетчеру. Загрузка сотен карточек занимает несколько минут; повторный запуск использует сохранённые данные. Недоступные карточки отмечаются явно.
- Если во время пагинации пришли новые заявки и выборка стала неполной, анализ блокируется до обновления списка. Короткий список рекомендаций — до 30 решений с аргументами; метаданные отчёта включают все рассмотренные идентификаторы. Это подтверждает состав переданных данных, но не гарантирует качество суждения модели.
- Список кешируется на 30 минут, карточки — на сутки. Даты источников видны в интерфейсе. Новая загрузка карточки сбрасывает прежние рекомендации для этого среза.
- Отчёт не является командой покупки. Ни загрузка карточек, ни анализ не вызывают принятие заявки, оформление заказа или оплату.

## API приложения

Все запросы используют обычную авторизованную сессию панели и проверку `requireRoot()` с SEO ACL:

| Запрос | Результат |
| --- | --- |
| `GET /api/root/gogetlinks/applications?campaignId=<GGL ID>` | Полный срез, `snapshotId`, количество источника, полнота, карточки, последний отчёт |
| `POST` с `{"action":"refresh","campaignId":123}` | Новый срез всех страниц |
| `POST` с `{"action":"cards","campaignId":123,"snapshotId":"<hash>"}` | Следующая партия ещё не прочитанных карточек |
| `POST` с `{"action":"cards","campaignId":123,"snapshotId":"<hash>","siteIds":[456]}` | Карточка выбранного участника этой кампании, в том числе повторная попытка |
| `POST` с `{"action":"analyze","campaignId":123,"snapshotId":"<hash>"}` | Отчёт диспетчера по всем заявкам среза; 409 при смене среза |

Срезы и карточки хранятся в существующей `PlatformSetting` с префиксом, включающим ID подключённого аккаунта и кампании. Изменений схемы БД нет.

## Нативный API GoGetLinks и api-anything

В `config/api-anything/sites/gogetlinks.json` добавлены чтения `listWebmasterApplications(campaignId,page)` и `getWebmasterSiteInfo(siteId)`. Они используют наблюдаемые формы сайта. POST здесь означает фильтрацию таблицы или получение карточки.

Для полной выборки приложение читает POST `/reviews/table` с `action=request`, `in_comp_id`, `page_num`, проверяет `ReviewsRequestData.pageNum/countAll` и уникальность строк. GoGetLinks игнорирует `page_num` в GET; обычное чтение одного URL не доказывает получение всех страниц. Нативный POST `/reviews/request` также проверен для компактной операции api-anything.

Диспетчер получает самодостаточное задание `wesetup_ggl_webmasters` через стандартную очередь ProjectsFlow. В задании есть каждая заявка, цены предложения и каталога, метрики, тематика, регион, возраст, индексация, ссылочность, скорость и первый пример размещения (все примеры доступны в API и карточке). Модель возвращает JSON; приложение отклоняет чужие ID, неполное покрытие и повторы рекомендаций. Инструменты покупки и cookie в задание не включаются.

SEO-анализ выполняет существующий Ralph: `C:/www/ralph/dispatch.ps1` supervises `dispatcher/wesetup-worker.ps1`; для типа `wesetup_ggl_webmasters` тот использует Ralph `llm-client.psm1` и его авторизованный Codex в отдельном временном рабочем каталоге без инструментов. Корень Ralph можно задать доверенной переменной окружения `RALPH_ROOT`. Авторизация Claude для этого задания не нужна. Общий дедлайн ожидания сайта — 100 секунд; произвольные ошибки и таймауты не вызывают повторной отправки.

Проверка движка без очереди: `powershell -NoProfile -File dispatcher/wesetup-worker.ps1 -TestRalphPromptFile <UTF-8 файл>`. При обновлении перезапускают только продуктовый воркер WeSetup, которым управляет Ralph.
