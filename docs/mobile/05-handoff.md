# 05. Что передать разработчику

Здесь всё, что вы получаете в консолях Apple, Google и Firebase и передаёте разработчику (Ярославу).
Он заносит значения в секреты GitHub (для сборки) и на сервер wesetup.ru (для push и ссылок) — по
[secrets.md](secrets.md).

**Что понадобится заранее** — пройденные разделы [01](01-apple-developer.md)–[04](04-firebase.md).

**Сколько времени** — 20 минут.

**Сколько стоит** — бесплатно.

## Таблица значений

| № | Значение | Как выглядит | Где взять | Кому и куда |
|---|---|---|---|---|
| 1 | **Team ID** | 10 символов, `A1B2C3D4E5` | developer.apple.com/account → Membership details ([01](01-apple-developer.md), шаг 3) | Разработчику → секрет GitHub `APPLE_TEAM_ID` и сервер `APPLE_TEAM_ID`. Вам — в Firebase (шаг 5 в [04](04-firebase.md)) |
| 2 | **Issuer ID** ключа App Store Connect API | `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` | App Store Connect → Users and Access → Integrations → App Store Connect API ([02](02-app-store-connect.md), шаг 4) | Разработчику → `ASC_ISSUER_ID` |
| 3 | **Key ID** ключа App Store Connect API | 10 символов | там же, строка ключа | Разработчику → `ASC_KEY_ID` |
| 4 | Файл ключа App Store Connect API | `AuthKey_XXXXXXXXXX.p8` | там же, **Download API Key** (один раз!) | Разработчику → `ASC_KEY_P8_BASE64` |
| 5 | Файл ключа APNs и его **Key ID** | `AuthKey_YYYYYYYYYY.p8` | developer.apple.com → Keys ([01](01-apple-developer.md), шаг 5) | **Никому не передавать**: вы сами загружаете его в Firebase ([04](04-firebase.md), шаг 5). Копию храните у себя |
| 6 | **Apple ID приложения** | число, `6740000000` | App Store Connect → приложение → App Information → Apple ID ([02](02-app-store-connect.md), шаг 2) | Разработчику → сервер `APPLE_APP_ID` |
| 7 | `GoogleService-Info.plist` | файл | Firebase → iOS-приложение ([04](04-firebase.md), шаг 3) | Разработчику → `GOOGLE_SERVICE_INFO_PLIST_BASE64` |
| 8 | `google-services.json` | файл | Firebase → Android-приложение ([04](04-firebase.md), шаг 2) | Разработчику → `GOOGLE_SERVICES_JSON_BASE64` |
| 9 | Ключ сервисного аккаунта Firebase | файл `.json` | Firebase → Project settings → Service accounts ([04](04-firebase.md), шаг 6) | Разработчику → сервер `FIREBASE_SERVICE_ACCOUNT_JSON` |
| 10 | Ключ сервисного аккаунта Google Play | файл `.json` | Google Cloud → Сервисные аккаунты → `play-publisher` → Ключи ([03](03-google-play-console.md), шаг 6) | Разработчику → `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON` |
| 11 | Отпечаток **SHA-256** ключа подписи приложения (Play App Signing) | `AB:CD:EF:...` (32 пары через двоеточие) | Play Console → Тестирование и выпуск → Целостность приложения → Подписание приложений ([03](03-google-play-console.md), шаг 7). Появится после первой загрузки сборки | Разработчику → сервер `ANDROID_CERT_SHA256`, вторым значением через запятую (первое — отпечаток ключа загрузки, он у разработчика уже есть) |

Значения 1–10 можно передать сразу, как только они появились. Значение 11 — после первой загрузки Android-сборки.

## Что разработчик передаёт вам

| Что | Зачем вам |
|---|---|
| Копию ключа загрузки Android `upload.jks` и пароль к нему (по запросу — он уже создан и хранится у разработчика) | Храните копию. Если разработчик потеряет свой — не придётся просить Google сбросить ключ. Никому больше не передавайте |
| Файл первой Android-сборки `.aab` | Для первой ручной загрузки в Play Console ([09-release.md](09-release.md)) |
| Телефон и пароль демо-входа для проверяющих | Вписать в анкеты Apple и Google ([08-review.md](08-review.md)) |

## Как передать безопасно

Ключи `.p8`, `.json` и пароли дают доступ к вашим аккаунтам. Их нельзя пересылать в обычном чате (Telegram,
WhatsApp), обычным письмом или ссылкой на облачный диск без пароля.

Один из двух способов:

1. **Менеджер паролей** (1Password, Bitwarden, KeePassXC и т. п.): общая папка с разработчиком или одноразовая
   ссылка с паролем и сроком жизни (например, Bitwarden Send: срок 1 день, удалить после первого открытия).
2. **Архив с паролем**: соберите файлы в архив 7-Zip → **Добавить к архиву** → **Шифрование: AES-256**,
   отметьте **Шифровать имена файлов**, придумайте длинный пароль. Архив отправьте любым способом,
   **а пароль — другим**: например, продиктуйте по телефону.

После передачи удалите файлы из папки «Загрузки» и из переписки. Оригиналы `.p8` и `.json` храните в одном
надёжном месте (менеджер паролей или зашифрованный диск).

## Частые ошибки

- Перепутаны два ключа Apple: **ключ App Store Connect API** (для сборки, передаётся разработчику) и **ключ APNs**
  (для push, загружается вами в Firebase). У них разные Key ID.
- Передан только Key ID без файла `.p8` (или наоборот) — сборка не подпишется.
- Передан только один отпечаток SHA-256. Нужны оба: ключа подписи приложения и ключа загрузки.
- Пароль к архиву отправлен в том же чате, что и архив.
