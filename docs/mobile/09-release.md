# 09. Выпуск: тестовые версии, отправка на проверку, публикация

**Что понадобится заранее**

- Пройдены разделы [01](01-apple-developer.md)–[08](08-review.md); разработчик занёс ключи ([05](05-handoff.md)).
- Ваш телефон (iPhone и/или Android) для проверки тестовых версий.
- Для Google — аккаунты Google (почты) тех, кто будет тестировать; для Apple — почты тестировщиков.

**Сколько времени** — ваши действия: около 2 часов. Проверка Apple — обычно 1–2 дня; проверка нового
приложения Google — обычно до 7 дней, бывает дольше (оценки, магазины сроков не обещают).

**Сколько стоит** — бесплатно.

## Шаг 1. Разработчик собирает первые версии

Разработчик запускает в GitHub: **Actions** → **«Выпуск приложений»** → **Run workflow**. У workflow три параметра:
`platform` (`both` / `android` / `ios`), `track` (куда отправить Android: `internal` — во внутреннее тестирование,
`none` — только собрать) и `play_status`. Для самой первой версии нужен **`play_status: draft`** — Google Play
отказывается принимать выпуск со статусом «completed», пока приложение хотя бы раз не было опубликовано; после
первой публикации разработчик переключает `play_status` на `completed`. Перед первым запуском iOS-сборки в App
Store Connect уже должна существовать запись приложения ([02](02-app-store-connect.md), шаг 1) — без неё сборка не
подпишется.

- **iOS** — сборка сама загружается в App Store Connect (раздел **TestFlight**), через 15–30 минут вам придёт письмо
  о готовности;
- **Android** — файл `app-release.aab`. Первый раз его нужно загрузить в Play Console вручную (так требует Google):
  разработчик присылает файл вам или загружает сам, если вы дали ему доступ ([03](03-google-play-console.md), шаг 8).

Отдельно, без вашего участия, при каждой правке в `mobile/` сам запускается второй workflow — **«Проверка
приложений»**. Он ничего не публикует и не требует секретов: собирает отладочный APK Android (можно скачать из
артефактов запуска и поставить на телефон отдельно от Google Play) и сборку iOS для симулятора без подписи —
это только самопроверка разработчика, на ваши действия она не влияет.

## Шаг 2. Google Play: внутреннее тестирование

1. Play Console → WeSetup → **Тестирование и выпуск (Test and release)** → **Тестирование** → **Внутреннее
   тестирование (Internal testing)**.
2. Вкладка **Тестировщики** → **Создать список адресов**: название `Команда`, впишите почты Google тестировщиков →
   **Сохранить**. Отметьте список галочкой → **Сохранить**.
3. Вкладка **Выпуски** → **Создать выпуск**.
4. Если появится вопрос о ключе подписи — выберите **Использовать ключ, созданный Google** (Play App Signing).
5. **Загрузить** → выберите `app-release.aab`. Дождитесь окончания проверки файла.
6. **Название выпуска** — оставьте предложенное (например, `1 (1.0.0)`).
7. **Примечания к выпуску** — между тегами `<ru-RU>` и `</ru-RU>` вставьте «Что нового» из [store-listing.md](store-listing.md).
8. **Далее** → **Сохранить и опубликовать**. Внутреннее тестирование проверки не ждёт.
9. На вкладке **Тестировщики** скопируйте **ссылку для присоединения** и отправьте тестировщикам. Они открывают её
   на телефоне под своим аккаунтом Google → **Стать тестировщиком** → **Скачать в Google Play**.
10. Скопируйте два отпечатка SHA-256 ([03](03-google-play-console.md), шаг 7) и передайте разработчику.

Дальше разработчик выпускает новые тестовые версии кнопкой — они попадают во внутреннее тестирование сами.

## Шаг 3. App Store: TestFlight

1. Письмо «The following build has completed processing» → App Store Connect → WeSetup → вкладка **TestFlight**.
2. Если у сборки статус **Missing Compliance** — нажмите **Manage** и ответьте про шифрование ([07](07-privacy-forms.md)).
3. Тестировщики-сотрудники сначала должны быть пользователями App Store Connect: **Users and Access** → **+** →
   почта, имя, роль **Developer** или **Marketing** → **Invite**. Человек подтверждает приглашение из письма.
4. **TestFlight** → слева **Internal Testing** → **+** → группа `Команда` → **Create** → **Add Testers** → выберите людей.
   Включите **Enable automatic distribution** — новые сборки будут приходить им сами.
5. Тестировщик ставит приложение **TestFlight** из App Store, открывает письмо-приглашение → **View in TestFlight** →
   **Install**.

Внешних тестировщиков (не из команды) тоже можно добавить — **External Testing**, но первую сборку для них Apple
проверяет (обычно до суток).

## Шаг 4. Проверка на своём телефоне

Пройдите список на iPhone и на Android. Если что-то не так — напишите разработчику, что именно и на каком экране.

- [ ] Вход по телефону и паролю, после входа — домашний экран, как на сайте.
- [ ] Приложение объясняет, зачем уведомления, и спрашивает разрешение.
- [ ] Push приходит (попросите разработчика отправить тестовое напоминание) и по нажатию открывает нужный экран.
- [ ] Ссылка из сообщения бота открывается в приложении.
- [ ] QR-плакат, отсканированный камерой телефона, открывает журнал в приложении.
- [ ] Печать журнала открывает системную печать.
- [ ] Скачивание отчёта открывает меню «Поделиться».
- [ ] Голосовой ввод: кнопка микрофона, разрешение, текст появляется в поле.
- [ ] Фото к записи: камера и галерея.
- [ ] Режим полёта → экран «Нет связи» → включить сеть → «Повторить».
- [ ] Android: кнопка «назад» возвращает на предыдущий экран, на домашнем — сворачивает приложение.
- [ ] «Профиль» → «Удалить аккаунт» — проверять только на тестовом аккаунте.

## Шаг 5. Google Play: отправка в рабочую версию

1. Проверьте, что на **Главной** (Dashboard) все задачи раздела «Настройте приложение» отмечены: карточка
   ([06](06-store-listings.md)), содержание приложения ([07](07-privacy-forms.md)), данные для входа ([08](08-review.md)).
2. **Тестирование и выпуск** → **Рабочая версия (Production)** → вкладка **Страны и регионы** → **Добавить страны** →
   **Россия** (и другие, где есть клиенты) → **Сохранить**.
3. Вкладка **Выпуски** → **Создать выпуск** → **Добавить из библиотеки** → выберите ту же сборку, что во внутреннем
   тестировании → примечания к выпуску → **Далее** → **Сохранить**.
4. **Обзор публикации (Publishing overview)**: включите **Управляемую публикацию (Managed publishing)** — тогда после
   одобрения приложение выйдет, только когда вы нажмёте кнопку.
5. **Отправить изменения на проверку** (Send changes for review).
6. После одобрения: **Обзор публикации** → **Опубликовать изменения**.

## Шаг 6. App Store: отправка на проверку

1. App Store Connect → WeSetup → **1.0 Prepare for Submission**.
2. Блок **Build** → **+** (Add Build) → выберите проверенную сборку → **Done**.
3. Проверьте, что заполнено всё из [06](06-store-listings.md), [07](07-privacy-forms.md) и [08](08-review.md).
4. **Add for Review** → **Submit for Review** (Отправить на проверку).
5. Статусы: **Waiting for Review** → **In Review** → **Pending Developer Release** (одобрено).
6. Нажмите **Release This Version** — приложение появится в App Store в течение суток.

Если пришёл отказ — [10-rejections.md](10-rejections.md).

## Шаг 7. После выхода

Сообщите разработчику, что приложения опубликованы: он заменит на сайте надпись о запуске приложений на ссылки
на магазины.

## Частые ошибки

- В Play Console нет кнопки загрузки через GitHub — первую сборку нужно загрузить вручную (шаг 2).
- Тестировщик Google открыл ссылку не тем аккаунтом Google, что в списке, — приложение ему «недоступно».
- В TestFlight нет сборки — не прошла обработка или ждёт ответа про шифрование (**Missing Compliance**).
- Отправили на проверку с неработающим демо-входом ([08](08-review.md)).
- Для iOS выбрана старая сборка — выбирайте ту, что проверяли на телефоне.
- Запустили выпуск с `play_status: completed`, пока приложение никогда не публиковалось, — Google Play отклонит
  выпуск; для самой первой версии нужен `play_status: draft`.
