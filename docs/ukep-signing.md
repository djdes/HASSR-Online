# Подпись журнала УКЭП

Документ журнала можно подписать квалифицированной электронной подписью (УКЭП): меню документа (⋯) →
«Подпись УКЭП». Подписывает руководитель (или сотрудник с правом «завершать» журнал) своим сертификатом на
токене через **КриптоПро ЭЦП Browser plug-in**.

## Что нужно на компьютере

- КриптоПро CSP (`https://cryptopro.ru/products/csp`) и КриптоПро ЭЦП Browser plug-in с расширением для
  браузера (`https://cryptopro.ru/products/cades/plugin`).
- Токен (Рутокен, JaCarta…) с сертификатом УКЭП, установленным в хранилище «Личное».
- Скрипт плагина `cadesplugin_api.js` подгружается с `cryptopro.ru` только при открытии окна подписи.
  Content-Security-Policy на сайте не задан (`next.config.ts`), так что загрузку ничто не блокирует.

На телефоне и в Mini App плагина нет: подписывать — с компьютера.

## Как устроено

1. `POST /api/journal-documents/[id]/ukep/prepare` — сервер собирает PDF документа (`generateJournalDocumentPdf`,
   язык — как у «Печати») и выдаёт его с SHA-256 и токеном на 15 минут (`src/lib/ukep-token.ts`: HMAC на
   `NEXTAUTH_SECRET` над документом, пользователем, организацией и хэшем).
2. Браузер подписывает ровно эти байты: откреплённая CAdES-BES, в подписи — сертификат подписанта
   (`src/lib/ukep-plugin.ts`: `CAdESCOM.Store` → `CAdESCOM.CPSigner` → `CAdESCOM.CadesSignedData.SignCades`).
3. `POST /api/journal-documents/[id]/ukep` — сервер сверяет токен и хэш, разбирает подпись
   (`src/lib/cms-signature.ts`) и сохраняет PDF и подпись в таблицу `JournalDocumentSignature`. ФИО, должность,
   организация, ИНН, СНИЛС, ОГРН, УЦ, серийный номер и срок берутся из сертификата внутри подписи.
4. `GET /api/journal-documents/[id]/ukep/[signatureId]?file=pdf|sig` — скачать PDF или подпись.

Почему байты в базе, а не в `/uploads`: загрузки отдаются по ссылке без входа, а журнал с ФИО сотрудников — нет.

## Что сервер проверяет и чего нет

- Проверяет: это CMS SignedData; подпись откреплённая; есть подписанные атрибуты (CAdES-BES); в подписи есть
  сертификат подписанта; сертификат действует на момент подписания; для SHA-2 — хэш PDF совпадает с подписанным.
- **Не проверяет математику подписи ГОСТ Р 34.10-2012** и цепочку до аккредитованного УЦ: ГОСТ-криптографии в
  Node нет. Подлинность проверяют по паре «PDF + .sig» на Госуслугах (`https://www.gosuslugi.ru/eds`) или в
  КриптоАРМ — ссылка есть в окне подписи.

## Проверено и не проверено

- Разбор подписи — на настоящей откреплённой подписи `openssl cms -sign` (RSA, SHA-256) с русскими полями
  сертификата (`src/lib/cms-signature.fixtures.ts`); структура CMS у ГОСТ-подписи та же, другие только OID.
- Обёртка плагина — на подставном объекте с API КриптоПро (константы сверены с `cadesplugin_api.js`
  21.11.2026). На живом токене с КриптоПро не проверялось: в среде разработки нет ни плагина, ни сертификата.
