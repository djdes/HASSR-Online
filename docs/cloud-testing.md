# Тесты и мониторинг в облаке

Всё работает без своего сервера: GitHub Actions, облачные сессии Claude и Sentry. На прод-сервер для этого ничего не ставится.

## Что и где работает

| Что | Где | Когда |
|-----|-----|-------|
| Сценарии на базе (`scripts/e2e/run-all.sh`, 20 сценариев) | GitHub Actions, `nightly-e2e.yml` | каждую ночь и на PR, которые их задевают |
| Смоук в браузере на ширине iPhone (`scripts/smoke/new-features.smoke.cjs`) | GitHub Actions, `nightly-e2e.yml` | так же; скриншоты лежат в артефакте запуска |
| Проверка прода (`scripts/monitor/prod-check.mjs`) | GitHub Actions, `prod-monitor.yml` | каждые 15 минут |
| Всё сразу одной командой (`npm run smoke:local`) | облачная сессия Claude | по запросу |
| Playwright MCP: Claude сам открывает сайт и прокликивает его | облачная сессия Claude (`.mcp.json`) | всегда доступен |
| Ошибки у живых пользователей | Sentry (sentry.io, данные в ЕС) | постоянно |

## Проверка прода

Каждые 15 минут проверяются `/api/health` (сервер жив, база отвечает, версия), главная, вход, `robots.txt` и `sitemap.xml`. Ещё проверяется, что прод отстаёт от master не больше чем на час.

GitHub проверяет сайт из-за рубежа, а оттуда соединение с сервером рвётся примерно через раз. Чтобы не было ложных тревог:

- на каждую страницу даётся до 6 попыток;
- если одна страница не ответила, а остальные ответили, это помеха связи, а не сбой;
- сбоем считается, когда сервер ответил ошибкой или не открылась ни одна страница.

Тревога приходит в Telegram (тот же бот и чат, что у выката) со второго подряд упавшего запуска, один раз. Когда всё восстановится, придёт ещё одно сообщение. Результат каждого запуска есть в Actions → «Prod monitor» → Summary. Запуск не краснеет из-за сайта, иначе GitHub присылал бы письмо каждые 15 минут сбоя.

Проверить вручную из облачной сессии: `NODE_USE_ENV_PROXY=1 MONITOR_NO_ALERT=1 node scripts/monitor/prod-check.mjs`.

## Смоук в облачной сессии

```bash
npm run smoke:local                      # сценарии на базе + смоук в браузере
SMOKE_ONLY=db npm run smoke:local        # только сценарии на базе
SMOKE_ONLY=browser npm run smoke:local   # только браузер (скриншоты в smoke-shots/)
```

Скрипт сам поднимает локальный PostgreSQL, создаёт одноразовую базу `haccp_smoke`, накатывает схему и сиды, запускает `next dev` и останавливает его в конце. Работает только с локальной базой, `.env` разработчика не использует.

`next dev` запускается без постоянного кэша Turbopack (`NEXT_DEV_FS_CACHE=0`, см. `next.config.ts`). На кэше от прошлого запуска сервер отдавал 404 на `/login` или бесконечно компилировал маршрут.

## Облачное окружение «HASSR-Online»

Это личное окружение Claude для этого репозитория. Скрипт подготовки при старте сессии ставит зависимости (`npm ci`), собирает клиент Prisma и скачивает `@playwright/mcp`, поэтому смоук и Playwright MCP работают сразу. Сеть ограничена: пакетные реестры, GitHub, `binaries.prisma.sh` и `wesetup.ru`. Для задач, которым нужен другой доступ (SEO-сервисы и т. п.), выбирайте окружение Default.

## Playwright MCP

`.mcp.json` запускает `scripts/dev/playwright-mcp.mjs`. Плагины из настроек репозитория облачная сессия не ставит, а серверы из `.mcp.json` подхватывает без вопросов.

- В облаке используется предустановленный браузер, без окна и через прокси сессии.
- На своём компьютере запускается обычный Chrome; Claude Code один раз спросит, включать ли сервер.
- Версия `@playwright/mcp` закреплена в скрипте и меняется вручную.

## Sentry: ошибки у живых пользователей

Аккаунт на sentry.io на почту владельца, организация `wesetup`, проект `javascript-nextjs`, данные хранятся в ЕС. Тариф бесплатный: 5 000 ошибок в месяц.

**Что ловит:**

- необработанные ошибки в браузере: сайт, приложение WeSetup и мини-приложение;
- ошибки экранов, которые показали «Что-то пошло не так» (`useReportError` в `error.tsx`);
- ошибки сервера: серверные компоненты, маршруты, proxy — с настоящим текстом ошибки (`onRequestError` в `src/instrumentation.ts`).

Включён только в продакшен-сборке на wesetup.ru (`src/lib/sentry-config.ts`). В `next dev`, CI и на localhost он выключен. На сервере его можно выключить без выкладки: `SENTRY_DISABLED=1` в `.env`, затем перезапуск.

**Что не уходит в Sentry:**

- пользователь, почта и IP;
- куки и заголовки, кроме браузера и языка;
- тела запросов и параметры в адресе;
- данные запросов к базе и локальные переменные;
- токены из ссылок: приглашения, QR, проверяющий, КП, вход по ссылке.

Браузер шлёт ошибки на свой домен, `/api/monitoring`; сервер пересылает в Sentry только тело события и только для нашего DSN. IP посетителя до Sentry не доходит, блокировщики рекламы ничего не режут. В самом проекте включены «не хранить IP» и приём только с wesetup.ru.

Код Sentry в браузере грузится отдельным файлом, когда страница уже открылась и браузер свободен (`src/lib/sentry-lazy.ts`). Поэтому первый экран не тяжелеет. Ошибки, случившиеся до загрузки, копятся и уходят сразу после. Это минимальный клиент `@sentry/browser`, а не `Sentry.init` из `@sentry/nextjs`: тот всегда тянет замеры производительности и добавлял бы 88 КБ gzip к каждой странице.

Сейчас подключены только ошибки, без трассировки и записи сессий: так страницы не тяжелеют и персональные данные не пишутся. Включаются в `sentry-config.ts`, если понадобятся; лимит бесплатного тарифа — 50 записей сессий в месяц. Стектрейсы браузера показываются по собранным файлам: для исходников нужен токен Sentry в секретах выката.
