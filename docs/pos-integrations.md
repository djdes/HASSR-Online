# Кассы и учётные системы: iiko, Poster, r_keeper

Что приходит в WeSetup из учётной системы ресторана и куда это попадает. Всё — на странице
«Настройки → Подключения», загрузка — кроном «Входящих» (`/api/cron/edo-sync`) и кнопкой «Забрать сейчас».

| Что | Куда в WeSetup |
|-----|----------------|
| Приходные накладные (iiko), поставки (Poster) | «Входящие накладные» (`/edo`) → «Принять» → строки журнала приёмки продукции |
| Акты списания (iiko), ручные списания (Poster) | «Потери» (`/losses`), источник «из iiko» / «из Poster» |
| Номенклатура и меню | Справочник продуктов: товары и ингредиенты — «Сырьё», заготовки — «Полуфабрикат», блюда — «Готовая продукция» |

Блюда с видом «Готовая продукция» сразу попадают в подсказки журнала бракеража (после своих недавних блюд,
`listNameSuggestions`) и в чек-лист «Температура готовых блюд на раздаче». Справочник пополняется только
недостающими позициями (по имени без учёта регистра): заведённое руками не меняется.

Склады iiko и Poster сопоставляются с точками («Склады … и объекты»): документы склада ложатся на его точку,
«Не загружать» — пропускаются.

## iiko

Сервер iiko (iikoOffice / iiko RMS): адрес, логин и пароль пользователя с правом входа по API. Каждая загрузка
входит на сервер и сразу выходит — лицензия API занята только на это время. Код: `src/lib/supply/iiko.ts`,
`iiko-map.ts`, `sync.ts` (`syncIikoData`).

## Poster

- Токен личной интеграции: в Poster «Доступ → Интеграции → Личная интеграция», вид `номер_аккаунта:ключ`,
  действует два года (продлевает поддержка Poster). Токен хранится зашифрованным, на странице — только номер
  аккаунта.
- API: `GET https://joinposter.com/api/{метод}?token=…&format=json`. Методы: `storage.getSupplies` и
  `storage.getSupplyIngredients` (поставки и строки), `storage.getWastes` и `storage.getWaste` (списания),
  `menu.getProducts` и `menu.getIngredients` (меню и ингредиенты), `storage.getStorages`, `storage.getSuppliers`.
  Суммы — в копейках, даты фильтров — `Ymd`. Выдержки документации —
  `.agent/tasks/pos-menu-poster-2026-11-21/raw/poster-docs/`.
- За одну загрузку — до 100 новых поставок и 100 списаний (у Poster ограничение частоты, ошибка 700); остальное
  забирается в следующий раз. Внешний id поставки — её номер в Poster, строки потерь — `poster:<списание>:<позиция>`.
- Код: `src/lib/supply/poster.ts` (клиент), `poster-map.ts`, `sync.ts` (`syncPosterData`), настройки —
  `/settings/integrations/poster`.

## r_keeper

Не подключаем. Открытого API для «своего» аккаунта у r_keeper нет: обмен с внешними системами идёт через
лицензируемые интерфейсы (XML-интерфейс кассового сервера, облачные сервисы UCS), которые включает дилер на
каждый ресторан. Без партнёрского договора с UCS и ключей конкретного ресторана интеграцию не сделать и не
проверить. Пока ресторан на r_keeper загружает накладные во «Входящие» через ЭДО (Диадок, СБИС) или файлом УПД,
а справочник — импортом из Excel.
